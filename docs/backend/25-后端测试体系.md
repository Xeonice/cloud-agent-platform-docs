# 25 — 后端测试体系：按批准设计重建

本项目尚未上线。用户已明确要求移除旧测试、重新规划；本文件与 `api/acceptance` 定义新的测试入口，旧测试数量与旧数据库升级路径不再构成验收依据。

规范来源是 [design-v2 产品规范](../design-v2/gap/product/README.md) 的 11 域 REQ/AC。`api/acceptance/manifest.json` 从当前规范逐行生成，保留 Given/When/Then、来源行号、后端/前端/共同职责和执行场景。1,016 是规范条目数量，不是已通过测试数。尚未映射的条目写 `planned`；关联了后端测试的 UI AC 也不等于完整浏览器验收。

## 1. 目录与边界

`acceptance/{wb,prj,lch,sbx,auth,crd,img,aut,sys,acc,dep}/{pure,service,sqlite,protocol}` 按产品域组织，而不按旧实现文件名称组织。

| 层       | 必须证明的事实                                             | 使用真实实现                                              | 可替换的边界                          |
| -------- | ---------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------- |
| pure     | 输入上限、状态转移、调度/提示符纯策略                      | 领域函数、schema                                          | 无 IO 替身                            |
| service  | 取消、单飞、竞态、失败补偿、幂等、资源释放                 | application/service/workflow                              | provider、授权厂商、clock、慢 IO 屏障 |
| sqlite   | 条件写入、同事务重验、回滚、删除级联、保留成果时刻         | 当前数据库初始化、production repository/UoW               | 网络和 provider                       |
| protocol | 路由、错误信封、认证、WS 帧、HTTP/MCP 一致性、完整 DI 装配 | 完整 AppModule/bootstrap、SQLite、真实 HTTP/WS/MCP 客户端 | 网络和 provider                       |

数据库测试从当前生产初始化创建干净库，不构造未上线产品的历史升级数据。凭证测试只使用合成材料，不输出明文。TTY 检测用真实子进程字节流；网络误报用本机真实 Git smart-HTTP fixture；这些边界不能被纯 mock 的期望值取代。

### 1.2. Vitest 工作区

统一采用 Vitest；源代码 alias 和 SWC decorator metadata 支持完整 Nest 装配。pure/service/sqlite/protocol 各有独立 include，不再运行旧目录。

### 1.4. 时间、ID 与并发屏障

Clock 与 IdGenerator 可注入；清扫直接调用 runOnce/sweep 或推进 fake timers。取消、撤销和删除用 deferred 控制跨异步先后顺序，断言晚到资源回收，不靠 sleep 猜时序。

### 1.5. 证据与覆盖率

不设置一刀切覆盖率阈值。必须核对产品结果、数据库副作用和失败补偿；manifest 的 planned/scenario-defined 不表示已执行或已通过。

### 1.7. worker 上限

vitest-capped 分两轮：pure/service/sqlite 最多四 worker，protocol 单 worker。VITEST_MAX_FORKS 只能进一步降低上限，每个测试须关闭自己的监听端口、目录和连接。

## 2. 首批关键场景与验收来源

| 产品域 | 必须保留或新建的关键场景                                                                                       |
| ------ | -------------------------------------------------------------------------------------------------------------- |
| PRJ    | 空项目就绪；排队取消；项目删除同事务活跃重验、规则/任务删除与失败回滚；成果登记/过期                           |
| LCH    | 项目/镜像门口拒绝零副作用；Unicode 指令上限；冻结镜像选择；任意准备阶段可取消                                  |
| SBX    | destroy 与 copy/create/start 的真实并发屏障；销毁超时与补偿；stop/start/delete 协议；成果离线读取              |
| AUTH   | 同 Agent 登录单飞；全机名额；取消与无人访问的过期清扫；清理失败/超时保留名额并重试                             |
| CRD    | SQLite 原凭证注入重验与绑定迁移；撤销补偿；SSH 首连主机指纹；同令牌真实仓库成功与 host-root 失败；DTO 不回显   |
| IMG    | 真实 digest 预检；版本参数继承与 Secret 密文；只读引用清单；destroyed 不阻挡删除、stopped 阻挡；同事务删除竞态 |
| AUT    | 规则上限/异常聚合；删除规则后运行任务继续；成功/失败真实终态；自动化成果登记失败可恢复                         |
| SYS    | 实际默认容量与任务准入一致；诊断按环境和证据下结论；审计脱敏与日志导出范围                                     |
| ACC    | 匿名保护请求不消耗 unlock 次数；显式错误口令计入共享限流；免口令/口令冷启动；HTTP/WS 同一访问策略              |
| DEP    | 初始化只采用真实检查结果；必需依赖未就绪不可放行；独立 DATA_ROOT 与完整 bootstrap                              |
| WB     | 真正 attached TTY 聚合等待输入；刷新查询和 WS 翻转一致；观察态不写领域状态/版本、不参与自动化决策              |

### 2.1. 同步 SQLite 事务

数据库场景使用当前生产 schema、repository 和 UnitOfWork。异步网络放在事务外暂停，同一同步事务重验项目、原凭证或镜像引用。失败必须断言所有关联行回滚。

### 2.3. CLI 字节 fixture

新解析场景直接构造合成 OSC 8、ANSI、折行与设备码字节，不依赖已退休的 CLI 捕获文件。覆盖折行错位、缺行和错误输出；真实子进程/TTY 场景单列，不以纯解析通过代替协议验证。

## 3. fixtures 与可复现性

新 support 仅负责本批场景所需的外部依赖，不携带旧 suite 的业务断言。数据库关键路径使用生产 SQLite 实现。所有进程、监听端口、临时目录、定时器在测试退出时关闭；协议测试用随机端口，不使用开发服务或用户数据目录。时间通过 Clock；竞态通过 deferred 屏障，避免以 sleep 猜时序。

### 3.4. 凭证不变量

新 CRD 场景核对明文不出现在 DTO/日志，注入只用已准备的 credentialId，同事务拒绝撤销/过期凭证。刷新 token 不得注入任务；清理失败须留下可恢复记录。

### 3.5. 镜像与环境策略

新 IMG/LCH 场景核对真实 digest 和冻结的 manifest ID；环境覆盖顺序、Secret 密文和保留字拒绝采用表驱动断言。版本切换继承参数，删除引用在同事务重验。

### 3.6. 等待输入观察

PromptHeuristic 无 IO 地处理 CLI 尾部；Detector 另测静默阈值、attached TTY 聚合、输入与 detach。完整网关验证 WS 翻转和查询一致，观察态不写 sandbox 版本或自动化状态。

### 3.7. 自动化决策

凭证、资源、前次 run、停用/删除规则及时区边界分别覆盖。真实 service/SQLite 场景另证任务独立收尾和登记失败重试，不以调度器 mock 的期望代替完整链路。

## 4. 旧测试退役顺序

1. 生成当前 11 域 AC manifest 和旧文件退役清单。
2. 把本轮新写的真实竞态/SQLite/CLI/Nest 回归按 AC 整理到新目录；重新构建必要 fixtures，为尚无关键场景的域写新测试。
3. 新场景源、断言与映射可评审；新入口跑通，类型检查、lint、关键协议装配通过。
4. 移除旧 HEAD 测试与仅服务旧 suite 的 helper/config 引用；再通过新 gates，确认不存在测试静默跳过。

不能把旧 suite 全量换名后称作重建；不能用删掉失败测试使 gate 变绿；不能把 AC 清单条数、计划条目或 skipped 条目报告为通过。

### 4.2. 授权挑战 fixture

按 Agent 保留合成 challenge 字节，覆盖设备码、完整 URL、OSC 8、折行 token、取消与超时。服务测试还覆盖 shutdown 后延迟 helper/adapter 返回的回收，禁止再写会话或凭证。

### 4.3. 注入与脱敏

记录 argv、stdin、环境和写文件字节，只用合成凭证。刷新 token 必须替换为约定占位值，任意分支和错误输出都不能泄漏。

### 4.4. 外部依赖最小化

新 support 仅替换当前场景的 provider、厂商授权和网络。SSH materializer 用实际文件核对权限、known_hosts 和 dispose；repository/事务用真实实现，不复制整套旧 helper 的业务语义。

## 5. 运行与报告

新入口由 `pnpm test:acceptance` 与分层项目组成；`pnpm check:acceptance` 只验证规范/测试源映射完整性，不验证行为。CI 必须报告实际执行的文件、测试数量、失败和 skip，并单独列未映射 AC。

精确命令、执行结果与未闭合项由最终 `api/acceptance/README.md` 和本轮报告记录。真实模型授权与需专用 Docker/BoxLite 主机的能力单列为环境验证，缺少环境时如实标明未运行。

### 5.1. 任务 HTTP/MCP

新 protocol 场景经真实客户端创建、查询、停止、启动和删除，核对准备期取消、错误信封和 REST/MCP 等价。实际完成的协议与场景单独报告，service 通过不标作 e2e。

### 5.7. 镜像协议

预检核对本次合法 digest；删除预览列真实项目与状态，stopped/failed 阻挡、destroyed 不阻挡。删除事务与参数继承由新 IMG 场景验证。继承场景使用当前 SQLite 与实际 AES-GCM，核对全部变量、原始密文、同 tag 原子切换以及重复更新不覆盖已编辑参数。

### 5.8. 完整 Nest 与终端

完整 AppModule 启动验证 DI 无循环；真实 WS 客户端核对 attach/input/output/exit、访问策略和断线清理。Native 子进程字节流验证等待输入 producer，不能只 mock QueryPort。

## 6. 协议与外部能力验证

HTTP/MCP/WS 通过实际客户端调用真实已装配 AppModule，核对错误信封、访问边界和数据来源。仅有 service 单测不能证明完整依赖图可启动；protocol gate 必须实际完成 bootstrap，并在结束时关闭服务。

### 6.1. 实际执行环境

Git/TTY 测试使用本机真实传输 fixture 验证字节、鉴权与错误分类。Docker/BoxLite/provider 的真实资源能力需要具备对应执行环境，不以 fixture 的通过代替厂商能力验收；环境验证结果单独记录。没有运行的条目保持未验证。
