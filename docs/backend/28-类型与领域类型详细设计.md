# 28 - 类型与领域类型详细设计（后端）

> 定位：[23](./23-领域模型与聚合设计.md) 讲**有哪些聚合/不变量**、[13](./13-后端数据库设计.md) 讲**表结构**、[shared/10 §7](../shared/10-接口契约与类型共享.md) 讲**对外 wire 类型**。本文补齐后端侧**实际的 TypeScript 类型声明**与**三层类型的映射**——拿到就能照着建 `contracts/`、`domain/`、`infrastructure/persistence/` 的类型。
> 权威链：wire 类型的单源是 zod（[02 §3](./02-MCP与OpenAPI双协议.md)）；领域类型是后端内部形态；DB row 是 Drizzle 推导。三者经 mapper 转换（§4）。

## 1. 三层类型总览

```
   contracts/（zod 单源）          domain/（领域类型）           infrastructure/persistence/（DB row）
   ── wire DTO / 枚举 ──   ◀──map──   聚合根 / 值对象 / 事件   ──map──▶   Drizzle $inferSelect/$inferInsert
   camelCase, 对外              branded ID, SecretMaterial            snake_case, 与 13 表 1:1
```

三条边界铁律（对应 01 §3 分层 + 审计 P1-5 / P0-2）：
1. **wire ↔ domain**：DTO 是扁平数据、domain 是带不变量的对象；转换在 application 层的 mapper，**不共用类型**（domain 不 implements DTO）。
2. **domain ↔ row**：字段名 snake↔camel、明文/密文分界（`SecretMaterial` 不入 row 的明文列）、派生字段不落表（`waitingInput`）——映射在 repository。
3. **同步写**（P0-2）：仓储"事务内写"是**同步签名** `saveSync(tx, agg): void`，异步端口只在事务外；类型上用返回 `void`（非 `Promise<void>`）从签名层堵死 async 写。

### 2.2 sandbox 上下文

```ts

  readonly id: SandboxId;
  readonly projectId: ProjectId;
  readonly runtime: string;

  initialTask: InitialTask;              // S5 裁决 D-14：「跑什么」（prompt + 一次性消费标记），不并进 ExecutionPolicy
  version: number;                       // 乐观锁
  private transitions: StateTransition[];// 内部实体，saveSync 时追加
  transitionTo(next: SandboxStatus): void;  // assert canTransitionTo（I-SBX-1），非法抛 InvalidSandboxTransitionError
  consumeInitialTask(at: Date): void;    // 一次性、不可回退（I-SBX-10）；bootstrapAgentSession 成功后调（03 §4.3 ⑤）

// 值对象
class SandboxStatusVO {                  // 转移表是静态数据、不散落 if-else（I-SBX-1 可穷举单测前提）
  static canTransitionTo(from: SandboxStatus, to: SandboxStatus): boolean;
}

interface InitialTask { prompt?: string; consumedAt?: Date; }   // 值对象，≤8000 字符；consumedAt 非空 ⇒ prompt 非空（I-SBX-10）
//   落列 sandboxes.initial_prompt / initial_prompt_consumed_at（13 §2.1.1）；**不进 SandboxDto**（10 §7.3）
interface StateTransition { from: SandboxStatus; to: SandboxStatus; at: Date; triggeredBy: TriggeredBy; }

interface SandboxRepository {
  findById(id: SandboxId): Promise<Sandbox | null>;
  findByProject(projectId: ProjectId, filter?: { status?: SandboxStatus[] }): Promise<Sandbox[]>;
  findByProviderHandle(handle: ProviderHandle): Promise<Sandbox | null>;
  listIdleCandidates(now: Date): Promise<Sandbox[]>;
  listNonTerminal(): Promise<Sandbox[]>;
  saveSync(tx: Tx, sandbox: Sandbox): void;          // 同事务写 sandboxes + transitions
  touchActivity(id: SandboxId, at: Date): void;      // 窄写入，自带极短事务（terminal 高频，§10.4）
}
```

领域事件（**用领域名，非 WS 投影名**——23 §12：领域事件是源、WS 是投影，非一一对应）：`SandboxCreated` · `SandboxStateChanged` · `SandboxDestroyed`。`waiting-input` **不是领域事件**（23 D-2）——是网关内存态，只经 WS + REST 派生字段。

## 3. DB row 类型（Drizzle 推导）

```ts
// infrastructure/persistence/schema/*.sqlite.ts —— 与 13 表 1:1，snake_case
import { sandboxes, projects, credentials, /* … */ } from './schema';
type SandboxRow      = typeof sandboxes.$inferSelect;      // { id, project_id, status, clone_status?, workspace_path, headless, timeout_minutes, initial_prompt?, initial_prompt_consumed_at?, version, … }

type CredentialRow   = typeof credentials.$inferSelect;    // { id, kind, runtime_id?, obtained_via, ciphertext?, encryption_key_id, masked_identifier, revoked_at?, … }

```
约束（13 §1）：不用 `pgEnum`（枚举用 `text` + CHECK，跨方言可移植）、不用 `.array()`、时间戳统一 JS `Date`——这些是 PG 双方言可迁移性的编写纪律。

## 4. 三层映射表（DB row ↔ domain ↔ wire DTO）

| 概念 | DB row（snake） | domain | wire DTO（camel） | 边界说明 |
|---|---|---|---|---|
| sandbox 状态 | `status` (12值CHECK) | `Sandbox.status: SandboxStatus` | `SandboxDto.status` | 三层同枚举字面量 |
| 等待输入 | **不落表** | 网关内存 | `SandboxDto.waitingInput`(派生) | 只出现在 DTO，投影自网关（§WS） |
| 凭证密文 | `ciphertext`(加密) | `SecretMaterial`(内存明文) | **不出现** | 明文永不越过聚合边界（I-CRD-2） |
| 凭证掩码 | 由 row 计算 | `toMaskedView()` | `MaskedRuntimeCredential` | 对外只掩码 |
| 项目来源 | `source_type`+`repo_url` | `Project.sourceType/repoUrl` | `ProjectDto.sourceType`(**无 repoUrl**) | 来源不对外展示（产品定案） |
| 时区 | `automations.timezone` | `Schedule.timezone` | `CreateAutomationRequest.timezone` | 快照，编辑不隐式重传（I-AUT-9） |
| ID | `id` (text) | `SandboxId`(branded) | `string` | branded 只在 domain，进出解/包 |

映射方向：**读** row →（repository.toDomain）→ domain →（application mapper.toDto）→ DTO；**写** DTO →（application）→ command →（domain 构造/方法）→ aggregate →（repository.saveSync）→ INSERT/UPDATE。

## 7. 端口 / SPI 接口类型（六边形边界——后端最核心的类型契约）

> application/domain 只依赖这些**端口接口**，不依赖具体实现（01 §3）。实现在 infrastructure，经 DI token 注入。这是"registry 可扩展 + 契约集中"（需求 6/7）的类型落点。

### 7.1 SandboxProvider / RuntimeAdapter（**权威在 04，本节只引用不重述**）

> ⚠️ **单一权威制**（交叉评审 P1-1/P1-2）：`SandboxProvider`、`RuntimeAdapter`、`ProcessStream`、`SandboxProviderContext`、`SandboxExecFn`、`SandboxProviderCapabilities`、`VolumeMount` 的**完整定义在 [04 §2/§3](./04-Contract与Registry扩展体系.md)**（发布为 `@platform/sandbox-contracts`，04 §9）——04 是这些 SPI 类型的唯一权威。本文**不重抄**（此前重抄引入了 6 处漂移已删除）。application/domain 从 `contracts` 包 import 这些接口。
>
> 引用时注意几个易抄错的点（以 04 为准）：
> - `SandboxProvider.name`（**不是 `.id`**；registry key，SP-01 断言 `handle.provider === provider.name`）；`RuntimeAdapter.id`（runtime 侧用 `id`）
> - `capabilities: SandboxProviderCapabilities` 是 **boolean 结构体**（`{ spawnTty, volumeMount, updateResources, pauseResume, snapshot, watchEvents }`，04 §2.5）——**不是 number 位掩码**（testkit CAP-01 逐位断言依赖字段名）
> - `ProcessStream.onData(cb: (chunk: Buffer) => void)`（**Buffer 非 string**）；`onExit(cb: (code:number)=>void)` 是 exit 帧的来源（10 §7.4 保留 exit 帧的理由）
> - `SandboxProviderContext.image: ResolvedImageSpec`（**已 resolve+validate**，非 `ImageRef`）；含 `sandboxId`/`labels`
> - `SandboxExecFn` 返回 `{ stdout, stderr, exitCode }`（04 §2.2 `toExecFn` 派生）
> - `createCredentialFromSecret(method: 'api-key'|'access-token-paste', secret)`（两个 method）
>
> `SandboxHandle`、`ProcessSpec`、`SandboxCommand`、`RuntimeTaskSpec`、`AuthChallenge` 同样以 04/10 §7.2 为准，本文不复制。

### 7.3 基础设施端口（Vault / Crypto / Clock / Id / UnitOfWork）

```ts
// —— 时间/随机可控化（25 §1.4；全仓禁 new Date()/Date.now()/randomUUID，走端口）——
interface Clock { now(): Date; }
interface IdGenerator { next(): string; }

// —— 事务（P0-2 同步）——
type Tx = Brand<object, 'Tx'>;                              // 不透明句柄，只在 saveSync(tx) 里传递
interface UnitOfWork { run<T>(fn: (tx: Tx) => T): T; }      // 同步返回；回调内禁 await（tsc 层面用 (tx)=>T 非 async 约束）

// —— 凭证 Vault（05 §4）——
interface CredentialVault {
  store(cred: RuntimeCredential): Promise<MaskedRuntimeCredential>;   // AES-256-GCM 落库
  materialize(credentialId: CredentialId, handle: SandboxHandle): Promise<void>;  // 注入
  revoke(credentialId: CredentialId): Promise<void>;                 // 擦除密文 + 联动清除
}
interface CryptoService { encrypt(plain: SecretMaterial, keyId: string): EncryptedBlob; decrypt(blob: EncryptedBlob): SecretMaterial; }
interface EncryptedBlob { ciphertext: Uint8Array; keyId: string; iv: Uint8Array; }   // keyId 支持轮换（P1-11）

// —— Outbox / 事件总线 ——
interface EventBus { publishInTx(tx: Tx, events: DomainEvent[]): void; }   // 与业务同事务写 domain_events（R-3）
```

## 11. 错误类型与 envelope 映射

```ts
// domain 错误（interface 层翻译成 ErrorEnvelope，02 §6）
class InvalidSandboxTransitionError extends Error {}   // → 409
class ConcurrencyConflictError extends Error {}        // 乐观锁 version 不匹配 → 409
class InvariantViolation extends Error {}              // 聚合不变量断言失败 = 编程错误 → 500
class ResourceExhaustedError extends Error {}          // → 携带 retryable=true
class DiskInsufficientError extends Error {}           // → 507（调度/工作区准备域，23 §5.6）
class WorkspacePrepareFailedError extends Error {}     // → 500（preparing-workspace 失败）
// provider 错误（04 §4，retryable 是一等字段——ErrorEnvelope.retryable 的来源）
interface SandboxProviderError extends Error { code: string; retryable: boolean; }
// 映射：interface 层 errorMapper(e): { httpStatus, envelope: ErrorEnvelope }
//   未映射 → { httpStatus: 500, code: 'INTERNAL', retryable: false }（永不缺省 code）
// env 校验：EnvValidationError → 400 + details[]（ENV_NAME_INVALID/ENV_NAME_RESERVED/ENV_LIMIT_EXCEEDED/ENV_DUPLICATE_KEY）
```
