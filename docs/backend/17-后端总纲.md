## 2. 限界上下文协作地图

```
                         interface 层（三协议面）
          REST Controller │ MCP Tools │ Terminal WS Gateway
                    └──────────┼──────────┘
                        application 层（协议无关门面）
   ┌────────┬────────┬────────┼────────┬────────┬────────┐
   ▼        ▼        ▼        ▼        ▼        ▼        ▼
 project  sandbox  runtime credential image  terminal automation
 (clone+  (调度+   (adapter  (Vault+  (manifest (会话+   (定时触发
  基线目录+  状态机+   选择/    Git 凭证) 校验+env  waiting-  →调 sandbox
  保留卷)  工作区)   鉴权)              合并)     input)   app service)
   │        │        │        │        │        │        │
   │ 领域事件总线（shared-kernel EventBus + domain_events Outbox）
   └────────┴────────┴────────┴────────┴────────┴────────┘
                              │
              platform/registry（三个 DI token registry）
                              │
              contracts 包（SandboxProvider / RuntimeAdapter / ImageSpec）
                              │
              infrastructure 实现（aio / boxlite / ClaudeCode / Codex / Sqlite）
```

**上下文间协作规则**（文档 01 §5）：不直接调对方 domain，走 application service 或领域事件。关键事件流：

| 事件 | 生产方 | 消费方 |
|---|---|---|
| `SandboxStateChanged` | sandbox | terminal（级联关会话）、WS 事件通道（推前端）、Outbox（domain_events 表） |
| `SandboxReconciledAsOrphan` | sandbox（对账） | 审计 / 前端提示 |
| `CredentialRevoked` | credential | sandbox（清除已注入文件，经 credential_sandbox_bindings 联动） |
| `ProviderEvent`（容器意外退出等） | infrastructure（watchEvents） | sandbox 状态机（经 SandboxStatusObserver） |
| `ProjectCloneProgress` / `ProjectCloneCompleted` | project（clone 编排，03 §7.2） | WS 事件通道（`project.clone_progress`，10 §3）；创建流程解除对基线目录的等待 |
| `AutomationRunFinished` | automation（03 §8） | webhook notifier（trigger_on 匹配）、失败计数与降频判定 |

**不进 Outbox 的推送**：`sandbox.waiting_input` 与 `project.clone_progress` 是可丢失的高频展示事件，由网关/编排器直接推 WS，不走 domain_events（理由见 10 §3.1）。

## 3. 四条核心流程的跨域串讲

每条流程标注途经的域与对应文档，作为 review 和实现时的导航索引。

### 3.1 创建 sandbox（REST/MCP → 运行）

```
interface(02) → SandboxApplicationService
  → image.validate(manifest) + env 三层合并与黑名单校验  [image · 04§7, 05§4.1]
  → SchedulerQueue → 互斥区配额登记               [sandbox · 03§3, 13§2 resource_allocations]
  → preparing-workspace：建宿主目录 + cp -a --reflink 从基线目录复制  [03§7.6 ★工作区先于实例，审计 P0-1]
  → registry.get(provider).create（挂载已存在的宿主目录）  [04§8 → aio(默认) / boxlite]
  → provider.start + CredentialVault.materialize/injectCredential  [05§4]
  → 状态机 pending→…→preparing-workspace→starting→running，每次转移事务内双写  [03§4, 13§3]
  → SandboxStateChanged → Outbox → WS 推前端      [13§2 domain_events]
  失败 → 回滚配额登记 + rm -rf 半成品目录 + status=failed  [03§3, 03§7.6]
```

产品进度卡的四格（P20 §3.3：初始化 → 拉镜像 → 准备工作区 → 启动实例）是**面向用户的叙述**，与技术状态顺序不同——技术上先备工作区再建实例（03 §4.0 已写明映射）。**没有「等待登录」阶段**（05 §2 决策 A）。

### 3.2 终端会话（前端 xterm ↔ 容器）

```
WS /terminal 连接（?socketSessionKey=）           [06§2, 13§2 terminal_sessions]
  → provider.spawn({tty:true, reuse: tmuxRef})    [04§2.4 ProcessStream, 06§6]
  → 双向流转发 + resize 同步 + 16ms 批量合并        [06§4/§7]
  → 同批刷 last_active_at（节流≥10s）+ waiting-input 检测  [06§8, 03§4.1/§4.2]
  断线 → tmux detach（或 ring buffer + grace）     [06§6]
  重连 → 凭 session key re-attach + replay        [06§6, 08§3 前端对端]
  sandbox 销毁事件 → 级联关闭全部会话               [06§5]
```

**idle 口径 = 终端无输入输出**（非进程 CPU）；`waiting-input` 是 running 的展示子态，**不落库、不驱动任何决策**（03 §4.1 红线）；stop 后重启开的是**新 agent 会话**，tmux 现场恢复只适用断线重连（03 §4.2 / P22 §2）。

### 3.3 runtime 鉴权（订阅登录 → 凭证复用）

```
begin → 在 auth helper 内 spawn({tty:true}) 起登录命令   [05§2 决策A, 11§1.1；★不依赖任何任务 sandbox]
  → adapter 正则捕获 AuthChallenge                 [04§3；脆弱点→golden fixture 04§10]
  → 前端展示，用户自己浏览器授权                     [05§2 安全边界]
complete → 写 helper pty stdin / 轮询输出           [05§3]
  → CLI 落盘凭证 → Vault 加密收编 → helper 内明文即时清除  [05§4, 13§2 credentials]
复用 → materialize 写回新 sandbox                  [05§3, 13§2 credential_sandbox_bindings]
吊销 → 擦除密文 + 联动清除已注入文件                 [13§2, 05§4]
```

端点**全部无 sandbox 维度**：`POST /api/runtimes/:rt/auth/{begin,complete}`、`GET .../auth/status`（05 §3）；聚合状态走 `GET /api/runtimes`（02 §5.1）。Git 凭证（kind='git'）是并列但独立的管道，**只在平台侧 clone 时使用、绝不注入 sandbox**（05 §3.2 / 03 §7.3）。

### 3.4 状态感知与对账（防状态漂移）

```
常态: SandboxStatusObserver
  ├─ capabilities.watchEvents=true → 原生事件流驱动状态机（aio 容器事件 / boxlite 回调）[04§6]
  └─ =false → 轮询 inspect（10s/60s 分频）                     [04§5]
补偿: 进程重启 onApplicationBootstrap 全量对账                  [13§4]
      事件流重连 → 立即全量 inspect 补偿                        [04§6]
      运行期 5min 增量对账                                     [13§4]
三路对比 → confirmed / orphaned(释放配额) / 清理野容器           [13§4]
补充清理: 扫 workspaces/ 下标记文件为 preparing 的目录一律 rm -rf  [03§7.6 半成品目录]
          clone_status='cloning' 但无子进程 → 判 INTERRUPTED     [03§7.2 不续跑]
```

### 3.5 项目 clone（异步，一次克隆多次复制）

```
POST /api/projects → 202 + clone_status='cloning'              [02§5.1, 13§2 projects]
  → 后台 job（独立队列，并发上限 2）git clone --depth=1 到基线目录  [03§7.2]
  → 按 URL 协议自动选 Git 凭证，经 CREDENTIAL_FACADE.prepareGitAuth 拿句柄（明文不出 credential；SSH 临时密钥 0600 / HTTPS helper 按 host 白名单绑定）[03§7.3, 05§3.2, 23§8]
  → --progress 解析 → 节流 1s → WS project.clone_progress       [10§3]
  → >10min 补 slow 事件；30min 硬超时终止 + rm -rf 半成品目录            [03§7.2]
  失败 → CLONE_FAILED_NETWORK / CLONE_FAILED_PERMISSION / DISK_INSUFFICIENT  [03§7.5, 02§6.1]
发起 Task 时：基线目录 →【cp -a --reflink 复制】→ Task 专属目录（03§7.1，独立副本）
```

### 3.6 自动化触发（v1.1）

```
每分钟扫描 (enabled, next_trigger_at) → 先推进 next_trigger_at 再执行  [03§8.1]
  → 决策：PREVIOUS_RUNNING skip / AUTH_EXPIRED skip / 资源不足 24min×5 重试 / 宕机 missed 不补跑  [03§8.2]
  → 创建【标准无头 Task】——走 3.1 同一条流程，不绕过配额/状态机/独立副本  [P21-7§9 硬约束]
  → 硬超时默认 2h（规则可配 30min/1h/2h/4h）→ 超时转 failed 并计入连续失败  [03§8.3]
  → 连续失败 ≥3 降频为每日一次；降频后再失败 7 次自动禁用；成功一次清零     [03§8.4]
  → 终态按 trigger_on 发 webhook（失败不影响 run 状态）              [03§8.5]
  → 原始 stdout/stderr 落盘 10MB×3 轮转 + 分页查询接口                [03§8.6]
```

## 4. 横切机制汇总

| 机制 | 设计要点 | 文档 |
|---|---|---|
| Registry 双通道 | DI token 动态模块（主）+ 插件目录扫描（semver 校验） | 04§8 |
| 错误模型 | contract 错误 → domain 错误 → REST 状态码 / MCP tool 错误，三层映射；domain 不依赖 contract 错误类 | 04§4 |
| Schema 单一来源 | 一份 zod → REST DTO + Swagger + MCP inputSchema | 02§3 |
| 事件与 Outbox | EventBus（进程内）+ domain_events 表（投递/回放/审计） | 13§2 |
| Guard | **MVP 即访问口令 Guard**（16 位口令、5 次锁 5 分钟、session 7 天、只存 hash），统一覆盖 REST/MCP/WS 三面；compose 默认只监听 127.0.0.1（审计 P0-3） | 11§3/§3.1 |
| 凭证安全 | AES-256-GCM + 密钥轮换字段 + 掩码回显 + revoke 擦除密文 | 05§4, 13§2 |
| **凭证 vs 镜像 env 双管道** | 三层合并（镜像→项目 v1.1→Task）+ 命名 regex + 黑名单；**凭证最后写入，同名永远赢**（安全性不依赖黑名单完整性） | 05§4.1, 13§2 |
| **错误码兜底** | 未映射码一律带 `code`+`traceId` 返回；前端显示「操作失败（错误码 XXX）」绝不裸抛；新增码必须同步 P22 §1 与 02 §6.1 | 02§6.1/§6.2 |
| **流式诊断** | `POST /api/system/diagnose` 用 **SSE**（不用 WS——诊断要能在 WS 坏掉时可用），单项超时 5s 不阻塞整轮 | 02§5.3 |
| 类型治理 | strictTypeChecked + no-unsafe-* + NestJS 豁免项（DI 空类/构造参数属性） | 14§4/§8 |

## 5. 启动时序

```
1. config 加载（@nestjs/config + zod 校验）
2. persistence 初始化 + drizzle migrate
3. registry 注册：内建 provider/adapter → 插件目录扫描（semver 校验，冲突 fail-fast）
4. 资源池初始化（os 探测 + 15% 预留）
5. 全量对账（resource_allocations vs provider inspect）
   5b. 清理标记为 preparing 的半成品工作区目录（03§7.6）
   5c. clone_status='cloning' 且无子进程的项目 → 判 INTERRUPTED（03§7.2，不续跑）
6. SandboxStatusObserver 启动（事件订阅或轮询）
7. auth helper 就绪探测（容器在否 + 两个 CLI 版本），结果纳入诊断项（11§1.1）
8. 三协议面挂载：Swagger + McpModule + WS Gateway
9. SandboxReaper / VolumeReaper / AutomationScheduler / Outbox relay 定时任务启动
```
