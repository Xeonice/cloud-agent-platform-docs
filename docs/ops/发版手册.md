# 发版手册

发布把版本提供给实例；**管理员决定实例何时升级**。本手册覆盖冻结输入、构建签名、发布目录、用户触发升级与失败处置。运行架构见 [生产架构](./生产架构.md)，具体实例基线见 [统一虚拟化与实例部署](./统一虚拟化与实例部署.md)。

2026-10-14 起，影响活跃实例的 CD deploy／promote 已停用。合并代码、构建成功、上传 Release、恢复 Jenkins 或刷新页面均不能代替管理员升级。当前后续 CLI 实验包仍是[实施计划](./2026-10-17-Codex与ClaudeCode升级发包计划.md)，不能记为已经发布。

## 0. 操作前提

1. 固定目标实例、渠道、来源已确认版本和目标版本，读取其实际状态、绑定与安装收据。
2. 固定 Root／API／Web 提交与构建工具版本；工作区或输入改变后重新构建并留新收据，不改写既有包。
3. 确认操作针对发布产物还是某个实例；本机与远端不可共用实例身份、私钥、运行根或升级历史。
4. 私有操作目录为 0700、文件为 0600。日志只保留所需状态与摘要，不输出令牌、Cookie、密钥或完整私有配置。
5. 写操作使用已审阅、与输入提交对应的工具；不从带未提交改动的克隆同步 Jenkins 模板或执行基础设施变更。

## 1. 发布怎么触发

CI 可以随提交或 PR 触发；发布任务也可以由维护者按受控流程触发。无论触发来源如何，CD 的终点都是不可变包、镜像、签名、摘要、目录和发布说明，不能调用实例升级、切换 API 路由、提升活跃实例的 Web 或停止沙箱。

实例校验自己的版本目录，发现兼容候选后展示新版本提示。管理员点击并授权后，Installer 才固定 requestId／attempt，下载、校验、准备候选、执行切换和确认。关闭提醒不会创建升级意图；完成后用户自行刷新。

构建作业是否启用、是否持有运行 socket，均不能证明其行为安全。恢复任何发布自动化前，须先审阅实际调用链，确认没有改变活跃实例的步骤；本轮不得恢复 deploy／promote。

## 2. 改动生效对照

| 改动 | 交付与生效方式 |
| --- | --- |
| API、Coordinator、Owner、Installer | 构建对应角色产物，按真实输入决定复用或替换，实例受控激活后生效 |
| Web | 构建版本化页面，随本实例目标版本激活；不通过共享前端提升让实例提前换页面 |
| 文档 | 提交并发布文档；不应导致运行实例升级 |
| CLI 或沙箱镜像 | 发布固定 OCI 坐标与各架构 digest，平台候选绑定已验证引用；已有 Guest 不原地升级 CLI |
| schema／迁移 | 补兼容计划、准备、writer 交接与失败恢复验证；不满足条件就拒绝该升级路径 |
| Jenkins 模板或构建工具 | 独立基础设施变更；先验证其不会恢复实例 deploy／promote |
| Colima、转发规则、容器权限 | 独立维护和隔离验证，不作为普通应用发版附带执行 |

## 3. 跨仓版本冻结

先完成 API 与 Web 变更及必要门禁，再记录主仓 gitlink 与发布输入。每份构建收据须给出完整三仓 SHA、平台、依赖与原生 ABI、实际 Web revision、产物大小、摘要和完整树身份。

发布工具使用的输入策略必须明示；不能混用构建时分支 head、后续 main head 和工作区文件。重试复用产物时须验证完整输入及产物一致，不能只看版本号或某个 API commit。

按 [CONTRIBUTING](../../CONTRIBUTING.md)处理提交与跨仓合并。合并完成只形成候选输入，不自动授权任何实例升级。

## 4. Jenkins agent 与工具变更

controller、CI agent 与可信发布 agent 的更新独立于业务角色升级。变更前记录镜像、工具、私有卷、socket、节点与作业启停状态；在隔离环境验证，确认计划与实际应用使用同一份已审阅工具和输入。

维护期间先停止排新构建并等待在途构建结束，再操作目标节点。只改目标基础设施，不重建 Foundation 或业务角色。恢复时核对节点、工具身份和原有作业状态，**不批量启用作业**。

仓库工具的 `refresh`、配置重载或升级脚本可能改变作业启停状态，不能把它们当作无副作用收尾操作。运行前审阅当前实现与实际计划；没有保持 deploy／promote 停用的证据，就停止应用并改用受控方案。

## 5. Jenkins 模板变更

模板在工作区通过静态校验后，才能由维护者从干净、固定提交的克隆同步。同步前后分别记录作业配置与启停状态，确认没有把发布产物的任务重新接到实例部署或共享 Web 提升路径。

单纯恢复 CI 不需要解除实例发布边界。不要沿用“刷新后启用全部作业”的操作习惯；节点上线、作业可构建和实例可升级是三个独立事实。

## 6. 发布验收清单

- 包名／版本、三仓 SHA、平台、字节数、SHA256、树身份及实际 Web revision 与收据一致。
- OCI 镜像使用固定坐标并记录各目标架构 digest，实际 CLI、PATH 和 Guest 入口经过验证。
- manifest、签名、固定信任根、实例、渠道、purpose、有效期、来源／目标路径一致；无私钥进入资产。
- 正式发布器要求的资格按实际结果填写；实验包明确标识实验，不把 `not-run` 改成 `passed`，不设为正式资格已通过。
- 上传资产逐项重新校验；目录可被目标实例读取并正确验签，发布说明列明兼容范围与限制。
- 发布后实例仍运行原确认版本，原 Guest、Owner 与任务未被发布动作改变；页面只出现新版本提示。

管理员实际升级的结果另外记录：同一 attempt 的真实进度、切换、confirmed／ready／generation、Web 身份、原资源与终端重连及失败恢复。上传成功不是实例升级成功。

## 7. 发布或升级卡住

先区分构建、上传、目录发现、下载、候选准备、切换、确认和浏览器刷新。读取原作业或 attempt 的事件、收据与实际角色状态；超时或连接断开可能意味着结果未知，不能直接认定底层操作失败。

构建或上传失败不会要求停止运行实例。修复后保留失败证据，按不可变输入重试；目标版本已被占用时不覆盖资产。

实例 attempt 仍有在途操作时不创建第二个请求来绕过它，不直接改 ready、删除失败事件或重复启动 Owner。无法确认 writer、绑定或 Guest 归属时保持真实失败／未知状态，交由维护者核对。

## 8. 数据库兼容与迁移

发布前明确来源 schema、目标 schema、读写兼容窗口及允许的升级／回退路径。可使用兼容桥、影子结构和在线转换降低影响；准备阶段完成耗时工作，交接只执行已经验证且有预算的有限操作。

破坏性变更、无法在旧角色继续读写时准备的迁移，或不能证明回退安全的路径，须拒绝在线升级或另行安排明确维护。不能以“用户点击升级”豁免数据一致性与资源连续性要求。

writer 交接和回退遵守唯一写者与 fencing；不整卷回写覆盖升级后新增业务写入。具体协议见[后端升级设计](../backend/changes/2026-10-10-不停机升级与运行环境分离.md)与[独立测试计划](../testing/changes/2026-10-10-不停机升级与沙箱续接测试计划.md)。

## 9. 熔断与回退

候选准备失败时不切换确认路由；当前实例继续服务，保留真实失败原因。进入切换后按同一受理计划核对可回退条件，恢复已确认路由；仍持有任务的 Owner 必须保留。

新旧 Owner 并存时，回退不等于杀掉新 Owner。它可能已接收新任务，须按实际资源归属保留并恢复路由。数据库已有新写入时不能使用备份覆盖运行卷来假装回到旧版本。

控制权、物理身份或 writer 无法证明时停止推进，不宣称已回退。灾难性数据丢失的离线恢复另见 [灾备与重建](./灾备与重建.md)，不能作为日常升级回退手段。

## 10. 沙箱镜像与 CLI 发版

平台包与 OCI 镜像分别发布并对账。镜像使用不可变 tag／digest，latest 漂移不构成实例升级。默认引用必须随目标版本生效、随允许的回退恢复；用户明确选择的镜像、已有任务冻结的 manifest／digest 不被覆盖。

新 CLI 只供升级后按新镜像创建的沙箱；运行中的旧沙箱继续使用其原版本。镜像登记、默认选择、实际 Guest 版本及旧引用仍可用必须一起验证。本轮实现范围与顺序见 [CLI 升级发包计划](./2026-10-17-Codex与ClaudeCode升级发包计划.md)。

## 11. 版本与发布记录

版本号、标签和资产必须唯一。正式版、实验包与部署基线分别标明；已经发布的字节不原地覆盖。CHANGELOG 写清用户可感知行为、兼容范围、升级路径和未验证项，不把计划写成已完成。

包构建、资产发布、目录发现和实例激活分别记录时间与收据。查看部署版本以该实例 confirmed 记录与实际角色／Web 身份为准，不能从 Release Latest 或仓库 HEAD 推断。

## 12. 必要验证与当前边界

改动涉及 BoxLite、Owner、凭据、迁移或角色替换时，先在隔离且同构的环境运行必要回归和真实 Guest 业务，再考虑向实例提供候选。测试独立覆盖前后端、失败／未知、原资源连续性与恢复，不能只看 HTTP 200。

当前统一部署 `.3` 的构建、签验、浏览器和真实 Guest／终端验证以[验收报告](../testing/results/2026-10-17-统一部署与在线升级验收.md)为准。没有完成的真实模型 Agent、跨升级连续性、完整故障矩阵与宿主冷启动恢复分别保持未验证；五类正式资格仍为 `not-run`。后续 CLI 现场升级采用[独立测试计划](../testing/changes/2026-10-17-CLI版本升级与用户触发更新测试计划.md)。
