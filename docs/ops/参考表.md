# 运维参考表

本表记录当前统一实例的查询入口、资源边界和工具职责。部署规则见 [统一虚拟化与实例部署](./统一虚拟化与实例部署.md)，本轮实际身份与验收见 [统一部署验收](../testing/results/2026-10-17-统一部署与在线升级验收.md)。本地开发见 [CONTRIBUTING](../../CONTRIBUTING.md)，不用于启动部署实例。

## 0. 命令入口

生产 Docker 操作必须显式指定实例的配置目录和 socket，不依赖全局 context。远端 SSH 别名为 `iflytek-mac`：

```sh
ssh iflytek-mac
export PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
/opt/homebrew/bin/colima --profile agent-platform-runtime status
/usr/local/bin/docker --config /Users/KYQXJL754N/agent-platform/docker-config \
  --host unix:///Users/KYQXJL754N/.colima/agent-platform-runtime/docker.sock \
  ps --filter label=agent-platform.instance=agent-platform-iflytek-20261017-r1 \
  --format '{{.ID}} {{.Names}} {{.Status}}'
```

Foundation 使用独立标签 `agent-platform.foundation`，不在上述五角色筛选结果中。查询 Foundation 时按同一 instanceId 筛选该标签。容器 ID、卷 mountpoint 和端口从当前持久配置及收据提取；不能将另一实例的配置套用过来。

本机 Jenkins 的管理工具为 `deploy/jenkins/manage.mjs`。使用 Node 22，在拥有本机私有配置的运维账号下执行只读的 `status`、`queue`；这些查询不启动实例升级。不要输出完整环境、私有配置或未经筛选的容器 inspect。

## 1. CI 作业与节点

| 作业／节点 | 职责与边界 |
| --- | --- |
| `agent-platform-contract` | 主仓文档、契约及部署工具门禁 |
| `agent-platform-native-ci` | 后端类型、测试、构建与原生模块门禁；作业名称不代表宿主部署方式 |
| `agent-platform-instance-package` | 构建实例安装包，发布产物不执行实例升级 |
| `agent-platform-upgrade-evidence` | 升级资格证据处理，结果须与精确输入绑定 |
| `agent-platform-web` | Web 构建及测试；产物身份必须与发布清单一致 |
| `agent-platform-sandbox-images` | 沙箱镜像检查或发布；镜像发布不替换已有 Guest |
| `agent-platform-ci-discovery` | 识别源码／PR 变化，作业状态以当前 Jenkins 查询为准 |
| `agent-platform-release`、`agent-platform-api` | 既有作业名；任何调用前核对是否包含实例部署副作用，当前不允许执行实例 deploy/promote |
| `agent-platform-service-monitor` | 只读状态采集；监控结果不能替代业务与升级连续性验收 |
| `linux-ci`、`linux-web-amd64` | build VM 中的独立 CI 执行节点 |
| `linux-deploy` | 可信产物处理节点；持有发布权限不构成替实例选择升级的权限 |
| Jenkins controller | 独立 jenkins VM；controller 不执行 PR 构建 |

作业名和模板不是启用状态的证明。模板同步、`refresh` 和维护结束不得恢复实例部署权限；本轮禁用的自动 deploy/promote 保持禁用。源码门禁见 [工程化规范](../shared/09-工程化规范.md)。

## 2. 来源与构建身份

发布单位是固定的 Root／API／Web 提交、平台、组件摘要与完整包摘要。PR、构建或合并完成只改变源码／产物状态，不能据此修改实例入口。发布来源、必需状态与跨仓契约见 [CONTRIBUTING](../../CONTRIBUTING.md)及[发版手册](./发版手册.md)。

候选必须绑定本实例的 instanceId、channel、信任根及兼容路径；不可借用另一实例的签名作用域、generation 或资格结果。复用组件保留真实 sourceRevision 与 Web revision，不用新标签伪造重建。

## 4. 运行组件

| 组件 | 身份／职责 |
| --- | --- |
| Foundation | StableEntry、CandidateSupervisor、持久入口绑定；标签 `agent-platform.foundation=<instanceId>` |
| ControlAPI | HTTP／WebSocket 控制面；角色标签 `api` |
| Web | 本实例版本化页面；角色标签 `web` |
| StateCoordinator | 业务库唯一写者、调度与 fencing；角色标签 `coordinator` |
| RuntimeOwner | BoxLite SDK home、Guest、终端和进程；角色标签 `owner` |
| Installer | 管理员意图对应的下载、校验、准备、切换与事件；角色标签 `installer` |

五角色使用 `agent-platform.instance=<instanceId>` 标签。升级期间可能存在仍持有 Guest 的旧 Owner，不能按容器数量或版本大小直接清理。当前绑定和资源归属决定其生命周期，禁止为页面更新停止 Guest。

## 5. 持久卷与路径

远端实例前缀为 `agent-platform-iflytek-20261017-r1`：

| 卷后缀 | 用途 |
| --- | --- |
| `-foundation` | 实例配置、路由、启动绑定及运行工具；运行根为卷 mountpoint 下的 `instance` |
| `-business` | 业务数据库、配置、工作区及文件；业务目录为卷 mountpoint 下的 `business` |
| `-artifacts` | 已校验的不可变安装包和解包产物 |
| `-source` | 本次迁移的封存来源副本，只作证据和受控恢复输入 |

实际 mountpoint 与 business alias 见验收报告。Owner home、角色状态与业务数据按部署工具的权限边界分开挂载，不从宿主旧安装目录取依赖。备份不能只包含 SQLite 主文件；主密钥、会话材料、业务文件、Owner 状态与升级 ledger 需按一致性边界分别保护。禁止 prune 或整卷覆盖当前写入，详见 [灾备与重建](./灾备与重建.md)。

## 6. 私有材料

| 材料 | 存放和输出边界 |
| --- | --- |
| 访问口令、Cookie 签名材料、业务主密钥 | 实例私有配置／持久状态；只验证可用性，不输出值 |
| 角色管理／应用 RPC 密钥 | 仅分配给必要角色，不复制进公开包和文档 |
| Jenkins API 与 GitHub／镜像凭据 | 本机 CI 私有目录或专属秘密卷；操作前校验属主及监听身份 |
| 实验发布私钥 | 仅本机持久私有目录；不传远端或 Release，公开根仅含公钥 |
| 验收 Cookie、原始日志、来源归档 | 私有证据目录，目录 0700、文件 0600 |

不要将完整 env、配置、凭据摘要或 Cookie 粘贴到报告。需提取状态字段时按允许清单输出。

## 7. 配置归属

| 配置 | 规则 |
| --- | --- |
| instanceId／channel／trust root | 本实例固定，首次安装与未来签验使用同一可信边界 |
| `DATA_ROOT`／数据库路径 | Linux 持久卷实际路径及部署工具建立的 alias；StateCoordinator 唯一写 |
| Owner home | 按 Owner 物理身份独立，不同时被两个 Owner 打开 |
| Web revision／产物 digest | 绑定本实例当前可用 Web，不以公共别名或标签猜测 |
| Origin／公开入口 | 本实例同源 HTTP／WebSocket；公网 HTTPS 与远端 IP HTTP 分别验证 Cookie 行为 |
| 角色端口／密钥／启动身份 | 从本实例持久配置和物理收据核对，不手动改状态以达成 ready |

## 8. VM 与虚拟化

| 项目 | 本机 runtime | 远端 runtime |
| --- | --- | --- |
| profile | `agent-platform-runtime` | `agent-platform-runtime` |
| 架构 | VZ、Linux arm64、嵌套虚拟化 | Colima 0.10.3／Lima 2.2.1、VZ aarch64、嵌套虚拟化 |
| 资源 | 6 CPU、16 GiB、120 GiB | 6 CPU、10 GiB、120 GiB |
| BoxLite | Linux `/dev/kvm`，由 Owner 持有 Guest | 同左，真实 Guest 已验收 |

CI 的 jenkins／build VM 与业务 runtime 分开。不要切换全局 Docker context，不默认挂载宿主 HOME；软件路径按本机实际安装推导。VM 启动不代表业务角色、Owner 或 Guest 已恢复，本轮未验证业务整机冷启动恢复。

## 9. 版本与不可变产物

CD 只构建、验证、签名和发布版本、安装包与目录。发布签验和正式资格是独立事实；当前远端为 qualification 实验基线，五类正式发布资格仍为 `not-run`。发现新版本仅提示；管理员主动触发后，Installer 才执行该实例已受理的升级意图。

签名私钥、固定根、候选清单与 CLI 实验包安排见 [CLI 发包计划](./2026-10-17-Codex与ClaudeCode升级发包计划.md)。当前 `.3` 基础部署成功不表示 CLI 新包已经发布或升级实验已通过。

## 10. 诊断判据

| 观察 | 下一步 |
| --- | --- |
| 页面不可达 | 先查宿主入口、VM、显式 Docker socket、Foundation 和当前绑定，保留原角色身份 |
| HTTP 200 但版本／就绪不一致 | 核对 instanceId、confirmed release、generation、availableWeb 和持久记录，不直接标成功 |
| Owner RPC 超时 | 结果可能未知，核对原 operation／handle，不能重建或销毁 Guest 当作补偿 |
| 凭据不可用 | 走正式授权／可用凭据筛选，保留失败；不在报告输出凭据 |
| 候选失败 | 按受理计划、fencing 与当前数据兼容边界恢复路由，不整卷回写覆盖新业务 |
| 宿主／VM 故障 | 按灾备流程处理；与在线升级连续性分开验收 |

具体只读步骤见 [运维手册](./运维手册.md)。

## 11. 退役与归档

本轮来源服务、安装目录和自启动项已退役；现行文档只保留统一模式。原始文档、失败事件和来源数据保存在私有归档，归档不是第二套在用部署。原路径不得以符号链接重新启用。新实例不得依赖归档的 Node、工作区或配置。

## 12. 宿主工具布局与 doctor

`deploy/containers/host-layout.mjs` 为本机 CI 工具推导运维账号、私有目录、软件路径、Colima socket 和启动参数；它检查属性和属主，不将凭据值写进报告。可选 `host-layout.json` 只覆盖工具允许的软件路径／Label 前缀，不能复制另一台机器的 HOME、UID 或 socket。

```sh
node deploy/containers/host-layout.mjs print
node deploy/containers/host-layout.mjs doctor --stage full
```

以上检查只适用于该工具要求的本机 CI 布局，不能作为仅部署业务 runtime 的远端实例就绪证明。远端按 §0 查询实际实例；宿主工具通过也不证明五角色、Guest、在线升级或断电恢复通过。工具报错先核对实际身份和路径，不放宽私有目录权限或补造另一套运行状态。
