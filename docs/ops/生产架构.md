# 生产架构

本文说明当前实例的运行结构、发布边界与故障域。两台已部署机器统一使用 **macOS 宿主 → Colima／Apple VZ Linux arm64 VM → Docker Foundation 与五个独立角色**；BoxLite Guest 在 Linux 中通过 KVM 运行。实例的实际版本、容器身份、卷、入口及验收收据见 [统一虚拟化与实例部署](./统一虚拟化与实例部署.md)和[统一部署验收](../testing/results/2026-10-17-统一部署与在线升级验收.md)。

本机主线上与 `100.73.71.22` 使用同一架构，拥有各自的数据、实例身份、信任根和升级历史。架构相同不代表运行版本或验收结果相同。

2026-10-20新增[独立升级控制系统目标设计](../backend/changes/2026-10-20-独立升级控制系统.md)与[失败恢复方案](./2026-10-20-升级失败恢复与回滚方案.md)。目标将控制与基础观察独立于业务版本维护，尚未实施；本文保留当前部署边界，不能用目标设计替代实际运行证据或据此直接调整角色。

## 1. 拓扑

用户请求先到本实例的稳定入口，再由入口路由到已确认的 ControlAPI 与 Web；API 通过 StateCoordinator 访问业务状态，并按资源归属找到 RuntimeOwner。Installer 通过受控接口准备候选并提交切换，浏览器不会直接访问角色管理端口。

| 入口 | 当前路径 |
| --- | --- |
| 本机主线上 | `agent.douglasdong.com` 跳转到同源 `agent-api` 入口；Cloudflare Tunnel 接入本机实例 |
| 远端实例 | `http://100.73.71.22:3000` → macOS IP bridge → Linux VM 内的 Foundation 稳定入口 |
| Jenkins | 本机独立 Jenkins VM；公网访问经过 Cloudflare Access、Tunnel 与 Jenkins 登录 |

Web 是本实例已确认版本的产物。用户刷新页面不会部署服务，也不会改变实例版本；发布新包只让实例发现新版本。

## 2. 组件清单

| 组件 | 职责与持久边界 |
| --- | --- |
| Foundation | 承载 StableEntry 与 CandidateSupervisor，保留路由、启动绑定及角色管理基础 |
| ControlAPI | HTTP／WebSocket 与业务请求转发；更新它不能结束 RuntimeOwner 中的沙箱 |
| Web | 本实例的版本化页面产物，随实例受控激活 |
| StateCoordinator | 业务库唯一写者、状态、调度和 Owner 路由；交接受 fencing 与兼容性门禁约束 |
| RuntimeOwner | BoxLite SDK home、Guest、进程及终端；既有资源持续归属原 Owner |
| Installer | 本实例升级控制器、下载校验与执行日志；只执行受理的管理员升级意图 |

Foundation 与五角色分别记录实际物理身份，不能用一个容器健康替代整套实例 ready。运行根及业务目录位于 Linux Docker 持久卷；仓库克隆仅用于查看代码、构建或运维工具，不代表当前已运行版本。

本机另有 Jenkins controller、构建 agent、发布 agent、DNS 与 Tunnel 等基础设施。它们与业务角色分工独立；远端业务实例不需要复制整套 Jenkins。

## 3. 构建与基础设施

Jenkins controller 为 0 executor，CI 在构建 agent 执行。构建输入必须固定到明确的 Root／API／Web 提交，并以收据记录；发布不能在后续阶段悄悄改用新的分支 head。PR 代码不取得运行实例的密钥或 Docker socket。

平台 Linux arm64 安装包携带角色产物；沙箱 OCI 镜像另外构建、验证和发布。镜像中的 CLI 与平台 tar 不是同一份产物。Web 构建工具与托管平台可以保留用于构建或独立预览，但实例页面由该实例已确认版本提供，发布系统不能通过共享域名提升替所有实例升级。

本机 Jenkins、build、runtime 各有独立 Colima profile 与 Docker socket。可信发布 agent 若持有 runtime socket，拥有很强的宿主运行权限，必须与 PR 构建隔离；它有权限不代表发布流程被授权改变活跃实例。

## 4. 发布与实例升级

| 动作 | 执行者 | 对活跃实例的作用 |
| --- | --- | --- |
| 合并代码、完成 CI | 开发者与 CI | 形成可构建输入；不直接更新实例 |
| 构建、签名、发布包与目录 | CD／发布人 | 提供不可变候选；不切换路由、不停止 Guest |
| 发现新版本 | 实例 | 显示提示与目标版本；不自动开始升级 |
| 点击升级并授权 | 管理员 | 由本实例 Installer 固定 attempt／requestId，执行准备、校验与受控切换 |
| 刷新页面、附着终端 | 用户 | 加载已确认页面，通过原书签重连原资源 |

2026-10-14 起，影响运行实例的 CD deploy／promote 已停用。不得因恢复构建、更新 Jenkins 模板或刷新配置而重新放开它们。发布路径与实例执行路径分别验收，操作规则见 [发版手册](./发版手册.md)。

更新 RuntimeOwner 时，新 Owner 使用独立 SDK home 接收未来分配；仍持有资源的 Owner 保留，Coordinator 保留并恢复其路由。数据库不兼容时先执行兼容性、准备与可恢复性门禁，不能把任意 schema 变更包装成无停机升级。

## 5. 信任边界

- 每个实例固定自己的身份、渠道、信任根、安装记录与升级历史。包摘要、签名、来源／目标及有效期必须同时匹配，不能借用另一实例的通过结果。
- 发布私钥留在受控持久私有目录；实例接收公钥与签名元数据。凭据、Cookie、session key、主密钥与私有配置不进入仓库、镜像、下载资产或诊断输出。
- StateCoordinator 是唯一业务写者；交接必须能证明 writer 与 fencing。未知状态不能按成功或失败猜测，更不能通过重复启动消除未知。
- RuntimeOwner 的数据和进程身份与入口版本分开。API 或 Web 更新不拥有销毁 Guest、重播任务输入的权限。
- 运维显式指定 profile、Docker socket、私有 Docker 配置和实例标签。全局 Docker context、服务名称相似或页面版本号都不足以证明目标实例。
- Cloudflare Access 保护 Jenkins；Tunnel、IP bridge 和稳定入口分别核对监听及鉴权，内部角色端口不单独对外开放。

## 6. 虚拟化、网络与隔离

VZ 嵌套虚拟化与 KVM 是 Guest 的必要条件。设备文件存在还不够，须用实际 Owner 权限验证 KVM，并用真实 BoxLite Guest 验证启动和终端。容器权限、挂载、网络与 cgroup 的实际限制以当前运行收据和隔离测试为准，不把 SDK 配置字段当作已经生效的安全保证。

Linux VM 的 host 网络属于 VM。Lima 可能把 VM 监听转发到 Mac；共享网关也可能让其他 VM 访问 Mac 回环，因此回环地址本身不是鉴权边界。端口转发只允许实例入口与已明确需要的基础设施端口，Guest 随机端口、角色控制端口、DNS 与指标不能意外出现在宿主通配监听。

不同机器的网关、guest 地址和 DNS 由实际网络分配，不照抄固定地址。修改 Lima override 前先核对该机器现有端口与 socket 转发需求，再校验配置；不得为更新规则例行重启正在运行用户任务的 VM。

## 7. 启动与恢复边界

宿主上的入口 bridge、Colima 生命周期、Docker、Foundation、五角色与 Guest 是不同恢复层。某一层有自启动项或容器重启策略，不代表整条业务链能够安全冷启动。

基础设施恢复前先核对实例持久绑定、原角色、Owner home 与唯一写者；不能批量重启角色、重跑首次部署或给所有角色加重启策略来替代恢复协议。运行中的 Guest 不因入口暂时不可用而被判作丢失。

本轮远端已完成统一部署与服务退役；该事实不授予完整宿主冷启动、Agent／模型或跨升级连续性资格。当前真实验证范围与未执行项见验收报告。灾备与新机器恢复按 [灾备与重建](./灾备与重建.md)逐项准备、隔离验证，不能从容器存活推断恢复成功。
