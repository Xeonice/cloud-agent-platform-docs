# 运维手册

本手册适用于统一的 Colima Linux arm64／Foundation 与五角色实例。日常检查以只读操作为主；实例身份、实际卷与入口见 [统一虚拟化与实例部署](./统一虚拟化与实例部署.md)，架构见 [生产架构](./生产架构.md)。发版见 [发版手册](./发版手册.md)，灾备见 [灾备与重建](./灾备与重建.md)。

## 0. 操作前提与维护边界

先固定宿主、运维账号、Colima profile、显式 Docker socket 与实例 ID。Mac 默认 Docker context 可能属于 OrbStack；不要使用裸 `docker` 或切换全局 context 判断生产状态。本机与远端的配置、端口和数据不能相互套用。

在远端先 `ssh iflytek-mac`，并按下节设置 PATH。SSH 的精简 PATH 可能使 Colima 找不到 Lima，即使 Colima 使用了完整路径。宿主与私有文件的身份按 [参考表](./参考表.md)核对；不把完整环境、inspect 或私有配置打印到日志。

Jenkins 维护与业务实例维护分开。需要暂停构建时，先记录作业启停状态、停止排新构建、等待空闲，再进入 quietDown；结束只解除此次维护并恢复原来允许的 CI。**影响实例的 deploy／promote 保持停用**，不能运行批量启用或未经审阅的 `refresh` 作为收尾。

会停止 VM、Foundation、Owner 或业务 writer 的动作具有实际中断风险。先核对真实资源和在途操作，制定维护与恢复方案；普通版本更新使用管理员发起的实例升级流程，不能用重启替代。

## 2. 日常巡检

每天及维护前检查以下项目，并记录采样时间与实例身份：

| 检查 | 判定与后续 |
| --- | --- |
| 用户入口与 health | 从用户网络和宿主分别观察，区分公网、bridge、Foundation 与业务角色故障 |
| 系统升级状态 | 鉴权读取本实例当前版本、confirmed／ready／generation、Web 身份、attempt 与阻塞原因 |
| Foundation 与五角色 | 核对物理容器身份、实例标签、启动绑定与真实运行状态；健康检查不代替业务 ready |
| Owner 与 Guest | 原资源仍归属原 Owner，无异常重建、销毁或丢失路由；不以重启验证存活 |
| 磁盘与内存 | 同时看宿主、VM、Docker 数据盘及业务挂载的实际剩余空间、压力和 OOM |
| Jenkins／Tunnel／DNS | 核对各自状态和外部可达性；基础设施监控与实例业务监控分开 |
| 作业启停 | deploy／promote 未被基础设施维护意外重新启用 |

不要把旧的 service-monitor 单容器结果作为整套新实例验收。没有已验证告警链路时，由外部主动检查用户入口；运行在故障 VM 内的监控不能覆盖该 VM 自身失联。

## 3. VM 停机、重启与恢复

VM 停机会同时影响该 VM 内的 Foundation、业务角色与 Guest，不属于普通升级步骤。宿主／VM 断电后的完整角色与 Guest 恢复尚未取得本轮资格，不能承诺自动恢复。

实际需要重启时先判断是否有运行资源与在途操作，明确可接受中断、当前绑定、恢复责任人与私有备份。查询该机器真实 launchd／Colima 管理方式；不能同时让多个 keeper 或手动进程启动同一 profile。

启动 VM 后先检查 Docker、网络、DNS与已有物理角色，再通过该实例经验证的恢复路径恢复入口和管理连接。禁止批量 `docker restart`、重复部署或直接重启 Owner。Owner home、writer 或绑定无法证明时停止，保留现有进程与卷供核对。

## 4. Lima 转发与 DNS

Lima override 可影响多台 VM。改动前读取当前接口、路由、转发配置、监听端口与 Docker socket 转发，明确每一条 allow／ignore 规则的范围；在隔离配置中校验后才安排必要维护。

只暴露已批准用户入口及基础设施端口；内部角色、Guest 随机端口、DNS 和指标不应意外出现在 Mac 通配监听。不能复制另一台机器的整份 override，或以“忽略全部”破坏 Jenkins／Docker socket 转发。

DNS 诊断先读取实际 eth0 地址、默认路由、resolv.conf、解析服务和上游连通性；guest 地址由网络分配，不写死。Colima 新版本的 DNS 行为须单独验证。解析通过、registry 可用或 VM 重启成功都不等于完整业务恢复通过。

## 5. 容量与清理

查询宿主可用空间、VM 数据盘、Docker 使用量和业务挂载的实际容量，再根据构建及 Guest 最大增量预算判断。Docker 卷、镜像和磁盘文件并非可互相替代的容量指标。

禁止例行执行 volume／image／system prune；没有挂载的卷仍可能包含持久绑定、Owner home、升级证据或备份，未打标签的镜像也可能仍被已确认版本与恢复路径引用。

清理只针对已经证明无引用的精确对象，先记录归属、摘要、保留范围与可恢复副本。构建缓存也须确认没有在途构建并核对所属 daemon，不在业务维护中顺手清理所有缓存。首次迁移封存与失败证据不因新服务运行就自动删除。

文件系统出现只读、I/O 或 ext4 错误时先保留故障事实并保护剩余数据，安排离线恢复；本手册不提供对运行盘直接修复的通用命令。

## 6. 内存与负载

同时观察宿主压力、VM 配额、容器限制和 Guest 内存。资源预算按实际机器确定，不照抄本机更大的配置；远端当前 VM 资源见统一部署记录。

Guest 冷准备可能包含镜像下载或解包。RPC 超时不证明底层启动失败，不能据此删除 workspace、Guest 或再次 start；先读取原 operation、Owner 与实际进程状态。增加等待预算也不能掩盖 OOM、失联或结果未知。

## 7. 凭据与配置

主密钥、session key、访问口令、Owner 凭据与发布签名材料分属不同用途，须核对作用域、当前使用者和持久位置。私有目录 0700、文件 0600，发布私钥不传实例或 Release。

轮换前确认代码支持的热更新或受控角色切换路径，记录旧／新材料的引用与恢复边界；不要修改所有运行角色共享的文件后批量重启。访问口令变化、session key 变化和模型凭据变化的用户影响不同，分别验收。

过期或撤销的模型凭据不得注入新建或恢复资源。凭据异常先检查有效性、绑定与原操作结果，不能复制另一实例的密钥来绕过失败。诊断只记录 ID、类别和状态，不输出秘密值。

## 8. 服务不可用排查树

1. **用户网络／公网**：从外部观察入口、TLS 或 IP 可达性，再查 Tunnel／bridge；保留时间和失败类型。
2. **宿主与 VM**：显式 profile、socket、Docker、磁盘、压力、DNS；不因查不到容器就创建替代实例。
3. **Foundation transport**：核对入口与 Supervisor、持久绑定和目标实例，保留既有角色。
4. **业务角色**：核对 confirmed 绑定、ControlAPI／Web、writer／fencing、Installer attempt；只读区分失败与未知。
5. **Owner／Guest**：按实际 assignment 找到原 Owner，核对 SDK home、进程、书签与路由；保留运行中的资源，不重播输入。

恢复入口与恢复数据是不同操作。页面打不开不能授权回写业务卷；API 不可达不能授权停止沙箱。无法证明安全下一步时记录阻塞事实，按 [灾备与重建](./灾备与重建.md)准备隔离恢复。

## 9. 只读诊断与交付

只收集必要字段：实例／角色 ID、启动时间、包摘要、路由 generation、confirmed／ready、操作状态、资源计数、错误类别与脱敏事件。接口、字段含义以[共享契约](../shared/10-接口契约与类型共享.md)为准；私有管理接口不可向外开放或省略授权。

`/api/deployment/status` 的资源与在途计数可辅助维护判断，但单次空闲快照不等于持续禁止新写入。正式冻结要使用受理屏障、锁与重复核验，不能手工看完一次计数就停服务。

终端验证使用普通 API 创建的自有测试资源，保存原书签及真实运行身份，检查输入输出和续接；结束仅通过普通 API 清理本轮自有资源。真实模型、跨升级、超时恢复和宿主冷启动分别留证，没有执行就标记未验证。
