# 统一虚拟化与实例部署

本机与 `100.73.71.22` 统一采用 **macOS 宿主 → Colima Linux arm64 VM → Docker Foundation 与五个独立角色**。Colima 使用 Apple VZ 并启用嵌套虚拟化，BoxLite 在 Linux RuntimeOwner 中通过 `/dev/kvm` 运行沙箱。安装包目标为 Linux arm64。

两实例已完成基础迁移与来源服务退役，历史浏览器／Guest／终端证据见[基础验收](../testing/results/2026-10-17-统一部署与在线升级验收.md)。本机本轮未更新，仍为`v0.3.15-experiment.online.20261018.2`／activation8／confirmed／ready1／schema29。远端`.19`四次更新均未完成：历史确认版本`.18`／activation6，当前入口75%走API`.18`、25%走API`.19`，Coordinator及新Owner为`.19`，实例transitioning／ready0／schema29；原口令、Cookie、Guest及两个终端身份保持。远端访问 **http://100.73.71.22:3000**。四次原始失败、外部超时及过期fence导致的恢复限制见[句柄额度发版验收](../testing/results/2026-10-19-BoxLite句柄额度发版与远端更新验收.md)，此前`.18`见[架构整改验收](../testing/results/2026-10-18-架构整改发版与远端更新验收.md)，双实例`.14`／`.15`见[升级优化验收](../testing/results/2026-10-18-升级优化发版与双实例更新验收.md)；完整正式资格和未执行的模型连续性保持分开记录。

## Foundation 与五个角色

| 组件 | 职责和生命周期 |
| --- | --- |
| Foundation | 常驻 StableEntry／CandidateSupervisor，保留已确认路由和启动绑定 |
| ControlAPI | HTTP／WebSocket 访问与请求转发；先准备候选再切流，不以 API 更新停止沙箱 |
| Web | 实例版本化页面；激活后由管理员方便时自主刷新 |
| StateCoordinator | 业务库唯一写者、状态、调度及 Owner 路由，受 fencing／交接约束 |
| RuntimeOwner | Guest、进程、终端和 SDK home；既有资源保留原 Owner，新 Owner 使用独立 home |
| Installer | 本实例升级 controller、下载／校验／执行日志；只执行明确受理的管理员意图 |

实例的业务数据、密钥、信任根、目录、安装记录和升级历史相互独立。不能复用另一实例的签名作用域、generation 或验收结果；不能把整棵数据目录与全部凭据挂给每个角色。

## 状态查询与运行纪律

远端已有独立 OrbStack registry。Colima 不切换全局 Docker context，查询使用专用 Docker 配置和 socket：

```sh
ssh iflytek-mac
export PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
/opt/homebrew/bin/colima --profile agent-platform-runtime status
/opt/homebrew/bin/colima --profile agent-platform-runtime ssh -- uname -srm

instance_socket=unix:///Users/KYQXJL754N/.colima/agent-platform-runtime/docker.sock
/usr/local/bin/docker --config /Users/KYQXJL754N/agent-platform/docker-config \
  --host "$instance_socket" ps \
  --format '{{.ID}} {{.Names}} {{.Status}} {{.Ports}}'
```

SSH 的精简 PATH 会使 Colima 找不到 Lima，须显式设置上面的 PATH；用 `--profile` 指定实例。不要输出完整环境、容器 inspect 或私有配置；只查询所需状态字段。

DNS 已经受控 VM stop／start 复验，registry 路径和全局 context 保持。guest `eth0` 为动态地址，诊断先读取接口、路由与解析结果，不硬编码某次分配值；本轮上游为 `192.168.5.2`。这项 VM 网络复验不代表整套业务角色或宿主冷启动恢复通过。

Foundation 恢复须先核验本实例持久配置、路由绑定及现存五角色身份，再使用受控恢复路径恢复 transport；不重复首次部署、不重复启动角色，不打开另一份 Owner home。故障先区分 VM／Docker／入口／角色／Guest，保留失败事件。不得整卷回写覆盖新写入、直接修改 ready 或因页面不可达取消任务。禁止 volume／image／system prune。

## 发布、管理员升级与签名

CD 只构建、验证、签名并发布不可变包、镜像和目录，不能向实例发升级命令或切 API／Web。实例只读发现版本；通过现有访问保护进入实例的管理员点击“立即升级”后才固定目标、下载、校验、准备候选及切换。百分比来自真实 attempt，失败或 unknown 如实展示。完成后管理员自主刷新，使用原书签附着原 Guest／shell，不重播输入。

远端实例实验信任根固定为 `sha256:6827a3be8d19449c8060d3035f5e319094e5fb84702b16df7ec33a75482ef6fe`，由本机持久发布密钥签候选。后续使用 `signQualificationManifest`，不为每个包重建 key／root。私钥只留本机受控目录（父目录 0700、文件 0600），不传远端、仓库、安装包或 Release。两实例信任根各自独立，不可混用。当前安装为 qualificationOnly、qualified=false；远端初次安装时 catalog 为空，后续候选由受控目录发布；签验能力不代表完整发布资格或升级实验通过。
