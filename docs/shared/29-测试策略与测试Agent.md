# 29 - 新版验收策略与测试协作（2026-10）

## 0. 范围与依据

用户已明确同意丢弃旧测试后重新规划，项目未上线，不承担历史数据迁移。当前依据 [领域规格](../design-v2/gap/product/README.md) 的247 REQ/1016 AC；历史测试计数与变异报告已退休。本文定义验收职责，实际通过数量以运行记录为准。

## 1. 新框架与证据

API `acceptance` 独立支持 fresh SQLite、真实服务与完整 Nest；web `src/acceptance` 独立MSW支持真实业务与DOM；全稿设计runner支持每稿数据状态；主仓跨仓runner支持浏览器到真实后端。

### 1.1 计数口径

REQ、AC、测试case、设计稿、截图是不同计数。一次case可覆盖多AC，一稿可有多主题/尺寸；代码审查闭合不等于每AC指定层已实跑。未知结果保留 planned/partial，不因测试总量增长自动闭合。

## 2. 协作职责

实现负责生产逻辑、契约与可操作设计；验收负责从用户触发定义断言、执行真实边界并反馈缺陷。共享workspace时按文件域分工，重建生产服务前同步，避免测试读半更新产物。

### 2.1 测试维护

新fixture只定义场景对象与外部边界，不复用已退休的旧套件 helper；失败先定位代码/夹具/装配，不放宽断言掩盖缺陷。

### 2.2 交接

记录命令、case数、输出路径、实际边界、未执行条件；结果可复跑。不得将代码存在、测试命名、截图文件存在说成全部行为通过。

## 3. 验收分层

### 3.1 真实跨仓

浏览器→生产web→HTTP/WS→完整Nest→freshSQLite→实际业务响应。外部资源Provider可替换为明确的可控夹具，终端数据使用真实子进程；不能在浏览器拦截API后称跨仓。

### 3.1.1 隔离环境

临时DATA_ROOT和数据库，固定或随机测试端口，显式环境变量；禁止读取用户凭证/数据库。Provider替身只承担外部传输，不手工new协议handler绕过生产注册，MCP需实际listTools/callTool。

### 3.2 组件验收

保留真实container/hook/service/store/view，使用HTTP边界状态；验证加载/失败/重试、取消和请求次数、有效期、模式确认、绑定预览及secret清空。

### 3.3 生命周期与事务

SQLite验真实撤销/注入、镜像引用、项目删除事务与文件提交后清理；service验终止、回收超时和durable补偿；协议验真实进程、WS detach与MCP发现。

### 3.4 视觉

每稿manifest关联本仓原稿与夹具、操作、route，暗/亮主题及桌面/窄屏跑实际生产页面；检查固定头尾、布局、滚动、焦点和token。自动溢出检查通过仍需人工审查关键截图。

### 3.5 有效断言

先证明目标阶段执行，再断言结果；例如已登录后取消必须实际dispose会话，删除失败必须证明旧行还在，断线后必须证明输出保留。只验证前置条件或mirror实现不算有效验收。

### 3.6 已退休历史度量

不保留旧覆盖率阈值/历史通过数来限制新框架。用领域行为与故障模式评估新用例，新增测试只在有必要验证边界时增加。

### 3.7 契约门禁

根 `pnpm docs:check` 保留13项检查；API实际发射OpenAPI后复制生成web类型；两份wire协议逐字一致。fixture使用同源类型/能力，维护检查脚本检查当前framework，不继续引用已删除旧文件。

## 4. 完成标准

生产功能覆盖已裁决需求；所有适用设计稿迁移并有真实页面证据；新验收/类型/lint/build/契约文档门禁通过；旧测试与旧规格入口退休；剩余仅明确裁决为deferred/superseded的项。报告实现迁移与实跑验证分别计数，不宣称未发生的真实外部环境验证。
