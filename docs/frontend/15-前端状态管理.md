## 1. 状态分类学（每个状态的归属判定）

| 状态 | 当前归属 | 权威与生命周期 |
|---|---|---|
| 项目、sandbox、runtime、镜像、规则、成果、系统资源 | TanStack Query | REST DTO缓存，按事件/动作失效；投影不替代权威实体 |
| 沙箱生命周期、实例/CLI启动子进度 | sandboxStatusSlice内存投影 | WS即时更新；创建响应或REST补种子；不persist |
| 项目克隆进度 | projectCloneSlice内存投影 | WS阶段/进度与真实startedAt；REST项目列表补齐或刷新 |
| 认证挑战、轮询、倒计时 | useRuntimeAuthFlow局部reducer/ref | 用户明确开始，切方式/收起/卸载取消，不落Query session或store |
| 认证聚合与单runtime已保存状态 | Query | 与短期挑战不同；完成时补取权威状态，WS失效刷新 |
| `/events`连接、重试次数、握手错误 | useSandboxEventsSocket局部hook状态 | AppFrame持久宿主，独立于任务业务生命周期 |
| PTY实例/socket句柄及连接投影 | terminalRegistrySlice及终端hook的ref | session粒度、非序列化、不persist |
| 终端标签、后端shellId、激活顺序 | terminalTabsSlice | 标签与实例分离；不persist会话凭据 |
| 选中项目/sandbox/无头task、主题、折叠等11项 | uiSlice + persist白名单 | 用户选择与显示偏好，见§3.5 |
| 菜单、modal、来源定位、筛选、清屏/诊断意图 | uiSlice内存 | 瞬时目标，不persist |
| 任务指令、回贴码、API key、本次草稿 | 对应container/hook局部态 | 有限生命周期；明文提交即清空，不进全局store |
| 分组树、状态/搜索匹配、等待输入数 | 纯函数派生 | Query资源与UI偏好的组合，不另存树或计数 |

判定顺序：服务端资源用Query；浏览器共享选择/投影用对应slice；流程内短期状态留在hook/container；可以从已有值算出的结果只作派生。view只能持有同步、由用户事件驱动的本地UI态，不能接管外部订阅或业务状态机。

## 2. TanStack Query 细化

当前Query key工厂属于拥有查询的领域hook；没有统一的 `services/api/queryKeys.ts`。共享同一资源时import同一个工厂/查询选项，而不是在另一个消费方手写不同key或选项。

### 2.1 Query key 工厂（集中管理，防 typo）

| 工厂/入口 | 真实文件（相对web/src） | 实际key |
|---|---|---|
| projectKeys.all | hooks/project/useProjects.ts | `['projects']`（列表本身） |
| sandboxListKeys.list | hooks/sandbox/useSandboxes.ts | `['sandboxes','list']`（全项目DTO列表） |
| sandboxKeys.detail | hooks/sandbox/useSandboxRestore.ts | `['sandboxes','detail',id]` |
| useTaskActionDetails | hooks/sandbox/useSandboxOperations.ts | `['sandboxes',id]`（菜单动作详情） |
| runtimeKeys.list | hooks/credential/useRuntimes.ts | `['runtimes','list']` |
| runtimeAuthKeys.status | 同上 | `['runtime-auth',runtimeId,'status']` |
| gitCredentialKeys.list | hooks/credential/useGitCredentials.ts | `['git-credentials','list']` |
| imageKeys.list | hooks/image/useImages.ts | `['images','list',runtimeId ?? null,provider ?? null]` |
| providerKeys.list | hooks/sandbox/useProviders.ts | `['providers','list']` |
| systemKeys | hooks/system/useAuditStream.ts | `['system','init'/'settings'/'resources'/'providers'/'diagnose']` |
| systemKeys.audit | 同上 | `['system','audit',filters]`；增量另加 `'incremental'` |
| automationKeys | hooks/automation/useAutomations.ts | `['automations','list',{projectId}]`、`['automations','attention']`、`['automations','runs',ruleId]`、`['automations','run',runId]` |
| retainedVolumeKeys.list | hooks/project/useRetainedVolumes.ts | `['retained-volumes','list',projectId ?? 'all']` |
| branchKeys.list | hooks/project/useProjectBranches.ts | `['project-branches',projectId]` |

`runtimeAuthKeys.session` 仍是声明的工厂成员，但当前挑战流程没有以它启动Query或refetchInterval；实际会话由useRuntimeAuthFlow持有。删除预检使用资源前缀下的独立key，打开目标后才启用、staleTime=0；镜像、规则与凭证预检显式retry=false，项目预检当前使用全局Query重试默认值。

前缀失效使用 `['sandboxes']`、`['images']`、`['automations']` 等整域覆盖。列表Query并没有 `{projectId}` 参数族；工作台全项目树读同一份列表。详情恢复与动作详情目前是两种实际key，文档不将它们虚构为自动normalize后的共享实体。

`providerKeys.list` 是 `GET /api/providers` 的能力registry；`systemKeys.providers` 是 `GET /api/system/providers` 的健康、runtime、镜像规格看板，两者资源和刷新频率不同。镜像key含runtime/provider，管理页与发起页各自缓存，但域动作统一失效imageKeys.all。

审计filters必须进key：改变类别、severity、时间窗或任务目标就换历史/增量缓存，旧before/since游标不沿用。自动化运行历史使用一把rule key与useInfiniteQuery，页码活在pageParam，按id去重；不再为每个page创建一把key。

### 2.2 staleTime / gcTime 分级

下面列当前源码明确配置；未指定gcTime的查询使用TanStack Query默认（浏览器5分钟），不要将文档建议值当作已配置值。

| 查询 | staleTime | 显式刷新/保留 |
|---|---|---|
| 项目列表 | 30s | 事件、创建/删除/恢复动作后失效 |
| sandbox列表/详情 | 全局30s | 列表没有固定45s轮询；事件/重连失效，详情恢复retry=false |
| runtime聚合/单runtime状态 | 60s | mutation与WS失效；初始化与凭证使用RUNTIMES_QUERY_OPTIONS同源 |
| Git凭证/镜像列表 | 60s | 保存/删除等动作失效 |
| provider registry | 5min | 能力发现，无健康轮询 |
| 系统资源/provider健康（看板） | 15s | refetchInterval=30s；资源耗尽拒绝后的capacity补充读取同resources key但staleTime=0 |
| 系统设置 | 系统页采用全局30s；初始化显式60s | 保存后失效对应key |
| 初始化判定 | Infinity | gcTime=Infinity；retry=false、retryOnMount=false；完成mutation写true |
| 诊断结果 | Infinity | gcTime=30min；enabled=false只读订阅，真实SSE逐帧setQueryData |
| 审计历史 | Infinity | gcTime=10min；有记录后不周期重拉全部历史页 |
| 审计增量 | 0 | 30s轮询since；首屏全空时由历史30s轮询兜底 |
| 自动化列表/跨项目attention | 60s | gcTime=10min；attention在挂载、返回前台、路由变化、动作后更新 |
| 自动化运行历史 | 30s | gcTime=5min；分页/用户动作刷新，不固定轮询 |
| 成果列表 | 30s | 删除后失效全成果、系统与项目 |
| 删除预检 | 0 | 只读、目标打开时请求；镜像/规则/凭证不自动重试，项目采用全局Query默认 |

根Providers当前默认 `queries: {staleTime:30_000,retry:2,refetchOnWindowFocus:true}`、`mutations:{retry:0}`；未显式覆盖的Query其他行为使用库默认。诊断和用户提交不自动重试；授权轮询由自己的hook调度，不能套用Query重试表。

审计有两个方向：历史 `useInfiniteQuery` 用before向旧页翻；增量轻量Query用缓存已见最大seq作为since，把新事件prepend进第一页。仅在已加载历史各页都为空时，历史查询30s重取首屏；有seq后改由增量请求轮询。增量拉满limit且hasMore时显式报告缺口，由[加载中间部分]一次补一段。

### 2.3 WS 事件 → 缓存 patch 映射表

`AppFrameContainer` 在根布局挂一次useSandboxEventsSocket，设置页导航也保留这条连接。EventsSocket先作wire校验，再把事件送入sandbox/clone slice和调用方回调。下面是当前实际路径，不是统一 `patchSandboxCaches.ts` 设计稿。

| 事件/时机 | 内存投影 | Query/恢复 |
|---|---|---|
| sandbox.created | 没有投影时种pending，已有更新不降级 | 失效sandbox列表与projects |
| sandbox.status_changed | status/phase/errorCode/observedAt/lastProgressAt；清理已退出启动阶段的子进度 | 失效sandbox列表，REST补齐failureMessage、failureOperation等 |
| sandbox.waiting_input | 生命周期slice不消费它，不覆盖主status | sandbox回调失效列表，REST waitingInput只在rawStatus=running时参与展示 |
| sandbox.removed | 删除生命周期、CLI、实例投影 | 立即从列表缓存移除并失效列表/projects；销毁操作也前缀移除匹配数组缓存 |
| project.clone_progress | projectClones保存阶段、进度、错误及真实startedAt | done/failed失效projects；useProjects.select组合项目状态 |
| runtime-auth.status_changed | 不保存第二份凭证实体 | useRuntimeAuthSync失效runtime聚合与该runtime状态 |
| runtime.install_progress | runtimeInstalls子文案，不作为失败原因来源 | 不直接写DTO字段；失败以status_changed/REST失败码为准 |
| sandbox.instance_progress | instanceStartups子文案；有状态时更新真实进展时刻 | 不伪造生命周期；imageStaged缺席是未知 |
| /events重新open | 保留投影，继续收后续事件 | 失效sandbox列表、详情前缀和projects，补回断线期间权威信息 |

**REST与WS的竞态纪律**：useSandboxes和useSandboxRestore在请求前记投影引用，返回后只有引用未变化才种入REST生命周期；请求在途期间若WS到达，较旧REST不得覆盖它。列表的select使用最新投影的rawStatus，waitingInput保持服务端子字段；新建POST只给尚未有投影的任务种初值，不能把已到达running的任务降回pending。

`observedAt`只由亲眼收到的状态转变或明确重启动作产生，普通REST恢复不虚构阶段开始时间；`lastProgressAt`用于无进展判断，与任务树更新时间不是一个字段。WS发送、浏览器PTy连接态与sandbox业务状态也分别保存，不能互相代替。

### 2.4 乐观更新（start/stop 按钮）

标题保留旧示例的锚点；当前start/stop不是给detail Query直接写一份通用乐观DTO。useSandboxOperations在调用前记原投影：start调用markSandboxRestart，stop/destroy先进入stopping/destroying投影；成功用服务端DTO校正并失效sandbox/project/system/成果资源。

409按真实状态冲突读取最新sandbox并提示，网络/未授权回滚已有投影且刷新；业务失败保留failureCode/failureOperation。销毁当前任务先清当前指向并返回总览，成功给成果去处，失败保留可理解的状态说明。

其他领域的乐观边界各自明确：镜像重新验证在服务器返回前不改validationStatus/digest；镜像禁用与规则开关可保存旧列表快照，失败回滚、settled失效。自动停用规则重新启用依赖返回的真实failure计数/降级状态，不在客户端猜恢复结果。mutation默认retry=0，任何补偿都必须由明确流程执行。

## 3. Zustand 细化

store承载浏览器共享选择、偏好和内存投影；服务端实体仍通过Query读写。当前结构和持久化白名单由 `web/src/stores/index.ts` 统一定义。

### 3.1 store 划分：单 store + slices（官方与社区共识）

```text
stores/
  index.ts                       合并为单一useAppStore，顶层persist一次
  createUiSlice.ts               选中、偏好、modal与瞬时指向
  createAccessSlice.ts           口令锁、原因与重试时刻
  createSandboxStatusSlice.ts    生命周期/CLI安装/实例启动内存投影
  createProjectCloneSlice.ts     克隆进度内存投影
  createTerminalRegistrySlice.ts 实例/socket不透明句柄与连接投影
  createTerminalTabsSlice.ts     标签、shellId、清单状态与激活序号
```

当前实际使用create + persist/createJSONStorage，没有immer或Zustand devtools中间件。slice action只做所属数据记账；网络、计时、授权取消、焦点和LRU选择放hook/lib，不能借store引入第二套流程。

currentModal实际联合为createProject、newTask、registerImage、retainedVolumes、automations、projectMenu或null。wizardData、wizardReturn和wizard取值均已删除；新任务与新项目dialog独立，不能恢复不存在的确认步回填协议。

selectedProjectForMenu只指“正在管理的项目”，不改工作上下文；例如在A工作时打开B规则，规则详情focusRuleId与成果sourceSandboxId也用独立瞬时字段。expandProject只负责选项目并展开组；路由/任务选择必须使用当前真实导航hook的入口，不假称每条路径都已调用同一展开action。

selectedSandboxTerminalAt仍表示本标签页首次观察到选中sandbox终态的时间，换选中会清除，重复观察不刷新。useSandboxRestore按它作30分钟自动恢复TTL；它不是后端updatedAt，不能宣称精准记录真实结束时刻。当前DTO已有updatedAt，但这个TTL判定仍使用上述观察戳；任务树更新时间来源另见§5。

### 3.2 Terminal Registry 生命周期

终端按sessionId管理。`useTerminalInstance` 的ref Map持有真正xterm/addon/writeBatcher；terminalRegistrySlice用不透明TerminalHandle/SocketHandle记录活实例的连接/renderer投影，socketSessionKey不持久化。PTY订阅的传输状态由终端hook驱动，切标签不等于stop任务。

```text
首次挂载 → attach（并发创建去重、撤销代次守卫）→ 建xterm/fit/addons → socket连接
连接断开 → hook退避重连或按协议停手 → registry连接态投影
同任务切标签 → 仍在mounted集合的实例保留，隐藏画布不重复创建
被LRU移出mounted集合/关闭/卸载 → dispose实例与连接；标签记录按相应动作处理
```

| 表 | 内容 |
|---|---|
| entries | sessionId→sandboxId、terminal/socket句柄、container、renderer、connState、socketSessionKey、lastActiveAt |
| bySandbox / activeSessionOf | 实例归属与当前激活session |
| shellTabsOf | 用户标签及后端shellId/runtimeId；Agent标签由sandboxId派生，不可关闭 |
| tabActivatedAt / tabActivationTick | 真正激活时记录的单调序号，是当前LRU排序输入 |
| shellInventoryOf | 未返回 / ok / unavailable；未知不能当确认空 |

`useTerminalSessions` 调用 `lib/terminal/terminalTabs.ts` 的selectMountedSessions，当前实例集合上限6，保护前台并按激活序号选其余session。LRU不读registry.lastActiveAt，也不因后台write刷屏更新激活顺序；registry.touch字段仍存在，但不将它说成当前淘汰依据。标签比实例长寿，重建标签要回带服务器分配的shellId；关闭标签和销毁后端shell是另一个明确动作。

### 3.3 selector 规范（防过度渲染）

按用途订阅细粒度selector，例如 `s=>s.selectedSandboxId`、`s=>s.sandboxStatuses[id]`、`s=>s.entries.get(sessionId)`；读取回调执行时的最新状态可用getState，不能因此把整个store订阅到所有组件。

合并多个字段时注意新对象引用，必要时用useShallow；slice更新Record/Map要创建新容器引用，不能原位修改后让React订阅失效。列表select/纯派生输出不要写回store。

### 3.4 与分层制度的结合

views禁止import stores；所需数据由container/hook传props。hooks与containers可以读store，container只装配，hook负责外部订阅/取数/流程与lib映射；stores可依赖自身类型与纯lib，但不依赖services或views。完整生产允许关系见文档07 §3。

### 3.5 persist 策略

`partializeAppState` 是当前唯一白名单，localStorage名为agent-platform-ui。它实际产出11个字段：

```typescript
{
  selectedSandboxId,
  selectedProjectId,
  selectedTaskId,
  selectedSandboxTerminalAt,
  sidebarCollapsed,
  taskListFolds,
  bannerDismissedToday,
  theme,
  terminalFontSize,
  lastUsedRuntime,
  lastUsedImage,
}
```

新增字段默认不落盘。任务指令、自动化prompt草稿、回贴code/API key、口令、输出、内部路径、菜单/来源目标、pendingProjectCreate、认证挑战、诊断意图、terminal实例/socketSessionKey/shellId、WS投影均不在白名单。鉴权明文只在AuthGateContainer本次分支局部态，提交清空；换方式重挂或卸载后消失。

initialPrompt不进前端持久化，与后端为异步启动持久化指令不冲突；前端刷新后用SandboxDto.name显示任务名，不为了重新派生名字存prompt。主题SSR默认dark并在首帧前应用实际偏好；指令不跟主题同存。安全验收以当前独立acceptance的真实交互/HTTP与白名单核对为准，不再指向退役store快照套件。

## 4. 连接态归属论证：Zustand（不是 Query）

PTY/xterm句柄不是可序列化REST资源；连接生命周期、重连凭据与实例强耦合，不能放Query模拟一次请求的resolve。终端连接的共享显示归registry，细节/计时归其hook。全局/events的connState、attempt、handshakeErrorCode在持久AppFrame使用的hook里，当前不把它强行搬入registry。

sandbox.status是服务端业务生命周期；当前WS内存投影与REST DTO共同提供最新显示，仍受服务端状态机权威约束。connState是浏览器到网关的传输状态，断线不等于任务已失败；系统页只读已有连接投影，不为点亮RTT再创建一条events连接。

## 5. 分组任务树的数据推导（不建平行结构）

```text
Query ['sandboxes','list'] ────┤

Zustand taskListFolds ─────────┤→ useProjectTaskTree → selectProjectTaskTree → filterProjectGroups
selectedProjectId / taskSearch / taskStatusFilter ─┘
```

| 规则 | 真实行为 |
|---|---|
| 数据范围 | AppFrame取全部项目和全部任务，一份列表支持任意页sidebar；不按当前项目切Query |
| 组与排序 | 项目API顺序，当前项目置顶；任务按lastActiveAt倒序；孤儿任务归“未分组” |
| lastActiveAt | useSandboxes将DTO.updatedAt解析为epoch ms，缺席为0；taskActivity据此派生副行。它代表服务端记录更新时间，不是终端键盘/输出活动的采样时间，也不再恒硬编码0 |
| 折叠 | collapsed只影响子项渲染，原始任务仍参与过滤与全局统计 |
| 搜索与状态 | AND过滤全项目task.name/状态，大小写不敏感子串；空匹配组消失，过滤计数用匹配数量 |
| 当前菜单 | 全部/准备中/运行中/等待输入/已停止/异常；paused类型仍有匹配函数，但AppSidebar未列该选项 |
| 等待输入 | countWaitingInput在原始全量tasks上算running且waitingInput，不受过滤/折叠影响 |
| 进入任务 | 实际导航hook设置task/project并写taskId深链，404清指向/显示原因；不将派生树写回store |

useSandboxes以最新rawStatus限定waitingInput，运行中筛选排除等待输入，使两类匹配互斥。无进展判断使用sandboxStatuses.lastProgressAt，不能拿任务树updatedAt或registry.lastActiveAt替代。

## 6. devtools

根Providers只在NODE_ENV=development挂ReactQueryDevtools；它用于观察实际key、失效和SSE缓存。当前useAppStore仅套persist，没有Zustand devtools或immer中间件，不把未接入的Redux DevTools/action命名机制写为现状。

浏览器MSW也由NEXT_PUBLIC_API_MOCK=1显式开启，默认联调真实后端；Storybook与独立acceptance各用自己的替身边界。调试工具与测试替身都不能成为生产数据的第二个权威。
