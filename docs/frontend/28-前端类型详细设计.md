# 28 - 前端类型详细设计

> 定位：[07](./07-前端目录结构与视图逻辑分离.md) 给分层与目录、[15](./15-前端状态管理.md) 给状态分类、[14](../shared/14-跨仓类型安全.md) 给类型安全机制（防漂移/防绕过）。本文补齐**前端实际的类型声明**——生成类型怎么消费、store/key/props/纯函数的类型契约。
> **前端不手写 wire 类型**：对外 DTO/枚举一律从 [shared/10 §7](../shared/10-接口契约与类型共享.md)（后端 zod 单源）经 `openapi.d.ts` 生成消费。本文写的是"如何消费生成类型 + 前端自有类型"。

## 1. 生成类型的结构与消费

```ts
// types/generated/openapi.d.ts —— openapi-typescript 产出，勿手改（14 §1）
// 用法：从 components.schemas 取，永不重新声明 DTO
import type { components, paths } from '@/types/generated/openapi';

type SandboxDto  = components['schemas']['SandboxDto'];       // 与 shared/10 §7.3 同形
type ProjectDto  = components['schemas']['ProjectDto'];
type RuntimeDto  = components['schemas']['RuntimeDto'];
type ImageDto    = components['schemas']['ImageDto'];
type ApiError    = components['schemas']['ErrorEnvelope'];    // 全站错误唯一形状（§5）

// provider registry（GET /api/providers）——**开放集，前端不得枚举闭集**（shared/10 §7.2）
type SandboxProviderDto          = components['schemas']['ProviderResponseDto'];
type SandboxProviderCapabilities = SandboxProviderDto['capabilities'];              // 6 位全 required
type SandboxProvider             = string;                                          // = ProviderId，registry 解析，不是联合类型
type SandboxCapabilityRequire    = NonNullable<components['schemas']['CreateSandboxDto']['require']>;
//   ↑ 后端加一位能力位 → generate:api → 这里编译期报红，而不是运行时静默少一位（shared/10 §7.6）

// 枚举同样从生成物取，不在前端重列字面量
type SandboxStatus     = components['schemas']['SandboxStatus'];      // 12 值
type CloneStatus       = components['schemas']['CloneStatus'];        // cloning|ready|failed
type CredentialStatus  = components['schemas']['CredentialStatus'];   // none|active|expiring|expired

// 请求体也取生成类型（service 层入参）
type CreateSandboxRequest = paths['/api/sandboxes']['post']['requestBody']['content']['application/json'];
```

**view props 一律 derive 自生成 DTO，永不手写**（14 的纪律落到类型）：

```ts
// views/sandbox-list/TaskListItem.view.tsx
interface TaskListItemProps {
  task: Pick<SandboxDto, 'id' | 'name' | 'status' | 'waitingInput' | 'lastActiveAt'>;
  onSelect(id: string): void;
}
// ✅ 用 Pick/Omit 从 DTO 裁剪；❌ 禁止 interface Task { status: 'running' | ... } 这类手写重复
```

**禁令**（呼应 14 第二部分，ESLint 落点）：`openapi.d.ts` 禁手改；禁 `as unknown as X`；wire 形状变更走后端 zod → 重新生成，不在前端"临时补个字段"。

## 2. WS 事件 union 类型

```ts
// types/ws-protocol.ts —— 与 shared/10 §7.4 手工同步（X-Schema-Hash 握手校验，14 §2.5）
export type TerminalServerFrame =
  | { type: 'data'; data: string }              // plain string，xterm 直接 write（非 base64）
  | { type: 'exit'; code: number }              // agent 进程退出（137=OOM），前端显示 exit code + 人话（08 §8）
  | { type: 'pong' }
  | { type: 'session'; socketSessionKey: string };
export type TerminalClientFrame =
  | { type: 'input'; data: string }
  | { type: 'resize'; cols: number; rows: number }
  | { type: 'ping' };

export type SandboxEvent =
  | { event: 'sandbox.created'; sandboxId: string; projectId: string }
  | { event: 'sandbox.status_changed'; sandboxId: string; status: SandboxStatus; phase?: string }
  | { event: 'sandbox.removed'; sandboxId: string }
  | { event: 'sandbox.waiting_input'; sandboxId: string; waiting: boolean; sessionId?: string }
  | { event: 'project.clone_progress'; projectId: string; phase: 'cloning'|'slow'|'done'|'failed'; receivedBytes?: number; totalBytes?: number; percent?: number; errorCode?: string }
  | { event: 'runtime-auth.status_changed'; runtime: string };

// applyEvent 按缓存形状判别（15 §2.3 的两个坑：list 是数组、detail 是单体，不能混写）
function applyEvent(e: SandboxEvent): void;   // 用 setQueriesData({ queryKey: sandboxKeys.all() }, predicate) 覆盖全族
```

**运行时校验边界**（16 §3）：WS 帧与不可信边缘**入口处 zod `.parse()`**——生成类型是编译期契约，WS 是无 openapi 保证的通道，必须运行时兜一层：

```ts
const SandboxEventSchema = z.discriminatedUnion('event', [ /* … */ ]);
socket.onMessage(raw => { const e = SandboxEventSchema.parse(JSON.parse(raw)); applyEvent(e); });
```

## 7. 类型总量与不手写边界

| 类别 | 数量 | 来源 |
|---|---|---|
| 生成 DTO/枚举消费点 | shared/10 §7 全量 | `openapi.d.ts`（**不手写**） |
| WS union | 2 通道 | `ws-protocol.ts`（手工同步 + X-Schema-Hash） |
| Store slice 类型 | 2（Ui + TerminalRegistry） | 前端自有 |
| Query key 工厂 | 9（+ `providerKeys`） | 前端自有（`as const`） |
| 纯函数契约 | 6（mapStatus×2 / projectGroupState / validateEnvVar / selectProjectTaskTree …） | 前端自有 |
| 错误消费 | 1（`ApiError`） | = 后端 envelope |

**一句话边界**：凡"过线"的类型（DTO/枚举/错误）来自后端 zod 单源、经生成消费、永不手写；凡"前端自有"的类型（store/key/派生纯函数）在前端定义，但**输入输出仍咬合生成的 DTO/枚举类型**——`SandboxStatus` 改了，`mapStatusToStage` 的 switch 在 tsc 阶段就红。

## 8. 四层类型流转（view/logic 分离的类型骨架）

> 07 §3 的分层铁律用类型表达：**类型从右往左收窄，副作用从左往右禁止**。一份 wire DTO 进来，每层只暴露下一层需要的形状。

```
generated DTO ──▶ service（唯一 fetch/WS）──▶ hook（唯一 useEffect/业务态）──▶ container（粘合）──▶ view（props 驱动，纯展示）
   SandboxDto        Promise<SandboxDto>         { data, isPending, mutate }      装配 props        Pick<SandboxDto,...>
```

| 层 | 类型职责 | 禁止 |
|---|---|---|
| **service** | 入参/返回全是**生成的 DTO/枚举**（`Promise<SandboxDto>`）；WS 帧是 `ws-protocol.ts` union | 不产生前端自定义形状 |
| **hook** | 返回**逻辑态契约**（Query result / mutation / 状态机 union / 派生纯函数结果）；对外暴露的是"视图要用的语义态"，不是原始 DTO | 不返回 `any`；不把 DTO 原样透传时要 Pick |
| **container** | 只做类型装配：`hook 返回` → `view props`；本身几乎无自有类型 | 不写业务类型 |
| **view** | props 是 `Pick/Omit<DTO>` 或 hook 结果的窄切片 + 回调签名 | 不 import service/hook 的类型以外的东西 |

## 11. 鉴权状态机类型（三分支 discriminated union）

```ts
// hooks/useRuntimeAuthFlow.ts —— 07 §6.2 三分支即时完成；状态机 idle→pending→polling→success/expired/error
type AuthFlowState =
  | { phase: 'idle' }
  | { phase: 'pending'; method: 'oauth-device' | 'setup-token' | 'api-key' }
  | { phase: 'polling'; method: 'oauth-device'; challenge: AuthChallenge; countdownSec: number; netErrorStreak: number }  // 连续 3 次网络错误转"网络异常"，不消耗倒计时
  | { phase: 'success'; masked: MaskedRuntimeCredential }
  | { phase: 'expired' }                                    // AUTH_CHALLENGE_EXPIRED → [重新获取]
  | { phase: 'error'; code: 'AUTH_REJECTED' | string; reasons: string[] };   // 就地红字，不弹层
function useRuntimeAuthFlow(runtime: string): {
  state: AuthFlowState;
  startAccount(method: 'oauth-device' | 'setup-token'): void;
  submitPasteCode(code: string): void;      // setup-token
  submitApiKey(secret: string): void;       // api-key 短路
  retry(): void;                            // expired/error 重走
};
// 关键：state 是 discriminated union → view 按 phase 穷举渲染，漏一个分支 tsc 红（无"忘了处理 expired"）
```

```ts
  { partialize: s => ({ /* 白名单（与 15 §3.5 同源）：selectedSandboxId, selectedProjectId, sidebarCollapsed, taskListFolds, bannerDismissedToday, terminalFontSize, lastUsedRuntime, lastUsedImage */ }) }));
// ⚠️ partialize 类型收窄从类型层保证 initialPrompt/socketSessionKey 不落盘（15 §3.5，CI 快照断言）

// 横幅优先级（useGlobalBanner 逻辑，view 只收结果）
type BannerPriority = 'blocking' | 'governance' | 'info';   // 🔴>⚠️>ℹ️（P21-1 §9）
interface Banner { id: string; priority: BannerPriority; text: string; action?: { label: string; run(): void };
                   autoDismissMs?: number /* info 5s；governance 不自动收起 */ }
```

## 15. 补充后的类型总量

| 类别 | 数量 |
|---|---|
| 生成 DTO/枚举消费点 | shared/10 §7 全量（不手写） |
| WS union | 2 通道（+ zod 运行时校验） |
| service 接口 | 7（+ `ProviderService`；方法签名全生成 DTO） |
| hook 返回契约 | 12+ |
| 鉴权状态机 union | 1（6 phase） |
| 表单/工作态 | 5 |
| Store slice + 组合 | 2 + AppStore |
| Query key 工厂 | 9（+ `providerKeys`） |
| 派生纯函数契约 | 6 |
| 组件 props 模式 | Pick/Omit 派生（列关键 6 个） |
| Banner / 错误消费 | 2 |

**一句话**：过线类型（DTO/枚举/错误/WS）来自后端单源、生成消费、永不手写；前端自有类型（service 签名咬合 DTO、hook 契约、状态机 union、store、派生纯函数、props 切片）在前端定义，但**输入输出全部咬合生成类型**——后端改一个枚举值，从 service 到 view props 到纯函数 switch，整条链在 tsc 阶段逐点报红。
