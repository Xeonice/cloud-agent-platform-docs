# 28 - 前端类型详细设计

当前 workspace 的类型设计。分层见 [07](./07-前端目录结构与视图逻辑分离.md)，状态归属见 [15](./15-前端状态管理.md)，生成与安全边界见 [shared/14](../shared/14-跨仓类型安全.md)。完整产品行为采用 [领域需求](../product/requirements/README.md)。

## 1. 生成类型的结构与消费

REST 的 wire 类型来自后端契约 → `api/openapi.json` → `web/openapi.json` → `src/types/generated/openapi.d.ts`。生成物不能手改；领域文件只建立别名，服务、hook、替身共用这些别名。

```ts
import type { components } from '@/types/generated/openapi';

type SandboxDto = components['schemas']['SandboxResponseDto'];
type ProjectDto = components['schemas']['ProjectResponseDto'];
type RuntimeDto = components['schemas']['RuntimeResponseDto'];
type ImageManifestDto = components['schemas']['ImageManifestResponseDto'];
type ProviderDto = components['schemas']['ProviderResponseDto'];
type ApiError = components['schemas']['ErrorEnvelope'];
type SandboxStatus = SandboxDto['status'];
type CloneStatus = ProjectDto['cloneStatus'];
type CredentialStatus = RuntimeDto['credentialStatus'];
type CreateSandboxInput = components['schemas']['CreateSandboxDto'];
type RequiredCapabilities = NonNullable<CreateSandboxInput['require']>;
```

生成物中没有独立的 `SandboxDto`、`ProjectDto`、`RuntimeDto` 或 `SandboxStatus` schema；以上是前端别名。Provider 是开放 registry 的字符串，不能硬编码 aio/boxlite 闭集。当前 capabilities 有七位，包括 `headlessTask`；能力存在还需要有实际端点与完整业务实现，才能提供 UI 动作。

镜像列表、删除预览、参数、预检与更新分别取真实生成 DTO。任务上的锁定镜像信息取任务响应，不能用管理页当前版本替代。枚举从具体字段派生，字段新增或改变通过生成与 typecheck 暴露。

## 2. WS 事件 union 类型

`types/ws-protocol.ts` 与后端 canonical 帧对账，`types/sse-protocol.ts` 对账诊断与预制镜像阶段。REST OpenAPI 不覆盖这些流；服务层入口执行运行时解码，合法帧才进入 reducer/store/query。

终端、`/events` 与无头 `/tasks` 分别处理握手、输入/输出、退出、错误与重连。`/terminal` 的 exit.code 必为 number，原生空退出码由 gateway 转为 -1，不视为成功，也不提供独立 signal 字段；`/tasks` 的 exitCode 则可缺席。等待输入是观察投影，不新增 SandboxStatus。帧不可信时保留已有现场并处理协议错误，不能把任意 JSON 断言成 union。

事件重新连接后重取项目、任务及当前详情。hook 在请求发出前捕获本地 sandboxStatuses 对象引用，响应到达时比较投影是否已变化，保留期间收到的 WS 状态；请求本身不携带事件序号。相关验收见新版 `events-rest-resynchronization`。

## 3. Store 类型（Zustand 单 store + slices）

`stores/index.ts` 合并 UI、访问控制、状态观察、项目克隆、终端 registry 与 tabs。服务端业务对象由 Query 管理；store 保存选择、显示偏好、现场连接及瞬时操作状态。

持久化的唯一实现是 `partializeAppState`，当前白名单为：selectedSandboxId、selectedProjectId、selectedTaskId、selectedSandboxTerminalAt、sidebarCollapsed、taskListFolds、bannerDismissedToday、theme、terminalFontSize、lastUsedRuntime、lastUsedImage。

登录挑战、明文凭证、初始指令、输出、socketSessionKey/shellId、pendingProjectCreate、终端实例不持久化。已退休的 wizardData 不属于当前 store。未知路径恢复清掉交互及无头选择，换到总览并留下可见说明。

## 4. Query key 工厂类型（`as const` 精确字面量）

key 工厂位于拥有查询的 hook；没有 `lib/queryKeys.ts` 统一文件。projectKeys 在 `useProjects`，sandboxListKeys 在 `useSandboxes`，sandboxKeys 在 `useSandboxRestore`，runtimeKeys/runtimeAuthKeys 在 `useRuntimes`，imageKeys 在 `useImages`，automationKeys 在 `useAutomations`，taskKeys 在 `useAgentTask`，systemKeys 在 `useAuditStream`。

项目/镜像/运行环境过滤和审计筛选进入各自 key，换筛选即换缓存，不能复用旧游标。`GET /api/providers` 是创建能力 registry，`GET /api/system/providers` 是运维结果，两者不混用。预览只在实际确认对象存在时启用，失败不当作空结果。

## 5. 前端自有值类型（派生逻辑的类型契约）

前端可声明展示模型、命令、编辑草稿和纯函数最小入参；它们不伪装成 wire DTO。例如 ImageCardModel、TaskImageSnapshot、AuthModeRow、DiagnosticsCardModel、AuditRowModel 都描述实际视图所需的数据。

转换在 `lib/` 或 hook 完成，view 只接 model 与回调。资源使用服务端 level、capacity 与阈值，不在前端另算业务阈值；单位、短 digest、有效期、相对时间是展示转换。未知和零、未返回和失败、过期和主动停止等待分别表达。

## 6. 错误消费类型（`ApiError` envelope）

`services/api/apiError.ts` 的 ApiError 是生成 ErrorEnvelope 别名；ApiErrorException 携带 envelope 和 HTTP 状态，网络服务层统一归一化不符合 envelope 的响应。

页面按操作与 `code` 提供可执行文案，未知码有兜底；`message` 是细节，不能从它解析业务码。字段错误由 `details[].path/code` 归位；环境变量错误的顶层是 VALIDATION_FAILED，具体 ENV_* 原因在 details 中，已有生产校验产出方。

读取失败保留 unknown 与重试出口；禁止把失败渲染成零项、没有凭证、没有引用或健康。取消确认框或编辑草稿不触发提交/删除 mutation，提交进行中禁用重复提交和关闭。取消登录会话、取消任务准备则调用各自真实业务请求，不能套用草稿取消语义。

## 7. 类型总量与不手写边界

不维护容易失效的手工类型数量。边界以生成文件、领域别名、ESLint 分层规则、类型检查及实际协议验收为准。

生成值约束可能只留下 string/number；如指令长度与受限变量名，UI 使用与契约对账的常量/验证，不声称 TypeScript 自动验证所有运行时值。严禁双重断言绕过未知响应；外部输入先收窄和验证。

## 8. 四层类型流转（view/logic 分离的类型骨架）

后端生成 DTO → service HTTP/流边界 → hook Query/状态机 → container 组装 model → view props。view 不能访问 service/store，hook 不反向依赖 view，container 的 DOM 操作放到专用 hook。

app 层装配 provider、路由和 container；主题 Toast 与未知路径恢复经 container 接线。纯展示模型可由 types 文件共享，不能因为 view 不能 import lib 而复制业务算法。

## 9. 服务层方法签名（唯一过线处，全是生成 DTO）

方法声明以实际 `services/api/*` 为准，不在文档维护一份虚构签名。沙箱的 create/get/list/start/stop 返回 SandboxResponseDto，destroy 返回 void；项目创建按响应语义处理 ready/cloning，不能把所有 202 都理解成正在克隆。

镜像注册 service 从 HTTP 200/201 得到 `created`，与 body 的 manifest/validation 组成前端 RegisterImageResult；这是 HTTP 元数据投影，不是后端隐藏字段。删除预览和删除各发真实请求，确认时后端再次检查竞争。

凭证保存、切方式、连接测试与删除分别使用生成请求/响应。Git 连接测试必须有真实仓库目标；没有目标时不发送 secret，也不伪造一次成功。

## 10. Hook 返回类型契约（逻辑层的对外形状）

hook 返回查询状态、实际模型、草稿、busy/error 和动作；由 container 决定宿主的关闭与回程。删除预览、诊断结果与启动进度保留各自完整状态，不能只返回 boolean 丢掉失败/未知。

初始化查询失败后的 shell 放行是一次状态决策，不能因新 consumer 挂载立即重新读取导致循环；显式重试仍执行真实请求。无头恢复在模式确认前不附着终端；取消已受理后保持 cancelling，直到实际退出结束。

## 11. 鉴权状态机类型（三分支 discriminated union）

`lib/credential/authFlow.ts` 的 AuthFlowState 按 branch/phase 判别：device-code、setup-token、api-key。真实 method 仍来自 RuntimeDto；access-token-paste 与 api-key 共用粘贴交互，但提交保留真实 method，两者落库的生效模式不同。

device-code 显式 begin 后轮询，challenge.expiresAt 未给时 secondsLeft 为 null，不显示假的 00:00；服务端过期与前端兜底停止等待分开说明。setup-token 的挑战、提交、错误与成功各保留完整数据；API Key 前缀来自 runtime metadata，不按厂商名字猜。

成功结果只含打码标识。取消/离开宿主清理真实会话；关闭后的迟到结果不写回，卸载不能遗留 helper。一个 AuthGate 复用在任务、凭证页和初始化；宿主专属说明由 props 控制。

## 12. 表单/工作态类型（跨 modal 的编辑中间态）

新任务和项目、镜像参数、自动化规则、代理各自持有草稿。客户端保留草稿不意味着持久化；凭证明文提交后清掉。Git 回程只保存目标与操作上下文，StrictMode 重挂载保留，真正离开路由才清理。

已保存 Secret 的输入值为空且 secretStored 为真；原值不进 props/DOM。PATCH 的 env 每条需要 value，空字符串配合已存 Secret 表示保持原密文；输入新值才覆盖，取消 secret 则必须提供明文。不能把省略必填 value 当作保持语义。

镜像运行参数属于 manifest 版本。任务创建锁定镜像配置并合并平台凭证注入；当前 CreateSandboxDto 没有任务级 env/资源覆盖字段，页面和文档不能承诺不存在的覆盖入口。更新版本可继承旧配置，已有目标编辑不覆盖。

## 13. 组件 props 体系（Pick/Omit 派生，不手写重复形状）

wire 字段可用 Pick/Omit/字段索引裁剪；展示文本、来源和交互状态则用明确的 view model。不能在 props 定义 DTO 根本没有的 lastActiveAt；任务列表真实排序/时间取已有 createdAt/updatedAt 或观察时间，并说清含义。

可访问名称、aria-disabled 理由、取消初始焦点、忙碌状态与 retry 回调也属于 props 契约。破坏性确认包含实际对象与后果；不可只凭空数组推断零项。Storybook 参数覆盖这些视图状态，container 验收验证真实读写次数和结果。

## 14. 组合 store 与 Banner 类型

Banner 的类型区分治理、阻断和状态未知；关闭方式、当天抑制与实际导航动作由模型表达。自动化关注来自跨项目接口，读取失败不展示旧快照；凭证页不重复展示全局到期提示。

命令项描述 id、分组、标签、同义词、disabledReason 与执行动作。自动化从任意页逐就绪项目提供具名入口，打开其它项目规则不切走当前任务；入口范围见 [产品裁决](../product/requirements/decisions.md)。命令面板不提供破坏性动作。

## 15. 补充后的类型总量

当前检查入口：`pnpm generate:api`、`pnpm typecheck`、`pnpm lint`、`pnpm check:mock-contracts`。主仓 `pnpm docs:check` 检查两份 OpenAPI 字节和 WS/SSE canonical 一致性。

验收在 `src/acceptance/`，实际执行入口见主仓 [实现状态](../../IMPLEMENTATION-STATUS.md)。类型正确、代码复核、测试通过和指定层级 AC 实跑分别记录，不以旧测试覆盖率或静态类型数量证明完整行为。
