# 12 - 前端验收测试体系（2026-10）

当前产品依据 [新版领域规格](../design-v2/gap/product/README.md)。按已确认的全量迁移决定，旧测试退休，新验收重新规划；旧覆盖率、断言数量与历史变异分数不作为当前验收结论。

## 1. 测试分工

组件验收使用真实 container/hook 与 HTTP 边界，验证用户操作、请求次数、可见结果和取消/失败副作用。视图变体由 Storybook 承载。浏览器设计验收使用生产构建和可重复数据。真实协议验收由后端完整 Nest + SQLite 及跨仓浏览器承担。

## 2. Storybook 与视觉

### 2.1 运行入口

`pnpm storybook`、`pnpm test:storybook`、`pnpm build-storybook`。Story 是纯 view 的状态样本，不能证明容器服务端行为。

### 2.2 状态变体

覆盖正常、加载、空、失败、忙、禁用、警示与破坏性确认。使用真实生成类型；不可把未知数据写成零或伪造健康。

### 2.2.1 通用组件

AppDialog/DialogSections 验证固定头尾、取消焦点、Esc 和忙时冻结；StatusPill 验证语义 token；表单验证可访问名称、错误说明和焦点。暗/亮主题及窄屏均需核对。

### 2.3 交互证据

play 断言具体交互结果；测试应实际触发到目标阶段，再断言取消/失败没有副作用。仅断言按钮存在不等于完成链路。

### 2.4 全稿浏览器

`web/scripts/check-design-*-v2.mjs` 对 manifest 的每稿读取仓内 `docs/design-v2/gap/drafts` 来源，设置对象与状态，驱动真实页面，记录运行错误、溢出和截图。默认暗/亮 ×1440/1024/390，失败先修复再重跑。

### 2.5 覆盖门禁

`pnpm check:stories` 与 `pnpm check:no-emoji` 保持执行。设计图片仍需人工视觉审查；截图存在不能自动认定像素一致。

## 3. 新版组件验收（Vitest）

### 3.1 独立框架

用例位于 `src/acceptance/**/*.test.ts(x)`；`vitest.acceptance.config.ts` 使用独立 `src/acceptance/support/setup.ts` 与 `support/server.ts`，不加载旧 mock 全家桶。HTTP baseline 只读；各场景显式定义对象、错误与 mutation。Query retry 由场景控制，StrictMode 验证生命周期。

### 3.1.1 替身边界

替身替换外部网络/导航/终端浏览器能力，保留真实业务 hook、store、service、container 和 view。不得 mock 被测业务函数，也不得把旧测试改名搬入新目录充数。

### 3.2 用例分工

以领域 REQ/AC 组织触发与结果，优先验证有副作用或竞态的边界：登录取消、凭证实际绑定、Git真实仓库目标、销毁/恢复、事件顺序、镜像引用竞争和口令锁。

### 3.3 Next.js 边界

隔离 navigation 的 browser shell；测试保留实际路由回程状态。生产构建浏览器验证补足 SSR/客户端装配、Dialog 和布局差异。

### 3.4 类型与值

wire fixture 使用生成 DTO 或 production schema 约束，修改契约从后端重新生成；禁止 `as unknown as`。真实资源 Provider 与脚本测试的运行环境仍需实际协议验证，不能由 fixture 值证明。

## 4. 浏览器与跨仓

### 4.1 两类数据来源

设计 runner 可以隔离 HTTP/WS，以稳定制造每稿状态；跨仓 `e2e-contract` 使用真实 Nest/SQLite 响应且浏览器不能 route 冒充 API。二者分别记录，不混称真实部署测试。

### 4.2 核心旅程

口令门→初始化判定→项目创建→发起任务→终端/无头输出→停止/启动/销毁→成果；另验凭证登录/删除、镜像管理、系统诊断/审计和自动化。全 AC 不要求一律用最慢浏览器验证，按规定最低层和风险分工。

## 5. 执行顺序

契约生成/一致性→类型检查→lint与story门禁→新版组件验收→生产构建→全稿浏览器→真实跨仓旅程。结果记录执行命令、日期、case数与证据路径，计划条目不能记为已通过。

## 6. 证据边界

代码审查可以确认实现迁移，但不能冒充实跑验收。外部云沙箱、SSH、镜像仓库与真实部署环境的运行条件应明确记录；隔离协议用例仅证明已实际执行的控制面/数据面边界。
