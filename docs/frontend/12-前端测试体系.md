## 1. 测试金字塔总分工

| 层级 | 工具 | 覆盖对象 | 数量级/速度 | CI 阶段 |
|---|---|---|---|---|
| L1 单元测试 | **bun test** | hooks 状态机、services 协议编解码/请求封装、lib 纯函数 | 多、毫秒级 | 第 2 道门（与 L2 并行同门） |
| L2 组件逐层验证 | **Storybook（Vitest addon）** | views 纯渲染多态、containers 的 hooks→view 映射与交互、（可选）视觉回归 | 中等、秒级 | 第 2 道门（与 L1 并行同门） |
| L3 集成/E2E | **Playwright** | 跨层真实链路：路由 + 数据 + WS + 终端渲染、鉴权全流程 | 少而精，只做关键路径 | 第 3 道门（L1+L2 过后再跑） |

四道门 = static-checks（1）→ 单测+组件测试并行（2）→ e2e（3）→ build（4），见 §5。

原则：**最快最便宜的检查最先失败**；三层边界清晰，同一场景不重复覆盖。

> **与逐页测试设计的分工**：本文管**体系与工具链**——分层选型、mock 边界、story 覆盖强制、CI 编排、跨页组件的必备 variant（§2.2.1）与 E2E 用例组 A–G 的边界（§4.2）。**每一页具体测什么**（断言级用例清单）写在 [pages/](./pages/README.md) 各页的「§7 本页测试设计」中，四层结构与本文一一对应：unit（bun）/ Storybook / 集成（container story + `play` + msw，**不是第四套运行器**，见 §3.2 的分工边界）/ e2e。两处不重复：pages/* 只声明"本页参与哪些用例组 + 本页独有场景"，绝不重新定义 mock 方案或 CI 顺序。

## 2. Storybook 逐层验证

### 2.1 版本与集成

- **`@storybook/nextjs-vite`**（当前 10.5.3；该框架包与 Vitest addon 测试体系均自 Storybook 9 引入并延续至今，下文统称 Storybook 9+）：官方推荐的 Vite-based Next.js 框架包，比 Webpack 版更快、测试特性更完整。仅当存在 Vite 不兼容的自定义 Webpack 配置时才退回 `@storybook/nextjs`。
- App Router / RSC：`.storybook/main.ts` 可开 `experimentalRSC`，但本项目 view 层纯 props 驱动，绝大多数 story 不需要。
- 历史插件 `storybook-addon-next` / `storybook-addon-next-router` **不再需要**，避免引入冲突。

### 2.2 逐层落地

| 层 | Story 写法 | 验证目标 |
|---|---|---|
| **view** | 只传 mock props，不引入任何 Provider/Context；每个 variant（loading/empty/error/data）各一个 story | 证明"纯函数式渲染"——若 story 无法脱离 QueryClientProvider/WS 渲染，说明混入了逻辑（boundaries lint 的双重保险） |
| **container** | decorator 注入 mock：预置数据的 QueryClientProvider；网络层用 **`msw-storybook-addon`** 拦截（REST + `ws` namespace） | 验证"容器正确把 hooks 输出映射为 view props"，覆盖 loading/error/连接中/已连接切换；handler 与 `mocks/handlers.ts` 共用一份定义 |
| **hooks** | **不写 story**（无 UI 输出，机制不适用） | 交给 bun test 的 `renderHook`（§3） |

```
// TerminalPane.view.stories.tsx —— 结构示意
export const Connected    = { args: { status: 'connected', lines: [...] } };
export const Disconnected = { args: { status: 'disconnected' } };
export const Reconnecting = { args: { status: 'reconnecting', retryInSec: 3 } };

// TerminalContainer.stories.tsx —— container 层
export const Default = {
  decorators: [withMockQueryClient({ sandboxes: mockSandboxes }), withMockWs(wsHandlers)],
};
```

`msw-storybook-addon` 接入要点：需要 `msw@2.x` 作 peer dependency，`tsconfig.json` 的 `types` 加入 `"msw-storybook-addon/types"`。CSF Factories 写法（Storybook 9 新式）在 `preview.ts` 里把 `addonMsw` 注册进 `definePreview()` 的 addons；CSF3 写法则在 `main.ts` 注册插件 + `preview.ts` 的 `loaders` 加 `mswLoader`，每个 story 用 `parameters.msw.handlers` 声明专属 mock。

#### 2.2.1 产品定稿新增组件的 story 覆盖要求

新组件同样受"每个 view 必有 story"约束（§2.5）；下表规定**每个组件至少要有哪些 variant**，避免只写一个 happy path 就算覆盖：

| 组件 | 必备 story variant |
|---|---|
| **ProjectTaskTree**（含 `ProjectGroupHeader` / `TaskListItem` / `EmptyGroupCta` / `WaitingInputSummary`） | 多项目多任务（含折叠组与展开组共存）· 单项目 · **空组 CTA** · 全部 Task 六态各一（🟡/🟢/🔵 等待输入/⏸️/🔴/淡出）· 🎁 卷保留倒计时 · 「⚡ N 个任务等待你输入」汇总行有/无 · 组头 hover「⋯」显形 · 列表降级角标「△ 数据可能非最新」 |
| **SettingsLayout / SettingsMenu** | 三个子页各自选中态 · [← 返回工作台] 存在性（快照即可） |
| **RegisterImageModal** | 空表单 · 验证中（按钮 loading）· ✅ 通过（出现 [保存]）· ⚠️ 警告（附后果说明，仍可保存）· ❌ 失败（禁用保存 + [查看镜像要求]） |
| **AuthGatePanel**（+ `DeviceCodeAuth` / `SetupTokenAuth` / `ApiKeyAuth`） | Tab 两态（帐号授权 / API Key）· device-code 轮询中（含倒计时正常/剩 5min 转黄/归零转红 + [重新获取]）· setup-token 待粘贴 / 提交中 / 授权码错误 · api-key 前缀非法红边 / 提交中 / `AUTH_REJECTED` 就地红字与原因列表 |
| **CurrentProjectIndicator** | 有当前项目 · 无项目（"未选择项目"）——**只读**，story 不得出现下拉展开态 |
| **ProjectSelectRow** | 默认当前项目 · 下拉展开（全部项目 +「＋ 新建项目…」）· 新建往返回填后的选中态 |
| **ImageSelect** | 默认 AIO · 含 ⚠️ 警告项（就地后果说明）· 该 runtime 无可用镜像（置灰 + [去镜像管理]） |
| **TaskPromptField** | 空 / 正常 / 接近上限 / **超 8000 字符红字计数** |
| **CreationProgress** | 五阶段逐阶段推进各一 · ⚠️ 可能卡住 · 失败就地变红 + [重试]——**任何 variant 都不得出现"等待登录"阶段** |
| **BannerStack** | 单条各级别（🔴/⚠️/ℹ️）· 🔴+⚠️ 混合（阻断在上）· ⚠️ 堆叠 2 条 +「还有 N 条」折叠 |
| **EnvVarEditor** | 普通变量行 · **已存 secret 行（值为空 + 「保持不变，输入即覆盖」placeholder）** · 新增行 · 校验失败提示 |
| **CredentialCard** | ◉ 帐号授权生效中 / ◉ API Key 生效中 / ○ 未配置 / ⚠️ <7 天预警 / ❌ 已过期 |

**a11y/交互 play 函数重点**：ProjectTaskTree 组头折叠的键盘可达性与 `aria-expanded`；AuthGatePanel 里遮罩输入框的 `type=password` 与 [展开查看] 切换；EnvVarEditor 的 secret 行**断言 DOM 内不含原值**（把安全红线写成可回归的断言）。

### 2.3 交互测试与 CI 执行

- **Storybook 9+ 的 Vitest addon**（取代旧 `@storybook/test-runner`）：基于 Vitest browser mode，一套配置跑 interaction / a11y /（可选）visual 测试。
- 写法：`play` 函数 + `@storybook/test`（instrumented Testing Library + expect）。例：DeviceCodeAuth 的 story 用 play 模拟"点击复制设备码 → 断言 clipboard"；ProjectGroupHeader 的 story 用 play 模拟"点击组头 → 断言 aria-expanded 翻转"。
- CI：`vitest --project=storybook`。

### 2.4 视觉回归

- **推荐 DIY**（不引入 Chromatic——付费且截图数据出网，对私有基建平台有合规顾虑）：Vitest addon/test-runner 驱动 headless Chromium 对 story 截图，`pixelmatch` 或 Playwright `toHaveScreenshot()` 与仓库 baseline 比对，超阈值 fail 并上传 diff 图 artifact。代价是 baseline 更新需人工 review 流程。
- 备选：Applitools Eyes（10.22，2026-01，Visual AI 降误报）；开源 BackstopJS（免费但需手动配置忽略区域）。
- **终端场景特殊性**：xterm 内容含动态时间戳/随机 id，视觉回归只覆盖 **UI 壳层**（工具栏、侧栏、鉴权卡片），不截终端内容本身，避免大量 false positive。

### 2.5 "每个 view 必须有 story" 的强制

1. **主方案：CI 脚本硬扫描**（`scripts/check-story-coverage.ts`）：glob `src/views/**/*.view.tsx`，检查同名 `*.stories.tsx` 存在性，缺失打印文件名并 exit 1。文件存在性检查用脚本比 AST 规则更简单可靠。
2. **可选进阶**：自定义 ESLint 规则 `no-view-without-story`，编辑器内即时报红；成本更高，团队扩大后再补。

boundaries 配置同步新增 story/mock 元素类型：story 允许 import view/container/type/mock，**不允许直接 import service**。

## 3. Bun 单元测试

### 3.1 现状确认（2026-07 官方文档核实）

- `bun test` 无 DOM 全局对象，需 `@happy-dom/global-registrator` 经 Bun **preload** 注册后，`@testing-library/react` 可正常工作；`renderHook` + `act` 已确认可用。
- **已知坑**：`GlobalRegistrator.register()` 必须放在**不 import @testing-library/react** 的独立 preload 文件——preload 顺序执行，混在一起会出现注册未完成 testing-library 已读取 `document` 的时序问题。

### 3.1.1 `mock.module` 的限制（决定 mock 策略的关键）

- **无 hoisting**：与 Jest/Vitest 不同，`mock.module()` 不会提升到文件顶部，是运行时就地 patch 模块缓存，调用必须早于被测代码 import 该模块。
- **无法真正 restore**：原地替换而非可撤销代理，`mock.restore()` 在部分场景不能恢复到 mock 前的真实实现（官方 issue 确认）。
- **测试文件间不隔离**：suite A 里 mock 的模块会**泄漏到 suite B**（全局替换模块缓存），混跑单测与"轻集成"测试极易出现依赖执行顺序的 flaky。
- **应对策略**：
  1. 严格守住"bun test 只测纯逻辑"边界，跨模块集成场景全部交给 Playwright；
  2. **优先依赖注入替代模块级 mock**——如 `ptySocket.ts` 的 WebSocket 构造函数通过参数传入而非直接 `new WebSocket()`，测试传 mock 实现，从根源减少对 `mock.module` 的依赖；
  3. 确需 `mock.module` 时，`afterEach`/`afterAll` 显式 `mock.restore()` 并保持 mock 粒度最小。

### 3.2 分工边界

| 层 | bun test? | 说明 |
|---|---|---|
| `hooks/**` | ✅ | `renderHook` 覆盖状态机分支（`useRuntimeAuthFlow` **三分支各自的** idle→pending→success/expired/rejected 与 api-key 的即时完成路径；`useSandboxTerminalSocket` 重连计数与"Task 转 stopped 时终止重连循环"，mock WebSocket 类；`useGlobalBanner` 优先级排序/堆叠裁剪/自动收起计时） |
| `services/**` | ✅ | `ptySocket.ts` 帧编解码、`runtime.service.ts` 鉴权端点参数拼装、`project.service.ts` 与 `image.service.ts` 的请求/响应映射（mock fetch/client） |
| `lib/**` | ✅ | 纯函数，最快；**`selectProjectTaskTree()` 分组派生是本层主战场**（多项目/空组/孤儿 Task/排序/折叠不影响汇总，文档 15 §5）；`validateEnvVar()` 覆盖正则/黑名单/长度/重复 KEY 各分支（文档 07 §8.3.1）；**终端子系统纯函数**：`writeBatcher` 的 rAF 合并/单批上限/隐藏会话不 flush/卸载 flush（08 §6.1）、`terminalTheme.buildOptions` 的 options 常量（08 §7.3）、`useTerminalSessions` 的多标签增删与激活切换（08 §5.1） |
| `stores/**` | ✅ | slice 的 action 纯逻辑（LRU 决策在 hooks 层、slice 保持"哑"——文档 15 §3.2，测试面小）；**必测 `partialize` 白名单快照**：断言输出不含 `initialPrompt`/`pendingProjectCreate`/任何凭证字段（文档 15 §3.5 安全红线） |
| `views/**` | ❌ 交给 Storybook | happy-dom 对 ResizeObserver/Canvas（xterm 依赖）模拟不完整，易出"测试过但浏览器不同"的假结果 |
| `containers/**` | ❌ 交给 Storybook | 多 hook 组合 + 渲染，story decorator 注入更贴近真实环境 |

这不是"bun 有硬伤退而求其次"，而是**不同测试对象天然适合不同工具**：bun 极快（无浏览器/bundler 开销）适合高频逻辑单测；组件测试复用已有 story，不重复写 fixture。

### 3.3 与 Next.js 共存注意点

- tsconfig `paths` 别名：bun 默认读取 `compilerOptions.paths`，一般无需配置；用了 Next 隐式 `baseUrl` 行为时在 `bunfig.toml`/`tsconfig.test.json` 显式确认。
- CSS/静态资源：`bunfig.toml` 的 `test.preload` 配 loader mock（返回空对象），等价 Jest 的 `moduleNameMapper`。
- next/image、next/font 只出现在 views 层，而 views 不用 bun 测——**分层测试设计天然规避了这批兼容性坑**。
- 覆盖率：`bun test --coverage` 原生支持，输出 lcov 可接 Codecov。

### 3.4 替身的**形状**可以手写,替身的**值**不能凭空 ★

> 起因是一次真跑:建沙箱在真后端下必然失败,而单测 / Storybook / Playwright
> **全绿**。根因不在断言写得松,而在**替身编码了和生产代码一样的错误假设**。

`SandboxTerminalContainer` 硬编码 `runtime: 'shell'` 建沙箱,而后端注册表里只有
`codex` / `claude-code`。之所以没有任何一层测试发现,是因为
`src/mocks/handlers.ts` 里两处也返回 `runtime: 'shell'` —— **前端与它自己的替身
完全自洽,真后端从头到尾没进过回路**。

#### 纪律

| 替身里的东西 | 能不能手写 |
|---|---|
| **形状**(字段名、可选性、嵌套结构) | ✅ 可以,但应从生成类型派生并用 `satisfies` / 显式返回类型咬住(见下) |
| **值**——取自后端**开放集**的那些(`runtime` / `provider` / 错误码 / 状态枚举) | ❌ **不能凭空**,必须是真实来源里存在的取值 |

理由:形状写错会被 tsc 抓住;**值写错不会** —— 它在类型上完全合法,于是替身
安安静静地把一个生产代码里的错误假设"确认"了一遍。

#### 落地要求

1. **mock 工厂必须有显式返回类型**,例如
   `function agentTaskDto(o: Partial<AgentTaskDto>): AgentTaskDto`。
   返回裸对象字面量时,DTO 加了必填字段 mock 会**静默缺失**,而全套测试照绿。
2. **开放集的值,替身取真实来源**:`runtime` 取 `GET /api/runtimes` 里真实存在
   的 id;`provider` 取 `GET /api/providers` 的 `name`;错误码取后端 enum。
   凭空造一个"看起来像"的值,等于给自己发了一张假的通行证。
3. **替身里的注释若声称"与后端一致",必须给得出依据**(端点/契约文件/
   commit),否则它只是一句愿望。

#### 这条纪律不能替代什么

替身再准,也只证明"前端与它理解的后端一致"。**真后端是否认这个值,只有真跑
知道**。所以这条纪律要和 [16 前端链路验证体系](./16-前端链路验证体系.md) 的真
链路验证配套 —— 前者降低概率,后者才是判据。跨仓那一层的完整讨论见
[14 §10](../shared/14-跨仓类型安全.md)。

## 4. 集成测试（Playwright）

### 4.1 Mock 策略

| 对象 | 方案 | 理由 |
|---|---|---|
| REST | Playwright 原生 `page.route()` / `context.route()` | 链路最短。`@msw/playwright` 共享 handler 方案**已否决**——依赖 Service Worker，与下行"E2E 层彻底不启 MSW"的边界规则冲突；mock 数据复用通过共享纯数据 fixture（`mocks/data.ts`）实现，不共享拦截层 |
| WebSocket | **Playwright 原生 `page.routeWebSocket()`（已 GA）** | 可完整模拟服务端：收 client 帧、按脚本推送、模拟断线；不经 Service Worker 中转 |
| MSW | **只保留在 Storybook container story 层**（含 `ws` namespace） | MSW 的 Service Worker 会让请求对 `page.route()` 不可见——E2E 层彻底不启 MSW，避免冲突 |

### 4.2 关键路径用例

覆盖面对齐产品定稿的主链路与页面规格；用例组 A–C 是**必跑门禁**，D–G 按功能上线批次补齐。

**用例组 A：分组任务树 → 选中 → 终端连接 → 回显**
1. mock `GET /api/projects` 返回 3 个项目 + `GET /api/sandboxes` 返回跨项目 5 条 → 断言侧栏出现 **3 个项目组头（含各自任务数）**，Task 归到正确的组下。
2. 点击组头 → 断言该组子项隐藏；**刷新页面 → 断言折叠状态仍保持**（`taskListFolds` persist）。
3. 点击**其他项目**的 Task → 断言当前项目指示器切到该项目、该组自动展开、右侧切到该 Task 终端（跨项目切换）。
4. 点击顶部 **CurrentProjectIndicator** → 断言树内定位并展开当前项目组；**断言不出现任何下拉菜单**（只读指示器）。
5. 终端 loading 态 → `routeWebSocket` 推送 `data` 帧 → 断言 xterm 内容（`page.evaluate` 读 buffer 或断言 DOM 文本）。
6. 终端输入字符 → 断言 mock WS 收到对应 `input` 帧（协议正确性）。
7. 模拟 WS close → 断言"连接已断开，正在重连…" → 第 N 次重试接受连接 → 断言恢复。
8. 切到另一个 Task → 断言原终端 DOM **仍存在但 `display:none`**（验证文档 08 §5 的实例管理策略，非销毁重建）。
9. 推送 `sandbox.waiting_input` → 断言该 Task 行转 🔵「等待你的输入」且**主状态仍是运行中**，侧栏出现「⚡ 1 个任务等待你输入」；点击汇总行 → 断言跳到该 Task 并展开其项目组。

**用例组 B：鉴权三分支——面板内即时完成（无等待登录）**
1. **device-code（Codex）**：Step 1 选无凭证的 runtime → 断言**插入无编号拦截面板**（标题不含 "Step 3" 之类编号）→ mock begin 返回 `{verificationUrl, userCode, expiresAt}` → 断言展示大字号 code + 倒计时；轮询前几次 `pending`、第 N 次 `success` → 断言 **2s 后自动进确认步**，且轮询次数符合 3–5s 间隔（防过度轮询）。
2. **setup-token（Claude Code）**：粘贴 code → 提交 → **断言输入框清空、`localStorage` 无明文残留** → mock 成功 → 断言进确认步并显示掩码帐号。
3. **api-key（两 runtime 通用）**：输入不合前缀的 key → 断言**就地红边提示**（Codex `sk-` / Claude Code `sk-ant-`）；输入合法 key 提交 → mock `AUTH_REJECTED` → 断言**就地红字 + 可能原因列表，不弹层**；再提交成功 → 断言直接进确认步。
4. **全链贯穿断言（决策 1 的回归防线）**：三个分支各跑一次到进度卡，断言**进度卡阶段数为 5 且不含「等待登录」**；断言鉴权请求路径**不含 sandbox 维度**（`page.route` 记录到的 URL 只匹配 `/api/runtimes/:rt/auth/*` 与 `/credentials/secret`）。
5. 异常：轮询返回 `expired` → 断言"已过期" + [重新获取] 可再次触发 begin；连续 3 次网络错误 → 断言"网络异常 [重试]"且**倒计时未被消耗**。

**用例组 C：向导确认步——项目行往返保值 + 镜像 + 指令**
1. 从工作台 ProjectA 进向导 → 断言确认步「项目」行默认值 = **ProjectA**（上下文继承）。
2. 在任务指令里填一段文本 → 项目下拉选「＋ 新建项目…」→ 创建弹层建成 ProjectX → **断言自动回到确认步、项目行已是 ProjectX、任务指令内容原样保留**（`wizardData` 回填，本组的核心断言）。
3. 任务指令输入 8001 字符 → 断言就地红字计数且 [发起] 不可提交；退回 8000 → 恢复可提交。
4. 镜像下拉：断言默认选中 AIO；断言只出现 `isActive && (valid || warning) && supportedRuntimes 含所选 runtime` 的镜像；⚠️ 警告项**可选**且旁边显示后果说明；mock 该 runtime 无可用镜像 → 断言下拉置灰 + [去镜像管理] + [发起] 禁用。
5. [发起] → 断言 `POST /api/sandboxes` 的 body 里 `projectId` **是确认步所选的 ProjectX**（而不是工作台的 ProjectA）。
6. 刷新页面（向导 modal 中途）→ 断言 modal 关闭回工作台；**断言 `localStorage` 中不存在任务指令内容**（安全红线回归）。

**用例组 D：设置页三子页与镜像注册弹窗**
1. 顶栏 ⚙️ → 断言 URL 为 `/settings/credentials`（**不是 `/settings?tab=`**）、左侧为设置菜单、**任务侧栏与终端区已隐藏**。
2. 菜单互切 → 断言 URL 变为 `/settings/images`、`/settings/system`；[← 返回工作台] / Esc → 断言回 `/`。
3. 镜像管理 [+ 注册新镜像] → 断言弹窗打开且焦点在 URI 输入框；[验证] mock ⚠️ 警告 → 断言显示后果说明且 [保存] 可用；保存后 → 断言列表出现该镜像，且**回到向导确认步时镜像下拉已包含它**。
4. mock ❌ 无效 → 断言 [保存] 不可用 + [查看镜像要求] 可见。
5. 环境变量行内编辑：打开已存 secret 的变量 → **断言输入框值为空、placeholder 为「保持不变，输入即覆盖」，且 DOM 中不含原值**。

**用例组 E：销毁保留卷 + Stop**
1. Task 右键 → [销毁] → 断言二次确认弹层出现且 **「☐ 保留工作区成果卷」默认勾选**。
2. 保持勾选确认 → 断言 `DELETE /api/sandboxes/:id` 的 body 为 `{ keepVolume: true }`。
3. 取消勾选 → 断言弹层明示"卷将永久删除"；确认 → 断言请求 body 为 `{ keepVolume: false }`。
4. Stop → 断言二次确认 + 列表转 ⏸️；[重启] 的文案与语义断言为**新会话**（不得出现"恢复现场"字样，P22 §2）。

**用例组 F：全局横幅优先级**
1. 同时注入 🔴 阻断类 + ⚠️ 治理类 + ℹ️ 提示类 → 断言渲染顺序 🔴 在最上。
2. 断言 ℹ️ 提示类 **5s 后自动消失**，🔴 与 ⚠️ **不自动收起**。
3. 注入 3 条 ⚠️ → 断言只展示 2 条 + 「还有 1 条」折叠。
4. 显式关闭一条 ⚠️ → 刷新页面 → 断言**当天不再出现**。

**用例组 G：核心用户旅程贯穿**（与文档 16 §7 的旅程脚本同一份，避免重复维护）
初始化 → 建项目 → 分组树 → 向导两步（含拦截面板）→ 确认步项目/镜像/指令 → 进度 5 阶段 → 终端回显。

## 5. CI 执行顺序（对应文档 09 workflow）

```
static-checks（lint + typecheck + prettier + story-coverage + openapi 漂移检测）   ← 最快失败
   ├──▶ unit-tests（bun test --coverage）        ┐ 并行
   └──▶ storybook-tests（vitest --project=storybook）┘
              └──▶ e2e-tests（Playwright，最重）
                      └──▶ build（next build）        ← 与 16 §6 / 18 §5 / 09 §1.3 一致：串行
```

## 6. 风险与备选

| 风险 | 缓解 |
|---|---|
| 三套测试体系维护成本 | §1 分工表严格执行，同一场景不重复覆盖 |
| MSW 与 Playwright route 冲突 | E2E 层只用 Playwright 原生能力（§4.1） |
| happy-dom 模拟不完整产生假结果 | 组件测试不进 bun，留在真实浏览器（Storybook/Playwright） |
| `mock.module` 跨文件泄漏导致 flaky | §3.1.1：依赖注入优先、bun 只测纯逻辑、显式 restore |
| 视觉回归误报（终端动态内容） | 只截 UI 壳层，不截终端内容 |
