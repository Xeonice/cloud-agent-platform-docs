# F21-4 · 设置 / 镜像管理 `/settings/images` 前端设计

> 状态：✅ 可评审 · 对应产品页：[P21-4 镜像管理](../../product/pages/21-4-镜像管理.md)
> 上级：[前端页面设计总纲](./README.md) · 架构依据：[07 §7.2/§8.3/§8.3.1](../07-前端目录结构与视图逻辑分离.md) · [15](../15-前端状态管理.md) · [12](../12-前端测试体系.md)

## 1. 页面职责

注册自定义 OCI 镜像、查看三级验证结果、管理启用状态与运行参数（环境变量）。**与发起向导共享同一份镜像数据源**——本页的启停/注册直接联动向导确认步的镜像下拉。

## 2. 路由与骨架落点

| 项 | 落点 |
|---|---|
| 路由 | `/settings/images`；深链 `?filter=warning`（进入即应用状态过滤） |
| 路由文件 | `app/settings/images/page.tsx` |
| 布局 | 共享 `SettingsLayout`（左侧设置菜单 + [← 返回工作台]，隐藏任务侧栏，07 §7.2） |
| 弹层 | **注册新镜像是弹窗**（`uiSlice.currentModal==='registerImage'`）；环境变量编辑是卡片内展开的行内表格（非弹窗） |
| 搜索词 | 落 `localStorage` 键 **`imageSearchQuery`**，**仅当前会话保留**：切走设置页即清、不跨会话、**刷新不恢复**（P21-4 §6）。因此它**不进 `uiSlice` 的 persist 白名单**——那是跨会话偏好，语义不同（15 §3.5） |

## 4. 状态与数据接入

| 类别 | 具体 | 来源 |
|---|---|---|
| Query | `imageKeys.list()` → `GET /api/images`（含 `validationStatus` / `isActive` / `supportedRuntimes` / `imageConfig`） | 15 §2.1 |
| Mutation | `validatePreflight` → **`POST /api/images/validate`**（注册**前**预检，**不落库**；后端 60s 超时，前端按钮 loading 覆盖全程） | 02 §5.1（审计 P1-3） |
| Mutation | `revalidateImage` → **`POST /api/images/:id/validate`**（已注册镜像重新验证，**写回 `validationStatus`**） | 02 §5.1（审计 P1-3） |
| Mutation | `createImage` → `POST /api/images` | — |
| Mutation | `toggleImage` → `PATCH /api/images/:id { isActive }`（**乐观更新**） | 02 §5.1、15 §2.4 |
| Mutation | `deleteImage` → `DELETE /api/images/:id`（被引用时后端 RESTRICT） | — |
| Mutation | `saveRunParams` → **`PATCH /api/images/:id { imageConfig }`**（与启停同一个部分更新端点） | 02 §5.1 |
| Zustand | `currentModal='registerImage' \| 'deleteImageConfirm'` | 15 §3.1.1 |
| container 局部 state + `localStorage` | 搜索词（键 `imageSearchQuery`，会话内有效；**不进 persist 白名单**，见 §2） | P21-4 §6 |
| container 局部 state | 注册表单草稿、env 编辑草稿、**secret 值输入**（提交即清空） | 07 §3 规则 2 |

**联动纪律**：`createImage`/`toggleImage`/`deleteImage` 成功后一律 `invalidateQueries(imageKeys.list())`——向导下拉与本页共用同一缓存，因此"禁用后向导下拉自动移除"是缓存失效的自然结果，**不需要任何跨页通知机制**。

## 5. 交互实现要点（产品交互表逐行映射）

| 产品交互（P21-4 §6/§10.2） | container + handler | 调用 |
|---|---|---|
| [+ 注册新镜像] | `handleOpenRegister()` | `currentModal='registerImage'`；打开后**焦点自动入 URI 输入框** |
| [验证]（注册弹窗内） | `handleValidatePreflight(uri)` | `image.service.validatePreflight(uri)` → **`POST /api/images/validate`**（不落库）；按钮 loading；60s 未返回按 `TIMEOUT` 处理，envelope 的 `retryable:true` 驱动 [重试]（P22 §1） |
| [重新验证]（已注册卡片内） | `handleRevalidate(id)` | `image.service.revalidate(id)` → **`POST /api/images/:id/validate`**（写回 `validationStatus`）→ invalidate `imageKeys.list()` 刷新卡片三态；**MVP 仅手动触发**，无周期自动重验证 |
| 验证结果渲染 | `ValidationResult.view` 接收 `{status, warnings, errors}` | ✅/⚠️ → 显示 [保存]；❌ → 禁用保存 + [查看镜像要求] 链接 |
| [保存] | `handleSave()` | `image.service.create({uri})` → 关弹窗 + invalidate + toast |
| [禁用]/[启用] | `handleToggle(id, next)` | 乐观 patch 本地缓存 → `PATCH /api/images/:id`；失败回滚（15 §2.4） |
| [删除] | `handleDelete(id)` | 仅自定义镜像可见；二次确认 → `DELETE`；后端 RESTRICT → 就地提示「该镜像被 N 个 Task 引用，请先禁用后再删除」 |
| 预置镜像（AIO） | — | 前端**隐藏 [删除]**，仅保留 [禁用]（P21-4 §9） |
| 搜索/过滤 | `handleSearch/handleFilter` | 纯客户端；`?filter=warning` 深链在挂载时注入初值 |
| [编辑环境变量] | `handleEditEnv(id)` | 卡片内展开 `EnvVarEditor.view`（行内表格），非弹层 |
| env 行编辑 | `handleEnvChange(rows)` | 逐行调 `lib/validateEnvVar.ts`（正则 `^[A-Za-z_][A-Za-z0-9_]*$`、黑名单、长度、重复 KEY——07 §8.3.1），错误码**与后端四个码同名**（见下表），错误以 `errors` prop 下传，view 只渲染 |
| 已存 secret 再编辑 | `EnvVarEditor` 的 secret 行 | **value 渲染为空串** + placeholder「（保持不变，输入即覆盖）」；**原值不进 props、不进 DOM** |
| 保存 env | `handleSaveEnv()` | `PATCH /api/images/:id { imageConfig }`；**secret 行传空 value = 保持不变**（后端语义已与前端设计对齐，不是清空）；有值则覆盖；后端 400 响应带逐项 `path` → **按 `path` 定位到具体变量行渲染红字**，不整表报错 |

**env 错误码映射（前后端同名，02 §5.1）**——前端 `validateEnvVar` 的分类直接用这四个码；后端 400 按**统一错误 envelope**（shared/10 §6.8）返回 `{ code:'ENV_VALIDATION_ERROR', message, retryable:false, traceId, details:[{path, code, message}] }`，前端按 `details[].path` 归位到具体变量行、`details[].code` 命中同一套文案，**不做二次翻译**：

| 错误码 | 触发 | 行内文案 |
|---|---|---|
| `ENV_NAME_INVALID` | 不匹配 `^[A-Za-z_][A-Za-z0-9_]*$` | 「变量名只能包含字母、数字、下划线，且不能以数字开头」 |
| `ENV_NAME_RESERVED` | 命中黑名单 / `GIT_`·`CODEX_` 前缀 | 「该变量名为系统保留，请使用凭证管理配置」 |
| `ENV_LIMIT_EXCEEDED` | KEY >64 / VALUE >4096 / 条数 >50 | 就地字符计数转红；条数到顶时 [+ 添加变量] 置灰 |
| `ENV_DUPLICATE_KEY` | 同一镜像内 KEY 重复 | 两行同时红边「变量名重复」 |

这样做的好处：前端提示与后端拒绝**永远是同一句话**——用户不会遇到"前端说没问题、后端换个说法拒绝"的割裂感；也让 §7.1 的单测可以直接断言错误码而非文案。

## 6. 状态矩阵落地

| 产品状态（P21-4 §5） | 渲染分支 |
|---|---|
| 加载中 / 空 | `isPending` → 卡片骨架；`data.length===0` → `ImagesEmptyState` + CTA |
| ✅ 有效 | `validationStatus==='valid'` → 绿勾 + 适用 runtime 列表 |
| ⚠️ 警告 | `warnings.length>0` → 黄色 + **后果说明**（"终端断线恢复将降级"），仍可用 |
| ❌ 无效 | `validationStatus==='invalid'` → 红 + errors 列表 + [查看镜像要求]；卡片标记"不可用于创建" |
| 验证中 | `validatePreflight.isPending` → 弹窗 [验证] loading、[保存] 不渲染；`revalidate.isPending` → 卡片内 [重新验证] loading、三态区显 spinner |
| 已禁用 | `isActive===false` → 卡片置灰 + [启用]；**同时从 `ImageSelect` 选项中消失**（同一缓存派生） |
| 排序 | ✅ > ⚠️ > ❌，同组按最后更新倒序（`lib/sortImages.ts`） |

### 7.1 unit（bun test：lib / hooks / services）

| 被测 | 用例（断言级） |
|---|---|
| `lib/validateEnvVar.ts` | ① `LOG_LEVEL` 通过；② `log_level` **通过**（小写不报错，仅惯例）；③ `1ABC` → `ENV_NAME_INVALID`；④ `A-B` → `ENV_NAME_INVALID`；⑤ `OPENAI_API_KEY` → `ENV_NAME_RESERVED`；⑥ `GIT_ANY` / `CODEX_ANY` → `ENV_NAME_RESERVED`（前缀整体拦截）；⑦ KEY 65 字符 → `ENV_LIMIT_EXCEEDED`、64 通过；⑧ VALUE 4097 → `ENV_LIMIT_EXCEEDED`、4096 通过；⑨ 51 条 → `ENV_LIMIT_EXCEEDED`、50 条通过；⑩ 同名 KEY → 两行都标 `ENV_DUPLICATE_KEY`。**断言的是错误码而非文案**（前后端同名，02 §5.1） |
| `lib/mapEnvErrorResponse.ts` | 输入是**统一错误 envelope**（10 §6.8）：① 按 `details[].path` 归位到对应行；② 未知 `code` → 走 P22 兜底文案而非丢弃；③ `path` 指向已删除的行 → 忽略不崩；④ `details` 缺失/为空 → 退化为整体错误提示（用 envelope 的 `message`），**不静默吞掉**；⑤ `traceId` 透传到错误详情供复制 |
| `lib/filterImagesForRuntime.ts` | 与 [F21-2 §7.1](./21-2-发起任务向导.md) 同一份纯函数（本页负责数据源正确性，向导负责消费）——此处补测：禁用后过滤结果减少 1 |
| `lib/sortImages.ts` | ✅/⚠️/❌ 混排 → 顺序正确；同级按 `updatedAt` 倒序；空数组不抛错 |
| `services/image.service.ts` | ① `validatePreflight` 拼 **`POST /api/images/validate`**（无 id）、`revalidate` 拼 **`POST /api/images/:id/validate`**——**两个方法不可互换**（前者不落库、后者写回 `validationStatus`，审计 P1-3）；② `toggle` 拼 `PATCH /api/images/:id` 且 body **仅含** `isActive`；③ `saveRunParams` 拼同一 `PATCH` 且 body **仅含** `imageConfig`（**两个方法各自只发自己那一半，不整体覆盖**——防止启停顺带把 env 冲掉）；④ `delete` 拼 `DELETE /api/images/:id`；⑤ 后端 400 的 `{path, code}` 数组被 `mapEnvErrorResponse` 归位为逐行 `errors`，而非整表报错（四个错误码见 §5，02 §5.1） |
| `hooks/useImages.ts` | ① `toggle` 乐观更新立刻改本地缓存；② mutation 失败 → 回滚到原 `isActive`；③ 四个 mutation 成功后均触发 `invalidateQueries(imageKeys.list())`；④ mutation `retry:0` |

### 7.4 e2e（Playwright）

- **参与 12 §4.2 用例组**：D（设置页三子页 + 镜像注册弹窗 + secret 不回显，全 5 步）、C 第 4 步（向导镜像下拉过滤，本页提供数据前置）。
- **本页独有补充场景**：
  1. 深链 `/settings/images?filter=warning` → 断言只列出 ⚠️ 镜像。
  2. 注册一个 ⚠️ 镜像 → 返回工作台开向导 → 断言该镜像出现在下拉且旁边显示后果说明（跨页联动的真实链路）。
  3. 删除被引用镜像 → 断言后端 RESTRICT 的人话提示，卡片仍在列表中。
  4. 搜索词填写后**刷新** → 断言搜索框**为空**（会话级、刷新不恢复）；切到 `/settings/system` 再切回 → 断言搜索框**已清空**且 `localStorage.imageSearchQuery` 已移除。

## 8. 依赖与缺口

- 依赖后端：`GET/POST /api/images`、`POST /api/images/validate`、`PATCH/DELETE /api/images/:id`。
- ✅ **运行参数（env）保存端点已定案**（02 §5.1）：**`PATCH /api/images/:id { isActive?, imageConfig? }`**——一个部分更新端点同时覆盖启停与运行参数。
  - 前端纪律：`toggleImage` 与 `saveRunParams` 是**两个只发各自字段的方法**，绝不整体 PUT——否则"点一下禁用"会把未加载的 `imageConfig` 冲成 undefined。§7.1 已把这条写成单测断言。
  - 乐观更新只对 `isActive` 用（布尔翻转易回滚）；`imageConfig` **不做乐观更新**，以服务端返回为准（校验可能失败，乐观改反而要回滚一整张表）。
- ✅ **env 校验错误码已定案**（02 §5.1）：400 + 逐项 `path` + `ENV_NAME_INVALID` / `ENV_NAME_RESERVED` / `ENV_LIMIT_EXCEEDED` / `ENV_DUPLICATE_KEY` 四码。前端 `validateEnvVar` **直接复用同一套码**（§5 映射表），后端拒绝时命中同一句文案——不做二次翻译、不出现"前端说 OK 后端换个说法拒绝"的割裂。
- ✅ **统一错误 envelope 已定案**（shared/10 §6.8，审计 P1-4）：`{ code, message, retryable, traceId, details?: [{path, code, message}] }`，所有非 2xx 遵守。本页是 `details[].path` 的**主用例**（逐行定位到具体环境变量行）；`[验证]`/`[保存]` 失败时的 **[重试] 按钮由 `retryable` 决定是否渲染**——例如 `TIMEOUT`（验证 60s 超时）`retryable:true` 给重试，`ENV_VALIDATION_ERROR` `retryable:false` 只让用户改表单。这套解析收敛在 `services/api/apiError.ts`，**container 与 view 只消费已解析的 `ApiError`**，不碰原始响应。
- ✅ **secret 语义与前端设计完全对齐**：传空 value = **保持不变**（不是清空），与「（保持不变，输入即覆盖）」placeholder 一致；因此"打开面板直接保存"是安全的无操作。
- 校验的**最终判定仍在后端**，前端只做即时提示、永不放宽（07 §8.3.1 纪律 3）；后端错误按 `path` 归位到具体变量行，不整表报错。

### 9.2 关键功能端到端验证脚本

#### VS-1 · 注册镜像到向导可选的闭环（跨页）

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | `/settings/images` → [+ 注册新镜像] | 弹窗打开，焦点在 URI 框 | — |
| 2 | 填 URI → [验证]，mock 返回 ⚠️（缺 tmux） | 就地显示"缺少 tmux → 终端断线恢复将降级"；**[保存] 可用** | 警告不阻断（产品明写） |
| 3 | [保存] | 弹窗收起 + 列表新增卡片（⚠️ 态）+ toast | — |
| 4 | 回工作台 → 开向导 → 确认步镜像下拉 | 该镜像出现，**旁边显示后果说明** | 跨页联动靠同一 `imageKeys.list()` 缓存 |
| 5 | 回镜像页 → [禁用] 该镜像 | 卡片置灰 | 乐观更新 |
| 6 | 再开向导 | 该镜像**从下拉消失** | 禁用即软下线 |
| **失败路径** | 步骤 2 mock 返回 ❌ | [保存] **不存在**；[查看镜像要求] 可见 | 无效镜像不可落库 |
| **失败路径** | 步骤 5 的 PATCH 返回 500 | 开关**回滚**为启用 + 错误 toast | 乐观回滚 |

#### VS-2 · 环境变量 secret 不回显（安全红线）

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 某镜像已存 `MY_SECRET`（secret 类型） | 卡片摘要显示 `MY_SECRET=***` | 摘要不含原值 |
| 2 | [编辑环境变量] | 该行 VALUE 输入框**值为空**，placeholder「（保持不变，输入即覆盖）」 | `input.value === ''` |
| 3 | 检查 DOM | 页面 HTML 全文**不含原值字符串** | 原值不进 props、不进 DOM |
| 4 | 不改任何东西 → [保存] | 请求体 `imageConfig` **不含该 secret 的 value 字段** | 空 = 保持不变（与后端语义对齐） |
| 5 | 输入新值 → [保存] | 请求体含新值 | 输入即覆盖 |
| **失败路径** | 输入 `OPENAI_API_KEY` 作变量名 | 就地红字「该变量名为系统保留，请使用凭证管理配置」+ [保存] 禁用 | `ENV_NAME_RESERVED` |
| **失败路径** | 后端返 400 + `details:[{path:'env[2].key', code:'ENV_DUPLICATE_KEY'}]` | **第 3 行**标红「变量名重复」，其余行无红字 | 逐行归位，不整表报错 |
