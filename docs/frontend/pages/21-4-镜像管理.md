# F21-4 · 镜像管理前端实现

本页对应 [产品说明](../../product/pages/21-4-镜像管理.md)；[IMG 需求](../../design-v2/gap/product/IMG.md) 定义全部 AC。组件清单取当前 workspace，验收结果以运行产物为准。

## 1. 页面职责

管理预制镜像与自定义镜像版本，验证真实契约、启停可选性并如实说明引用与删除后果。

## 2. 路由与骨架落点

`/settings/images`。使用 AppFrame/SettingsLayout 与 AppDialog；DialogSections 固定头尾，正文独立滚动。

## 3. 组件树

ImagesContainer、ImageCardView、PresetImageDownloadView、RegisterImageModalView、ValidationResultView、DeleteImageConfirmView、PresetDisableDialogView。Container 编排查询与命令，view 只接 props；wire 使用生成 DTO。

## 4. 状态与数据接入

images CRUD、validate、activate、check-update、deletion-preview；preset-image/provision SSE 与 system/diagnose SSE。

后端结果由 Query 持有，选择与临时编辑由 Zustand/组件持有；事件失效相关 query，不使用事件名称本身冒充业务状态。

## 5. 交互实现要点

登记时解析并钉住 digest；校验 Entrypoint 或 Cmd、实际运行条件。下载有真实阶段和耗时，下载完成后执行真实诊断再收起；删除前读服务端引用，引用仍存在时保留禁用按钮及原因。

停止/失败但未销毁任务仍可引用镜像；后端事务复查避免预览后的竞争；停用只影响新任务；配置来源三层合并，不保存黑名单凭证变量。

## 6. 状态矩阵落地

独立加载、空、失败状态；验证成功/警告/失败分别显示；进行中为中性状态；未知进度为不定值条；失败保留最后阶段且不自动重试。

未知数据不可转换为零、成功或空集合。颜色取 v2 语义 token，图标为 SVG；控件保持可访问名称和焦点。

## 7. 本页测试设计

新版验收位于 `web/src/acceptance/`，本域场景：image-registration-deletion / image-download-recheck / image-provision-conflicts。真实 container + HTTP 边界验证交互与副作用；旧单测已退休，不把旧覆盖率当验收。Storybook 验证 view 变体；设计 runner 验证实际页面状态与布局。

## 8. 依赖与契约

OpenAPI 生成类型与 shared schema 是传输形状依据。新预览接口的真实性由后端 SQLite/协议验收验证；浏览器固定数据只用于可重现视觉，不能证明真实外部基础设施健康。

## 9. 验证计划

全量 AC 台账位于主仓 `artifacts/migration-audit/`；计划、代码审查、实际测试与视觉审查分别标注。不得仅因存在截图或测试名就判定全部 AC 实跑通过。

## 9.1 功能验收

按 IMG 的 Given/When/Then 执行，断言用户可见结果、请求次数与真实副作用；覆盖取消、失败、重试和竞争。

## 9.2 关键链路

生产构建启动后使用 `web/scripts/check-design-*-v2.mjs`，隔离 HTTP/WebSocket 数据；暗/亮主题及1440/1024/390宽度记录页面错误、溢出与截图。

## 9.3 证据与缺口

每稿 runner manifest 记录来源、夹具、动作与实跑结果；失败必须修正代码或夹具后重跑，不能改成通过。真机条件另行登记，不能由隔离浏览器替代。

## 9.4 产品裁决

依本仓完整领域规格与 open-questions 的已选决定实现；明确 superseded/deferred 的条目保留理由，不算待迁移功能。

## 10. 参数与引用

EnvVarEditor 处理本地校验；删除框读服务端 deletion-preview，不推断引用数量。下载未知进度使用 indeterminate，不生成百分比；工作目录可默认，启动契约要求 Entrypoint 或 Cmd。
