# F21-4 · 镜像管理前端实现

本页对应 [产品说明](../../product/pages/21-4-镜像管理.md)；[IMG 需求](../../product/requirements/IMG.md) 定义全部 AC。组件清单取当前 workspace，验收结果以运行产物为准。

2026-10-09 变更：镜像支持用户设置别名，并将管理页和新任务镜像选择的搜索扩展到别名。第 11–14 节与[交互设计预览](../../design/task-search-image-alias.html)记录当前设计；业务视图已接入注册别名、独立行内编辑和真实 `imageAlias` 契约，执行证据见[变更与验收记录](../../product/changes/2026-10-09-任务选择与镜像别名.md#8-本轮交付检查)。

本轮设计增量接续原有 v2 全流程设计稿，来源、复制处理与文件校验值见 [BASELINE.json](../../design/v2-base/BASELINE.json)。保留原页面外壳与单列完整镜像卡片，原「全部/有效/警告/无效」筛选、验证结论、版本信息、运行参数和所有既有动作维持。镜像页增量仅为注册表单的可选别名、卡头独立行内别名编辑、别名展示及现有搜索范围扩展；新任务增量为三个选择器的输入搜索。

## 1. 页面职责

管理预制镜像与自定义镜像版本，验证真实契约、启停可选性并如实说明引用与删除后果。

## 2. 路由与骨架落点

`/settings/images`。使用 AppFrame/SettingsLayout 与 AppDialog；DialogSections 固定头尾，正文独立滚动。

## 3. 组件树

ImagesContainer、ImageCardView、PresetImageDownloadView、RegisterImageModalView、ValidationResultView、DeleteImageConfirmView、PresetDisableDialogView。Container 编排查询与命令，view 只接 props；wire 使用生成 DTO。

镜像管理页搜索覆盖别名、名称、ref 和 tag；卡片以别名或真实 ref 为标题，辅助坐标保留。`RegisterImageModalView` 已增加可选别名，卡头通过独立 `ImageAliasEditorView` 编辑；草稿、焦点与保存由 `useImageAliasEditor` 编排，`useSaveImageAlias` 只提交 alias，核对服务端回包后同步并失效全部镜像列表变体。既有验证、启停、版本历史与运行参数交互维持。

生产组件实施沿现有视图作受控替换，复用既有外壳、卡片结构、尺寸、文案、token 和数据编排。保留检查更新、重新验证、启用/禁用、删除、版本历史/切换、运行参数编辑、下载与诊断入口及其原状态和权限条件。现 Web 与 v2 原稿的个别视觉偏差单独记录，不能据此扩大为本轮页面重绘；设计增量需与原稿逐项对照。

## 4. 状态与数据接入

images CRUD、validate、activate、check-update、deletion-preview；preset-image/provision SSE 与 system/diagnose SSE。

后端结果由 Query 持有，选择与临时编辑由 Zustand/组件持有；事件失效相关 query，不使用事件名称本身冒充业务状态。

## 5. 交互实现要点

登记时解析并钉住 digest；校验 Entrypoint 或 Cmd、实际运行条件。下载有真实阶段和耗时，下载完成后执行真实诊断再收起；删除前读服务端引用，引用仍存在时保留禁用按钮及原因。

停止/失败但未销毁任务仍可引用镜像；后端事务复查避免预览后的竞争；停用只影响新任务；配置来源三层合并，不保存黑名单凭证变量。

## 6. 状态矩阵落地

独立加载、空、失败状态；验证成功/警告/失败分别显示；进行中为中性状态；未知进度为不定值条；失败保留最后阶段且不自动重试。

未知数据不可转换为零、成功或空集合。颜色取 v2 语义 token，图标为 SVG；控件保持可访问名称和焦点。

## 7. 本页测试设计

组件验收位于 `web/src/acceptance/`，本域场景：image-registration-deletion / image-download-recheck / image-provision-conflicts。真实 container + HTTP 边界验证交互与副作用。Storybook 验证 view 变体；生产构建浏览器验收验证实际页面与布局。

## 8. 依赖与契约

## 11. 别名展示、登记与编辑（已实现）

对应 REQ-IMG-060、061。别名属于整张 Image，各个 manifest 版本共享；它用于识别镜像，不替代原始镜像名、ref、tag、digest 或 ID，也不改变验证、启停、provider 兼容性和运行参数。预制与自定义镜像均可设置/清除别名；修改别名不提供修改镜像坐标的入口。

卡片标题优先显示非空 `imageAlias`，并在辅助行显示当前版本的完整 ref；无别名时以真实 ref 为主标题，原始镜像名可作为辅助信息。版本历史仍展示各自真实 tag/digest。别名允许重复，每张卡和每个新任务选项必须给出 ref 以消歧，交互始终使用稳定 ID。现有任务的镜像坐标与 digest 快照保持不变，复制诊断信息仍输出实际坐标。

注册弹层在 URI 下增加「别名（可选）」单行输入，提示「用于识别镜像，不修改镜像地址」。URI 验证结论由 URI 决定，仅编辑别名不作废已获得的镜像验证结论；保存时只提交合法非空的别名，未填写或 trim 后为空时省略 alias，保持既有幂等行为。仅新建 Image 时可通过注册设置别名；注册已有 Image（含同一镜像的新版本）时，省略 alias 或提供与当前相同的规范化值沿用原注册规则。明确提供不同 alias 时，返回 `VALIDATION_FAILED` 的 alias 字段错误并零写入，原位说明「这张镜像已经注册，修改别名请在镜像卡片上操作。」并提供 [定位到该镜像]；不覆盖旧别名、不插入新版本，也不显示假的改名成功。已有 Image 的别名不能通过注册清除；设置、改名或清除都定位后使用卡头独立编辑入口。

卡头「编辑别名」原位展开独立行内编辑器，展示镜像 ref 作为只读上下文、别名输入、字符计数以及 [保存别名]/[取消]，与运行参数编辑器分别控制。已有别名预填，空值代表清除；保存为独立 mutation，不顺带发送 `imageConfig` 或 `isActive`，不重新解析/下载镜像。取消或空闲时 Esc 只丢弃草稿并收起该编辑器；保存失败保留编辑器与草稿，并提供原位重试；保存中锁定该编辑器、防重复提交且禁止取消。成功后收起编辑器，以服务端回包为准并失效镜像 query，更新管理卡片和新任务搜索，不更换当前选中的镜像 ID。

## 12. 输入与接口边界（已实现）

请求字段为 `alias: string | null`，响应字段为 `imageAlias: string | null`。注册时未填写或 trim 后为空省略 alias，新建 Image 得到 `imageAlias: null`，已有 Image 保持原值；独立编辑必须明确发送 `alias`，清除时发送 `alias: null`。先拒绝原始输入中的 Unicode `Cc` 控制字符及 `U+2028`/`U+2029`，不能先 trim 吞掉首尾 Tab/换行后放行；其余输入再 trim，非空最多 64 个 Unicode 码点，用 `Array.from(trimmed).length` 计数，与后端口径一致。独立编辑中 trim 后为空转为 `null`，注册中不将空值发送为清除请求。重复别名允许保存，不设计唯一性报错。

字符数超限或包含控制字符时在输入旁给字段错误，保存不可执行；错误通过 `aria-invalid`/`aria-describedby` 关联到输入。服务端仍是最终校验者，400 字段错误归位到别名输入，一般网络失败在当前注册表单或行内编辑器内说明。输入以普通文本渲染，不能解释为 HTML；不把别名塞进镜像 ref、运行命令或环境变量。

OpenAPI/schema 更新后同步生成 `web/openapi.json` 与 `web/src/types/generated/openapi.d.ts`，`web/src/types/image.ts` 继续使用生成 DTO 别名，不手写另一套 wire 结构。展示模型需要区分原始名称、别名与 ref；聚合以 `imageId` 为准，各版本响应的同一个 `imageAlias` 不能产生多张卡片。

## 13. 搜索、状态与可访问性（已实现）

管理页沿用现有「搜索镜像」输入，将占位说明改为「按别名、名称、坐标或 tag 搜索」。在已加载的卡片列表中匹配别名 `imageAlias`、原始名称 `imageName`、当前版本 ref、tag 全四项；关键词 trim 后做不区分大小写的包含匹配，任一字段命中即可，并与现有状态筛选取交集。新任务镜像选择器采用同一检索范围。不新增每次输入的后端请求，不更改列表排序与启停可选性。清空搜索恢复符合状态筛选的全部卡片；无匹配明确说明筛选无结果，不能冒充尚未注册镜像或读取失败。

新任务镜像搜索使用共用 shadcn Combobox；展示、默认入口、禁用原因、provider 过滤和键盘行为见[发起任务向导设计](./21-2-发起任务向导.md#10-搜索单选设计已实现)。新任务关键词只筛选结果，不改变 ID、不自动选中第一项，也不作为任务创建参数。

| 状态              | 设计表现                                     | 数据与副作用                                   |
| ----------------- | -------------------------------------------- | ---------------------------------------------- |
| 无别名            | 以真实 ref 为主标题；编辑输入为空            | 不生成伪别名、不改变坐标                       |
| 有别名/重名       | 别名为标题，ref 始终可读；不同卡片独立可编辑 | 以 imageId 区分；所有版本共享别名              |
| 编辑中            | 输入预填当前值，显示字符计数与清除说明       | 草稿只留编辑局部状态，取消无请求               |
| 输入不合法        | 原位显示长度/控制字符原因                    | 不发保存请求、不改已有展示                     |
| 保存中            | 保存显示忙碌，输入和退出操作锁定             | 不重复保存、不乐观改写卡片                     |
| 保存失败          | 草稿保留，显示字段错误或可重试失败           | 既有别名与镜像元数据保持，失败不关闭           |
| 保存成功/清除成功 | 更新标题与搜索；清除后以真实 ref 为主标题    | 以回包更新 query；ref/digest/启停/环境变量不变 |
| 搜索无匹配        | 专用筛选无结果提示及清空入口                 | 不自动挑选镜像；读取失败仍用原失败状态         |

行内编辑器展开后焦点进入别名输入，取消/收起后回到原卡片的「编辑别名」触发器；保存成功即使新别名使卡片不再匹配当前筛选，也应将焦点回到稳定的搜索或列表容器，并宣布保存成功，不能掉到页面顶端。中文输入法组合期间 Enter 不保存，组合结束后才校验完整输入。按钮、输入与只读 ref 都有可访问名称；忙碌与错误真实表达。

窄屏卡片头部允许别名换行，长 ref 使用换行或横向可控的展示，不撑宽页面；行内编辑区域宽度受卡片约束，按钮可换行且可触及。暗/亮主题、缩放、长中文/emoji 别名和重复别名均需视觉核对。镜像页不因展开行内编辑器丢失当前搜索、状态筛选或已展开的版本信息。
