## 1. 页面职责

用户停留最久的主工作区：左侧按项目分组的任务树一览全部 Task，选中后右侧即时查看/交互该 Task 的终端；顶部承载只读项目指示器与全局横幅。**本页是所有跨页导航的原点与逃逸终点**。

## 2. 路由与骨架落点

| 项 | 落点 |
|---|---|
| 路由 | `/`；深链 `/?taskId=<id>`（自动选中并开终端，命中其他项目时切上下文并展开该组） |
| 路由文件 | `app/page.tsx` — 只装配 container，不写业务逻辑（分层铁律 07 §3 规则 6） |
| 布局 | `app/layout.tsx` 提供全局 shell（主题、Provider、BannerStackContainer、cmdk）；工作台自身是「顶栏 + 左侧栏 + 右侧终端区」三分栏 |
| modal | 本页承载三个弹层：发起向导（`CreateTaskWizardContainer`，见 [F21-2](./21-2-发起任务向导.md)）、创建项目弹层与项目菜单侧弹层（见 [F21-6](./21-6-项目管理.md)）；由 `uiSlice.currentModal` 单一开关控制，**不堆叠**（P20 §8.4） |
| 客户端边界 | 终端区经 `next/dynamic({ssr:false})` 懒加载（08 §2），左侧栏与顶栏不需要 |

## 5. 交互实现要点（产品交互表逐行映射）

| 产品交互（P21-1 §6/§9） | container + handler | 调用 |
|---|---|---|
| 单击项目组头折叠/展开 | `ProjectTaskTreeContainer.handleToggleFold(projectId)` | `uiSlice.toggleProjectFold(projectId)`（persist 自动落盘） |
| 单击本项目 Task | `handleSelectTask(id)` | `uiSlice.setSelectedSandboxId` → registry `touch(id)`；终端 `display` 切换不销毁（08 §5） |
| 单击其他项目 Task | `handleSelectTask(id)` 内先 `expandProject(task.projectId)` | 一个 action 同时切 `selectedProjectId` + 展开组（15 §3.1.1 纪律 1） |
| 点击顶部指示器 | `CurrentProjectIndicatorContainer.handleLocate()` | `uiSlice.expandProject(selectedProjectId)` + 滚动定位；**不打开任何下拉** |
| 树底 [＋ 新建项目] | `handleOpenCreateProject()` | `uiSlice.currentModal='createProject'`，`wizardReturn=false`（区别于向导来源） |
| 组头 hover「⋯」 | `handleOpenProjectMenu(projectId)` | 置 `selectedProjectForMenu` + `currentModal='projectMenu'`（不改 `selectedProjectId`，15 §3.1.1 纪律 2） |
| 点击「⚡ N 个任务等待你输入」 | `handleJumpToWaiting()` | 取第一个 `waitingInput` Task → 复用 `handleSelectTask` |
| 右键 [重启] | `handleRestart(id)` | `sandbox.service.start(id)`；乐观置中间态、终态等 WS（15 §2.4）；文案走「重启并开新会话」（08 §8） |
| 右键 [Stop] | `handleStop(id)` | 二次确认 → `sandbox.service.stop(id)`，乐观置 `stopping` |
| 右键 [销毁] | `handleDestroy(id)` | `DestroyTaskDialog`（「☐ 保留工作区成果卷」**默认勾选**）→ `sandbox.service.destroy(id, { keepVolume })` → `DELETE /api/sandboxes/:id` |
| 右键 [改名] | `handleRename(id, name)` | 1–60 字符校验（`lib/validateTaskName.ts`）→ `sandbox.service.rename` |
| 搜索 / 状态过滤 | `handleSearch` / `handleFilter` | 纯客户端，防抖 200ms；**只作用于已展开的 Task，不跨项目** |
| 终端标签切换 | `TerminalTabsContainer` → `useTerminalSessions.selectTab` | `activeSessionOf` + `display:none` 切换，**不销毁实例**；转可见补一次 fit（08 §5.2） |
| 终端标签 [×] | 同上 → `closeTab` → 发 `close_shell{shellId}` | 销毁那一个 `platform-shell-<id>` tmux 会话（06 §5.4）。⛔ 断连/LRU 淘汰**不**销毁。**Agent 标签没有 [×]**：关掉它不会停任务，那个按钮只会误导 |
| 终端 [+ 新终端] | 同上 → `openShellTab` | 新标签走 `kind=shell` 握手 ⇒ 后端开一个**独立** tmux 会话。⚠️ 文案是「+ 新终端」**不是**「+ 新建」——左下 [＋ 新任务] 才是发起新 Task，两者曾都叫"新建" |
| 刷新页面后标签栏恢复 | `TerminalTabsContainer` ← Agent 连接的 `shells` 帧 → `receiveShellInventory` | **只加不减**地把后端还活着的 `platform-shell-*` 补回标签栏（06 §5.5）。编号按 tmux 创建顺序重编 ⇒ 刷新后可能位移（已知代价，08 §5.1）。⚠️ 会话属于 Task 不属于浏览器：换台机器打开也列得出来 |
| 清单**问不出来** | 同上，`shells: null` | 标签栏就地出「这个任务下是否还有别的终端，现在查不到」。⛔ 绝不渲染成「你没有开过终端」——那是把「不知道」说成「没有」 |
| [+ 新终端] 选启动什么 | `TerminalTabBar` 下拉 → `openShellTab(runtimeId?)` | Codex / Claude Code / 终端（06 §5.6）。⛔ 下拉只列 `SandboxDto.availableRuntimes`（沙箱里真的注入了凭证的那些），**不是** `/api/runtimes` 全集 —— 列出来点开必然失败的选项，就是「点了再报错」 |
| 标签名分得开 | `shellTabLabel(seq, displayName?)` | `Agent`（任务自己的会话，无 [×]）/ `Codex 1`（用户开的 CLI，可关）/ `终端 1`（纯终端）。同一个 Codex 沙箱里前两者跑同一个 CLI，只靠序号区分不了 |
| 侧栏折叠 / 树折叠 | 触发 `ResizeObserver` → debounce fit → `resize` 帧（08 §4） | — |
| Cmd+K | 全局 `CmdkDialog` | 新任务 / 切换 Task / 切换项目 / 打开设置 |
| Logo 点击 / Esc | 全局逃逸（P20 §8.4 分层规则） | — |

**横幅**：`useGlobalBanner` 汇总凭证过期（来自 `runtimeKeys.list()`）、WS 降级、离线模式等来源，按 🔴 > ⚠️（堆叠≤2，不自动收起，关闭后当天不再弹）> ℹ️（5s）排序裁剪后交给 view（07 §8.4）。⚠️ **落地进度**（design-notes.md §4 Phase 3 第 3 条）：`🔴` 两个 id（`platform-state-unknown` / `offline`）与 `⚠️`（`automation-needs-attention`，来自 `lib/automation/automationAttention.ts` 的定时规则自动停用/被放慢判定）**已经是真生产方**，接线在 `lib/system/globalBanner.ts`；「凭证过期」「WS 降级」「ℹ️ 提示类」仍是本节描述的目标态，尚无生产方（`types/banner.ts` 的 `BannerSeverity` 因此暂时只有 `'blocking' | 'warning'` 两个取值，`info` 留到它有第一个真生产方时再加——同一条纪律见该文件文件头）。

**顶栏健康提示**：`healthLabel` 正常（含检查中）时为 `null`，`WorkbenchShellView` 整行不渲染；只有 `health.isError` 时才挂载一句「后端不可用」（design-notes.md §1 问题 5 / §4 Phase 3 第 4 条）。

**「发起新任务」弹层外壳**：`SandboxTerminalContainer` 的 `newTaskModal` 本轮从手写 `ModalShellView` 换成 shadcn `Dialog`（Radix，普通可关闭的那一份，不是向导专用的 `BlockingDialog`），焦点陷阱/`aria-modal`/关闭后焦点归位交给 Radix；内容仍是同一个 `NewSandboxPanelView`，字段未变（design-notes.md §4 Phase 3 第 5 条）。

**本轮收口（design-notes.md §4 Phase 3 补平批次，2026-09-12）**：Phase 0–3 早前几轮只点名换了组件，没有照原型把工作台补齐——这一批把差距收平：

- **搜索 + 状态筛选是真过滤**：`useProjectTaskTree` 新增 `searchQuery`/`statusFilter` 两个入参，经 `lib/project/filterTaskTree.ts`（纯函数，`src/lib/project/__tests__/filterTaskTree.test.ts` 覆盖每个 chip 各自的判据 + 搜索子串匹配 + 两者 AND）对已分组的树做二次过滤；搜不到时 `hasNoFilterMatches` 告诉 view 渲染「没有找到匹配…/没有 X 的任务」，与"这个人还没建过任务"是两句不同的话，不共用一个空态。⚠️ 本批次落地时是**四个 chip、未做 200ms 防抖**——**已在 2026-09-13「工作台三项收尾」中补齐，见下方新增的一条**，这里保留原句是历史记录，不代表当前状态。
- **组头折叠箭头真的能点了**：`toggleProjectFold` 这个 store action 在本轮之前一直存在却没有任何 UI 调用它——折叠状态有地方存，却没有入口写它。`ProjectGroupHeader.view` 新增一个独立的折叠箭头按钮（与「⋯」菜单按钮同一模式：兄弟按钮而不是嵌套按钮），只切折叠、不改变选中项目；组头计数徽标同时改为右对齐的独立数字（原来是拼在项目名后面的「· N」）。
- **任务行副行「活跃于 X 前」接了真实数据源**：`lib/project/taskActivity.ts` 基于 `Sandbox.lastActiveAt` 派生，`lastActiveAt<=0` 视为「没有真实时间戳」整段不渲染——⚠️ **今天恒为这个状态**：`useSandboxes.ts` 把 `lastActiveAt` 硬编码成 `0`（`SandboxDto` 还不带时间戳，见该文件注释里的 backlog），所以副行眼下只会在任务等待输入时显示「等待输入」，「活跃于…」要等后端接上时间戳字段才会出现——这不是本轞的 bug，是刻意不用估算值顶替真实数据。
- **终端仪表壳内补了工具栏**：`TerminalFrame`（`components/ui`）新增可选 `toolbar` 插槽（纯新增、旧调用点零影响），`TerminalPaneView` 转发，新建的 `TerminalToolbar.view.tsx` 渲染面包屑（`${项目名} / ${任务名}`）+ [复制][清屏][A-][A+]；四个按钮全部接了真实的 xterm 操作（`useTerminalInstance` 新增 `clear`/`getSelectionText`/`setFontSize` 三个方法），不是原型里那种固定字符串的摆设按钮。字号接的是 `uiSlice.terminalFontSize`/`setTerminalFontSize`——这两个 persist 字段本轮之前就存在，却和 `toggleProjectFold` 一样从未被任何 UI 调用过（有地方记、没有入口写）。⚠️ **刻意不复刻原型里的 [+ 新标签]**：多标签在这套代码里已经用 `TerminalTabBarView` 的 [+ 新终端] 做完且做对了（标签栏在仪表壳**外面**），仪表壳内再放一个同义按钮只会变成两个互相不知道对方存在的"加终端"入口。
- **顶栏补了 ⌘K 提示与系统状态入口**：⌘K 是纯视觉提示（与原型一致，命令面板本身不在这轮范围）；「系统状态」链接指向 `/settings/system`，与既有的「凭证管理」链接并列——⚠️ **此处的"两条直链并列、待镜像管理页落地后再收成菜单"是本批次（2026-09-12）的状态，已在下面「工作台三项收尾」里收口，不代表当前状态**。

**工作台三项收尾（用户看过原型效果后点名要补的三项，2026-09-13）**：

1. **筛选 chips 四档 → 六档**：`types/domain.ts` 的 `TaskStatusFilter` 从 `'all' | 'running' | 'waitingInput' | 'paused'` 扩到 `'all' | 'preparing' | 'running' | 'waitingInput' | 'paused' | 'error'`，与产品文档 P21-1 §6 的六档口径（全部/准备中/运行中/等待输入/已暂停/异常）对齐——`design-notes.md` 原型只画了四档，属于原型与产品文档口径不一致，用户已裁决以产品文档为准。`lib/project/filterTaskTree.ts` 的 `matchesStatus` 新增 `preparing`/`error` 两个分支，「运行中」与「等待输入」互斥的既有判据（`status==='running' && !waitingInput`）原样保留。⚠️ **`SandboxStatus` 的第 6 个值 `'stopped'`（已停止：停止/销毁流转的终态）在六档里没有对应 chip**——产品文档给的六档本来就只覆盖这五个具体档 + 全部，`stopped` 只计入"全部"，五个具体 chip 均不命中它；这是文档口径本身的取舍，不是这一轮漏掉了一档。`filterTaskTree.test.ts` 新增一条用例，喂入覆盖全部六个 `SandboxStatus` 的数据集，一次性断言五个具体 chip 互不重叠、并集恰好是除 `stopped` 外的全部任务（即"六档命中数之和 = 全部档命中数 − 1"，那 1 正是无处安放的 `stopped`），⛔ 不是逐档各写一条互不关联的用例。
2. **搜索补 200ms 防抖**：新增通用 hook `hooks/project/useDebouncedValue.ts`，`WorkbenchContainer` 用它把"喂给受控输入、敲什么立刻回显什么"的 `searchQuery` 和"喂给 `useProjectTaskTree` 做真过滤"的 `debouncedSearchQuery` 分成两根线——上一批次判断"数据量两位数以内用不上防抖"没有做，用户已要求与产品文档 P21-1 §6 对齐补上。`useDebouncedValue.test.ts` 用 `vi.useFakeTimers()` 精确断言 199ms 时旧值仍在、满 200ms 才变，并覆盖"防抖不是节流"（连续多次变化只在最后一次之后生效一次）；`WorkbenchContainer.test.tsx` 另加一条端到端用例，用 `vi.advanceTimersByTimeAsync` 证明 199ms 时不匹配的任务仍在列表里、满 200ms 后才被过滤掉。
3. **顶栏「凭证管理 / 系统状态」收成一个真菜单**：`/settings/images` 镜像管理页已经落地，`design-notes.md` 原定"待镜像管理页落地后再收"的条件已满足。`WorkbenchShell.view.tsx` 把两条并列直链换成 shadcn `DropdownMenu`（`npx shadcn@3.8.5 add dropdown-menu` 装的，⚠️ 锁定 3.x CLI——`@latest` 会切到 4.x 的 Base UI + 另一套 OKLCH 调色板，与本项目已定案的 Radix + HSL token 选型冲突），菜单含三个子项（凭证管理 `/settings/credentials`、镜像管理 `/settings/images`、系统状态 `/settings/system`），图标与 `app/settings/layout.tsx` 左侧菜单同一套语义（KeyRound/Package/Settings）。触发器保留可见文字「⚙️ 设置」作为无障碍名，不额外挂 `aria-label`；Radix primitive 自带键盘操作（Enter/Space/ArrowDown 展开、方向键在项间移动、Esc 关闭）。`WorkbenchShell.view.stories.tsx` 的 `SettingsMenuOpensWithThreeItems` story 用键盘（聚焦 + Enter 展开、`ArrowDown` 逐项移动）验证三个子项各自的 `href`；⚠️ 菜单内容经 Radix `Portal` 挂到 `document.body`，断言改用 `within(document.body)`（与 `InitWizardShell` 的 `BlockingDialog` 断言同一条纪律），关闭走退出动画，需 `waitFor` 而不是同步断言。新增 Radix 依赖 `@radix-ui/react-dropdown-menu`（`package.json`/`pnpm-lock.yaml` 已跟进）。

## 6. 状态矩阵落地

| 产品状态（P21-1 §5） | 渲染分支 |
|---|---|
| 加载中 | `projects.isPending \|\| tasks.isPending` → `ProjectTaskTree.view` 骨架屏变体（不是 spinner） |
| 全新用户（无项目） | `projects.data.length === 0` → `WorkspaceEmptyState.view variant="no-project"`（[用我的代码库]/[开空项目]） |
| 有项目无任务 | 该组 `tasks.length === 0` → `EmptyGroupCta.view`；全局无任务时 `WorkspaceEmptyState variant="no-task"` |
| 常态 | 树正常渲染 + 右侧恢复 `selectedSandboxId` 的终端 |
| 🟡 准备中 | `status ∈ {pending, scheduling, **preparing-workspace**, creating, starting}` → 脉冲黄点 + 阶段名（审计 P1-8：技术状态从 11 增到 12，`preparing-workspace` 归入准备中） |
| 等待输入 | `status==='running' && waitingInput` → `TaskListItem` 🔵 变体 + 顶部 `WaitingInputSummary` |
| 卷保留中 | `status==='stopped' && preserveVolume` → 行右下 🎁 + 剩余天数倒计时 |
| 无头输出（v1.1） | `task.mode==='headless'` → 右侧渲染 `HeadlessOutputPane.view` 而非 xterm |
| 全部已暂停 | 所有 Task `⏸️` → 右侧 `WorkspaceEmptyState variant="all-paused"` |
| 列表数据降级 | `wsConnected===false \|\| query.isError` → 树头角标「△ 数据可能非最新」，45s 轮询兜底 |
| 终端重连中 | `connState==='reconnecting'` → `ConnectionStatus.view` 黄条「正在重连…（第 n 次）」 |

**12 技术状态 → 6 用户状态的映射是本页的唯一权威落点**（产品 P21 §2.1）：

| 用户状态 | 技术状态 |
|---|---|
| 🟡 准备中 | `pending` · `scheduling` · **`preparing-workspace`** · `creating` · `starting` |
| 🟢 运行中 | `running`（且 `waitingInput` 为假） |
| 🔵 等待输入 | `running` + `waitingInput`（子态，不改主状态） |
| ⏸️ 已暂停 | `idle` · `stopping` · `stopped` |
| 🔴 异常 | `failed` |
| （淡出） | `destroying` · `destroyed` |

**CI 断言（审计 P1-8）**：`lib/mapTechStatusToUserStatus.ts` 的输入枚举**必须穷举 12 个技术状态**，单测用"枚举全覆盖"断言——从 contract 生成的 `SandboxStatus` union 取全集，逐个断言有归宿，**漏一个即 fail**。这样后端再加状态时前端会在 CI 上红，而不是在页面上静默渲染成空白行。

### 7.4 e2e（Playwright）

- **参与 12 §4.2 用例组**：A（分组树 → 选中 → 终端连接 → 回显，全 9 步）、E（销毁保留卷 + Stop）、F（横幅优先级）、G（核心用户旅程第 ①③⑦ 步）。

  1. 深链 `/?taskId=<其他项目的 Task>` → 断言自动切当前项目、该组展开、终端打开。

### 9.2 关键功能端到端验证脚本

> 可直接当验收脚本执行（人工走查或落成 e2e）。每步给「操作 → 期望 → 判定」，**含失败路径**。

#### VS-1 · 分组树跨项目切换（主链路）

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 准备 3 个项目、跨项目 5 个 Task，进入 `/` | 左侧 3 个组头，各显示项目名 + 任务数 | 组头任务数 == 组内可见行数（展开态） |
| 2 | 折叠 ProjectA 组头 | A 的子行消失，箭头翻转 | A 组子行数 = 0，B/C 不受影响 |
| 3 | 刷新页面 | A 仍折叠 | 折叠态来自 persist 而非默认值 |
| 4 | 点击 ProjectB 下的某 Task（当前项目是 A） | 指示器变 ProjectB；B 组展开；右侧终端切到该 Task | 三者同时满足，缺一即失败 |
| 5 | 点击顶部指示器 | 树滚动定位到 B 组并保持展开 | **不出现下拉菜单**（只读回归） |
| 6 | 切回 A 的某 Task | B 的终端 DOM 仍在但 `display:none` | 实例未被销毁（LRU 未触发时） |
| **失败路径** | 断开 mock WS | 出现「△ 数据可能非最新」角标 | 45s 后仍有数据（轮询兜底生效） |
| **失败路径** | 让 `GET /api/projects` 返回 500 | 骨架 → 错误态 + [重试]，**不是空白页** | 错误提示为人话且带行动按钮（P22 §1） |

#### VS-2 · 销毁 Task 与保留卷

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 右键某 Task → [销毁] | 二次确认弹层出现 | 「☐ 保留工作区成果卷」**默认已勾选** |
| 2 | 保持勾选 → [确认销毁] | 行淡出移除 | 请求体 `{ keepVolume: true }` |
| 3 | 对另一 Task 取消勾选 | 弹层出现"卷将永久删除"明示 | 文案明确不可逆 |
| 4 | [确认销毁] | 行淡出移除 | 请求体 `{ keepVolume: false }` |
| 5 | 回到项目菜单 → [已保留卷] | 步骤 2 保留的卷可见 | 与 [F21-6](./21-6-项目管理.md) 的 `/api/retained-volumes` 一致 |
| **失败路径** | 销毁请求返回 500 | 行**回滚**为原状态 + 错误 toast | 乐观更新已回滚，列表无幽灵行 |

#### VS-3 · waiting-input 展示（决策 4）

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 某 Task 运行中，推送 `sandbox.waiting_input` | 该行转 🔵 + "等待你的输入" | **主状态仍是 running 派生**，不是 ⏸️/🔴 |
| 2 | 观察侧栏顶部 | 出现「⚡ 1 个任务等待你输入」 | 计数跨全部项目 |
| 3 | 折叠该 Task 所属项目组 | 汇总行**仍显示 1** | 折叠不影响汇总（易错点） |
| 4 | 点击汇总行 | 跳到该 Task，其项目组自动展开 | 跳转 + 展开同时发生 |
| 5 | 在终端键入任意字符 | 后端推回 `waitingInput:false`，行转回 🟢 | 前端**不自行超时猜测**（判定权在后端） |
| **失败路径** | 推送一条 `waitingInput` 且主状态为 `stopped`（脏数据） | 该行按 ⏸️ 渲染，不计入 ⚡ 汇总 | 子态不覆盖主态 |

#### VS-4 · 断线重连恢复现场

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 打开某 Task 终端，产生若干输出 | 内容正常回显 | — |
| 2 | 断开 WS | 顶部黄条"正在重连…（第 1 次）" | 黄条出现且计数递增 |
| 3 | 保持断开约 3 次退避 | 计数递增，间隔呈指数增长 | 退避策略生效（08 §3.1） |
| 4 | 恢复连接 | 黄条消失；**内容由后端重绘，前端未清屏** | 重连请求 URL 带回**服务端下发的** `socketSessionKey` |
| 5 | 观察内容 | 断线前的历史仍在（tmux re-attach） | 文案可以说"恢复现场" |
| **失败路径** | 重连期间把 Task 状态推成 `stopped` | **重连循环停止**，不再出现新的"第 n 次" | 08 §8 要点 1；否则会对不存在的 pty 无限重试 |
| **失败路径** | 连续失败到上限 | 转"连接超时 [手动重连]" | 不无限重试（P22 §2） |
