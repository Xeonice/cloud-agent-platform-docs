## 1. 页面职责

用户停留最久的主工作区：左侧按项目分组的任务树一览全部 Task，选中后右侧即时查看/交互该 Task 的终端；顶部承载只读项目指示器与全局横幅。**本页是所有跨页导航的原点与逃逸终点**。

## 2. 路由与骨架落点

| 项 | 落点 |
|---|---|
| 路由 | `/`；深链 `/?taskId=<id>`（自动选中并开终端，命中其他项目时切上下文并展开该组） |
| 路由文件 | `app/page.tsx` — 只装配 container，不写业务逻辑（分层铁律 07 §3 规则 6） |
| 布局 | `app/layout.tsx` 提供全局 shell（主题、Provider、BannerStackContainer、cmdk）；工作台自身是「顶栏 + 左侧栏 + 右侧终端区」三分栏 |
| modal | 本页承载三个弹层：发起向导（`CreateTaskWizardContainer`，见 [F21-2](./21-2-发起任务向导.md)）、创建项目弹层与项目菜单侧弹层（见 [F21-6](./21-6-项目管理.md)）；由 `uiSlice.currentModal` 单一开关控制，**不堆叠**（P20 §8.4） |
| 客户端边界 | 终端区经 `next/dynamic({ssr:false})` 懒加载（08 §2），左侧栏与顶栏不需要 |

## 5. 交互实现要点（产品交互表逐行映射）

| 产品交互（P21-1 §6/§9） | container + handler | 调用 |
|---|---|---|
| 单击项目组头折叠/展开 | `ProjectTaskTreeContainer.handleToggleFold(projectId)` | `uiSlice.toggleProjectFold(projectId)`（persist 自动落盘） |
| 单击本项目 Task | `handleSelectTask(id)` | `uiSlice.setSelectedSandboxId` → registry `touch(id)`；终端 `display` 切换不销毁（08 §5） |
| 单击其他项目 Task | `handleSelectTask(id)` 内先 `expandProject(task.projectId)` | 一个 action 同时切 `selectedProjectId` + 展开组（15 §3.1.1 纪律 1） |
| 点击顶部指示器 | `CurrentProjectIndicatorContainer.handleLocate()` | `uiSlice.expandProject(selectedProjectId)` + 滚动定位；**不打开任何下拉** |
| 树底 [＋ 新建项目] | `handleOpenCreateProject()` | `uiSlice.currentModal='createProject'`，`wizardReturn=false`（区别于向导来源） |
| 组头 hover「⋯」 | `handleOpenProjectMenu(projectId)` | 置 `selectedProjectForMenu` + `currentModal='projectMenu'`（不改 `selectedProjectId`，15 §3.1.1 纪律 2） |
| 点击「⚡ N 个任务等待你输入」 | `handleJumpToWaiting()` | 取第一个 `waitingInput` Task → 复用 `handleSelectTask` |
| 右键 [重启] | `handleRestart(id)` | `sandbox.service.start(id)`；乐观置中间态、终态等 WS（15 §2.4）；文案走「重启并开新会话」（08 §8） |
| 右键 [Stop] | `handleStop(id)` | 二次确认 → `sandbox.service.stop(id)`，乐观置 `stopping` |
| 右键 [销毁] | `handleDestroy(id)` | `DestroyTaskDialog`（「☐ 保留工作区成果卷」**默认勾选**）→ `sandbox.service.destroy(id, { keepVolume })` → `DELETE /api/sandboxes/:id` |
| 右键 [改名] | `handleRename(id, name)` | 1–60 字符校验（`lib/validateTaskName.ts`）→ `sandbox.service.rename` |
| 搜索 / 状态过滤 | `handleSearch` / `handleFilter` | 纯客户端，防抖 200ms；**只作用于已展开的 Task，不跨项目** |
| 终端标签切换 / [×] / [新标签] | `TerminalContainer` 对应 handler | registry 内多 pty 会话；[×] 关会话不影响 Task |
| 侧栏折叠 / 树折叠 | 触发 `ResizeObserver` → debounce fit → `resize` 帧（08 §4） | — |
| Cmd+K | 全局 `CmdkDialog` | 新任务 / 切换 Task / 切换项目 / 打开设置 |
| Logo 点击 / Esc | 全局逃逸（P20 §8.4 分层规则） | — |

**横幅**：`useGlobalBanner` 汇总凭证过期（来自 `runtimeKeys.list()`）、WS 降级、离线模式等来源，按 🔴 > ⚠️（堆叠≤2，不自动收起，关闭后当天不再弹）> ℹ️（5s）排序裁剪后交给 view（07 §8.4）。

## 6. 状态矩阵落地

| 产品状态（P21-1 §5） | 渲染分支 |
|---|---|
| 加载中 | `projects.isPending \|\| tasks.isPending` → `ProjectTaskTree.view` 骨架屏变体（不是 spinner） |
| 全新用户（无项目） | `projects.data.length === 0` → `WorkspaceEmptyState.view variant="no-project"`（[用我的代码库]/[开空项目]） |
| 有项目无任务 | 该组 `tasks.length === 0` → `EmptyGroupCta.view`；全局无任务时 `WorkspaceEmptyState variant="no-task"` |
| 常态 | 树正常渲染 + 右侧恢复 `selectedSandboxId` 的终端 |
| 🟡 准备中 | `status ∈ {pending, scheduling, **preparing-workspace**, creating, starting}` → 脉冲黄点 + 阶段名（审计 P1-8：技术状态从 11 增到 12，`preparing-workspace` 归入准备中） |
| 等待输入 | `status==='running' && waitingInput` → `TaskListItem` 🔵 变体 + 顶部 `WaitingInputSummary` |
| 卷保留中 | `status==='stopped' && preserveVolume` → 行右下 🎁 + 剩余天数倒计时 |
| 无头输出（v1.1） | `task.mode==='headless'` → 右侧渲染 `HeadlessOutputPane.view` 而非 xterm |
| 全部已暂停 | 所有 Task `⏸️` → 右侧 `WorkspaceEmptyState variant="all-paused"` |
| 列表数据降级 | `wsConnected===false \|\| query.isError` → 树头角标「△ 数据可能非最新」，45s 轮询兜底 |
| 终端重连中 | `connState==='reconnecting'` → `ConnectionStatus.view` 黄条「正在重连…（第 n 次）」 |

**12 技术状态 → 6 用户状态的映射是本页的唯一权威落点**（产品 P21 §2.1）：

| 用户状态 | 技术状态 |
|---|---|
| 🟡 准备中 | `pending` · `scheduling` · **`preparing-workspace`** · `creating` · `starting` |
| 🟢 运行中 | `running`（且 `waitingInput` 为假） |
| 🔵 等待输入 | `running` + `waitingInput`（子态，不改主状态） |
| ⏸️ 已暂停 | `idle` · `stopping` · `stopped` |
| 🔴 异常 | `failed` |
| （淡出） | `destroying` · `destroyed` |

**CI 断言（审计 P1-8）**：`lib/mapTechStatusToUserStatus.ts` 的输入枚举**必须穷举 12 个技术状态**，单测用"枚举全覆盖"断言——从 contract 生成的 `SandboxStatus` union 取全集，逐个断言有归宿，**漏一个即 fail**。这样后端再加状态时前端会在 CI 上红，而不是在页面上静默渲染成空白行。

## 7. 本页测试设计

### 7.1 unit（bun test：lib / hooks / stores）

| 被测 | 用例（断言级） |
|---|---|
| `lib/selectProjectTaskTree.ts` | ① 3 项目 × 5 任务 → 返回 3 组且组内条数等于该组 `taskCount`；② 折叠组返回 `collapsed:true` 且 `items` 仍完整（折叠只影响渲染）；③ `projectId` 不在 projects 中的 Task → 归入「未分组」组且不丢失；④ 组内按 `lastActiveAt` 倒序；⑤ 当前项目组排第一；⑥ 空 projects → 返回空数组不抛错 |
| `lib/mapTechStatusToUserStatus.ts` | **枚举全覆盖断言**：遍历 contract 生成的 `SandboxStatus` union（**12 个**，审计 P1-8），逐个断言映射到 6 个用户状态之一，**漏一个即 fail**；`preparing-workspace` → 🟡 准备中；`running` + `waitingInput` → 🔵 而非 🟢；后端新增状态时本用例先红 |
| `lib/formatLastActive.ts` | `<1min→"刚刚"`、`<1h→"n 分钟前"`、`<24h→"n 小时前"`、更早 → 日期串（四档边界值各一） |
| `lib/validateTaskName.ts` | 0 字符拒绝、1 字符通过、60 通过、61 拒绝、允许重名 |
| `hooks/useWaitingInputCount.ts` | ① 2 个 `running+waitingInput` → 2；② 其中一个所属组折叠 → **仍为 2**；③ `stopped+waitingInput`（脏数据）→ 不计入 |
| `hooks/useGlobalBanner.ts` | ① 🔴+⚠️+ℹ️ 同入 → 顺序 🔴,⚠️,ℹ️；② 3 条 ⚠️ → 返回 2 条 + `collapsedCount:1`；③ ℹ️ 假时钟推进 5s → 自动移除；④ 🔴/⚠️ 推进 60s → 仍在；⑤ 关闭一条 ⚠️ 后同日重新计算 → 不返回该条 |
| `stores/createUiSlice` | ① `toggleProjectFold` 翻转指定 key 不影响其他 key；② `expandProject(p)` 同时置 `selectedProjectId=p` 且 `taskListFolds[p]=false`；③ `setSelectedProjectForMenu` **不改** `selectedProjectId`；④ `partialize` 快照包含 `taskListFolds` 且不含 `selectedProjectForMenu`/`currentModal` |
| `hooks/useSandboxTerminalSocket.ts` | ① 断线 → 重连计数递增且间隔指数退避；② Task 状态转 `stopped` → **停止重连循环**（08 §8 落地要点 1）；③ 达最大次数 → `errored` |

### 7.3 集成（container story + play 函数，mock 边界在网络层）

> 采用 12 §1 既定分层：containers **不进 bun test**，集成级交互用 Storybook Vitest addon 跑（`@storybook/test` 即 instrumented Testing Library），网络层由 `msw-storybook-addon` 拦截——等价于"mock 边界在 service 之下"，且不与 E2E 的 Playwright route 冲突（12 §4.1）。

| 交互流 | 断言链 |
|---|---|
| 折叠持久化 | 点击组头 → `taskListFolds[p]` 为 true → 子项从 DOM 消失 → 重挂载组件（模拟刷新，store 从 persist 读回）→ 仍折叠 |
| 跨项目切换 | 点击 ProjectB 的 Task → `selectedProjectId==='B'` → B 组 `aria-expanded=true` → 指示器文案为 ProjectB → `onSelectTask` 已触发终端切换 |
| waiting_input 推送 | 注入 WS 事件 `sandbox.waiting_input{id}` → 该行转 🔵 且**主状态文案仍是"运行中"派生的 🔵 等待输入**（不变成 stopped）→ 汇总行出现「⚡ 1 个任务等待你输入」 |
| 多缓存同步（审计 P2-3） | 预置 `list(undefined)` 与 `list('A')` 两份缓存 → 注入一条 `sandbox.status_changed` → 断言**两份缓存都被更新**（`setQueriesData` 全族覆盖）；再断言 `detail(id)` 缓存形状未被写坏（仍是单体不是数组） |
| 销毁保留卷 | 右键 → [销毁] → 确认框默认勾选 → 确认 → 断言 `destroy` 被以 `{keepVolume:true}` 调用；取消勾选再确认 → `{keepVolume:false}` |
| 搜索不跨项目 | 展开 A、折叠 B，搜索 B 组内某任务名 → 断言结果为空（不跨组过滤） |
| 横幅降级 | 断开 mock WS → 出现降级角标 → 恢复 → 角标消失 |

### 7.4 e2e（Playwright）

- **参与 12 §4.2 用例组**：A（分组树 → 选中 → 终端连接 → 回显，全 9 步）、E（销毁保留卷 + Stop）、F（横幅优先级）、G（核心用户旅程第 ①③⑦ 步）。
- **本页独有补充场景**：
  1. 深链 `/?taskId=<其他项目的 Task>` → 断言自动切当前项目、该组展开、终端打开。
  2. LRU 淘汰后重新点击被淘汰的 Task → 断言**静默重建、无任何提示**（P21-1 §9）。
  3. 刷新页面 → 断言恢复 `selectedSandboxId` 与折叠状态，终端经 tmux 重绘出现历史内容。
  4. 键盘路径：Cmd+K → "切换 Task" → 回车 → 断言选中变化；Esc 分层关闭（先关 confirm 再关 modal）。

## 8. 依赖与缺口

- 依赖后端：`GET /api/projects` 聚合任务数、`waiting-input` 子状态推送（P20 §9.8）、`DELETE /api/sandboxes/:id { keepVolume }`。

### 9.2 关键功能端到端验证脚本

> 可直接当验收脚本执行（人工走查或落成 e2e）。每步给「操作 → 期望 → 判定」，**含失败路径**。

#### VS-1 · 分组树跨项目切换（主链路）

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 准备 3 个项目、跨项目 5 个 Task，进入 `/` | 左侧 3 个组头，各显示项目名 + 任务数 | 组头任务数 == 组内可见行数（展开态） |
| 2 | 折叠 ProjectA 组头 | A 的子行消失，箭头翻转 | A 组子行数 = 0，B/C 不受影响 |
| 3 | 刷新页面 | A 仍折叠 | 折叠态来自 persist 而非默认值 |
| 4 | 点击 ProjectB 下的某 Task（当前项目是 A） | 指示器变 ProjectB；B 组展开；右侧终端切到该 Task | 三者同时满足，缺一即失败 |
| 5 | 点击顶部指示器 | 树滚动定位到 B 组并保持展开 | **不出现下拉菜单**（只读回归） |
| 6 | 切回 A 的某 Task | B 的终端 DOM 仍在但 `display:none` | 实例未被销毁（LRU 未触发时） |
| **失败路径** | 断开 mock WS | 出现「△ 数据可能非最新」角标 | 45s 后仍有数据（轮询兜底生效） |
| **失败路径** | 让 `GET /api/projects` 返回 500 | 骨架 → 错误态 + [重试]，**不是空白页** | 错误提示为人话且带行动按钮（P22 §1） |

#### VS-2 · 销毁 Task 与保留卷

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 右键某 Task → [销毁] | 二次确认弹层出现 | 「☐ 保留工作区成果卷」**默认已勾选** |
| 2 | 保持勾选 → [确认销毁] | 行淡出移除 | 请求体 `{ keepVolume: true }` |
| 3 | 对另一 Task 取消勾选 | 弹层出现"卷将永久删除"明示 | 文案明确不可逆 |
| 4 | [确认销毁] | 行淡出移除 | 请求体 `{ keepVolume: false }` |
| 5 | 回到项目菜单 → [已保留卷] | 步骤 2 保留的卷可见 | 与 [F21-6](./21-6-项目管理.md) 的 `/api/retained-volumes` 一致 |
| **失败路径** | 销毁请求返回 500 | 行**回滚**为原状态 + 错误 toast | 乐观更新已回滚，列表无幽灵行 |

#### VS-3 · waiting-input 展示（决策 4）

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 某 Task 运行中，推送 `sandbox.waiting_input` | 该行转 🔵 + "等待你的输入" | **主状态仍是 running 派生**，不是 ⏸️/🔴 |
| 2 | 观察侧栏顶部 | 出现「⚡ 1 个任务等待你输入」 | 计数跨全部项目 |
| 3 | 折叠该 Task 所属项目组 | 汇总行**仍显示 1** | 折叠不影响汇总（易错点） |
| 4 | 点击汇总行 | 跳到该 Task，其项目组自动展开 | 跳转 + 展开同时发生 |
| 5 | 在终端键入任意字符 | 后端推回 `waitingInput:false`，行转回 🟢 | 前端**不自行超时猜测**（判定权在后端） |
| **失败路径** | 推送一条 `waitingInput` 且主状态为 `stopped`（脏数据） | 该行按 ⏸️ 渲染，不计入 ⚡ 汇总 | 子态不覆盖主态 |

#### VS-4 · 断线重连恢复现场

| 步 | 操作 | 期望 | 判定通过 |
|---|---|---|---|
| 1 | 打开某 Task 终端，产生若干输出 | 内容正常回显 | — |
| 2 | 断开 WS | 顶部黄条"正在重连…（第 1 次）" | 黄条出现且计数递增 |
| 3 | 保持断开约 3 次退避 | 计数递增，间隔呈指数增长 | 退避策略生效（08 §3.1） |
| 4 | 恢复连接 | 黄条消失；**内容由后端重绘，前端未清屏** | 重连请求 URL 带回**服务端下发的** `socketSessionKey` |
| 5 | 观察内容 | 断线前的历史仍在（tmux re-attach） | 文案可以说"恢复现场" |
| **失败路径** | 重连期间把 Task 状态推成 `stopped` | **重连循环停止**，不再出现新的"第 n 次" | 08 §8 要点 1；否则会对不存在的 pty 无限重试 |
| **失败路径** | 连续失败到上限 | 转"连接超时 [手动重连]" | 不无限重试（P22 §2） |
