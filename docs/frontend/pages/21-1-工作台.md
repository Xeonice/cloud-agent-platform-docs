## 1. 页面职责

侧栏浏览项目、任务与设置；主区显示项目总览、任务终端或无头任务输出。当前选择、状态、计数与后端事件保持一致。

## 2. 路由与骨架落点

`/`；项目总览与任务终端在主区切换。使用 AppFrame/SettingsLayout 与 AppDialog；DialogSections 固定头尾，正文独立滚动。

现有顶栏右上使用32px中性按钮、16px Lucide CircleArrowUp。catalog verified installable newerRelease（立即升级另看权限）、可信已受理ongoing，或实例activation-confirmed且Webready/page不同才显示；available和ready待刷新有静态点，ongoing无点。今日未关闭浮卡依次是待升级立即升级（无attempt/percent）、受理后0–99阶段、installed100待刷新。page已target/sameWeb不能掩盖service待升级；没有合法条件或对应unknown/失败/延期才隐藏。系统详情/check常驻，固定浮卡不占布局/盖操作/全宽横幅。

## 3. 组件树

WorkbenchContainer、WorkbenchShell、WorkbenchOverviewView、SandboxTerminalContainer、HeadlessTaskContainer、AppFrame、CommandPaletteContainer/CommandPaletteView。Container 编排查询与命令，view 只接 props；真实服务数据使用生成 DTO。

现有VersionUpdateContainer／PopoverView／NoticeView及useInstanceUpgrade，共用AppFrame内只读catalog／实例状态及日偏好；唯一upgrade command仅由有权限用户明确点击，其他check／lookup／刷新只读。工作台WorkbenchHeaderView与设置页内联header接同一headerActionsSlot，保留新任务且更新图标最右；浮卡固定在header下，升级不接GlobalBanner。

## 4. 状态与数据接入

项目/沙箱列表、单对象查询、任务输出与成果查询、销毁命令，以及 /events 与终端 WebSocket。

后端结果由 Query 持有，选择与临时编辑由 Zustand/组件持有；事件失效相关 query，不使用事件名称本身冒充业务状态。

## 5. 交互实现要点

选择项目打开总览；选择任务打开终端；命令面板能搜索项目、任务和动作。销毁使用统一确认框，取消不发请求，确认后先显示删除中再移除。

终端输入与订阅生命周期分开；断线保留最后输出和选中对象；销毁解绑数据面后保留用户选定的成果。

## 6. 状态矩阵落地

加载显示结构骨架；读取失败给重试；空集合给明确建项目/任务入口；等待输入来自服务端终端检测；无头输出区分运行、断线、成功、失败、取消。

未知数据不可转换为零、成功或空集合。颜色取 v2 语义 token，图标为 SVG；控件保持可访问名称和焦点。

升级提示与连接状态独立于 sandbox／task 生命周期：兼容更新可稍后刷新；网络恢复失败不清选中、不清屏、不创建替代终端。只有认证后的清单与运行身份确认才可显示续接成功；恢复过程不调用 create／start 或重发指令。

CD只发布版本与包，不下载到本实例、起候选、跑线上migration、切API或共享Web alias。catalog确认installable available后，版本读取用户看到服务vA→vB待升级的图标/点/浮卡/只读详情，立即升级仅给有实例升级权限用户，没有attempt或0%。用户明确点击且server幂等/CAS受理后才ongoing0–99，目标固定于manifest/digest，不随目录新版本变更；完整activation-confirmed、生产Web绑定/兼容确认才100，只有page确实不同才刷新。同Web的新service release可升级但不强刷。

立即升级提交targetDigest＋expectedActivationGeneration＋requestId，server检查实例权限/Origin/CSRF、digest/架构/可安装性和幂等CAS；沿用已有访问保护，不新增升级授权或多人管理流程。同一操作人的双击／多标签至多受理一次，冲突重查后由用户决定；超时只lookup原requestId，不自动POST/新attempt。受理目标固定，可包含manifest声明的桥链和合格安全回退，新的升级必须用户再发起；浏览器不拿部署密钥/Docker权限。

×/稍后按非凭据user-scope+instance本地自然日关闭浮卡，贯穿available→提交→ongoing→ready及同日target/attempt、多标签/route/reload；关闭不改权限或启动/取消升级，合法主动入口保留。00:00、可见性恢复和日期timer仅核验catalog/权限/实例状态，有verified available、ongoing或installed ready/page不同才再提醒，非24h/永久revision，跨日绝不启动部署。

进度来自 controller 只读事实，绑定 `instanceId + attemptId + generation + seq`、冻结可测量口径／`totalWork` 及可测 `completedWork`；前端不计时累加。首次载入／真实 reload 读取当前 attempt 最新进度，同 attempt 单调，旧／重复／乱序不覆盖，不同 attempt 不能继承百分比。停滞、度量未知、过期或断网显示“等待进度确认”及最后已知百分比／阶段／时间；整项发布 unknown 时隐藏 trigger／点／浮卡，系统卡保留等待信息／check，不假计数或补到 100%。具名 progressbar 使用 aria-valuemin／max／now／text，未知不填 now，不逐 1% live 播报。

图标覆盖verified available（无升级权限仍可只读查看）、受理ongoing和installed ready待刷新，点在available/ready，ongoing无点；page相同仅去掉刷新需要，不去掉service升级。失去对应可信状态收起控件，焦点仅区域内返现存操作；Escape/外点只关popover。系统版本详情/check常驻；进度、实际页面和原终端分别确认，100不改页号或保证已接回。

服务release/activationGeneration来自本实例激活ledger，catalog发布与当前页构建不互相改写。page标识来自实际加载的不可变Web artifact；必须本实例版本化Web入口/固定产物，CD不得promote共享alias让未升级实例自动换Web。部分切换待确认+上次完整激活；API复用保留真实commit，runtime仍原owner。刷新只读取已经ready的Web并attach原资源，不部署或重放指令。

2026-10-18增量按[优化提案](../../product/changes/2026-10-18-升级体验与启动可观测性优化.md)及[前端方案§2.7](../changes/2026-10-10-升级提示与原终端续接.md#27-2026-10-18优化增量一次升级与真实等待)落实：提交未确认只查原requestId；用户级`operation`始终固定最终目标与兼容节点；中间技术attempt完成不显示用户整体100%。总体工作量未知时仍显示真实阶段字节、百分比和时间，不固定权重。系统版本卡将服务可用性、上次完整版本、最终结果及实际页面分开，部分组件更新失败不宣称全部回退；只展示服务端合格修复方案对应的明确动作。
