# F21-1 · 工作台前端实现

本页对应 [产品说明](../../product/pages/21-1-工作台.md)；[WB 需求](../../design-v2/gap/product/WB.md) · [SBX 需求](../../design-v2/gap/product/SBX.md) 定义全部 AC。组件清单取当前 workspace，验收结果以运行产物为准。

## 1. 页面职责

侧栏浏览项目、任务与设置；主区显示项目总览、任务终端或无头任务输出。当前选择、状态、计数与后端事件保持一致。

## 2. 路由与骨架落点

`/`；项目总览与任务终端在主区切换。使用 AppFrame/SettingsLayout 与 AppDialog；DialogSections 固定头尾，正文独立滚动。

## 3. 组件树

WorkbenchContainer、WorkbenchShell、WorkbenchOverviewView、SandboxTerminalContainer、HeadlessTaskContainer、AppFrame、CommandPaletteContainer/CommandPaletteView。Container 编排查询与命令，view 只接 props；真实服务数据使用生成 DTO。

## 4. 状态与数据接入

项目/沙箱列表、单对象查询、任务输出与成果查询、销毁命令，以及 /events 与终端 WebSocket。

后端结果由 Query 持有，选择与临时编辑由 Zustand/组件持有；事件失效相关 query，不使用事件名称本身冒充业务状态。

## 5. 交互实现要点

选择项目打开总览；选择任务打开终端；命令面板能搜索项目、任务和动作。销毁使用统一确认框，取消不发请求，确认后先显示删除中再移除。

终端输入与订阅生命周期分开；断线保留最后输出和选中对象；销毁解绑数据面后保留用户选定的成果。

## 6. 状态矩阵落地

加载显示结构骨架；读取失败给重试；空集合给明确建项目/任务入口；等待输入来自服务端终端检测；无头输出区分运行、断线、成功、失败、取消。

未知数据不可转换为零、成功或空集合。颜色取 v2 语义 token，图标为 SVG；控件保持可访问名称和焦点。

## 7. 本页测试设计

新版验收位于 `web/src/acceptance/`，本域场景：workbench / sandbox-lifecycle / headless / realtime。真实 container + HTTP 边界验证交互与副作用；旧单测已退休，不把旧覆盖率当验收。Storybook 验证 view 变体；设计 runner 验证实际页面状态与布局。

## 8. 依赖与契约

OpenAPI 生成类型与 shared schema 是传输形状依据。新预览接口的真实性由后端 SQLite/协议验收验证；浏览器固定数据只用于可重现视觉，不能证明真实外部基础设施健康。

## 9. 验证计划

全量 AC 台账位于主仓 `artifacts/migration-audit/`；计划、代码审查、实际测试与视觉审查分别标注。不得仅因存在截图或测试名就判定全部 AC 实跑通过。

## 9.1 功能验收

按 WB、SBX 的 Given/When/Then 执行，断言用户可见结果、请求次数与真实副作用；覆盖取消、失败、重试和竞争。

## 9.2 关键链路

生产构建启动后使用 `web/scripts/check-design-*-v2.mjs`，隔离 HTTP/WebSocket 数据；暗/亮主题及1440/1024/390宽度记录页面错误、溢出与截图。

## 9.3 证据与缺口

每稿 runner manifest 记录来源、夹具、动作与实跑结果；失败必须修正代码或夹具后重跑，不能改成通过。真机条件另行登记，不能由隔离浏览器替代。

## 9.4 产品裁决

依本仓完整领域规格与 open-questions 的已选决定实现；明确 superseded/deferred 的条目保留理由，不算待迁移功能。
