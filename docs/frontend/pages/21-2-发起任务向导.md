# F21-2 · 发起任务向导（modal / `/new`）前端设计

> 状态：✅ 可评审 · 对应产品页：[P21-2 发起任务向导](../../product/pages/21-2-发起任务向导.md)
> 上级：[前端页面设计总纲](./README.md) · 架构依据：[07 §6/§7/§8.2](../07-前端目录结构与视图逻辑分离.md) · [15](../15-前端状态管理.md) · [12](../12-前端测试体系.md) · [16 §7](../16-前端链路验证体系.md)

## 1. 页面职责

两步完成一次 Task 发起：选 runtime → 确认创建，随后进入阶段进度卡。**鉴权不是步骤**——仅所选 runtime 无生效凭证时，在两步之间插入一个无编号的一次性拦截面板（三分支均在面板内即时完成）。

## 2. 路由与骨架落点

| 项 | 落点 |
|---|---|
| 常态形态 | **modal**（不占路由），挂在工作台上，由 `uiSlice.currentModal==='wizard'` 控制；刷新即关闭（可接受权衡，P20 §8.5） |
| 深链路由 | `app/new/page.tsx`，支持 `/new?runtime=codex` 预选；该路由渲染同一个 `CreateTaskWizardContainer`，仅初始 step 与 runtime 由 URL 注入 |
| 前置条件 | **须已有选中项目**，否则入口不可用（工作台先走建项目引导，P20 §8.2） |
| 弹层纪律 | 向导内需要去凭证管理时**替换为路由页面**（保留浏览器后退），不嵌套 modal；创建项目弹层是唯一允许的向导内二级弹层（经 `wizardReturn` 回程） |

## 4. 状态与数据接入

| 类别 | 具体 | 来源 |
|---|---|---|
| Query | `runtimeKeys.list()` → `GET /api/runtimes`：`[{ id, displayName, vendor, authMethods, credentialStatus: 'none'\|'active'\|'expiring'\|'expired', maskedIdentifier?, expiresAt?, activeAuthMethod? }]`——**一次请求喂满 Step 1 全部卡片，不按 runtime N+1 查状态**（02 §5.1） | 15 §2.1 |
| Query | `imageKeys.list()` → `GET /api/images`（下拉选项源，前端按三条规则过滤） | 15 §2.1 |
| Query | `projectKeys.list()` → 项目行下拉选项 | 15 §2.1 |
| Query | `runtimeAuthKeys.session(provider)`（staleTime 0 + `refetchInterval` 3–5s，到 `expiresAt` 停） | 15 §2.2 |
| Mutation | `useCreateSandbox` → `POST /api/sandboxes { projectId, runtime, image, provider, initialPrompt? }`，乐观插入列表（15 §2.4） | — |
| Mutation | 鉴权三分支：`beginAuth` / `completeAuth` / `saveSecret`（07 §6.3） | — |
| Zustand | `currentModal='wizard'`；`wizardReturn`；`wizardData{runtime, selectedProjectId, image, initialPrompt}` | 15 §3.1.1 |
| Zustand（persist） | `lastUsedRuntime`、`lastUsedImage`（下次预选） | 15 §3.5 |
| container 局部 state | 粘贴的授权 code / API key（提交即清空，**不进 store**） | 07 §6.4 |
| WS | `sandbox.status_changed` → 驱动进度卡阶段推进 | 15 §2.3 |

**两条安全红线**：① `wizardData.initialPrompt` **仅内存、不 persist**（15 §3.5）；② 授权 code / API key 只在 `AuthGateContainer` 的 `useState`，绝不进全局 store。

## 5. 交互实现要点（产品交互表逐行映射）

| 产品交互（P21-2 §6/§9） | container + handler | 调用 |
|---|---|---|
| 选 runtime 卡片 | `handleSelectRuntime(id)` | 写 `wizardData.runtime` + persist `lastUsedRuntime`；读该 runtime 凭证状态决定 `next = 'gate' \| 'confirm'` |
| [下一步] | `handleNext()` | 有生效凭证 → 形态 C；无/过期 → 形态 B（**无编号**） |
| 面板 Tab 切换 | `AuthGateContainer.handleSwitchMethod(m)` | 只切本地 method，不发请求；默认选中当前生效模式 |
| device-code 开始 | `handleBeginAuth()` | `runtime.service.beginAuth(rt)` → 展示 `userCode/verificationUrl/expiresAt` → Query 轮询 `pollAuthStatus` |
| device-code [复制] / [重新获取] / [后台继续] | 对应 handler | 复制走 clipboard API；[重新获取] 重走 `beginAuth`；**[后台继续]** 关面板但**保留轮询 Query**（轮询归属提到向导之上的层级，面板卸载不取消）——成功 → 徽标转 ✅ + toast「Codex 授权完成，凭证已保存」(1s)；超时/失败 → toast「Codex 授权未完成，请重试」+ 卡片保持未授权态 |
| setup-token [提交] | `handleSubmitPastedCode(text)` | `runtime.service.completeAuth(rt, { pastedText })`；**提交即 `setState('')`** |
| api-key [保存并继续] | `handleSaveSecret(key)` | 前端仅前缀格式提示（`sk-` / `sk-ant-`）→ `runtime.service.saveSecret(rt, {method:'api-key', secret})`；**提交即清空** |
| 鉴权成功 | `onAuthSuccess()` | `invalidateQueries(runtimeAuthKeys.all())` + `runtimeKeys.list()` → **2s 后自动进形态 C** |
| 项目下拉选择 | `handleSelectProject(id)` | 写 `wizardData.selectedProjectId`（不改工作台的 `selectedProjectId`） |
| 「＋ 新建项目…」 | `handleCreateProjectFromWizard()` | 置 `wizardReturn=true` + 把当前表单**全量写入 `wizardData`** → `currentModal='createProject'` |
| 项目创建成功回程 | `onProjectCreated(newId)` | `wizardReturn` 为真 → 回形态 C，`wizardData` 回填、项目行选中 `newId`、**任务指令原样恢复** |
| 任务指令输入 | `handlePromptChange(v)` | 写 `wizardData.initialPrompt`（仅内存）；`v.length > 8000` → 就地红字计数 + 禁用 [发起] |
| 镜像下拉 | `ImageSelect` 选项由 `useImages` + 过滤纯函数产出 | `isActive && (valid \|\| warning) && supportedRuntimes 含所选 runtime`；⚠️ 项仍可选并就地显示后果 |
| [发起] | `handleCreate()` | `useCreateSandbox.mutate({ projectId: wizardData.selectedProjectId, ... })` → 形态 D |
| [上一步] | `handleBack()` | 回上一形态，**已填数据保留**（数据在 `wizardData`，不随形态卸载丢失） |
| [取消] | `handleCancel()` | Step 阶段直接关；创建中取消 = 二次确认 + 终止创建并回收资源 |
| [后台运行] | `handleBackground()` | 关 modal，进度延续到列表项（工作台 `TaskListItem` 显示阶段名 + 进度条） |
| 进度阶段 [重试] | `handleRetryStage()` | 仅失败阶段可点；已 ✅ 阶段锁定不重跑 |

## 6. 状态矩阵落地

| 产品状态（P21-2 §5） | 渲染分支 |
|---|---|
| Step 1 首入 | `step==='runtime'`；`lastUsedRuntime` 高亮；`runtimes.isPending` → 卡片骨架 |
| → 拦截面板 | 所选 runtime **`credentialStatus ∈ {'none','expired'}`** → 形态 B（标题「首次使用 X：完成一次全局登录」，**无步骤编号**） |
| → 确认步 | **`credentialStatus ∈ {'active','expiring'}`** → 形态 C + "将以 a***@gm 身份运行"；`expiring`（<7 天）**不拦截**，只在卡片与横幅上给 ⚠️ 预警 |
| 面板·轮询中 | `authFlow.state==='polling'` → 倒计时 + "等待授权中…" |
| 面板·过期 | `state==='expired'` 或倒计时归零 → 红色 + [重新获取]（对齐 `AUTH_CHALLENGE_EXPIRED`） |
| 面板·成功 | `state==='success'` → "✅ 配置完成"，2s 定时器后 `setStep('confirm')` |
| 面板·API key 拒绝 | `AUTH_REJECTED` → `ApiKeyAuth.view` 的 `error` prop 渲染就地红字 + 原因列表（**不弹层**） |
| 创建中 | `mutation.isPending` → 形态 D，阶段由 WS 事件映射 |
| 拉镜像卡住 | 当前阶段 `>5min` 无进展 → "⚠️ 可能卡住"；`>10min` → [强制停止] |
| 失败 | `mutation.isError` → 对应阶段变红 + P22 §1 人话映射 + [重试]/[上一步] |
| 成功 | WS `status==='running'` → 关 modal + 选中新 Task + 开终端 |

**阶段映射表**（后端 12 个技术状态 → 进度卡 **5 个展示阶段**，多对一；**没有第 6 个"等待登录"阶段**）：

| 后端状态（技术状态机顺序，审计 P0-1） | 进度卡格 |
|---|---|
| `pending` / `scheduling` | 初始化 |
| **`preparing-workspace`** | **准备工作区** |
| `creating` | 拉取镜像 |
| `starting` | 启动实例 |
| `running` | 连接终端 |

⚠️ **展示顺序 ≠ 状态机顺序，这是刻意的**：技术上工作区必须先备好（`scheduling → preparing-workspace → creating → starting`，这样 `provider.create()` 时卷已存在）；但用户心智里"拉镜像"在"准备工作区"之前（先有环境再有代码），因此进度卡仍按「初始化 → 拉取镜像 → 准备工作区 → 启动实例 → 连接终端」渲染。**实现时不要"顺手把展示顺序改成和状态机一致"**——`mapStatusToStage` 只负责状态→格的映射，格的顺序由 `CreationProgress.view` 的静态数组决定，两者解耦。

## 7. 本页测试设计

### 7.1 unit（bun test：lib / hooks）

| 被测 | 用例（断言级） |
|---|---|
| `lib/filterImagesForRuntime.ts` | ① `isActive=false` 被排除；② `invalid` 被排除；③ `warning` **保留**且带 `consequence` 文案；④ `supportedRuntimes` 不含所选 runtime 被排除；⑤ 结果为空 → 返回空数组（由 view 渲染置灰态）；⑥ 平台默认 AIO 排第一 |
| `lib/validateApiKeyPrefix.ts` | `codex + "sk-xxx"` → ok；`codex + "sk-ant-xxx"` → ok（`sk-` 前缀成立）；`claude-code + "sk-xxx"` → **fail**；空串 → fail；仅提示不阻断提交前的输入 |
| `lib/mapStatusToStage.ts` | ① **12 个技术状态全部有归宿**（审计 P1-8）：`pending`/`scheduling`→初始化、**`preparing-workspace`→准备工作区**、`creating`→拉取镜像、`starting`→启动实例、`running`→连接终端；终态（`stopping`/`stopped`/`idle`/`failed`/`destroying`/`destroyed`）不映射到任何格（进度卡已退出）；② **断言展示格数恒为 5**（无登录阶段的结构性回归——注意这是多对一映射，状态多了格数不变）；③ **断言格的顺序数组是「初始化,拉取镜像,准备工作区,启动实例,连接终端」**，与状态机顺序不同是预期（见 §6）；④ 未知状态 → 兜底不抛错 |
| `hooks/useRuntimeAuthFlow.ts` | ① device-code：`idle→pending→polling→success`，`refetchInterval` 在 3–5s 区间，到 `expiresAt` 置 `enabled:false`；② 轮询连续 3 次网络错误 → `networkError` 态且**倒计时未被重置**；③ setup-token：提交成功 → `success`，提交失败 → `error` 且**返回的 state 不含 pastedText**；④ api-key：`saveSecret` 成功 → 直接 `success`（不经 polling）；⑤ unmount → `AbortController` 已 abort |
| `hooks/useCreateSandbox.ts` | ① 乐观插入的列表项状态为"准备中"；② `onError` 回滚该乐观项；③ mutation **不自动重试**（`retry:0`）；④ 请求体 `projectId` 取自 `wizardData.selectedProjectId` 而非 `uiSlice.selectedProjectId` |
| `stores/createUiSlice`（向导片段） | ① `wizardReturn` 置真后写 `wizardData` → 回程读回完全一致；② `partialize` 快照**不含** `wizardData.initialPrompt`；③ 关闭向导 → `wizardData` 清空 |

### 7.4 e2e（Playwright）

- **参与 12 §4.2 用例组**：B（鉴权三分支即时完成，含"阶段数=5 且无等待登录""请求 URL 无 sandbox 维度"两条结构性断言）、C（确认步项目行往返保值 + 8000 上限 + 镜像过滤 + projectId 归属 + 刷新后 localStorage 无指令残留）、G（旅程第 ④⑤⑥ 步）。
- **本页独有补充场景**：
  1. 深链 `/new?runtime=codex` → 断言 Step 1 已预选 Codex。
  2. [后台运行] → 关向导 → 断言工作台该 Task 行显示阶段名 + 进度条，且完成后自动转 🟢。
  3. 创建中 [取消] → 断言二次确认后请求终止且列表乐观项被回滚。
  4. 面板页脚 [管理所有凭证] → 断言**跳到 `/settings/credentials` 路由页**（不是嵌套 modal），浏览器后退可回。

## 8. 依赖与缺口

- 依赖后端：`GET /api/runtimes` 聚合（P22 §4.11）、auth helper 编排（P22 §4.12）、`POST /api/sandboxes` 接受 `projectId`/`initialPrompt`。
- 无头模式与超时下拉属 v1.1，MVP 渲染为禁用态 + "v1.1" 角标。
