# F21-6 · 项目管理前端实现

本页对应 [产品说明](../../product/pages/21-6-项目管理.md)；[PRJ 需求](../../design-v2/gap/product/PRJ.md) 定义全部 AC。组件清单取当前 workspace，验收结果以运行产物为准。

## 1. 页面职责

项目是代码工作区与任务的容器。创建、克隆恢复、同步、重命名、归档、成果与删除有完整退出路径。

## 2. 路由与骨架落点

`/` 的项目总览、项目信息与管理弹层。使用 AppFrame/SettingsLayout 与 AppDialog；DialogSections 固定头尾，正文独立滚动。

## 3. 组件树

WorkbenchContainer、NewProjectContainer、ProjectRecoveryContainer、ProjectInfoContainer、ProjectMenuContainer、DeleteProjectConfirmView、RetainedVolumesContainer。Container 编排查询与命令，view 只接 props；wire 使用生成 DTO。

## 4. 状态与数据接入

projects CRUD、branches、retry-clone、cancel-clone、convert-to-empty、sync、deletion-preview；retained-volumes 查询、归档下载与删除。

后端结果由 Query 持有，选择与临时编辑由 Zustand/组件持有；事件失效相关 query，不使用事件名称本身冒充业务状态。

## 5. 交互实现要点

侧栏、总览、命令面板、欢迎态打开同一新建项目弹层。克隆可以取消/重试/改空；权限失败跳 Git 凭证并提供回程。删除先读真实预览，有运行任务则明确阻止。

服务端事务决定删除范围，数据库提交后才清理文件；排队克隆取消不能后续复活；工作区与任务副本隔离；未命名编号依据当前集合生成。

## 6. 状态矩阵落地

加载/空/错误；克隆排队/运行/中断/失败/就绪；归档只读；同步冲突与失败；成果保留、过期与清理。失败项目可打开总览处理，不形成导航死角。

未知数据不可转换为零、成功或空集合。颜色取 v2 语义 token，图标为 SVG；控件保持可访问名称和焦点。

## 7. 本页测试设计

新版验收位于 `web/src/acceptance/`，本域场景：project-workflows / workbench。真实 container + HTTP 边界验证交互与副作用；旧单测已退休，不把旧覆盖率当验收。Storybook 验证 view 变体；设计 runner 验证实际页面状态与布局。

## 8. 依赖与契约

OpenAPI 生成类型与 shared schema 是传输形状依据。新预览接口的真实性由后端 SQLite/协议验收验证；浏览器固定数据只用于可重现视觉，不能证明真实外部基础设施健康。

## 9. 验证计划

全量 AC 台账位于主仓 `artifacts/migration-audit/`；计划、代码审查、实际测试与视觉审查分别标注。不得仅因存在截图或测试名就判定全部 AC 实跑通过。

## 9.1 功能验收

按 PRJ 的 Given/When/Then 执行，断言用户可见结果、请求次数与真实副作用；覆盖取消、失败、重试和竞争。

## 9.2 关键链路

生产构建启动后使用 `web/scripts/check-design-*-v2.mjs`，隔离 HTTP/WebSocket 数据；暗/亮主题及1440/1024/390宽度记录页面错误、溢出与截图。

## 9.3 证据与缺口

每稿 runner manifest 记录来源、夹具、动作与实跑结果；失败必须修正代码或夹具后重跑，不能改成通过。真机条件另行登记，不能由隔离浏览器替代。

## 9.4 产品裁决

依本仓完整领域规格与 open-questions 的已选决定实现；明确 superseded/deferred 的条目保留理由，不算待迁移功能。

## 10. 项目恢复与事务边界

ProjectRecoveryContainer 对重试/改空包装无参数 handler，SyntheticEvent 不传入项目id。删除后缓存清理由真实响应决定，文件清理失败不回滚已提交数据库。
