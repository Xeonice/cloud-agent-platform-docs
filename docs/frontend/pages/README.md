## 1. 这一层解决什么

领域文档（07/08/12/15/16）回答"每个域怎么设计"，18 回答"这些域如何拼成一个前端"，**本层回答"产品的每一页在前端怎么落地、怎么测"**——一页一份，与产品页一一对应、同号可映射。

三层的分工是硬边界，避免同一件事写三遍：

| 层 | 管什么 | 不管什么 |
|---|---|---|
| 领域文档 07/08/12/15/16 | 分层铁律、组件层通用规格、状态归属与 key 工厂、测试体系与工具链、链路验证矩阵 | 单页的组件树与逐条交互 |
| **pages/**（本层） | 每页的路由落点、组件树、消费的 key/字段/事件、交互→handler→service 的映射、状态矩阵渲染分支、**本页四层测试用例清单** | 跨页共识（分层规则、key 工厂定义、CI 编排）——只引用不重复定义 |
| 18 总纲 | 索引与统合视图 | 细节 |

## 3. 统一模板

每份逐页设计固定八节，缺项写"无"而不是省略章节——保证可比对、可 review：

| 节 | 内容 | 硬性要求 |
|---|---|---|
| 1 · 页面职责 | 一句话职责 + 与相邻页的边界 | 与产品页 §1 语义一致 |
| 2 · 路由与骨架落点 | app/ 路由文件、layout、modal/弹层形态、进入与退出 | 路由必须出自 [07 §7.1](../07-前端目录结构与视图逻辑分离.md)，不自造 |
| 3 · 组件树 | view/container 完整分解树，一行一职责 | 组件名与 [07 §2/§8](../07-前端目录结构与视图逻辑分离.md) 一致；**页面私有 vs 复用必须标注** |
| 4 · 状态与数据接入 | Query keys / Zustand 字段 / WS 事件 / mutation | key 与字段名严格取自 [15 §2.1/§3.1.1/§2.3](../15-前端状态管理.md)；**需要新 key 时先合入 15，页文档只引用**（见 §6） |
| 5 · 交互实现要点 | 产品页交互表**逐行**映射到 container handler + service 方法 | 端点只用 [07 §6.3](../07-前端目录结构与视图逻辑分离.md) / [18 §8](../18-前端总纲.md) 的定案集合 |
| 6 · 状态矩阵落地 | 产品状态矩阵**每行**对应的渲染分支/骨架/空态组件 | 行数与产品页对齐，不漏态 |
| 7 · 本页测试设计 | 四层（unit / Storybook / 集成 / e2e），**断言级**用例 | 见 §5 分工边界 |
| 8 · 依赖与缺口 | 依赖的后端端点、待定契约、版本门 | 缺口须指回产品/技术文档的登记条目 |
| **9 · 验证计划（验收视角）** | 9.1 功能验收清单（功能 → 验收标准 → 验证方式 → 覆盖状态）· 9.2 关键功能端到端验证脚本 · 9.3 覆盖缺口汇总 · 9.4 产品侧待补验收标准 | 功能清单**从产品页的交互表/状态矩阵逐行取**，不从组件出发；与 §7 不重复（§7 是"怎么测"，§9 是"什么算做对了、有没有漏"）。汇总见 §6 |

## 5. 逐页测试设计与 12 全局测试体系的分工

**[12](../12-前端测试体系.md) 管"体系与工具链"，pages/* 管"每页测什么"**——两者不重叠，且用例最终落在同一套代码里。

| 维度 | 12 负责 | pages/* 负责 |
|---|---|---|
| 金字塔分层与工具选型 | ✅ 定义（bun test / Storybook Vitest addon / Playwright） | 引用，不重新论证 |
| mock 策略与边界 | ✅ 定义（E2E 只用 Playwright 原生 route/routeWebSocket；MSW 只在 Storybook 层） | 遵守，不另立 mock 方案 |
| CI 四道门与执行顺序 | ✅ 定义 | 不涉及 |
| story 覆盖强制与新组件 variant 清单 | ✅ [12 §2.2.1](../12-前端测试体系.md) 给跨页组件的必备 variant | 补本页私有组件的 variant 与 play 断言 |
| E2E 用例组 A–G | ✅ [12 §4.2](../12-前端测试体系.md) 定义组的边界与断言 | 声明"本页参与哪些组" + 列**本页独有**的补充场景 |
| 单测的具体用例 | 只给分工边界（哪层用 bun 测） | ✅ 列到断言级（输入 → 期望输出） |
| 核心用户旅程 | [16 §7](../16-前端链路验证体系.md) 定义七步与契约段 | 各页只对应自己那一步 |

**"集成"这一层的口径**（重要，避免与 12 的分层冲突）：12 §3.2 明确 `containers/**` 与 `views/**` **不进 bun test**（happy-dom 对 ResizeObserver/Canvas 模拟不完整）。因此各页 §7.3 的"集成"指 **container story + `play` 函数**——`@storybook/test` 就是 instrumented Testing Library，跑在 Storybook 的浏览器模式 Vitest 里，网络层由 `msw-storybook-addon` 拦截，等价于"mock 边界在 service 之下"，且不与 E2E 的 Playwright route 冲突。**不新增第四套测试运行器。**

四层的选择准则：

| 想验证的东西 | 放哪层 |
|---|---|
| 纯输入输出（分组、校验、格式化、状态换算） | unit（bun） |
| 单组件在某个 props 组合下长什么样、点一下调用了什么回调 | Storybook view story（+ play） |
| 多组件 + 数据流 + 网络响应共同决定的交互流 | 集成（container story + play + msw） |
| 真实路由、真实 WS、真实浏览器行为、跨页链路 | e2e（Playwright） |

**安全红线必须落到可回归的断言**（三条，各页对应位置已写死）：任务指令/授权 code/API key 不进 persist、镜像 secret 原值不写入 DOM、创建流程无"等待登录"阶段且鉴权端点无 sandbox 维度。

读法与纪律：

- **❌ 29 项是本轮最有价值的产出**——它们是"设计写了、测试没覆盖"的功能。补齐顺序建议按"用户可见性 × 出错代价"排：F21-1 #12 默认任务名（每一行列表都受影响）、F21-2 高级选项四项（整块折叠区零覆盖）、F21-1 #16 终端多标签（08 §5.1 刚改的 registry 键最需回归）优先。
- **⚠️ 31 项多数是"只有单层覆盖"**（常见形态：有纯函数单测但无 UI 断言，或有静态 story 但无交互断言），补齐成本通常是一条集成用例。
- **🕐 41 项不计入缺口**（F21-7 整页 v1.1 + 各页的 v1.1/v1.5 分支）；它们的验收标准**现已全部写死**（含本轮补的 webhook 退避 5s/25s、时区快照、编辑不重传 timezone），是开工时的验收依据。
- **"其他" 4 项是非前端职责**（日志脱敏、备份不含密钥、旧口令失效、工作区独立副本）——已在各页显式标为**后端/部署验收项**，前端不重复覆盖，但也不能因为"不归我"就从清单里消失。
- **否定性验收是最容易被破坏的一类**（"不该出现下拉""不该弹二次确认""不该自动重验证""离线时不该隐藏入口"）。它们在各页 §9 里单独成行，因为正向功能坏了会有人报 bug，而"多做了一点"往往没人发现。

**产品侧待补验收标准**：**已清零（0 项）**。经三轮 doc-vs-doc 复核收敛：**24 → 10 → 1 → 0**——八页 §9.4 全部只剩"已闭合"回溯说明，无待补条目。所有验收标准都已改写进对应页的 §9.1 功能行，产品侧不再是任何一条功能无法验收的原因。

> 因此**剩余的 ❌/⚠️ 全部是"测试实现层还没写用例"**，不再混杂"产品没定义所以没法写"。两类问题此前容易被混为一谈——现在 §9.3（覆盖缺口，我方待补）与 §9.4（产品待补，已清零）边界清晰：**接下来补齐 ❌ 29 项与 ⚠️ 31 项是纯实现期工作，不需要再等任何产品裁决。**
