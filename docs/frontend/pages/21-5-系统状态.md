## 1. 页面职责

展示服务端资源、Provider 健康、真实诊断与审计；不能测量时说明原因，不编健康值或修复动作。

现有顶部版本与更新卡区分当前实例service、实际页面、catalog installable release、固定active目标；CD只发版本/包，用户决定实例升级。已通过已有访问保护的用户直接点击立即升级是唯一启动command，其他目录check/lookup/版本读取/页面刷新只读；不开放部署密钥/Docker/备份/手动回退/停止任务。见 [前端计划](../changes/2026-10-10-升级提示与原终端续接.md#26-用户启动实例升级与受理边界planned)；2026-10-18优化增量见同文§2.7，代码与验证结果单独留证。

## 2. 路由与骨架落点

`/settings/system`。使用 AppFrame/SettingsLayout 与 AppDialog；DialogSections 固定头尾，正文独立滚动。

顶栏右上32px中性/16px CircleArrowUp在verified available（解锁后可直接立即升级）、已受理ongoing，或activation-confirmed且Webready/page不同显示；available与ready待刷新有静态点，ongoing无点。今日未关闭浮卡：待升级立即升级（无attempt/percent）→受理0–99阶段→installed100待刷新；page已target不掩盖service待升级，sameWeb完成不强刷。无合法条件/对应unknown/失败延期才隐藏，本页check常驻，固定浮卡不占布局/盖操作/抢焦点。

## 3. 组件树

SystemStatusContainer、ResourcePoolCardView、SandboxEnvStatusCardView、DiagnosticsCardView、AuditStreamContainer。Container 编排查询与命令，view 只接 props；wire 使用生成 DTO。

顶部使用VersionUpdateCardView、共享VersionUpdateContainer/Popover/Notice，useInstanceUpgrade统一读取catalog／实例状态并处理已解锁后的明确提交，useUpgradeReminder仅日期。AppFrame两个header接同一来源；生成契约及upgrade.service分别提供read-only catalog/状态/lookup和唯一upgrade command，不能在effect或query中自动调用command。

## 4. 状态与数据接入

system/resources、providers、providers/:id/logs、diagnose SSE、audit、audit/export、version、settings。

后端结果由 Query 持有，选择与临时编辑由 Zustand/组件持有；事件失效相关 query，不使用事件名称本身冒充业务状态。

### 4.1 版本目录、实例事实与命令边界

| 信息 | 来源与展示规则 |
| --- | --- |

| 升级百分比与阶段 | 明确授权command经server幂等/CAS受理后才有attempt/generation/seq与冻结totalWork/completedWork；controller计算，catalog/CD无实例百分比 |

## 5. 交互实现要点

显式执行诊断，SSE逐项更新，离开再回来保留最后结果。Provider 日志只在点击后读取真实日志尾部；审计可筛选、展开详情、下载脱敏数据与定位对象。

诊断脚本可在服务故障时独立执行；使用实际数据目录与端口；后端日志必须脱敏；访问口令轮换通过已记录接口/部署变量，不为暂缓需求新造管理页。

### 5.1 版本卡与刷新

本页卡常驻服务/实际页/catalog/固定attempt/状态/时间。catalog verified installable available且有实例升级权限才提供立即升级，无attempt/percent；明确点击后固定targetDigest+expectedActivationGeneration+requestId，server校权限/CSRF/架构/目标可安装及幂等CAS受理才ongoing0–99。响应丢失/超时只lookup原requestId，不重新POST/自动newattempt；同一操作人的双击／多标签至多受理一次，冲突不静默换最新目标。受理前无实例下载/候选/线上迁移，active目标不随CD改变。

×/稍后按非凭据scope+instance+localDate抑制available→submit→ongoing→ready和全部同日目标，多标签/route/reload同步；不取消受理或改变权限，合法主动操作仍在。00:00/可见性/日期timer仅核验catalog/权限/实例事实，仍verified available、ongoing或installed ready/page不同才再提醒，非24小时/永久revision，不触发部署。

进度按instance/固定attempt/generation/seq及冻结计划归属；目录available无percent，受理后同attempt单调/乱序保护，恢复attempt独立不继承100。目录与实例源unknown分别保lastseen/check；无可信事实不假计数/ready。activation-confirmed历史成功不可改写，后续熔断追加撤销/恢复；只读查询不重启已失败attempt，新尝试用户再发起，本次授权可包括固定manifest桥链及合格安全自动回退。

进度条仅实际受理ongoing具名role=progressbar、aria-valuemin/max/可信now/text；unknown无now，不逐1%live打断focus/selection。available和ready有点、ongoing无点；日关闭只抑浮卡。失效收起控件，仅移除区域内安全返焦；Escape/外点只关popover，check/lookup/跨日不自动reload、部署或操作任务。

只有本实例activation-confirmed100、目标Web经版本化入口/固定artifact真正生产ready、兼容可达且page不同才刷新。CD不能promote共享alias改变未升级实例Web；sameWeb的新service release仍可升级，完成无需刷新。reload前只读复核及沿离开规则保表单/IME/书签，实际webRevision才改页号/attach原terminal，不部署/create/start/replay或自动reload。

### 5.2 一次最终目标与失败后的实际状态（2026-10-18增量）

卡片分列服务可用性及其确认时间、上次完整确认版本、固定最终目标与本次结果、实际页面构建。用户点击一次受理用户级`operation`；兼容准备及最终版本的技术attempt保留独立记录，中间100%不冒充本次完成，最终节点确认前不显示刷新。响应未确认显示“正在确认升级请求”，只查原requestId；不能用长达240秒的控制预算代替及时受理与轻量查询。

总体percent未知时保留当前可测阶段字节、总量和阶段percent，明确标阶段范围；长检查显示真实阶段时长、最后实质进展和最后确认。缓存状态有独立时间及fresh／stale／checking含义，旧证据不因页面查询成功而变新。只读检查不重启失败attempt。

部分切换后失败显示“升级未完成，部分组件已更新”，服务是否可用由独立服务证据决定，不用health200或历史确认版本替代最终安装成功。细节才显示实际组合和诊断；可用时提供继续使用。只有服务端基于当前组合核验有安全、明确目标的repair计划时显示对应修复动作，否则检查状态／复制脱敏信息，不提供无条件回退／重启。确有受管默认镜像更新时，完成文案仅覆盖之后选择该默认镜像的新任务，已有沙箱、自定义默认及显式其他镜像保持原配置。

## 6. 状态矩阵落地

CPU/RAM/磁盘按服务端阈值；样本不足显示未知；超时明确未测完；取消/断线保留已收到项目；已删除对象展示记录但禁止无效跳转。

未知数据不可转换为零、成功或空集合。颜色取 v2 语义 token，图标为 SVG；控件保持可访问名称和焦点。

| 版本状态 | 本卡显示与动作 |
| --- | --- |
| 已确认无较新service且page已当前 | 隐藏更新控件，系统当前服务/页/check常驻；page已target不能覆盖另一可安装service release |
| 目录确认installable available | 所有版本读取用户保留图标/点/未关闭浮卡/只读详情，无attempt/percent；已通过已有访问保护即可直接立即升级，sameWeb可升级 |
| 已受理ongoing / installed100 | ongoing固定目标0–99无点、不刷新未ready；activation-confirmed100且Webready/page不同才有点/刷新；sameWeb不强刷 |
| 今天关闭或稍后 | available→提交→ongoing→ready及同日目标不重现，跨页/reload/多标签；合法主动命令/刷新保留，不启动或取消attempt |
| 次日本地00:00 | 先只读catalog/权限/实例；verified available、ongoing或installed ready/page不同才提醒，不部署，unknown/失败延期不造事实 |
| 未受理候选／失败／延期 | 未受理候选不冒充ongoing；失败/延期控件隐藏，系统保目标/原因/check；修复新尝试用户再发起，非自动部署重试 |
| 部分产物切换、整体未确认 | 状态“切换中／待确认”与“上次完整发布 vA”，实际页面和已切换 artifact 详情分开；不强填旧/新整体版本 |
| catalog/实例/提交结果unknown | 对应lastseen/check；超时只lookup原requestId，缓存不启动/刷新；可信ongoing仅度量缺失可等待，不假100 |
| actual page已target / 仍旧revision | 只决定是否刷新；若service有available或ongoing仍展示合法入口，CD新包不改页号或activation |
| 整体 release 更新、API/runtime 复用 | 整体版本与真实 artifact/owner 详情分别显示，不冒充全部运行内容已更新 |
