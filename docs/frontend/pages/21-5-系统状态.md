# F21-5 · 系统状态前端实现

本页对应 [产品说明](../../product/pages/21-5-系统状态.md)；[SYS 需求](../../product/requirements/SYS.md) 定义全部 AC。组件清单取当前 workspace，验收结果以运行产物为准。

## 1. 页面职责

展示服务端资源、Provider 健康、真实诊断与审计；不能测量时说明原因，不编健康值或修复动作。

## 2. 路由与骨架落点

`/settings/system`。使用 AppFrame/SettingsLayout 与 AppDialog；DialogSections 固定头尾，正文独立滚动。

## 3. 组件树

SystemStatusContainer、ResourcePoolCardView、SandboxEnvStatusCardView、DiagnosticsCardView、AuditStreamContainer。Container 编排查询与命令，view 只接 props；wire 使用生成 DTO。

## 4. 状态与数据接入

system/resources、providers、providers/:id/logs、diagnose SSE、audit、audit/export、version、settings。

后端结果由 Query 持有，选择与临时编辑由 Zustand/组件持有；事件失效相关 query，不使用事件名称本身冒充业务状态。

## 5. 交互实现要点

显式执行诊断，SSE逐项更新，离开再回来保留最后结果。Provider 日志只在点击后读取真实日志尾部；审计可筛选、展开详情、下载脱敏数据与定位对象。

诊断脚本可在服务故障时独立执行；使用实际数据目录与端口；后端日志必须脱敏；访问口令轮换通过已记录接口/部署变量，不为暂缓需求新造管理页。

## 6. 状态矩阵落地

CPU/RAM/磁盘按服务端阈值；样本不足显示未知；超时明确未测完；取消/断线保留已收到项目；已删除对象展示记录但禁止无效跳转。

未知数据不可转换为零、成功或空集合。颜色取 v2 语义 token，图标为 SVG；控件保持可访问名称和焦点。

## 7. 本页测试设计

组件验收位于 `web/src/acceptance/`，本域场景：system-diagnostics-audit / initialization。真实 container + HTTP 边界验证交互与副作用。Storybook 验证 view 变体；生产构建浏览器验收验证实际页面与布局。

## 8. 依赖与契约

OpenAPI 生成类型与 shared schema 是传输形状依据。新预览接口的真实性由后端 SQLite/协议验收验证；浏览器固定数据只用于可重现视觉，不能证明真实外部基础设施健康。

## 9. 验证计划

本页按对应领域的 Given/When/Then 维护验收映射。计划、代码审查、测试执行与视觉审查分别记录；测试名称或截图存在不能证明全部 AC 实跑。

## 9.1 功能验收

按 SYS 的 Given/When/Then 执行，断言用户可见结果、请求次数与真实副作用；覆盖取消、失败、重试和竞争。

## 9.2 关键链路

Storybook 核对当前视图状态，生产构建与跨仓浏览器验证真实路由和页面装配；暗/亮主题、桌面与窄屏记录错误、溢出、焦点与截图。

## 9.3 证据与缺口

运行报告关联场景、操作、截图与实际结果；需要真实后端的行为另附 API/跨仓证据。未运行的条件明确列出。

## 9.4 产品裁决

依 [当前产品裁决](../../product/requirements/decisions.md) 与对应领域需求实现；superseded/deferred 保留理由，并明确当前适用范围。
