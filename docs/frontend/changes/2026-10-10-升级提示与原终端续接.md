# 不停机升级与原终端续接 · 前端实施方案

平台发布新版本时，已有沙箱、Agent 进程和无头运行继续执行；浏览器恢复连接或由用户刷新后，回到同一个沙箱及原终端。前端保留任务选择和已显示的输出，不把连接中断当作停止任务，也不以重新发起任务代替续接。

本文件描述现有前端的实施边界及2026-10-18优化增量。2026-10-12已接入实际版本状态、幂等命令、进度及原终端书签恢复；2026-10-17至18已完成两实例`.20261017.7`实验发布，具体证据和限制见[CLI镜像与双实例更新验收](../../testing/results/2026-10-17-CLI镜像与双实例更新验收.md)。该结果不代表全部正式故障矩阵已通过。2026-10-18按[升级体验与启动可观测性优化](../../product/changes/2026-10-18-升级体验与启动可观测性优化.md)先同步既有文档和原型，再完成前端源码与本地验证，Web提交为`17e6769`；已完成两实例`.14`实际更新与`.15`新界面单次异步升级、原请求查询和同Web无刷新验收，见[本轮发版验收](../../testing/results/2026-10-18-升级优化发版与双实例更新验收.md)。具体范围和限制见[本轮实现验证](../../testing/results/2026-10-18-升级体验与启动观察实现验证.md)，不以设计稿或旧上线记录替代本轮上线证据。

目标保持：**CD只发布版本与包，已通过现有访问保护进入平台的用户决定何时升级本实例**。产品规则以[UPG需求与AC](../../product/requirements/UPG.md)为准。右上角CircleArrowUp和紧凑浮卡沿用现有布局，分别表达可安装最终目标、提交待确认、用户计划进行中及页面待刷新；目录available无attempt/percent。没有独立升级密钥、授权按钮或再次输入口令。今日关闭只抑制浮卡，系统详情和只读检查常驻，页面已新不能掩盖服务仍待升级。

本轮由单个已通过现有访问保护的操作人升级当前实例，不新增用户管理、RBAC 或多人切换流程。系统版本卡和右上浮卡在有可安装新版时直接提供“立即升级”；没有升级专用口令、授权按钮、输入表单或grant状态。会话真实过期时仍走原访问解锁流程，打开提示、检查更新和解锁本身均不创建 attempt。

## 1. 已有能力与实施缺口

审查基线：主仓 `6ae9497416340c02dfbc7c34772c00b86f38386b`，API `7688294cefbecd261f9e82d6579dfe63e39c701b`，Web `c6b848ecaca755fbd8543656d4f0165984189cbb`。下表保留首次审查的历史基线，用于定位原职责；不作为当前代码尚未实现的判断。代码路径均相对主仓，当前实现以源码及验收记录为准。

| 现状 | 已实现来源 | 本轮缺口与处理 |
| --- | --- | --- |
| 选中的项目、沙箱、无头运行可跨刷新保留 | `web/src/stores/index.ts` 的 persist 白名单 | 沿用不透明资源 ID；版本提示不得清空这些字段 |
| 工作台选任务会写 `?taskId=`，刷新时读取真实沙箱详情 | `web/src/hooks/workbench/useWorkbenchRoute.ts` | URL 的 `taskId` 实际指向 `SandboxDto.id`，与无头 `AgentTaskDto.id` 不同；本轮只复用该入口，不新增深链功能 |
| 网络错误不清选中，确认 404 或项目归属不符才回落 | `web/src/hooks/sandbox/useSandboxRestore.ts` | 发布暂时不可达、runtime 接管未完成要保留指向；不得用临时查询失败合成 404 |
| 同页 PTY 重连带回 `socketSessionKey` 和 `shellId` | `web/src/services/ws/ptySocket.ts` | 凭据在 API 重建后的效力不能由前端猜测；需要服务端确认原会话及所属 sandbox 的身份 |
| 用户终端从服务端 `shells` 清单恢复，清单未知时不删除标签 | `web/src/stores/createTerminalTabsSlice.ts` | 沿用清单；服务端需要区分查询未知、原会话存在、原会话已结束，并禁止恢复入口悄悄创建替代会话 |
| 刷新后活跃终端回落 Agent；标签编号可能重排 | `web/src/hooks/terminal/useTerminalSessions.ts` | 新增可落盘的非凭据终端选择书签，由认证后的服务端清单校验，恢复到原标签 |
| 同页断线不清终端，输入不排队；无头输出按 seq 续播 | `web/src/containers/terminal/TerminalMount.tsx`、`web/src/hooks/task/useTaskStream.ts` | 延续纪律，跨版本恢复不 replay 输入、不重复执行 initialPrompt、不另起无头运行 |
| `/events` 重连后重新读取项目、列表和详情 | `web/src/containers/workbench/AppFrameContainer.tsx` | 接入发布状态及 runtime 连续性确认；旧 REST 响应仍不能覆盖新事件 |
| schema 差异停止终端重连并要求刷新；普通 attach 失败可显示会话结束 | `web/src/lib/terminal/handshakeErrorCopy.ts`、`web/src/containers/terminal/TerminalMount.tsx` | 按兼容协商结果及明确的失败分类处理，不能只凭版本/hash 不等判定失败或任务结束 |
| 终端连接条无条件说任务还在运行 | `web/src/views/terminal/ConnectionStatus.view.tsx` | 恢复完成必须有原运行身份确认；未知状态只能说正在恢复或暂时无法确认 |
| 系统状态页没有版本卡，工作台与设置页的 header 分支没有版本入口 | `web/src/containers/system/SystemStatusContainer.tsx`、`web/src/containers/workbench/AppFrameContainer.tsx`、`web/src/views/workbench/WorkbenchHeader.view.tsx` | 两种 header 接同一图标/popover，外壳接固定轻量浮卡及今日关闭偏好；日关闭不移除主动刷新；系统顶部卡区分页面、整体 release 与 API artifact |
| API 有版本三元组；settings 也有另一版本字段，Web 尚无对应版本展示 | `api/apps/api/src/platform/system/system-version.service.ts`、`system-settings.service.ts`、`web/src/services/api/system.service.ts` | 实际 artifact 使用真实注入值；整体 release 从本实例生效记录读；当前页面从本页构建标识读，不能混用或以 package 版本兜底 |

当前构建事实：`deploy/containers/Dockerfile.api` 把 `APP_VERSION` 设为 `APP_COMMIT`，发布构建传入的是 API SHA，因此既有版本端点两字段均为 API SHA，不是产品 release tag。Web 当前没有注入独立页面产品版本/webRevision。实现必须新增受信的本实例完整激活 release 记录及 Web artifact 身份注入，不能把这些计划来源当作已有可靠接口，也不能把 API SHA 或 `settings.version.platform` 当成产品版本号。

现有文档曾将 `?taskId=` 列为计划能力，实施时统一到上述源码事实。`selectedSandboxId` 和 `selectedTaskId` 保持各自语义：前者是运行环境，后者是该环境内的一轮无头运行。

## 2. 用户交互与状态边界

### 2.1 提示位置与行为

| 情况 | 展示与动作 | 现场保护 |
| --- | --- | --- |
| catalog确认可安装较新release，实例未升级 | 显示服务vA→vB“待升级”；版本读取用户看到图标、静态点、今日未关闭浮卡和详情；已进入平台即可直接点击“立即升级” | available无attempt/percent，不能显示0%；page已target／sameWeb不隐藏service待升级；真实访问会话失效由原访问保护拒绝，不另设升级授权流程 |
| 明确点击，提交／受理结果待确认 | 捕获targetDigest、expectedActivationGeneration、requestId，按钮防重复；只有server幂等/CAS受理后才ongoing | 网络超时只lookup原requestId，不自动POST／新建attempt；权限、CSRF、目录、架构与兼容性均由server检查 |
| 已受理目标正在升级 | 本实例controller确认固定目标及ongoing attempt后显示图标；今日未关闭浮卡显示0–99%／阶段／详情／×，进行中无点 | 实例下载、候选、线上迁移仅在受理后执行；0–99不刷新未ready目标，新catalog不改本attempt目标 |
| 实例升级已完成 | 整体activation-confirmed、实际生产绑定及兼容／连续性确认后到100；目标Web不同且ready时才有点和“刷新页面” | 100不是CD目录published，也不代表浏览器／终端已恢复；sameWeb无需刷新；有下一service release另按available判定 |
| 用户查看更新 | 图标主动开popover，分列服务／实际页面／catalog可用release／固定attempt目标 | 立即升级是唯一授权command；目录check、请求lookup、版本读取、页面刷新只读，不触发部署；available点表示可处理更新，不冒充已安装 |
| 操作人关闭浮卡或稍后 | 当前操作人＋instance＋本地自然日抑制available→提交→ongoing→ready及全部同日目标；合法主动升级／刷新仍可找 | 同一操作人跨页/reload/多标签同步；关闭不改权限、不启动或取消已受理升级，不改页面身份 |
| 无可用升级／失败／延期／相关观测unknown | 隐藏失效控件并收起popover，系统卡保留对应lastseen及check；catalog与实例观测分别判断 | catalogunknown不撤销可信ongoing；缓存不授权启动或刷新；page已target仅消除刷新需要，不能覆盖service待升级 |
| 第二天仍有条件 | 00:00后只读核验verified installable available、ongoing，或已安装ready且page不同后再显示 | 非24小时／永久revision；跨日、可见性恢复和check不触发部署，不靠缓存推算 |
| 已知的连接移交 | 原终端上方内嵌中性/警示条，说明正在接回原终端 | 保留当前任务、终端标签、画布和滚动位置；不使用全屏遮罩 |
| 恢复超过提示阈值 | “暂时还没接上原终端”与“重试连接”，保留查看状态的入口 | 超时不改变 sandbox/task 的领域状态；重试仍针对同一资源 |
| 确认客户端不兼容 | 本实例已有生产ready的兼容Web时才给用户刷新，否则只读查看系统状态／升级资格 | 刷新不部署；保留书签与原任务，不自动停机或重跑 |
| 无头运行恢复 | 原只读输出保持；同一 taskId 按上次 seq 续播，刷新时按持久化运行记录恢复 | 不挂 Agent 交互终端，不 POST 新一轮运行 |
| 恢复成功 | 原终端 attach 与原运行身份已确认，内嵌条消失 | 不清屏；不把 socket.io transport 的 `connect` 事件单独当作恢复成功 |

目录、授权命令、实例升级、页面和连接状态分开。图标条件为版本读取权限下的installable available、可信受理ongoing或已安装ready且page不同；静态点在available／待刷新，ongoing无点。page已target不能全局过滤service升级。今日关闭仅影响浮卡，Escape／外点只关主动popover；失效仅在焦点位于将移除区域时返现存操作，弹层外保持。浮卡固定在顶栏下、不占布局／盖操作／超时消失／动画／遮罩／autofocus，不改选区／IME／表单或卸载终端，不逐1%live播报。×具名今天不再提醒；系统check常驻且只读，连接恢复条单独简短播报。

### 2.2 失败分类

| 服务端确认结果 | 前端动作 | 不允许的推断 |
| --- | --- | --- |
| access session 确实失效 | 现有口令门解锁；成功后继续恢复原选择和原会话 | 正常发布保持认证签名 secret 和有效 cookie；不能因新 API 启动要求重输口令 |
| 协议兼容，页面有新版 | 自动续接；新版刷新可延后 | 不因 commit 或 schema hash 不同直接拒绝兼容请求 |
| 协议确实不兼容 | 停止无意义重试；已有本实例生产ready兼容Web时可手动刷新，否则只查状态 | 不把刷新变成部署，不将不兼容叫口令错误或任务结束 |
| runtime 接管中 / 暂时未知 | 轻量恢复提示，受控重试和显式重试动作 | 不宣称原进程已死，不发 restart/start |
| 确认 runtime 或 sandbox 不存在 | 说明真实状态，按 PRD 提供查明原因的入口 | 不用一个空沙箱或新 Agent 伪装恢复成功 |
| 原终端已结束，sandbox 仍存在 | 保留原输出与退出原因；重新开终端是用户的独立动作 | 不在 attach 入口自动创建替代终端，不重跑 initialPrompt |
| 无头运行已结束 | 同一 taskId 取回结果与产物 | 不把连接失败改成业务 failed，不自动发起下一轮 |

“运行中”以服务端已确认的 sandbox 实例、Agent/运行身份和目标终端存在为依据。浏览器 transport 已连接但 attach 未完成时，仍处于恢复中。真实退出与暂时无法探测必须使用可辨识的 wire 结果，不继续复用一个不可重试的 `exit` 哨兵覆盖所有异常。

版本值与来源必须分开：

| 值 | 权威来源 | 展示纪律 |
| --- | --- | --- |
| 当前服务版本／activationGeneration | 本实例受信activation-confirmed整体release记录，带实例与单调激活代际 | CD目录published不改当前；candidate／失败目标不覆盖它，部分切换未确认保留上次完整激活 |
| 当前页面版本与 webRevision | 构建注入：当前浏览器实际加载的 Web artifact 标识 | 现有构建已注入；本页生命周期内不能被 API 状态响应改写；刷新后按真正加载的新 Web revision 确认 |
| catalog可安装release／installable | 本实例API提供受信版本目录投影，校验来源、包digest、通道、架构／兼容性及实例适用性 | 以service激活版本判断newerRelease，不按页面号过滤，不仅凭semver或GitHub latest；目录published不等于实例安装／Webready |
| 已受理目标／attempt | server持久化受理的固定releaseId/digest、冻结计划及实例进度 | 新目录不改active目标或自动追加attempt；受理前无attempt/percent |
| 可刷新Web／readiness | 已安装目标在本实例版本化Web入口／固定产物的真实生产绑定，兼容和整体激活确认 | CD不能promote共享生产alias让未主动升级实例自动换Web；staged／包下载完成不是ready，page不同才刷新 |
| 实际 API artifact 信息 | 复用现有 `/api/system/version` 的真实 APP_VERSION/APP_COMMIT/APP_BUILT_AT 来源及后端新增的 provenance | 当前 APP_VERSION 与 APP_COMMIT 都是 API SHA，作为 artifact 详情保留；整体 release 更新但复用 API 时不改旧 commit、不伪造为本轮 ROOT_SHA 或产品 tag |
| 存量 runtime 版本 | 原 RuntimeOwner/实例的真实 provenance；需要时在详情说明仍由原 owner 服务 | 新控制 API 或新 release 不代表全部 runtime/存量实例已经升级 |

控制API只读查询StateCoordinator实例状态和受信catalog，不新增写者／scheduler／pump。目录check、进度、请求lookup、普通读取与页面刷新均不触发部署；唯一写入意图是§2.6已进入平台的用户明确发起的upgrade command。浏览器仅向本实例受保护API提交，不接部署密钥、Docker socket或Jenkins控制面。原有访问会话直接用于升级命令；settings／现有API三元组不能互相兜底为release，当前Web身份与完整激活来源已独立建模，本轮继续保持。

Query按instance、访问scope、activation／升级generation、catalog revision及请求代次分别隔离；另一实例／迟到结果不覆盖新确认。目录可更新available，不改已受理固定目标；旧Web仍显示实际构建值。

原请求lookup只确认该命令是否已终结，不作为当前实例状态源。单个操作人串行A→B后恢复A，A的operation已completed／failed／deferred，或legacy attempt已activation-confirmed／failed／deferred／candidate-rejected／reverted时，只解除仍匹配当前instance、访问scope、存储key与requestId的pending。删除前重读同key标识，不能删除已存入的下一请求；迟到A也不能清同scope新提交C的内存等待。B的版本、阶段与刷新资格继续取状态Query，B进行中不因A完成变ready。未终结、404、畸形响应和网络失败均保留原ID按原协商方式继续lookup，不自动POST。

入口先判catalog installable（立即升级另按实例权限）、受理ongoing、安装ready待刷新三个分支；只有刷新分支看page差异，sameWeb的新service release仍可升级。纯candidate／仅目录目标不能冒充ongoing；无相应合法事实或失败／延期／相关观测unknown才隐藏。catalog与实例状态分别核验，目录unknown不撤掉独立可信ongoing。今日关闭贯穿available→ongoing→ready及同日目标，不启动／取消升级；系统check常驻，日期规则见§3.4。

点击刷新前重新确认完整发布100%及本实例目标Web ready、生产入口绑定、兼容且可访问，按原离开规则保护表单/输入法，再保留原资源书签执行reload。新页面启动后核验实际webRevision，确为目标才显示页面新版，再确认原sandbox/terminal续接。命中旧artifact或目标暂缓时，保持实际页面身份和可重查动作，不先改数字或自动循环reload。

### 2.4 可信升级百分比与阶段

进度仅属于用户upgrade command经server幂等/CAS明确受理后的实例升级；CD目录available无attempt/percent，受理前不能显示0%假进度。进度为实例升级controller只读事实，经本实例受信状态投影提供，绑定 `instanceId + attemptId + generation + seq`、目标 release/Web 身份、阶段、确认时间及冻结的计划身份。发布开始前冻结允许测量的步骤、`totalWork` 和可测 `completedWork` 口径，例如实际传输字节、已完成校验项或已确认操作；百分比由 controller 按该计划计算并持久化，浏览器只校验/展示。前端不能用客户端 timer、动画、请求次数、阶段文案或固定权重自行累加；计划未冻结、总体工作量无法测量时总体percent为null；仍展示有独立真实总量的当前阶段进展，见§2.7，不编整体数字。

同 attempt 的有效 seq 前进，进度0–99单调；旧 seq/重复帧或较旧 generation 不覆盖当前读数，另一 instance/attempt 不混入。已确认新 attempt 使用自己的目标/冻结计划和读数，不能继承前次百分比；同 seq 冲突或较新 seq 的工作量倒退视为待确认并只读复核，不能用 `Math.max` 掩盖契约错误。真实 reload 后重新读取同一 ongoing attempt 的最新 seq/阶段/百分比，不能从0重新播放假进度，也不能把 localStorage 数字当权威。

安全回退使用独立的 `recoveryAttemptId`，关联原升级 `attemptId`，具有新的 generation、独立 seq 和冻结的 `recoveryPlan`；这些均由后端受信投影提供，前端不创建恢复尝试。整体确认前失败的原升级 attempt 记录 failed/reverted；已经 activation-confirmed 后发生故障则保留当时成功及100%的历史，追加当前 ready 撤销和独立 recovery 事件，不能改写成从未成功。两种情况都不能把原100%、完成量或最后seq继承到回退。恢复进度若有可测工作量，只在系统卡明确标为“安全回退”，不能接入升级进度或派生新版 ready；回退完成必须另有当前数据库、实际 API/Web 组合、控制 fence 和原运行连续性的确认。回到较旧 release 时 generation 仍向前，不能按 tag 大小丢弃真实回退，也不能因原历史100或迟到 complete 帧重新给“刷新到失败目标”。

100% 仅在整体发布事实、激活记录、生产入口绑定、目标 Web ready/兼容及所有完成确认均成立时提供。子阶段100%、全部传输完成或候选 health 成功都仍不代表整体100%；确认前最高99%或等待确认。0–99没有刷新到未ready目标，ready撤销立即撤掉刷新/点；发布状态变failed/deferred/unknown时入口/浮卡收起，系统卡保留真实阶段/原因及最后已知进度，不把旧100当当前完成。页面是否实际加载目标 webRevision、原终端attach-ready及运行身份，分别确认，不合入这个发布百分比。

进度不明、停滞、过期或断网时停止推进，显示“等待进度确认”及最后已知百分比/阶段/确认时间。发布状态仍可信ongoing、只是度量暂缺时，浮卡可显示等待文本而非确定百分比；整项发布状态无法确认时隐藏trigger/点/浮卡，常驻系统卡展示等待和最后已知信息、手动check。不得通过超时补到100或假装完成；复连先只读复核同instance/attempt时序。

可测进度条具名，使用 `role="progressbar"`、`aria-valuemin="0"`、`aria-valuemax="100"`、可信 `aria-valuenow` 与包含阶段/百分比的 `aria-valuetext`；度量未知时不设 `aria-valuenow`，可访问文本说明等待确认及最后已知。每1%变化不使用live播报打断终端焦点/选择；阶段重大变化如需播报也须简短低频，不抢焦点。原型 `scene=upgrade-progress` 的20/45/75/95/100与手动start/step仅为可复现演示，不能替代真实controller、DTO及门禁证据。

### 2.5 发布熔断与安全回退（planned）

熔断由发布 controller 执行，暂停发布推进、冻结扩流和后续迁移批次。候选尚未接流时可以隔离并禁止新增流量；B 已部分或全部接流时保留最后已应用路由，在没有合格替代路径时不能先把 B 权重清零。确认存在危险写入时仅隔离受影响范围并记录真实影响，不能将熔断理解为关闭健康服务或停止原任务。浏览器在明确启动后只展示实例升级／恢复事实，不自动触发熔断、重试发布、切路由或恢复备份；唯一显式upgrade command见§2.6。硬异常、单纯观测缺失、控制器崩溃及回退失败必须区分，不能把“已熔断”直接写成“已恢复旧版”。

| 受信状态 | 系统版本卡与连接提示 | 展示／副作用边界 |
| --- | --- | --- |
| 发布已熔断 | 显示失败阶段、脱敏原因、原目标及上次完整发布；明确本次发布已暂停 | 隐藏更新 trigger/点/浮卡、撤销失败目标刷新并收起 popover；不清任务、终端或输入，不把发布失败合成任务 failed |
| 安全回退中 | 显示独立 recoveryAttemptId 对应的恢复阶段、最后确认时间及已确认的实际组件组合 | 升级进度停止作为当前完成事实；不沿用100/seq，不自动 reload；部分退回不能称整体回退完成 |
| 回退已确认 | 只有拟恢复的实际 API/Web 组合兼容最新数据、仍可能打开的 Web A/B 及全部原 owner，目标真健康且控制 fence、实际入口和运行连续性均确认后，展示真实恢复组合／确认 release | Web-only 可退指针并保留健康 B API；当前页面仍按实际 Web build 显示 B，回退 Web 指针不会改变已打开页面；不把已撤销目标恢复为 ready 或自动提示降级刷新 |

只有后端核验拟恢复组合对最新数据库、仍可能打开的 Web A/B 与全部原 owner 均兼容、实际目标健康且控制 fence 有效时，才允许自动退 API 路由或 Web 指针。Web-only 故障可只退到旧 Web 指针并保留健康 B API，需核验 Web A/API B 及仍已加载 Web B/API B，不强求 API A 健康；API 回退可以选择健康兼容的旧 API 或保留桥版本。两个组件都需退时，由已冻结方案证明每个中间组合兼容，不能临场拼步骤或先移除唯一可服务路径。前端不能用旧 tag、旧 health 缓存或单组件成功推导可回退。观测软缺失先表现为“等待确认”，不能把未知当明确硬异常或回退成功；控制器崩溃后按持久化 attempt／fence 只读恢复，不能由浏览器重新执行发布。回退再次失败保持待确认，不自动重复同一个升级 attempt，也不以循环回退／重新升级掩盖异常。

暂停迁移发生在安全事务边界：未提交批次按确认结果撤销，已提交数据与 checkpoint 保留；已经开始的同步 SQL／长 DDL 不能由一次熔断保证立即中断。提交结果或回执不明时先核验持久化结果，不盲目重新执行，也不把“请求暂停”写成迁移已经全部停止；发布前须证明批次、锁等待和截止预算。

上述状态仍遵循现有失败隐藏规则，仅通过常驻系统版本卡查看，不新增醒目横幅；原型补充部分切换失败和有／无修复方案的离线场景。若状态变化移除正在操作的入口，按§2.1安全返焦；终端恢复条只描述本终端连接及已确认的运行事实，不能无证据承诺原进程正在运行。今日关闭偏好不被恢复 attempt 重置；后续新发布也仍受同日抑制。

| 身份 | 用途与寿命 | 前端存储 |
| --- | --- | --- |
| sandboxId | 同一个用户运行环境；升级、连接移交、刷新均保持 | 复用已有选中 ID 和 `?taskId=` |
| 无头 taskId | 沙箱内本轮运行；按它读取状态、输出 seq 与产物 | 复用已有 `selectedTaskId`；不与 URL `taskId` 混淆 |
| public terminalIdentity 书签 | 非认证的稳定公开终端引用，关联到服务端已有会话；具体 wire 字段由后端契约确定 | 仅保存选择指向，不保存命令、终端输出或凭据 |
| socketSessionKey / 会话授权凭据 | 临时认证/重连能力，API 代际变化时由认证通道重新签发或验证 | 仅内存；不写 URL、localStorage、日志或验收截图 |
| runtime / 进程启动身份 | 证明恢复的是原运行，不是相同 sandbox ID 下重建的进程 | 服务端权威；测试采集去敏标识，UI 按确认结果展示 |

现有 `shellId` 被存储纪律视作会话凭据，不能直接加入 persist 白名单作为书签。实现需先定义非认证的 public terminalIdentity 及权限校验，再保存“这个 sandbox 上次选择哪个终端”。恢复必须等待认证后的 inventory：匹配到同一个资源才激活；清单未知保留书签；明确已结束则说明真实状态。选择书签不能授权连接，不能令前端创建终端，也不能指向另一 sandbox 的会话；`shellId`、`socketSessionKey`、AuthToken 均不落盘。

### 3.2 兼容协商

后端先提供按 REST、`/terminal`、`/tasks`、`/events` 通道声明的受支持协议版本/能力范围及恢复结果；前端根据明确协商结果使用兼容解码与 attach。发布版本用于提示用户有新页面，协议版本用于判断能否安全通信，schema hash 继续用于诊断和精确契约校验。

新增可选字段或已支持的兼容版本不得只因 hash 不同拒绝旧页面。确实不支持当前页面时返回明确的不兼容分类，用户手动刷新；不能通过取消 zod 校验、接受未知帧或跳过鉴权达成“兼容”。协议升级与退役窗口由 UPG PRD 及后端方案约束，并覆盖旧 Web 配新 API、新 Web 配旧 API、移交与回滚组合。

数据库不兼容变更优先通过兼容桥版本拆开交付：建立影子字段／表，由唯一 StateCoordinator 在同一事务维护双表示；按游标／rowRevision 分批回填，对并发新增、修改、删除进行对账，再灰度新读、切换新读并保留旧表示与回退窗口，最后才独立执行 contract。窗口关闭前禁用旧表示不能承载的新不可逆业务语义。前端只消费已确认阶段／能力：未启用的新能力不提前显示为可用，不通过刷新或关闭版本提示完成迁移；不能读懂新表示的旧页面／API 必须在兼容桥内获得受支持投影。长 SQLite DDL／表重建不能当作无锁动作，未证明锁预算和请求连续性则延期相关变更，保留原服务和任务。兼容桥、能力切换及迁移投影按实际已签计划和实现核验，不能以schema/hash校验豁免替代；本轮进一步补齐用户级固定链。

四种 Web A/API A、Web A/API B、Web B/API B、Web B/API A 组合都须在最新数据库和原 owner 上验证；退 Web 指针后已加载 Web B 仍是 B，API 退回 A 后它仍须可读写、认证并续接原终端。旧回退目标退役或 contract 移除其兼容基础后，不能仅凭旧镜像存在宣称仍可安全自动回退；应延期危险切换或进入待处置状态。

### 3.3 刷新与重试的副作用边界

刷新/续接流程只读取原资源、认证原访问、订阅原运行并 attach 原终端。必须证明没有 `POST /api/sandboxes`、sandbox `start`/`stop`、销毁、任务 `cancel`、无头 run 请求，也没有重新发送 initialPrompt。断线键入不缓存、不在接回后回放；resize 可以按原纪律补发尺寸。用户显式停止、销毁、关终端或发起下一轮的既有操作保持明确的独立边界。

熔断／回退前后已确认的业务写入、任务结果和输出 cursor／seq 不能因切到旧 API 被抹掉或倒退；旧 REST、旧 generation 和历史状态不得覆盖新确认。真实用户删除、正常完成等仍按最新权威业务事件呈现，不靠永久保留旧缓存冒充数据保护。结果不明的业务操作先按原 operationId 查询结果，不能因换 API 盲目重发；已确认成功也不能仅因版本回退被显示为未发生。终端字符、initialPrompt 不排队重放，连接恢复不修改选区、组合输入或未提交表单；发布 controller 的恢复操作与用户业务操作权限继续分离。

### 3.4 今日关闭与次日复查

关闭偏好仅存非凭据 `dismissedLocalDate`，沿用现有认证状态提供的非认证作用域＋当前实例身份分区，不新增用户体系。不能用 cookie、AuthToken、口令、shellId 或 socketSessionKey 作键，也不能在作用域／实例未知时借用全局抑制记录。先读取当前范围偏好再判定浮卡，避免 reload/新标签闪现已关闭提示；保留真实身份、作用域或实例错配拒绝，不把切换用户作为本轮产品流程或验收前置。

当 ×“今天不再提醒”或详情“稍后”被主动点击时，记录浏览器本地日历日期，抑制当前操作人＋当前实例当天全部升级浮卡，贯穿available→提交待确认→ongoing→confirmed100/ready与同日所有目标/attempt。日期而非 revision/百分比是抑制条件；同日换目标、到100%、跨页/reload都不能重现。持久化偏好配合同源storage或BroadcastChannel同步同一操作人的标签，新标签启动也读取；消息核对现有作用域及当前实例，拒绝错配。available的合法图标／已进入平台用户直接立即升级仍可找，ongoing只查进度，installed ready的点/刷新保留；关闭不改权限、不启动或取消升级；不落盘发布凭据、终端输出或认证数据。

次日本地00:00后只读核验catalog／权限、实例attempt／阶段／seq：仍verified installable available、可信受理ongoing，或installed100/ready且page不同，才再显示；非24小时／永久revision。日期timer、可见性／焦点恢复、重连、跨页和初载只读补核，绝不执行upgrade command、下载／候选或迁移，不靠缓存推算。失败／延期／对应事实unknown或无合法条件才隐藏；page已target仅消除刷新，不覆盖service待升级。available→ongoing→ready不重置当天偏好，系统check常驻，浮卡不超时淡出。
