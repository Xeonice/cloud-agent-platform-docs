# 16 - 前端链路验证（2026-10）

## 1. 链路定义

领域 AC 的 Given/When/Then → 用户动作 → container/hook → service → 生成 DTO → 后端 → 持久化/Provider →事件或响应→ Query/store → view。每项证据标记实际跑到的最远边界。

## 2. 类型链路

后端 shared schema → Nest/OpenAPI → `web/openapi.json` → `src/types/generated/openapi.d.ts` →类型别名→业务 props。生成物不手改，新增字段不由前端编造。生产发射 OpenAPI 必须完成真实 Nest 装配，不能沉默退出后复用旧产物。

## 3. 运行时链路

HTTP/WS/SSE 使用实际解析边界；请求成功不表示副作用已完成。未知结果、失联、超时与错误保持可辨状态。预览与执行之间由后端事务复查约束，不能仅用前端计数保护。

## 4. 验证矩阵

| 边界 | 验证 | 证据 |
|---|---|---|
| props/语义/主题 | Storybook、真实浏览器 | screenshot与交互断言 |
| hook/container→HTTP | 新组件验收，真实业务对象 | 请求/响应/DOM/副作用 |
| HTTP/WS/MCP→Nest→SQLite | api acceptance protocol | 实际网络及数据库结果 |
| browser→真实API | e2e-contract | 不挂route的跨仓旅程 |
| 真实外部环境 | 专项运行 | 实际Provider/仓库/镜像结果 |

## 5. 故障模式

重点验证装配缺失、取消后复活、乱序事件、超时补偿、SQLite事务回滚、提交后文件清理、登录会话销毁、凭证注入时撤销竞争、镜像引用竞争。测试必须先证明操作已到达相应阶段，再验证未发生错误副作用。

## 6. 门禁与记录

遵循 [12 新框架](./12-前端测试体系.md) 的执行顺序。根文档门禁检查端点、错误码、MCP注册、跨仓OpenAPI/WS/SSE及链接；API/web各执行新版验收、类型、lint和构建。全量台账中 `code-review`、`test-passed`、`planned` 分开标记。

## 7. 核心旅程

全屏口令门解锁重新判初始化；新建项目实际落库；新建任务使用已登记digest与实际资源；终端经WebSocket收发真实进程字节；stop/start/destroy遵循生命周期；销毁成果可读且审计有对象关联。取消默认焦点与返回路由由真实浏览器补查。
