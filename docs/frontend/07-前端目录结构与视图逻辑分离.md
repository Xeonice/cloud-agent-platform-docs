## 2. 目录组织（2026-08-25 重构后）

### 2.0 一条组织原则：层优先，层内按功能

`containers/` `hooks/` `lib/` **三层各自按功能分子目录**，与 `views/` 早就有的划分同名：

```
access · project · sandbox · task · terminal · credential · workbench · _shared
```

```
src/
├── app/          路由层（只做布局编排）
├── containers/   ┐
├── hooks/        ├─ 三层都按功能分子目录 + 各自的 __tests__/
├── lib/          ┘
├── views/        纯展示（本来就按功能分）+ 每个功能下 __stories__/
└── services/  stores/  types/  components/ui/
```

**为什么不改成 feature-first**（`src/features/project/{hooks,lib,…}`）：`boundaries` 的元素类型
按目录匹配，feature-first 要重写 10 条 pattern，且每加一个功能都要复核护栏是否仍然生效。
那套护栏（`view` 连 `hook` 都不能碰）是这个仓最值钱的东西之一，**不值得为目录美观去动它**。
层内加一级子目录则一条规则都不用改——`src/hooks/**` 本来就匹配 `src/hooks/project/useProjects.ts`。

**`_shared/` 的判据只有一条**：删掉某个功能，它是否还该留下。
`utils`/`writeBatcher`/`reportError` 是；`projectClone`/`sandboxErrorCopy` 不是。
归属看名字定不了的（`handshakeErrorCopy` / `affectedTasks` / `useFollowOutput`），
**按实际 import 定**：只被一个功能引用就进那个功能。

**测试与 story 分别收进 `__tests__/` 与 `__stories__/`**。此前 `lib/` 22 源 : 21 测、
`views/` 33 view : 34 story，`ls` 出来一半是测试或 story，两边互相淹没——
这正是"Storybook 好像不存在"的由来（它一直都在：`pnpm storybook` 起得来、
34 个 story、a11y+vitest 两个 addon、`check:stories` 硬门禁，只是看不见）。

`vitest` 的 include、`.storybook` 的 stories glob 都用 `**` 跨层匹配，**均未改动**；
唯一跟着改的是 `check-story-coverage.ts`（它按"同目录同名"找 story）与
`eslint.config.js` 里两处**写死了 `src/hooks/useTerminalInstance.ts` 旧路径**的 ignores。

## 3. 分层铁律（与 lint 规则一一对应）

| # | 规则 | lint 落点 |
|---|------|----------|
| 1 | `views/**` 只能 import：React、其他 view、`types/**`、纯 UI 库（shadcn 组件） | boundaries/element-types |
| 2 | `views/**` 禁止 `useEffect`/`useLayoutEffect`/`fetch`/`new WebSocket`；`useState` **不拦**，但拦住会让它不再是「本地 UI 态」的语法：`async` 函数 / `await` / Promise 链（`.then/.catch/.finally`）/ 定时器（`setTimeout`/`setInterval`/`queueMicrotask`/`rAF`/`rIC`）/ 浏览器全局（`window`/`document`/`localStorage`/`sessionStorage`/`navigator`/`history`/`location`）/ `useReducer` / `useSyncExternalStore` | no-restricted-syntax（views 块共 11 条 selector；`__stories__/**` 与 `*.stories.tsx` 走上一档 5 条，因为 story 的 `play` 天然是 async）|
| 3 | `containers/**` 是唯一允许同时 import `views/**` 与 `hooks/**` 的层，本身不写 DOM 操作：禁 `document.*`、禁节点增删改（`innerHTML`/`outerHTML`/`insertAdjacentHTML`/`classList`/`appendChild`/`removeChild`/`replaceChild`/`insertBefore`/`setAttribute`/`removeAttribute`/`createElement`/`createTextNode`）、禁命令式调用（`.focus()`/`.blur()`/`.scrollIntoView()`/`.click()`/`.select()`）。**允许**创建 `ref` 并传给 view 或 hook —— 这正是 `useModalFocus`/`useEscapeKey`/`TerminalMount` 挂 xterm 走的那条边 | boundaries/element-types + no-restricted-syntax（containers 块；`__tests__/**` 除外，测试要造真实 DOM）|
| 4 | `hooks/**` 只能 import `services/**`、`stores/**`、`types/**`、其他 hook，禁止反向依赖 `views/**` | boundaries + no-restricted-imports |
| 5 | `services/**` 是唯一允许出现 `fetch`/`WebSocket`/API 地址 env 读取的地方 | no-restricted-syntax（全局禁 + services 白名单） |
| 6 | `app/**` 只允许 import `containers/**`、`views/**`（布局装配），不直接触达 hooks/services | boundaries/element-types |

> ⚠️ **规则 2 为什么不按「useState 需 eslint-disable + 理由」落地**（2026-09 修订，文档跟随实现的正确性）。
>
> 原文那半句从未有过门禁：`views/` 里裸写 `useState` 一直零报错，全仓 4 处 `eslint-disable`
> 没有一处是它。补的时候发现按字面做是净负收益：
>
> 1. **产出全是噪音**。现存 10 个用 `useState` 的 view（`ProxyConfigForm` / `UnlockForm` /
>    `AllowedHostsEditor` / `SetupTokenAuth` / `ImageCard` / `AutomationDetail` /
>    `RunHistoryList` / `RetainedVolumesPanel` / `NewProjectForm` / `TaskOutputPane`）逐个核过，
>    全是受控表单值、展开/折叠布尔、选中项 id、选中集合 —— 10 条理由会是 10 条
>    「这是受控组件本地态」的同义反复。
> 2. **它挡不住要挡的东西**。`eslint-disable` + 注释是「减速带」不是门禁：真往 view 里塞
>    非 UI 态的人，照样会写「这是受控组件本地态」。规则的判别力为零。
> 3. **它还会开洞**。`views/` 的 `no-restricted-syntax` 是**一条规则装了 11 个 selector**，
>    在 `useState` 那行写 `eslint-disable-next-line no-restricted-syntax`，
>    同行的 `useEffect`/`fetch`/双重断言禁令一并失效。
>
> 所以改成**给「本地 UI 态」一个可机检的判据**：*同步、由用户事件驱动、不依赖宿主环境与外部系统*。
> 凡是需要**等待**（async/await/Promise 链）、需要**计时**（定时器）、来自**宿主环境**
> （`window`/`document`/`localStorage`/…）、或**订阅外部源**（`useReducer` 状态机 /
> `useSyncExternalStore`）的状态，都不是本地 UI 态 —— 直接在语法层拦掉，`useState` 本身放行。
> 这 6 类在落地时对现存 view 源码**命中 0**，纯增量防线；10 处合规 `useState` 一条注释都不用加。
> 真需要例外时仍可 `eslint-disable` + 理由 —— 那才是这个机制该用的地方（罕见例外），
> 而不是 10/10 的既有代码。
>
> 每条规则均以**注入样本**验证过「它红过」：写违规文件 → `pnpm eslint <file>` 变红 → 删除；
> 同时确认 `pnpm lint --max-warnings=0` 对既有代码保持绿。

依赖方向单向流动：

```
app → containers → views
          ↓
        hooks → services
          ↓        ↓
        stores   types
```

## 4. ESLint 强制配置（flat config 思路）

### 4.1 boundaries 层级声明

```js
// eslint.config.js
import boundaries from 'eslint-plugin-boundaries';

export default [
  {
    plugins: { boundaries },
    settings: {
      'boundaries/elements': [
        { type: 'view',      pattern: 'src/views/**' },
        { type: 'container', pattern: 'src/containers/**' },
        { type: 'hook',      pattern: 'src/hooks/**' },
        { type: 'service',   pattern: 'src/services/**' },
        { type: 'store',     pattern: 'src/stores/**' },
        { type: 'type',      pattern: 'src/types/**' },
        { type: 'app',       pattern: 'src/app/**' },
      ],
    },
    rules: {
      'boundaries/element-types': ['error', {
        default: 'disallow',
        rules: [
          { from: 'view',      allow: ['view', 'type'] },
          { from: 'container', allow: ['view', 'hook', 'type', 'store'] },
          { from: 'hook',      allow: ['service', 'store', 'type', 'hook'] },
          { from: 'service',   allow: ['type', 'service'] },
          { from: 'app',       allow: ['container', 'view', 'type'] },
        ],
      }],
      'boundaries/no-private-files': 'error',
      'boundaries/no-unknown-files': 'warn',
    },
  },
];
```

### 4.2 view 层副作用封禁

```js
{
  files: ['src/views/**/*.tsx'],
  rules: {
    'no-restricted-syntax': ['error',
      { selector: "CallExpression[callee.name='useEffect']",
        message: 'views/ 禁止 useEffect，副作用移至 hooks/ 层' },
      { selector: "CallExpression[callee.name='useLayoutEffect']", message: '同上' },
      { selector: "NewExpression[callee.name='WebSocket']", message: 'views/ 禁止直接创建 WebSocket' },
      { selector: "CallExpression[callee.name='fetch']", message: 'views/ 禁止 fetch，走 services/ 层' },
    ],
    'no-restricted-imports': ['error', {
      patterns: [
        { group: ['**/services/**'], message: '视图层禁止依赖 service 层，经 hooks/container 注入' },
        { group: ['**/stores/**'],  message: '视图层禁止读写全局 store，由 container 传 props' },
      ],
    }],
  },
},
{
  files: ['src/hooks/**/*.ts'],
  rules: {
    'no-restricted-imports': ['error', {
      patterns: [{ group: ['**/views/**'], message: 'hooks/ 不应依赖 views/' }],
    }],
  },
},
```

> 📌 上面是**思路示意**，不是现状：真配置在 `web/eslint.config.js`，selector 抽成了共享常量
> （`NO_USEEFFECT` / `VIEW_NO_ASYNC_FN` / `CONTAINER_NO_DOCUMENT` … ）再按块拼接。
> 与本节示意相比多出两块：**view 源码块**（§3 规则 2 的「本地 UI 态」判据，排除 `__stories__`）
> 与 **container 块**（§3 规则 3 的 DOM 禁令，排除 `__tests__`）。

⚠️ 配置注意：ESLint 同名规则是**整体覆盖而非合并**——上面 views 层这份 `no-restricted-syntax` 会覆盖全局配置里的双重断言禁令（文档 14 §4 的 `TSAsExpression > TSAsExpression` selector），因此 views 层的 selector 数组必须把全局条目一并带上，或抽成共享常量数组拼接。

### 4.3 辅助规则

- `react-hooks/exhaustive-deps`: error（逻辑层质量）
- `import/no-cycle`: error（防 container↔hook↔service 环）
- 进阶可选：`eslint-plugin-code-policy`（主张 React 组件不持有 state/effect，逻辑必须在自定义 hook）作为自写 AST 规则的替代

### 4.4 渐进启用策略

新增代码强制 error；若未来引入存量代码，用 grandfather 名单按目录渐进修复：先 `warn` 跑一个迭代观察误报，再切 `error` 进 CI 门禁。CI 侧用 `--max-warnings=0` 确保违规无法以 warning 形式绕过合并（详见文档 09）。

## 5. 状态管理与数据流（概述，完整设计见文档 15）

- **服务端资源**（项目列表、Task 列表、runtime 聚合与鉴权状态、镜像列表）→ TanStack Query；**推送为主、轮询兜底**：WS 事件 `setQueryData` patch 缓存 + 30–60s 低频轮询兜底。
- **纯客户端态** → Zustand（单 store + slices；Terminal 实例注册表持有非可序列化对象，不能进 Query cache）。
- **WS 连接状态归 Zustand，`sandbox.status` 业务状态归 Query**——传输层状态与服务端业务状态是不同维度（论证见文档 15 §4）。
- **分组树是派生数据不是新状态**：左侧树由 `projects` × `sandboxes` 两个 Query 结果在 selector 中派生，不建平行数据结构（文档 15 §5）；只有折叠状态 `taskListFolds` 属于 UI 偏好，落 Zustand + persist。
- **向导暂存**：`wizardReturn` / `wizardData`（确认步「＋ 新建项目…」往返的回填载体）落 uiSlice；其中 `wizardData.initialPrompt` **仅内存、永不进 persist**（可能含敏感上下文，安全红线，文档 15 §3.5）。
- Context 仅用于主题/测试替身注入，不承载业务数据流。
- 状态分类学、query key 工厂、staleTime 分级、WS→缓存 patch 映射表（含 `sandbox.waiting_input` / `project.clone_progress`）、乐观更新、terminal registry 生命周期、selector 规范、persist 策略详见 [文档 15](./15-前端状态管理.md)。

## 6. Runtime 鉴权 UI（拦截面板 + 凭证页内嵌，无独立鉴权页）

> 完整鉴权链路（含后端凭证注入 sandbox）见文档 05；产品语义以 [P20 §5](../product/20-核心使用链路.md) / [P21-2 形态 B](../product/pages/21-2-发起任务向导.md) / [P21-3](../product/pages/21-3-凭证管理.md) 为准；此处只描述前端 UI 层。

### 6.1 形态：鉴权不是页面、也不是向导步骤

**独立鉴权页在 v1.1 前不存在**（原 `/auth/runtime-accounts` 路由已取消）。鉴权 UI 只出现在两个位置，且**复用同一批 view + 同一个 `AuthGateContainer`**：

| 位置 | 触发 | 说明 |
|---|---|---|
| 向导 **无编号拦截面板**（形态 B） | Step 1 选中的 runtime 无生效凭证 / 凭证已过期 | 插在 Step 1 与 Step 2 之间，**不占步骤编号**；配置成功后 2s 自动进确认步，此后永不再现 |
| 凭证管理页 `/settings/credentials` **卡片内嵌** | [立即授权]/[重新授权]/[添加 API Key]/[更换] | 卡片就地展开，不弹新 modal（modal 不堆叠，P20 §8.4） |

### 6.2 三分支均在面板内即时完成（关键约束）

登录流跑在**平台 auth helper**（文档 05 §2 决策 A），**不依赖、不等待、也不创建任何 sandbox**。因此：

- 面板内没有"先选一个 running sandbox 作为登录宿主"的前置步骤——三种方式**均无前置**；
- **阶段进度卡固定 4 步**：初始化 → 拉取镜像 → 准备工作区 → 启动实例，**没有「等待登录」阶段**；凭证注入由后端在「启动实例」阶段完成，用户无感知（P21-2 形态 D）。⚠️ **原文写「5 步」并多出一格「连接终端」，2026-08 订正**：代码 `lib/sandbox/sandboxLifecycle.ts` 的 `STARTUP_PHASES` 只有 4 格，且 `running` **根本不点格**（`classifyStatus('running')` 返回 `'running'`，进度卡就此退出、切去开终端）。产品侧权威（P21 §2.2）写的也是 4 格。21-2 已于上一轮改正，而本文与前端 28 **没有跟着改** —— 一处改对、两处还在说旧话，是本仓反复出现的那种漏传播。

面板顶部是**方式切换 Tab**：「帐号授权（推荐）」/「API Key」，可用方式由 `getAuthMethods()` 下发，默认选中该 runtime 的当前生效模式；Tab 下一句取舍说明"帐号授权使用订阅额度；API key 按量计费、配置最快"。模式名直接取 contract 的 `RuntimeAuthMethod` 值（文档 04 §3），不另造 UI 枚举。

| 分支 | Provider | 前端交互 | 端点 |
|---|---|---|---|
| **A · oauth-device** | Codex（RFC 8628 设备码） | 大字号 userCode + [复制] + 二维码 + [打开验证链接] + 15:00 倒计时（剩 5min 转黄、归零转红 + [重新获取]）+ "等待授权中…"轮询态 + [后台继续] | `POST /api/runtimes/:rt/auth/begin` → 轮询 `GET /api/runtimes/:rt/auth/status` |
| **B · setup-token** | Claude Code | 授权链接 + [打开链接] → code 粘贴框（password 遮罩，[展开查看] 纯前端切换）→ [提交]（提交即清空本地值，**绝不落 localStorage**） | `POST /api/runtimes/:rt/auth/complete { pastedText }` |
| **C · api-key** | 两 runtime 通用 | key 输入框（password 遮罩）→ [保存并继续]；**前端即时前缀校验**（Codex `sk-`、Claude Code `sk-ant-`，不匹配即红边提示）；提交后按钮 loading（后端真实性校验最长约 2s） | `POST /api/runtimes/:rt/credentials/secret { method:'api-key', secret }` |

- **模式二选一、全局生效**：在面板中完成配置的方式即成为该 runtime 的当前生效模式；之后在凭证管理页用 ◉/○ 单选切换 → `PUT /api/runtimes/:rt/auth-mode`（两类凭证可同时留存，切回免重新登录）。
- **失败反馈就地化**：`AUTH_REJECTED` 在面板内红字 + 可能原因列表（格式错误/无权限/额度不足），不弹层；`AUTH_CHALLENGE_EXPIRED` 转红 + [重新获取] 重走 begin；device-code 轮询连续 3 次网络错误 → "网络异常 [重试]"，**不消耗设备码倒计时**（P22 §2）。
- 通用：状态接口只回显掩码标识（`sk-...ab12` 或邮箱）**永不回显明文**；面板卸载/路由离开时 `AbortController` 取消轮询；页脚 [管理所有凭证] 跳凭证管理页（**替换为路由页面，面板数据保留**，不嵌套 modal）。

**统一状态机**：`idle → pending → polling → success / expired / error`，由后端驱动状态，前端只展示 + 轮询。

| `ConfirmConfig.view` | 承载 Runtime/身份行、项目行、模式、任务指令、镜像、▸ 高级选项（隔离等级 / 自定义镜像 URI 仅本次生效 / 运行参数覆盖 + 来源标签 / idle 回收阈值）；确认步可零修改直接 [发起] |
| `CreationProgress.view` | **固定 4 阶段**（⚠️ 原写 5 阶段含「连接终端」，2026-08 订正，见 §2.0 同条）：初始化 → 拉取镜像（含字节进度）→ 准备工作区 → 启动实例；**无登录步**；阶段 >5min 无进展显示"⚠️ 可能卡住"，>10min 出现 [强制停止]；已 ✅ 阶段锁定，仅失败阶段可 [重试] |

#### 8.3.1 环境变量的前端即时提示规则（EnvVarEditor）

| 检查 | 规则 | 提示形态 |
|---|---|---|
| 变量名格式 | `^[A-Za-z_][A-Za-z0-9_]*$`（与 P21-4 §10.4/§10.6 定案同源，**大写是推荐惯例而非强制**） | 不匹配 → 该行 KEY 输入框红边 + 「变量名只能包含字母、数字、下划线，且不能以数字开头」 |
| 大写惯例引导 | placeholder 用大写示例（`LOG_LEVEL`、`CACHE_TTL`）；输入小写**不报错、不自动改写** | 仅 placeholder 引导，无警告——避免把"惯例"误伤成"错误" |
| 保留变量名黑名单 | 命中 `ANTHROPIC_API_KEY` / `CLAUDE_CODE_OAUTH_TOKEN` / `OPENAI_API_KEY` / `CODEX_*` / `GIT_*` 等（清单见 P21-4 §10.6） | 红边 + 「该变量名为系统保留，请使用凭证管理配置」，**该行禁止保存** |
| 长度与数量上限 | KEY ≤64 字符、VALUE ≤4096 字符、每镜像 ≤50 条 | 就地字符计数转红；条数到顶时 [+ 添加变量] 置灰并提示上限 |
| 重复 KEY | 同一镜像内 KEY 重复 | 两行同时红边 + 「变量名重复」 |

三条纪律：① **黑名单与正则的清单常量从 contract/生成类型取，不在 view 里硬编码字面量**（后端调整清单时前端不需要改代码）；② 校验是**逻辑**，实现放 `lib/validateEnvVar.ts` 纯函数 + hook 调用，`EnvVarEditor.view` 只接收 `errors` 并渲染（分层铁律 §3 规则 1–2），该纯函数是 bun test 主战场（文档 12 §3.2）；③ 前端提示**永不放宽后端**——后端拒绝时仍按 P22 §1 就地显示人话原因。

### 8.4 全局横幅优先级系统（BannerStack + useGlobalBanner）

多条横幅同时命中时的唯一权威规则（P21-1 §9）：

| 级别 | 例子 | 行为 |
|---|---|---|
| 🔴 **阻断类** | 离线模式、运行时无响应 | 最高优先级，**不自动收起**，须显式关闭 |
| ⚠️ **治理类** | 凭证过期/即将过期、自动化规则失败 | **可堆叠最多 2 条** + 「还有 N 条」折叠；**不自动收起**，须显式关闭且**当天不再弹** |
| ℹ️ **提示类** | 一般成功/信息提示 | **5s 自动收起** |

排序与收起策略是**逻辑**，归 `hooks/useGlobalBanner.ts`；`BannerStack.view` 只接收已排好序、已裁剪到 2 条的数组 + `collapsedCount`，自身不做优先级判断（分层铁律 §3 规则 1–2）。"当天不再弹"的抑制记录属 UI 偏好，落 Zustand + persist。
