### 1.1 shadcn/ui 与主题

主题入口是 `src/app/globals.css` 与 `src/app/design-tokens.css`，组件位于 `src/components/ui/`。`web/components.json` 保留 shadcn 配置；实际组件源码已入仓，行为以这些文件为准。

`button`、`dialog`、`dropdown-menu`、`input`、`label`、`switch`、`radio-group`、`accordion`、`tooltip`、`skeleton`、`separator`、`card`、`badge`、`progress` 是现有原语。`status-pill`、`outcome-icon`、`terminal-frame`、`blocking-dialog` 是现有组合组件。业务普通对话框还可使用 `views/common/AppDialog.view.tsx`；初始化阻断壳使用 `BlockingDialog`，两者的关闭语义不同。

暗色是出厂默认值；用户可选暗色、亮色、跟随系统。根 `layout.tsx` 在首帧前读取持久化主题偏好，`useTheme` 负责后续同步；终端画布保持自己的主题约束。`ToastsContainer` 在根 Provider 下挂载 sonner，主题切换与全局轻提示都已接入。组件 story 位于对应 `__stories__/`，当前验收框架见文档 12。

### 2.0 一条组织原则：层优先，层内按功能

`containers/`、`hooks/`、`lib/`、`views/` 各自在层内按功能归类。实际目录包含 `_shared`、access、audit、automation、banner、credential、image、init、project、sandbox、settings、system、task、terminal、workbench；各层只创建自己需要的功能目录，并不要求每层都有完整同名集合。

```text
src/
├── app/          路由、根 Provider 与布局装配
├── containers/   view 与 hooks 的装配
├── hooks/        取数、订阅、状态机、焦点及业务流程
├── lib/          纯映射、校验、格式化与可注入的浏览器动作
├── views/        props 驱动的展示与同步本地 UI 态
├── services/     REST / SSE / WS 外部边界
├── stores/       单一 useAppStore 的六个 slices
├── types/        生成契约与前端投影类型
├── acceptance/   独立验收入口及 support
└── components/ui/  共享 UI 原语
```

`_shared` 只放删除某个领域后仍需要保留的工具。领域规则放对应领域目录，例如环境变量预检在 `lib/image/validateEnvVar.ts`，任务筛选在 `lib/project/filterTaskTree.ts`。生产依赖方向不因目录整理改变；story 留在对应 `__stories__/`，新验收放 `src/acceptance/`，不把已退役的旧测试目录写成现行测试入口。

## 3. 分层铁律（与 lint 规则一一对应）

| 层 | 允许的生产依赖 | 行为边界 |
|---|---|---|
| app | container、view、type、component | 路由和布局编排；`providers.tsx` 另有显式 mock 引导例外 |
| container | view、hook、type、store、component | 装配 props/回调；可持有 ref 和短生命周期表单值；不直接做 DOM 操作 |
| view | view、type、component | 同步、本地、由用户事件驱动的 UI 态；禁止 IO、环境访问、计时与外部订阅 |
| hook | service、store、type、hook、lib | 业务状态机、Query、订阅、副作用、DOM 焦点与流程整合 |
| service | service、type、lib | REST/SSE/WS 协议边界、错误信封与反序列化 |
| store | store、type、lib | 数据投影与记账 action；不负责网络流程 |
| lib | lib、type | 纯函数或显式注入依赖的动作，不反向依赖 React 展示 |

`views` 禁 `useEffect` / `useLayoutEffect`、async/await/Promise 链、定时器、浏览器全局、`useReducer`、`useSyncExternalStore`、fetch、WebSocket。`useState` 可承载受控输入、展开、选择等同步本地 UI 状态；业务流程仍归 hook。

`containers` 禁直接查询/增删改 DOM 及 `.focus()` / `.blur()` / `.scrollIntoView()` 等命令式操作。DOM/ref 可作为参数交给 `useModalFocus`、`useReturnFocus`、`useWorkbenchObjectFocus` 等 hook。`@xterm/*` 的唯一生产 import 点为 `hooks/terminal/useTerminalInstance.ts`。

```text
app → containers → views → components
           ↓
         hooks → services
           ↓        ↓
         stores    lib/types
```

实际完整规则以 `web/eslint.config.js` 为准，测试与 story 的专门规则不扩大生产依赖边界。

## 4. ESLint 强制配置（flat config 思路）

当前采用 flat config：`web/eslint.config.js` 同时声明层级、类型规则、React Hooks 规则、DOM/IO 禁令以及测试/story 例外。下面给出配置的读法；修改边界应同步本节与文档 12 的门禁。

### 4.1 boundaries 层级声明

`boundaries/elements` 匹配 app、container、view、hook、service、store、type、lib、component、mock 十类目录。`boundaries/element-types` 以 `default: 'disallow'` 限制生产依赖，允许集合见 §3。

当前 `boundaries/no-private-files` 与 `boundaries/no-unknown-files` 均为 `off`；不把它们写成已启用的 error/warn。`app/providers.tsx` 的 app→mock 例外仅承接 `NEXT_PUBLIC_API_MOCK=1` 的显式浏览器替身引导；常规页面不依赖 mock。

### 4.2 view 层副作用封禁

view 的限制由共享 AST selector 组合，不复制一份容易漂移的示例配置。通用 view 块检查 effect、fetch/WebSocket 与双重断言；生产 view 块再禁止 async/await/Promise、计时器、浏览器全局、外部订阅和 reducer。story 的 `play` 可以使用 async 与真实 DOM 操作，按独立配置处理。

container 块禁止命令式 DOM，hook 块禁止反向 import view。ESLint 同名规则会整体覆盖；新增局部 `no-restricted-syntax` 配置必须保留该块原有 selector，不能借局部覆盖移除通用防线。

### 4.3 辅助规则

`react-hooks/rules-of-hooks` 与 `react-hooks/exhaustive-deps` 为 error，类型规则限制未经校验的边界值、双重断言和不安全访问。当前配置没有启用 `import/no-cycle`；环路约束主要来自单向层级与类型检查，不将计划规则写为已执行门禁。

### 4.4 渐进启用策略

当前生产层级规则统一以 error 执行，不靠虚构的存量祖父名单放行。新增例外必须具体到文件和用途，保留其他规则；先用真实违规样本确认规则会报错，再跑当前 lint 和类型门禁。命令与验收配置见文档 12，不将已退役测试作为新增例外的依据。

## 5. 状态管理与数据流（概述，完整设计见文档 15）

REST 项目、任务、runtime、镜像、系统资源、成果和规则使用 TanStack Query。`/events` 由根 `AppFrameContainer` 持久订阅：生命周期/克隆/启动子进度先写 Zustand 内存投影，再由调用方失效相关 REST Query；读取中的旧 REST 不能覆盖后到的 WS 生命周期帧。当前任务列表没有固定45秒轮询，恢复来自事件、重连重取和 Query 的挂载/聚焦策略；系统资源和环境看板单独30秒轮询。

UI 选中、弹层指向和偏好归 uiSlice；终端实例、标签、口令锁、沙箱状态与克隆进度分别归各 slice。树是 `projects × tasks × folds × filter` 的派生输出，不另存一份树。认证挑战由 `useRuntimeAuthFlow` 的 reducer/ref 及定时轮询持有，不存到 Query session 或 Zustand。

新任务表单与新项目表单彼此独立，没有 `wizardReturn` / `wizardData`。指令、粘贴码、API key、输出与终端会话凭据不进入前端持久化；11项白名单与字段语义见 [文档 15 §3.5](./15-前端状态管理.md#35-persist-策略)。

## 6. Runtime 鉴权 UI（拦截面板 + 凭证页内嵌，无独立鉴权页）

鉴权运行在平台 auth helper，不借任务沙箱完成。三宿主共用 `AuthGateContainer` 和 `useRuntimeAuthPanel`，但授权会话必须由用户明确开始；流程权威见 [CRD](../product/requirements/CRD.md) 和 [DEP](../product/requirements/DEP.md)。

### 6.1 形态：鉴权不是独立页面；三个宿主共用一套面板

| 宿主 | 展开入口 | 实际行为 |
|---|---|---|
| 新任务单表单内，`SandboxTerminalContainer` | 所选 runtime 无可用凭证时点配置入口 | 就地展示鉴权面板；配置成功后保留原表单，不跳虚构确认步 |
| 凭证管理，`CredentialsContainer` | 点帐号/API Key 对应配置入口 | 当前卡片内展开；可携带 `activateOnSuccess`，成功后按意图切生效模式 |
| 初始化向导，`InitWizardContainer` | 凭证配置步骤内点 runtime 入口 | 占初始化流程自身步骤编号，复用同一面板 |

服务端凭证状态决定能否发起任务，`useRuntimeAuthPanel.target` 决定面板是否在场。展开或切 runtime 本身不调用 begin；帐号分支先处于 idle，用户点 [开始帐号登录] 才申请挑战。切 Tab、收起或卸载会清理/取消在途授权，已卸载后晚到的 begin 响应也会取消其挑战。

授权成功由 `useRuntimeAuthCompletion` 补取权威 runtime 状态、按意图切模式，并在成功展示窗口结束后通知宿主；刷新失败保留 [重试]，不把凭证已保存误当整个流程完成。

### 6.2 三分支均在面板内即时完成（关键约束）

| 分支 | 交互与状态 | 外部调用 |
|---|---|---|
| oauth-device | 显式开始后显示设备码、复制、授权页入口；无二维码。倒计时来自 challenge.expiresAt，缺席时不画倒计时，不固定15:00 | begin 后用 challengeRef 轮询 status |
| setup-token | 显式开始后显示授权链接与回贴输入；也轮询 status，兼容浏览器回调直接完成；回贴提交即清空 | begin / status / complete |
| api-key（或声明的粘贴方式） | 本地遮罩输入；格式提示来自 runtime 的 apiKeyPrefix，缺席不猜；提交即清空，真实性由后端判断 | credentials/secret |

挑战与轮询由 `useRuntimeAuthFlow` 驱动：轮询间隔3秒，连续网络失败显示就地重试；到期与客户端10分钟等待上限分开描述，后者不谎称设备码已过期。任务创建阶段由 `SandboxStartupProgress.view` 展示四阶段，不包含登录阶段。

`AuthGateContainer` 只持有本次粘贴码/key；切方式以组件 key 重挂清空。三分支的状态是各自的判别联合，不能用单个通用 `idle → pending → success` 列表替代真实分支状态机。

### 6.2a 分支 A 的新标签页：三条约束都是踩得到的坑（v1.2）

1. **先明确开始，再同步打开链接**。点 [开始帐号登录] 获取挑战后，用户再点 [打开授权页]；后一 click 直接交给 `useOpenAuthPage`，在任何 await 前同步 `window.open`，随后才异步复制设备码。展开面板不是启动授权的替代动作。
2. **打开失败与复制失败分别表达**。新标签页使用 `noopener,noreferrer`；返回 null 时原位显示手动链接。剪贴板失败不阻止链接打开，设备码和复制入口仍可用。
3. **结果由平台 status 轮询取得**。不依赖授权站与本页的跨源 storage/BroadcastChannel 回调；切方式/卸载取消挑战，客户端等待上限与真实过期原因分别显示。

可注入浏览器动作在 `lib/credential/openAuthPage.ts`，hook 保存 `popupBlocked` 与 `codeCopied`，view 只渲染这些结果与回调。

### 6.3 端点表（与文档 05 §3 一一对应，前端不自造路径）

实际调用集中于 `services/api/runtime.service.ts`，wire 类型来自生成契约。

| 用途 | 端点 |
|---|---|
| runtime 聚合 / 权威凭证状态 | `GET /api/runtimes`、`GET /api/runtimes/:rt/auth/status` |

| 提交回贴 code | `POST /api/runtimes/:rt/auth/complete` |

| 切换模式 | `PUT /api/runtimes/:rt/auth-mode` |

这些鉴权端点没有 sandboxId 维度。成功/取消/吊销的刷新使用真实 Query key，见文档 15 §2.1。

### 6.4 扩展位与分层落地

| 层 | 实际文件 | 职责 |
|---|---|---|

runtime 名称、厂商、authMethods、apiKeyPrefix 均由 runtime DTO 提供，宿主透传；不在 view/container 另造一份 provider 能力表。

## 7. 路由与页面骨架

根布局是 `Providers → AppBootGate → AppFrameContainer → 页面children`。首次初始化未完成时由 gate 展示初始化向导；正常放行后所有页面共用同一应用框架。口令未授权先进入全局解锁门。

### 7.1 路由表

| 路由 | 当前承接 |
|---|---|
| `/` | 项目总览、所选项目克隆/恢复或所选任务主区；新建和项目管理弹层在该页装配 |
| `/?taskId=<id>` | `useWorkbenchRoute` 拉真实任务后恢复项目/任务；404清掉无效指向并显示原因 |
| `/?new=1&project=<id>` | `NewTaskDeepLinkContainer` 在项目选择之上消费；ready项目打开新任务单表单 |
| `/settings/credentials` | Runtime/Git 凭证管理 |
| `/settings/images` | 镜像管理；`?filter=warning` 或任务来源参数由镜像hook消费 |
| `/settings/system` | 系统看板、诊断、审计、同页成果清理宿主 |
| 其他路径 | `not-found.tsx` 的真实恢复界面 |

没有 `/new` 或可选 BFF `app/api` 路由。新任务深链只承载开关和项目，不带指令/key；项目列表未取得权威结果时保留参数，避免401误删有效深链。普通打开会写入这两个query，关闭仅删它们；popstate同步前进/后退。刷新深链会重新承接打开，但本次表单内容不持久化。

### 7.2 SettingsLayout（`app/settings/layout.tsx`）

设置的三个独立子路由只替换主列内容。`AppFrameContainer` 位于根layout，保留相同sidebar DOM、选中上下文、项目分组与 `/events` 订阅；设置页不另画一个隐藏工作台树的设置侧栏。

`app/settings/layout.tsx` 读 pathname 后向 `SettingsLayoutView` 传宽度和标题，使用 `hideHeader`，因为56px页头由共享AppFrame提供。凭证页使用form宽度，镜像/系统使用wide主区。设置导航、项目菜单、查找、主题、快捷键、收起侧栏与新建项目入口都在共享sidebar。

### 7.3 项目管理没有独立路由

项目创建是 `NewProjectContainer + NewProjectForm.view` 的独立AppDialog，入口来自sidebar项目区新建按钮、总览和全局查找；不在新任务表单嵌套新项目弹层。项目组菜单通过 `ProjectGroupMenu.view` 平铺详情、成果、自动化、删除与克隆恢复出口。

菜单指向用 `selectedProjectForMenu`，打开B菜单不切换当前A工作上下文。导航型入口在任意页可返回 `/` 装配同一个项目/规则对话框；系统页成果清理由该页宿主保持原页。删除、成果清理等确认在同一dialog内切换，不叠加第二层modal。

## 8. 组件层规格（产品定稿落点）

本节给出迁移后的真实组件落点。产品细节分别见仓内产品规则 WB、LCH、PRJ、IMG、AUT、SYS；组件索引见 §2.1，状态细节见文档15。

### 8.1 左侧栏：ProjectTaskTree（取代 SandboxList）+ CurrentProjectIndicator（取代 ProjectSwitcher）

本节保留旧标题锚点；树当前由 `AppSidebar.view.tsx` 展示，不存在 `ProjectTaskTree.view`。

| 能力 | 实际落点与口径 |
|---|---|
| 项目分组与任务行 | AppSidebar接收 `useProjectTaskTree` 输出；全部项目由共享AppFrame取数 |
| 组头与项目菜单 | ProjectGroupHeader / ProjectGroupMenu；持久化折叠，菜单目标与当前工作项目分离 |
| 克隆/失败 | 组头标状态；主区 ProjectCloneContainer / ProjectRecoveryContainer 显示进度与恢复出口 |
| 空项目与新建 | AppSidebar组内发起CTA、项目区新建按钮；总览也有入口 |
| 等待输入 | 任务导航计数与行标记；跨全项目统计，不随折叠、搜索或筛选变小 |
| 状态过滤 | AppSidebar状态菜单和移除chip；对所有项目任务计算，空匹配组不渲染，未展开组也参与 |
| 搜索 | taskSearch与状态AND过滤任务名；全局Find由CommandPalette另行检索项目/任务/动作 |
| 项目指示器 | ProjectInfoContainer / CurrentProjectIndicator的项目chip及信息内容；与组头管理入口分工 |

当前菜单顺序为全部、准备中、运行中、等待输入、已停止、异常；domain仍保留paused类型及纯函数分支，但没有当前菜单选项。任务显示由后端主状态与waitingInput/操作进度投影得到；不要把展示标签当后端状态回写。

### 8.2 向导组件（modal 四形态）

本节保留历史标题锚点；新任务实际为**单表单dialog**，不是Step1/Step2向导。`SandboxTerminalContainer` 持有项目、runtime、镜像、分支与任务指令草稿，向 `NewSandboxPanel.view` 传入模型与动作。任务名由服务端根据指令派生，表单不另设名字输入。

项目选择只允许ready项目；总览发起时可未选项目，必须先明确项目。镜像由 `useLaunchImages` 按runtime/provider能力过滤并读取provider默认；警告级可选并显示后果，不可用时给原因和镜像页出口。指令可选、8000字符上限，仅内存与创建请求。镜像运行参数按manifest版本锁定，当前创建表单和CreateSandboxDto没有任务级env/资源覆盖入口。

无凭证时就地给配置入口并阻止发起，用户明确开始登录后才创建挑战。创建成功立即进入真实任务视图；`SandboxLifecycleContainer + SandboxStartupProgress.view` 展示初始化、拉取镜像、准备代码副本、启动实例四阶段及真实进度，REST恢复不能编造进入阶段时刻。项目新建与任务新建彼此独立，没有向导往返数据载体。

### 8.3 设置页组件

| 页面 | 当前组件与动作 |
|---|---|
| 凭证 | CredentialsContainer / GitCredentialsContainer；RuntimeCredentialCard、GitCredentialCard，行内AuthGate、吊销预检和同dialog确认 |
| 镜像 | ImagesContainer；ImageCard、RegisterImageModal、ValidationResult、版本历史、参数编辑、删除预检；网络失败与无效结论分开，修改URI清掉旧结论 |
| 系统 | SystemStatusContainer；资源、环境、连接、代理、诊断卡；AuditStreamContainer独立审计流；ProviderLogPanel点开才取日志 |

镜像注册是 `currentModal='registerImage'` 的dialog，打开聚焦URI，失败保留输入并可重试；保存成功刷新同域列表。环境变量本地草稿与来源/掩码分开，已存secret不写入DOM，空值代表保持既有secret而非泄露明文。

#### 8.3.1 环境变量的前端即时提示规则（EnvVarEditor）

前端预检唯一入口为 `lib/image/validateEnvVar.ts`，由hook计算，EnvVarEditor只接errors和计数。

| 检查 | 当前规则 |
|---|---|
| KEY | ASCII `^[A-Za-z_][A-Za-z0-9_]*$`，最多64字符；空新行先不标名字错误 |
| VALUE | UTF-8最多4096**字节**，用TextEncoder计数；不是4096字符 |
| 重复 | 大小写敏感，两个同名行同时报ENV_DUPLICATE_KEY |
| 保留名 | 真实保留列表与CODEX_/GIT_前缀；含HOME、PATH、凭证及配置重定向变量 |
| 条数 | 最多50；到上限添加入口仍可聚焦但aria-disabled，不执行添加 |
| 错误映射 | details[].code/path的ENV_NAME_INVALID / ENV_NAME_RESERVED / ENV_DUPLICATE_KEY / ENV_LIMIT_EXCEEDED；后端仍作最终校验 |

secret草稿只保留本次编辑值，已存secret显示掩码/占位而不回显原值；修改/取消/失败按本地草稿与服务器快照分开处理。

### 8.4 全局横幅优先级系统（BannerStack + useGlobalBanner）

`GlobalBannerContainer` 挂在AppFrame主列顶部，使用 `hooks/system/useGlobalBanner.ts` 与 `lib/system/globalBanner.ts` 产出；`BannerStack.view` 接已排序/裁剪的模型。

| 类型 | 当前规则 |
|---|---|
| 阻断 | 平台状态未知、确证离线；优先显示；关闭为会话内抑制，条件消失后回收，下一次再触发可出现 |
| 治理 | 磁盘/成果压力、凭证登录到期、跨项目规则自动停用或降级；按首次出现稳定排序，显式关闭写当天抑制 |
| 堆叠 | 全栈最多2条，剩余用溢出说明；关闭一条补下一条；每条抑制独立 |

自动化关注由跨项目GET attention取得，挂载/返回前台/路由变化及规则动作后刷新；读不到不编造提示，链接点名所属项目。资源与初始化/诊断各用其权威缓存；未知网络结果不等于离线。凭证页不重复本页已有的凭证治理横幅。当前横幅没有信息类5秒自动关闭；一般成功反馈由sonner另行承担。
