# P21-6 · 项目管理（左侧任务树 + 顶部指示器 + 弹层，无独立页面）

> 状态：✅ 可评审 · 上级：[P21 总览](../21-页面信息架构与交互.md) · 概念模型见 [P20 §0](../20-核心使用链路.md)

## 1. 职责与形态决策

**Project = 工作区（git repo 或空目录）+ Task 集合的容器**；Task 仍是第一概念，Project 是分组与共享上下文。管理形态采用**轻量化**：无独立 `/projects` 页面——**顶部当前项目指示器**（只读，点击在左侧树定位展开）+ 左侧任务树（分组承担项目浏览/切换）+ 树底 [＋ 新建项目] + 树组头「⋯」项目菜单侧弹层（项目职能少：名称/状态，用户不会频繁编辑；项目多或功能扩展后再升级独立页）。

## 2. 进入方式

左侧任务树（组头/树底 [＋ 新建项目]/组头「⋯」菜单，常驻）；确认步项目行「＋ 新建项目…」；Cmd+K → "切换项目 / 创建项目"；首次进入的欢迎态引导（§5）。

## 3. 布局与信息层级

### 3.1 顶部当前项目指示器与左侧任务树（原顶部切换器下拉已由树取代）

```
┌─ 工作台顶栏 ──────────────────────────────────┐
│ Logo  【📁 ProjectA】(只读指示器)  cmdk  横幅位 │
└──────────────┬───────────────────────────────┘
               ▼ 点击 = 在左侧树中定位并展开该组（无下拉）

┌─ 左侧任务树（项目浏览/切换的唯一主入口）────────────────┐
│ ▾ 📁 ProjectA (3) 🟢2 ⋯  ← 当前项目高亮+⋯菜单          │
│    ● Task-001 …                                       │
│ ▸ 📁 ProjectB (1)         ← 点组头/任务即切换          │
│ ▸ 📁 ProjectC (0) ⏸️归档   ← 归档淡显（v1.1）           │
│ 🔴 📁 ProjectD ⚠️克隆失败 ⋯ ← 失败态，组头菜单可处置    │
│    点击展开 → [重试克隆]/[改为空项目]/[删除]            │
│ ────────────                                          │
│ [＋ 新建项目]              ← 树底常驻入口               │
└─────────────────────────────────────────────────────┘
```

### 3.2 创建项目弹层（两种来源）

```
┌─ 创建项目 ────────────────────────────────┐
│ 项目名称: [________________]（1–40 字符，   │
│           禁止重名，项目上限 50 个）        │
│ 来源:                                     │

│       （凭证管理 → Git 凭证，21-3 §10）      │

└───────────────────────────────────────────┘

```

### 3.3 项目菜单（管理当前项目，侧弹层）

```
┌─ 项目菜单 ────────────────────────┐
│ ProjectA                          │
│ 任务数: 5  创建时间: 2024-08-01  │
├──────────────────────────────────┤
│ [重命名]  [归档]  [删除]          │
│ ⚙️ [自动化规则]（v1.1）           │
│ 🎁 [已保留卷]（管理成果，v1.1）   │
└──────────────────────────────────┘
```

菜单项说明：
- **自动化规则**：定时任务规则（Task 级prompt + 调度 + webhook 通知）
- **已保留卷**：Task 销毁时选择保留的工作区卷（可查看/下载/删除，决策 2）

## 4. 状态矩阵

| 状态 | 判定 | 用户看到 |
|---|---|---|
| 无任何项目（冷启动） | projects 空 | 欢迎态建项目引导（§5），顶部指示器显示"未选择项目"（不可点击） |
| 正常 | 有项目且选中 | 顶部指示器显示当前项目名；任务树该组高亮展开 |
| 克隆中 | 创建 mutation 进行 | 弹层进度态；完成自动选中新项目 |
| 克隆失败·网络/URL | url 无效/网络/仓库不存在 | 就地红字"仓库不可访问：检查 URL 或网络" + [重试] / [改为空项目] |
| 克隆失败·权限（401/403） | 私有仓库无凭证或凭证无权 | 就地引导"[配置 Git 凭证]" → 跳凭证管理 Git 分区（21-3 §10）→ 配置完成回弹层 [重试克隆] |
| **已失败项目（cloneStatus=failed）** | **克隆失败持久留存** | **树组头显示**：`🔴 📁 ProjectName ⚠️ 克隆失败 ⋯`（红点标记、失败标文案、菜单按钮）；**点击组头展开**；**组头菜单入口**（⋯）显示 [重试克隆] / [改为空项目] / [删除]；**计入项目上限 50**（占用名额但无法切换或发起 Task）；**无法选为当前项目**（点任务无效，组头点击仅展开，不切换） |
| 归档项目（v1.1） | status=archived | 下拉底部淡显；选中后工作台只读（不能发起新 Task） |

## 5. 首次进入引导（接管 P20 §2.1 欢迎态第一步）

```
欢迎使用 —— 第一步：为你的代码建一个项目
  [📦 用我的代码库]（输入 git URL 克隆）
  [📄 开一个空项目]（快速开始）
     ↓ 项目就绪，自动选中
  第二步：发起第一个任务 →（向导，继承项目上下文）
```

新用户先建立"项目"心智（先有代码库、再跑 agent），比直接面对 Task 抽象更符合开发者直觉。

## 6. 交互细节

| 交互 | 行为 |
|---|---|
| 切换项目 | **左侧树内点击**该项目组头/任务 → 正常项目切换、该组展开；右侧终端切到所点任务；顶部指示器同步；selectedProjectId persist；**failed 项目组头点击仅展开，不切换 currentProjectId**（无法选为当前项目） |
| 创建项目 | 弹层 → git clone（后端异步，进度推送；>10min 提示「仓库较大或网络缓慢 [继续等待]/[取消]」，**30min 硬超时终止转失败**）/ 空项目即时 → 成功自动选中 + toast；**失败项目即刻显示在树中**（弹层关闭后仍可见）|
| 点击 failed 项目组头 | 展开/折叠 Task 列表（如有关联 Task）；**不切换 currentProjectId**（组头文案"⚠️ 克隆失败"提示不可用）；右侧保持原选中项目的终端 |
| [重试克隆]（组头菜单） | 仅 failed 项目可用；重新触发后端 clone（进度同 §6）；成功则转正常状态，failed 态消去；**失败仍保留 failed 态**（可多次重试，每次更新失败原因） |
| **[改为空项目]**（组头菜单） | **放弃对该项目的克隆，转为空项目继续使用**（语义：认可项目 ID/已关联 Task，仅工作区变空）；点击后：① 项目 source 改为 `empty`；② 工作区转为空目录；③ cloneStatus 转 `ready`；④ 组头红点标记消失；⑤ 项目恢复正常态，后续可在该项目内继续发起 Task；⑥ 无需刷新，列表即时更新 |
| [删除项目]（组头菜单） | 失败项目点击 [删除]：二次确认"将删除该项目及其 N 个关联 Task"（无 running task，因 failed 项目无法发起新 Task）；级联销毁项目记录 + 工作区（若有 Task 则一并删除） |
| 组头「⋯」菜单（failed 项目） | **常驻三个出口**：[重试克隆] / [改为空项目] / [删除]；弹层关闭后用户**只能从这里再次处置失败项目**（无其他路径） |

## 7. 数据依赖

`['projects','list']`（GET /api/projects，含各项目 Task 数聚合）· `POST /api/projects`（克隆进度经 WS 事件）· `DELETE /api/projects/:id` · Task 列表 query 变为 `['sandboxes','list',{projectId}]`。

## 8. 退出路径

下拉收起回工作台；创建成功自动回工作台并选中新项目。

## 9. 边界规则

- **工作区隔离（混合方案）**：MVP 默认**每个 Task 独立副本**（创建时 clone/复制项目工作区到专属卷——agent 大量改文件，共享卷并发写是灾难）；"协作共享卷"作为项目级开关 v1.1 提供。
- **成果处理**：MVP 仅"Task 销毁时询问是否保留工作区卷"（保留的卷在项目菜单可见）；diff 导出 v1.1、git push 汇回 v1.5。
- MVP 支持**公开仓库、私有仓库（经全局 Git 凭证，21-3 §10）与空项目**——私有化部署前提下企业内网 git 基本是私有仓，故 Git 凭证随 MVP 提供；per-project 独立凭证 v1.1 再评估。
- 项目删除是唯一的级联破坏性操作，确认文案必须列出受影响 Task 数。
- 凭证/镜像与项目**无关**（保持全局），项目级默认 runtime 仅作向导预选优化（v1.5）。
- **项目上限 50 达到时的 UI**：`[＋ 新建项目]` 按钮**置灰** + tooltip「已达 50 个项目上限，请先删除部分项目」；failed 项目也计入名额（占用但无法用）。
- **「未命名项目 N」编号规则**：
  - 新建自动命名为「未命名项目 N」（取历史最大 N+1，**不复用已删除的号**）
  - 原因：避免与已删除项目的保留卷、成果 diff、历史日志的旧引用混淆
  - 用户可经组头菜单改名后覆盖
- **归档项目的只读范围**：
  - **不能操作**：发起新 Task、改项目配置（重命名 v1.1、自动化规则）
  - **可查看/回放**：已有 Task 终端历史只读回放、成果卷查看、运行历史
  - **可恢复**：[解档] 按钮回复原状态、权限复原
- **空项目一键创建的命名规则**：欢迎态 [开空项目] 一键路径自动命名「未命名项目 N」，创建后可经组头「⋯」菜单改名（重命名 v1.1）（与 §3.2 弹层的名称必填不矛盾——一键路径跳过弹层）。
- **clone 失败项目的完整生命周期**：（1）创建项目时 URL clone 失败 30min 硬超时后转 failed 态；（2）弹层就地显示红字 + [重试] / [改为空项目]；（3）弹层关闭后项目**持久留在左侧树**，组头显示 🔴 + "⚠️ 克隆失败"标文案 + 菜单按钮；（4）**无法选为当前项目**（组头点击仅展开，不切换）；（5）**占用项目上限 50 名额**（但无法发起 Task）；（6）处置入口仅组头菜单 [重试克隆] / [改为空项目] / [删除]（无其他路径），防止"点不动也删不掉"的死角；（7）[重试克隆] 可多次，每次失败更新失败原因；（8）[改为空项目] 即时转 `ready` 态（既有枚举 cloning/ready/failed，非 success），消失红标记。
