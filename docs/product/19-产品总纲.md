## 1. 产品定位与价值主张

**一句话定位**：一个零用户体系、开箱即用的 Agent 任务运行中心——用户进来**发起 Task**（选一个 agent runtime、让它在隔离沙箱里干活），凭证登录一次全局复用。

**解决什么问题（差异化）**

| 现状 | 痛点 | 本平台 |
|---|---|---|
| 手动本机跑 codex/claude code | 凭证反复配置、无法并发多实例、无集中状态观察 | 凭证一次登录全局复用（Vault）、并发调度、统一控制面板 |
| 云厂商 Sandbox 服务 | 需云帐号与成本管理、集成官方 CLI 困难、订阅凭证需交给第三方 | 单机自托管零成本起步；凭证不出本机；OCI 镜像直接注册 |

**核心价值**：
1. **零成本起步**：docker-compose 单机拉起。
2. **安全的凭证管理**：后端不触碰用户密码——"容器内 CLI 交互 + 用户自己浏览器授权"（技术 05 §2）。
3. **两档隔离**：`aio` 容器（默认，开箱即用 agent 工作环境）/ `boxlite` micro-VM（独立内核强隔离）（技术 04 §2.1）。
4. **集中可观测**：所有 Task 的生命周期、终端、鉴权状态一个界面。
5. **渐进扩展**：provider/runtime/镜像三层可注册（镜像层随镜像管理切片落地）；多节点、用户体系路径已预留。

**产品边界（明确不做/明确说清）**：用户认证体系（无帐号/角色；MVP 即提供轻量访问口令 + 默认监听 127.0.0.1 作第一道防护，审计 P0-3；完整多用户体系 v2 前不做）、云供应商代理、镜像构建服务、Agent 任务流持久化编排（归上层 MCP 消费端）。**私有化部署是一等公民**（数据/代码/凭证不出本机），但 **Agent 需能出网访问 OpenAI/Anthropic API——不支持完全离线运行 Agent**（物理约束，见 pages/21-8 §1）。

## 2. 目标用户与画像

| | ① 个人开发者 | ② 团队平台工程师 | ③ 上层 Agent 应用开发者 | ④ SaaS 运营方（远期） |
|---|---|---|---|---|
| 场景 | 本地并发跑多个 agent 做批量任务 | 10–50 人团队共享运行中心 | 通过 MCP 程序化调度 | 多租户运营 |
| 技术水平 | 中高（会 Docker/API） | 高（K8s/Docker 经验） | 高（会写 MCP client） | 中高 |
| 使用形态 | 日均 5–10 次，单次 10–30min | 20–50 活跃 sandbox | 程序化高频、无人工干预 | 多租户高并发 |
| 核心诉求 | 快启动、并发、凭证自动注入、实时终端 | 公平调度、审计、团队镜像、多节点预留 | MCP 稳定性、幂等、错误码、事件推送 | 隔离计费、水平扩展（仅架构预留） |

MVP 以①③为主要服务对象；②是 v1.x 目标；④只做预留不做承诺。

## 3. 功能分级（MoSCoW）与 MVP 切割线

### MUST（v1.0 / MVP）
- **Project 容器**：创建（git clone **含私有仓** / 空项目，入口=树底/确认步项目行）、左侧分组任务树（切换/折叠/⋯管理菜单）+ 顶部当前项目指示器、删除（级联确认）；Task 挂靠项目、发起时继承项目上下文；工作区默认**每 Task 独立副本**（pages/21-6）
- **Git 凭证**（SSH 密钥 / HTTPS Token，全局作用域，clone 私有仓用——私有化部署的前置，pages/21-3 §10）
- **镜像运行参数**：env 全局配置（含 secret 掩码）+ Task 级覆盖 + 三层合并可溯源（pages/21-4 §10）
- **初始化向导**：首次部署出网检测/代理配置/资源确认（pages/21-8 §2）
- Task 发起主链路（P20 全链路：项目上下文 + 两步向导 + 一次性鉴权拦截面板（两种模式均即时完成，auth helper——技术 05 §2 决策 A）+ **可选初始任务指令 initialPrompt** + 终端）
- sandbox 生命周期 + **资源自动分配与调度**（后端根据镜像 resource_defaults 和调度策略，用户无感）
- **aio / boxlite 两档隔离 provider**（aio 默认；boxlite 微虚拟机独立内核强隔离，同 MVP 可选）
- **REST(OpenAPI) + MCP 双协议面**——MCP 是原始核心需求，不出 MVP
- 凭证双模式：帐号授权（Codex oauth-device）+ **API key 直存**（两 runtime 通用，不经 sandbox）+ Vault 全局复用
- **WS 事件推送**（sandbox.* 事件驱动状态实时化；MVP 依赖 WS 推送实现 waiting-input（🔵 等待输入）与四阶段进度卡）
- WS 终端双向转发 + tmux 断线恢复 + **任务状态拆分 🟢 执行中 / 🔵 等待输入**（pty 静默检测，决策 4 进 MVP）
- **访问口令**（NoopAuthGuard；默认监听 127.0.0.1 + 访问口令防护；私有化部署无用户体系时的第一道验证，pages/21-8 §3）
- SQLite 单机部署 + 状态机 + 错误处理基线

### SHOULD（v1.1–v1.5）
- 项目增强：项目归档/重命名、成果 diff 导出、共享卷协作模式、项目默认 runtime、项目级镜像参数覆盖
- 私有化部署增强：访问口令启停管理界面、启动命令可编辑；升级与备份完整流程 v1.5
- Claude Code setup-token 模式、**无头 Task 形态 + 自动化规则**（配套 feature：定时唤起必然无头，共用执行引擎——规则 CRUD、简化预设调度、运行历史、**webhook 失败通知（决策 3 提前至 v1.1）**、无头硬超时默认 2h 可配，见 pages/21-7）
- 镜像管理页**完整管理 UI**（注册/验证/启停的全量形态）、凭证管理页完整形态——注：镜像**运行参数区**（env 配置）属 MVP（见 MUST），可延后的是完整管理界面
- 资源监控、idle 自动回收、凭证过期提醒/吊销
- Playwright e2e 全量、staging 契约检查

### COULD（v2.0+）
- 多节点调度、用户体系/多租户、Postgres、插件生态

**MVP 切割线**：可砍——Claude Code（先 Codex 单 runtime 跑通）、镜像管理**完整 UI**（运行参数区除外，其属 MUST）、无头 Task；**不可砍**——MCP 面、终端链路、凭证复用、WS 事件推送、aio/boxlite 双隔离、访问口令防护（分别对应原始需求 3/5/9 与审计决策 P0-1/P1-9）。

## 4. 非功能需求（产品视角）

| 维度 | 目标 |
|---|---|
| 终端体感 | 键入回显 < 200ms；> 500ms 显示"响应缓慢"标识 |
| 列表加载 | < 1s；> 3s 显示重试 |
| Task 发起耗时 | 同镜像 ~20s；首次拉镜像 1–2min（向导预先告知） |
| 安全信任表达 | 凭证永远掩码；"授权在您自己的浏览器完成，平台不接触您的密码"明示；日志脱敏 |
| 扩展性表达 | "内置 aio/boxlite 两档隔离，任何符合 contract 的实现均可注册" |

## 5. 成功指标

- **北极星**：每周有效 Task 数（发起后至少完成一次终端交互或任务执行才算"有效"）。
- 过程指标：首次部署成功率 > 80%；首次进入到终端可用 < 5min；鉴权完成率 > 85%；**凭证复用率 > 70%**（衡量"登录一次全局复用"核心价值兑现度）；API 可用性 99.9%；异常自助解决率 > 60%。
