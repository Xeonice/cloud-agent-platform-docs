# 镜像 CLI 版本信息

平台需要让用户看清每个镜像版本声明的 Codex 与 Claude Code 版本，便于选择镜像和比较更新。版本与镜像 digest 绑定，在镜像管理和新建任务选项中展示；本轮不调整 CLI 版本、不发布镜像或升级线上服务。

## 1. 产品与交互

新增 [REQ-IMG-062、063](../requirements/IMG.md#REQ-IMG-062)，共 2 条需求、8 条 AC。沿用原 v2 镜像卡、版本历史、更新对比弹层和新建任务的可搜索单选；[设计入口](../../design/image-cli-versions.html)直接进入镜像页，保留原导航与所有已有操作。示例版本只演示呈现，不代表线上或将发布的版本。

- 当前镜像卡在 digest 附近显示「镜像声明」：`Codex 0.150.1 · Claude Code 2.1.251`。
- 版本历史与更新对比按各自 digest 显示两个版本，不能沿用当前卡的版本值。
- 新建任务镜像的默认项、普通候选和已选项保留真实坐标，并补充同一组 CLI 版本。版本信息不改变选择身份、禁用原因或默认镜像规则；保留坐标/别名搜索并额外支持 CLI 版本搜索。
- 缺失、格式错误、旧数据或第三方未报告的单项显示「未报告」。不能据此说「未安装」，也不猜 `latest`、平台服务版本或宿主 CLI。
- 「镜像声明」指构建声明，未报告表示未知；UI 说明「任务实际版本以任务环境为准」。自定义派生镜像可能继承旧标签；标签是元数据，不是对当前文件内容执行过探测的证明。

## 2. 数据来源与可信边界

镜像使用单一 OCI config label：

```json
{"platform.runtimeVersions":"{\"codex\":\"0.150.1\",\"claude-code\":\"2.1.251\"}"}
```

只接受 `codex` 与 `claude-code` 两个键，值为不带 `v` 前缀的精确 SemVer，可带合法 prerelease/build，单项最多 128 字符。无效 JSON、非对象、非法值按未知处理；一项错误不抹去另一项有效值，不因版本标签缺失/损坏判镜像不可用。该 label 与 `platform.supportedRuntimes` 分别表达版本声明和预装声明，不能相互推导。

官方镜像构建在真实 `codex --version`、`claude --version` 与固定版本校验通过后写入标签。自定义镜像应在修改 CLI 后重新验证并更新自己的声明；平台不把继承来的标签表述为运行实测。

读取复用 registry manifest/config 元数据解析；列表读取已保存的数据，不下载镜像层、不启动 Guest、不执行 CLI。运行中任务已有的 `runtime_installation` / `--version` 记录仅证明该任务实际运行的一个 runtime，不能填充镜像内所有 CLI 的版本。

## 3. 实施顺序与文档

1. 后端增加 digest 级持久化与元数据解析，扩展既有响应，保持旧客户端兼容；[后端设计](../../backend/changes/2026-10-17-镜像CLI版本元数据.md)。
2. 官方构建新增 label，保留并加强真实版本门禁；本轮固定版本不变。
3. 生成并同步 OpenAPI，前端将两个字段加入卡片、历史、对比与任务镜像选项；[前端设计](../../frontend/changes/2026-10-17-镜像CLI版本展示.md)。
4. 执行[独立前后端测试计划](../../testing/changes/2026-10-17-镜像CLI版本信息测试计划.md)，区分协议/持久化证据、组件交互与浏览器视觉；现网发版另行记录。

接口权威见 [10 接口契约](../../shared/10-接口契约与类型共享.md#64-image)与 [27 能力目录](../../backend/27-接口暴露设计（DDD到API与MCP）.md)。功能复用现有 image API，不新增端点或 MCP tool。
