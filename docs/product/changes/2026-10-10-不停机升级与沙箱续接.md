# 不停机升级与沙箱续接

本轮先交付需求、沿用现有风格的交互设计及实施／测试计划。目标是：**CD 只发布版本和安装包，由用户选择实例升级时机；升级不打断已有任务，刷新后接回原沙箱和终端。** 权威验收见 [UPG：9 条需求、52 条 AC](../requirements/UPG.md)，[设计稿](../../design/upgrade-sandbox-reconnect.html#task-login)可离线打开；默认新版未升级为 `?scene=upgrade-available`，明确发起后的过程为 `?scene=upgrade-progress`，已安装待刷新为 `?scene=upgrade-ready`，操作及设计／生产证据边界见 §2.2、§7。

## 1. 本次问题与范围

**本轮确定：CD 只发布版本和安装包，实例升级时机由用户主动决定。** published release 不等于实例已安装，页面刷新也不执行服务升级。2026-10-12 已开始按此实现前后端与发布工具，源码／实际局部检查见[实施验证记录](../../testing/results/2026-10-12-升级实现验证记录.md)；完整同构门禁仍未通过，不能声称既有实例已完成改造或上线。下文现状对比保留 v0.3.8 审查基线。

2026-10-10 的发布暴露了平台 API 替换需要停库、备份和重新启动，用户会感知不可用及连接断开。现有工具在活跃业务存在时返回 `waiting-idle`，没有直接强停任务；但发版指引建议停止任务或暂停自动化来解除等待，这不应成为常规发布路径。

当前 API 容器同时承载 HTTP／WS、BoxLite、任务执行监控、自动化调度和 SQLite 迁移。`detach: true` 的进程恢复能力，不能当作 API 容器替换时微 VM 保持运行的证明。去掉空闲门禁或复制第二套 API 并共享数据卷，都不能满足本需求。

| 用户目标 | 本轮确定的产品规则 |
| --- | --- |
| 升级时机由我决定 | CD只发布目录／安装包；本实例核验可安装新版后只提醒，有权限用户明确立即升级且命令接纳后才执行；检查、开页、目录变化和CI重试不自动升级 |
| 升级不要让我停手 | 用户主动实例升级满足无计划停机目标，旧健康组合在合格候选安全切换前继续服务；原任务／自动化保持 |
| 已有沙箱任务不能被升级停掉 | 保持原 owner、VM、执行进程和任务轮次；不能停止、销毁、重新启动或重发指令 |
| 刷新后能接回原沙箱 | 沿用现有任务路由与选择恢复，再认证、验证清单、attach 原会话和原选中终端 |
| 不要反复弹窗或强制刷新 | 右上发现新版本／立即升级、已发起真实进度、已安装待刷新分开；自然日暂停贯穿三态及同日新版本；API单变或Web复用不要求刷新 |
| 我要知道现在和将要用哪个版本 | 系统卡分别显示实例已确认服务、可安装release、loaded页面和已接纳固定target；available无attempt／percent，CD发布与实例100不混同，page已target不掩盖服务待升级 |
| 连接失败不要让我误以为任务没了 | 连接与运行状态分开；未知时保留现场，真实确认后才说运行中或已结束 |
| 更新失败也别把我的结果倒回去 | 先熔断发布推进，保留确证健康的服务组合与原任务；回退须兼容当前数据，不能退时修复前进，不恢复活跃整卷 |

本次覆盖CD产物发布、经真实性／架构／版本链／兼容核验的实例available提示、有权限用户主动Web／API／主仓实例升级、数据库分阶段兼容化和存量RuntimeOwner保护。planned实例权限不能以现有共享访问口令默认admin；普通用户仅查版本，服务端新增实例范围授权与审计，本文不声称已有RBAC。原始不兼容数据库变更必须先评估兼容桥、影子结构和在线转换，不能直接排除为停机维护。只有在线方案仍无法满足连续性预算或安全门禁的残余步骤，才延期该变更、限制对应新功能，必要短维护单列证据与影响；原任务仍在原 owner 继续，不将该维护计为常规不停机通过。宿主或 VM 重启、停止整个 Docker／Colima、任务自身退出及用户主动停止，仍属于各自的业务／维护事件，需明确记录和安排。

### 1.0 从发布版本到用户选择升级（planned）

CD完成测试、产物验证与版本／安装包发布 → 本实例只读核验目录真实性、manifest／digest／签名或等价受控信任provenance、架构／允许版本链／schema及组件兼容 → 显示available／待用户升级，无attempt／percent → 有权限用户明确点击立即升级 → 服务端重新核验精确target和固定计划、requestId幂等及instance CAS，接纳一个attempt → 才下载／校验／迁移／候选／切换 → 实例整体激活确认activation-confirmed／100 → loadedWeb不同且本实例实际ready时可自主刷新页面。

重复点击、多个用户竞争及断网后查询同requestId结果，不能重开attempt；目录新target不换掉已确认目标。每实例Web入口固定已安装产物，CD不promote共享生产alias或远程迁移实例。首次／次日检查、开页、关闭／稍后、目录变化与CI重试均不触发升级。一次用户明确发起允许计划内安全自动熔断／回退；熔断后重试、新target和独立破坏contract必须用户重新发起，不能由CD修复后自动重发。

### 1.1 升级出问题，先熔断推进，再判断能否回退（planned）

以下策略尚待实现和真实故障演练；当前单容器脚本的停库／备份回退不能冒充这套能力。在用户明确发起的实例计划中事前固定统计劣化阈值、观察窗口、观测有效期、每阶段兼容证据与回退资格；CD产物发布不执行这条实例流程。单次误 stop、重复执行、双写者、数据损坏或任务身份错配立即熔断；错误／延迟、积压等统计劣化或观测缺失按事先固定的策略熔断。

| 异常位置 | 实例升级控制器应做什么 | 用户任务和数据怎样保护 |
| --- | --- | --- |
| 候选准备／验证失败，还未切流 | 停止推进，不给候选新增流量，冻结后续迁移批次 | 保留健康旧服务；迁移事务按安全边界处理，不停止原任务或自动化 |
| API 或 Web 已切换后异常 | 冻结推进、后续扩流／新增分配步骤和后续迁移批次；没有合格 fallback 不先清零唯一安全 B 路由，再验证回退目标健康、当前 DB／新写数据、Web B、全部 owner 与控制权 | 资格全部成立后才转移 API 路由／Web 指针；保留最新产物、日志、取消意图和幂等记录，不恢复旧整卷或重放业务 |
| 当前数据不能被旧版无损理解 | 不盲退旧二进制，保留确证健康组合，使用预审兼容桥或修复前进 | 不丢弃新语义、不把结果倒回发布前；对应功能限制及只能前进边界须事前通过门禁 |
| 共享 DB／owner 故障、控制权失效或观测未知 | 不假定 API 退版能解决；冻结危险步骤并针对共享故障处置 | 不接管未知 owner，不释放真实占用；是否仍运行／可用按证据说明 |
| 恢复失败，或修复后用户准备再发 | 保留证据，同attempt不循环重试；有权限用户再次明确发起才接纳新attempt重过全门禁，CD重试／新目录不创建它 | 用户检查和诊断只读，不触发部署；原任务不被重新发起 |

回退用关联用户已发起的原实例升级 attempt 的独立 recoveryAttempt、新 generation 与预先固定的恢复工作计划。确认前失败的原 attempt 记录 failed／reverted 和真实阶段；实例已整体激活确认后发生新故障，保留不可改写的历史成功与 100%，追加当前 ready 撤销、故障及独立恢复事件，不倒写为当时发布失败。原进度均不沿用作恢复完成，恢复自身完成不证明原升级目标当前ready；CD published release和实例activation-confirmed历史分开保留。自动恢复仅限本次用户发起允许的安全范围，之后升级再试由用户重发。Web 指针退回只影响之后加载的页面，已经打开的 Web B 仍需兼容回退后的 API；界面显示实际服务组合与真实历史，不强制刷新、跳页或报未完成升级成功。

### 1.2 原始不兼容数据库变更，优先分阶段完成（planned）

兼容版本链的执行从用户升级命令接纳后开始，目录预检只读，CD不发起迁移。最后独立contract的破坏步骤另需用户主动发起和门禁，不能在窗口到期或新版本发布时自动删除。

影子转换失败时也要保护正常旧业务：仅在旧表示仍完整且没有不可逆新语义的条件下，撤掉新读，由兼容桥同事务保留旧业务和待补投影的持久变更记录，暂停迁移；修复只补投影，不重做用户操作。共享库损坏、旧权威不完整或原事务／持久 change／outbox 提交失败不适用此降级，不能 catch 后假报成功；正常旧业务必须与持久变更记录一起真实提交。

1. 先上线兼容桥版本，使当前服务能理解旧、新两种表示；回退资格按实际数据语义证明，不能只比较 schema hash。
2. 新建影子字段／表，唯一 StateCoordinator 在同一事务内维护两种表示。迁移执行者持锁编排，仍通过唯一写入控制更新数据，不能引入两个业务写者。
3. 按版本／游标分批回填，持续对账并发新增、更新和删除；批次可中断恢复，旧批次不能覆盖更晚更新或复活删除数据。
4. 灰度读新表示，确认结果一致后再切读新；旧表示在回退窗口内无损保留。旧版不能理解的新语义在窗口关闭前禁用或隔离，不能静默截断或近似降级。
5. 无法无损保留旧表示时，在接纳该新语义前明确只能修复前进、不能向旧版回退，并完成前向恢复演练。旧依赖及回退窗口退出后才独立 contract，不能和首次切读一起删除旧结构。

SQLite WAL 不保证长 DDL／全表重建无锁。优先影子结构、限额回填和短 epoch 切换，在真实持续写入下证明 HTTP／任务连续性；超预算就暂停／延期对应迁移或限制新功能，必要短维护仅处理已证明无法在线完成的残余。任务保留原 owner，备份用于专门灾难恢复证据，不作为在线升级恢复活跃整卷的许可。

## 2. 需求与设计先行

### 2.1 需求落点

新增独立 UPG 领域，保持原 250 个 REQ、1036 个 AC 的编号，新增 9 个 REQ、52 个 AC。沿用 SBX 的显式停止和启动语义，沿用 WB 的输出保留、自动重连和事件重同步；修正过时的任务深链说明及“附着失败就重发任务”的终端文案。

### 2.2 设计交互（本轮手动升级模型）

继续沿用 v2 任务树、任务顶栏、Agent／用户终端标签、画布、Geist 字体及暗／亮主题；新增交互只在原页面右上，使用独立增量 CSS／JS，保留原稿与搜索原型。

[设计稿](../../design/upgrade-sandbox-reconnect.html#task-login)的默认评审场景为新版已发布但本实例未升级：显式入口 `upgrade-sandbox-reconnect.html?scene=upgrade-available#task-login`。页面应直接显示“发现新版本”，列当前实例与可安装版本；有实例升级权限的示例用户才有“立即升级”，未点击不建立 attempt、不显示0%或其他进度。普通无更新对照保留，不能把默认 available 场景当生产已有来源或授权实现。

`?scene=upgrade-progress#task-login` 是用户明确发起且命令已接纳后的过程示例；手工推进模拟真实下载／验证、候选、切换与核对激活，百分比只作 fixture，不承诺正式权重、不按时间自增、不调用真实升级。`?scene=upgrade-ready#task-login` 是本实例已安装、目标 Web 在本实例入口 ready 且 loaded 页面仍旧时的“刷新页面”示例；不是版本目录刚发布就可刷新安装。模拟 API 单独更新或 Web artifact 复用时不要求页面刷新。演示恢复工具仅主动恢复 fixture／演示偏好，不绕过生产权限、CD／实例分离、自然日暂停或原任务保护。

1. **发现新版本**：受信目录验证manifest／digest／签名或受控信任provenance、架构／版本链／兼容后，投影本实例 installable available。CircleArrowUp 与静态点、轻量常驻浮卡显示“发现新版本”，有权限者可“立即升级”；其他用户只读。无attempt／percent，不以CD发布成功冒充实例已更新，page已target也不能掩盖服务待升级。
2. **主动实例升级**：只有明确点击且服务端接纳受权幂等命令，才下载／校验／迁移／部署候选／切换。按requestId复查断网或重复点击结果，instance CAS保证一个活动attempt，目标固定；目录新target不替换正在执行的目标。进行中无点，真实0–99与固定计划工作证据绑定，CD build／package／publish进度不能混入。
3. **已安装待刷新**：本实例 API路由／固定Web入口、兼容／连续性和整体激活确认才100。loadedWeb不同且实际ready时才“刷新页面”，页面相同或仅API变化没有强制刷新。实际加载新构建才改页面版本；刷新／原终端reconnect与实例进度分开，任务不重跑。
4. **今天不再提醒**：关闭或稍后按用户＋实例＋本地自然日暂停浮卡，贯穿available→用户发起→ongoing→待刷新、阶段／百分比、同日新版本与多标签／reload；有效按钮／按权限手动操作保留，次日仅核验提醒，不启动升级。不是24h或永久revision，记录不含认证／终端凭据。
5. **主动查看与输入保护**：popover只点击打开，检查只读，详情才转系统卡并定位；Esc／外部关闭不记日暂停。无移焦／动画／定时消失／全宽横幅或侧栏入口，保留终端选区、表单与中文组合输入，刷新沿原离开保护。
6. **断连及未知**：原位接回原终端，保留URL／任务／标签／画布，不新建会话或重放输入；真实确认后才说原任务仍运行。版本／实例进度未知各标上次值及时间，查询与用户重连不创建升级attempt或重启任务。
7. **失败／延期／熔断**：无独立有效更新状态时隐藏顶栏，系统卡保留真实实例组合与原因；确认前failed／reverted，确认后历史成功／100不改，另记ready撤销与恢复。该次用户同意内可安全自动熔断／回退，熔断后再试或新target必须用户重新发起；CD重试不能替用户创建新attempt。影子转换与共享故障按§1.1／1.2处置，不停原任务或退整卷。

当前服务、可安装 release、已接纳 target 和 loadedWeb 必须分别可查；每实例 Web入口固定已确认产物，CD不promote共享alias让未升级实例也换页面。原型将目标一栏明确标为“本次已受理目标”，未点击时为“—（尚未发起升级）”，不将目录候选冒充已受理目标。原型状态、示例权限和百分比都不代表真实runtime、RBAC或controller已实现；本轮交互校验见§7，真实功能门禁独立验证。

## 5. 完成定义

- CD只发布版本／安装包，目录核验后available无attempt／percent；每实例Web入口固定，未选择升级的实例不因CD发布／promote换版。planned实例权限由服务端校验，共享口令不默认admin。
- 明确立即升级且受权命令接纳后，才单attempt下载／验证／迁移／切换；CAS／requestId覆盖并发、重复点击与断网查结果，新目录不换固定target。查询、开页、日提醒、关闭／稍后和CIretry不发起升级。
- 同一任务在正常升级、刷新和兼容回退前后，Sandbox／Provider 实例、进程启动标识、tmux、AgentTask 执行轮次保持；没有停止／销毁／取消／重新执行。
- 连续请求达成 HTTP 可用性目标，原终端按目标时间恢复；签名密钥保持，访问会话不因升级丢失。
- 单调执行计数和持久化日志无遗漏／重复，产物和游标不倒退；自动化不暂停、漏发或重发。
- 原始不兼容数据库变更先兼容桥和影子结构在线转换，单 StateCoordinator 同事务维护双表示；分批回填／并发新增更新删除对账、灰度读和窗口内无损回退可证明，旧依赖退出后才独立 contract。
- 熔断阈值／窗口及回退资格事前固定；单次硬不变量立即触发，先冻结推进、扩流／新增分配步骤和后续批次；未接流候选可隔离，已切流无合格 fallback 不清零唯一安全 B 路由，不停止健康业务。回退须兼容当前数据、已加载 Web B 和全部 owner；共享故障／资格缺证据不盲退，必要时修复前进，不覆盖最新数据。
- recoveryAttempt 独立关联原 attempt，以新 generation／固定计划证明恢复；确认前失败保留 failed／reverted，实例已整体激活确认后新故障保留历史成功／100并追加当前 ready 撤销与恢复事件，不改写历史或继承进度，同 attempt 不循环重试。修复后有权限用户重新发起才接纳新attempt重过全门禁，独立破坏contract另行用户发起，CD不自动重发；诊断和用户检查只读；长锁超预算或残余不可证明步骤延期／限制新功能，维护影响另列，原任务仍归原 owner。
- CircleArrowUp／浮卡区分verified available、用户已发起ongoing、已安装待刷新；available与ready静态点，ongoing无点。实例activation-confirmed／100需固定入口／兼容／整体证据，不混CD进度；不同实际ready页面才刷新，仅API或Web复用无需刷新，page已target不掩盖服务待升级；未核验／未知不伪成功，输入／原任务保持。
- 日暂停贯穿available→用户发起→进行中→待刷新、阶段／百分比及同日新版本，跨页／刷新／多标签保持；次日只核验有效状态再提醒，不自动升级。进度不由前端timer虚增，不与客户端刷新或终端重连混成下载／安装。
- 当前实例服务、可安装release、当前页面和已接纳固定target各有真实来源，CD published不等于实例已升级；稍后仍可查更新，候选失败／延后／读取失败／部分切换不伪报已更新。

本轮只以文档、原型和规划的校验作为设计交付证据；生产连续性完成状态由上述真实门禁及后续发布记录确认。
