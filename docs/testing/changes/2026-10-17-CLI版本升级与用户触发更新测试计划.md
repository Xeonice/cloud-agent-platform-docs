# CLI 版本升级与用户触发更新测试计划

本计划验证 Codex `0.150.1→0.163.0`、Claude Code `2.1.251→2.1.302` 的实际交付，以及管理员手动升级时原沙箱的连续性。对应 [升级与实验发包计划](../../ops/2026-10-17-Codex与ClaudeCode升级发包计划.md)。下列场景按本轮构建和实际演练逐项执行；本计划本身不构成测试通过回执。用户已明确授权本次发包并更新实例，运维可代用户提交普通升级请求，CD 仍不得触发升级。

## 统一部署前置验收

本机与 `100.73.71.22` 均使用 macOS 宿主、Colima Linux arm64／VZ 嵌套虚拟化、Docker 分离角色。远端已完成基础迁移与来源封存退役，结果见 [迁移验收报告](../results/2026-10-17-统一部署与在线升级验收.md)。本轮升级前的物理来源分别为本机已确认 C（generation=3）和远端旧 `.3`（generation=1），各自使用其专属实例／渠道与固定信任根；基础迁移和真实新 Guest 通过不等于跨升级连续性或 CLI 发包通过。

每次执行仍分别冻结实际来源版本、实例／渠道、信任目录、API／Web 入口、角色物理身份及原始运行资源，作为下表中的“来源基线”。本机 C／远端旧 `.3` 的实际身份是各自物理来源，不能混用；历史预演身份与通过结论不得替代本轮测量。

本轮平台验收目标为`.20261017.7`：本机 `v0.3.12-experiment.online-bridge.20261017.7` → `v0.3.13-experiment.online.20261017.7`，远端 `v0.3.12-experiment.iflytek-bridge.20261017.7` → `v0.3.13-experiment.iflytek.20261017.7`；OCI tag为 `v0.3.12-cli.20261017.1`。精确三仓SHA及包摘要以[本轮验收报告](../results/2026-10-17-CLI镜像与双实例更新验收.md)的第七轮冻结记录为准。历史`.1`至`.6`的包与失败样本保留，不能用新演练覆盖原测量。

历史`.4`请求准备时，本机最后确认的基线为 C、activation generation=3，但失败的 `.3` 桥接 attempt 已占 generation=4；bridge4正常修复预期受理attempt5、确认activation4；之后final5从activation4受理attempt6、确认activation5。修复入口须读取实际 `repairableCurrent`／`sourceActual`，不将混合角色伪称完整 C，也不改写原失败结论。远端旧 `.3` generation=1，桥接／最终版预期受理 2／3。每次分别核对attempt与activation两个独立序列：尝试编号取历史最大值加1，确认编号只在成功后从原activation加1；受理编号不能冒充确认编号。这些预期不是新升级成功结果。

| B17 大历史与迁移写锁 | 真实大历史SQLite验证全库完整性／外键检查在独立只读worker执行、HTTP及fence续租继续响应；事务内只检查实际变更的image表。保留500ms写批次，包含receipt的超时完整回滚；全库坏数据在写前拒绝，提交后失败保留29和原receipt且status重新验证，await后失效fence不能ack。20秒请求worker退出并等待实际exit，不冒称原生SQLite可立即中断；prepare／status的120秒RPC预算不用于延长batch／健康／attach。 |

成功流程与失败注入先在隔离环境完成。在线实验只进行管理员自选的正常升级，不在线上制造故障，也不操作用户原有资源的生命周期。首次真实 API／Coordinator／Owner 更新的结果不能由历史 Installer-only 记录代替。

隔离预演保留既有资源预检，本轮远端同构预演（R3）的可用磁盘须至少 20 GiB；不足时停止准备。只清理本轮明确归属的可再生构建中间态，并复核剩余空间；不得放宽门槛、清理业务卷或删除包／签名／测量证据来继续验收。

## 测量、证据和清理

从用户点击前开始连续采样同一 IP／公网入口的 API health、Web、Guest 计数与 WebSocket，记录时间、响应状态、延迟、超时和断连；保留失败样本，区分真实切换、连接延迟和未能确定的异常。原始 TTY 有 ANSI 重绘，不能把画面重复历史行判为业务计数回退；递增前缀由实际 Guest 文件验证，WS 另验证真实新增输出。

保存包与镜像收据、前后版本／digest、角色 container/PID/birth、Owner assignment／home、Guest live snapshots、ready/撤销事件、浏览器进度与请求计数、原 bookmark 两次 attach 耗时。签名私钥、口令、cookie、socketSessionKey 和凭据内容不进入报告／仓库。

`.4` 构建阶段已保留四包原生依赖／ABI／全树与空缓存 tar 检查，实际编译 2 次 API／0 次 Web；本机两包重编 API 并严格复用已签验 `.3` Web，远端两包严格复用已签验本机 `.4` API／Web。同阶段 Installer 元组相同，较各自 `.3` 来源变化。根仓升级模块 199 项、API 主分支升级回归 238 项及桥接分支相关回归 50 项全部通过，包含 [最终激活边界](../../../deploy/upgrade/native-activation-window.test.mjs)、[链式来源入场](../../../deploy/upgrade/native-source-admission.test.mjs) 与 [SQLite 探针投影](../../../api/acceptance/upg/sqlite/upgrade-store.spec.ts)。`.3` 曾有 612 项组合回归（608 通过、4 项预期跳过），不当作 `.4` 的新组合回归结果。上述快速合约测试不声称采集了真实 60 秒流量。API 的 19 项针对性验证见 [retained artifact proof](../../../api/acceptance/upg/pure/retained-artifact-proof.spec.ts) 和 [初始 source 锚](../../../api/acceptance/upg/sqlite/initial-source-anchor.spec.ts)；这些源码／构建检查不替代 B02～B06、B09 以及前端现场验证，真实结果另记验收报告。

### B19 大数据库观察与真实采样不互相阻塞
