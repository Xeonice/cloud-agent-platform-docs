# 不停机升级与沙箱续接 · 前后端统一测试计划

本文件是本轮**统一测试范围、执行层、逐 AC 映射与交付门禁的权威计划**。依据 [UPG PRD](../../product/requirements/UPG.md) 的 **9 条 REQ、52 条 AC**，不新增或删除产品编号。前后端实现方案分别见[前端方案](../../frontend/changes/2026-10-10-升级提示与原终端续接.md)与[后端方案](../../backend/changes/2026-10-10-不停机升级与运行环境分离.md)；产品背景见[需求变更](../../product/changes/2026-10-10-不停机升级与沙箱续接.md)。

本轮已接纳[升级体验与启动可观测性优化](../../product/changes/2026-10-18-升级体验与启动可观测性优化.md)的 P-01 至 P-07，沿用本文件更新前后端、契约、联调和同构测试范围；启动与镜像跨域验收分别追踪 LCH／SBX／IMG 原 AC，不增加 UPG 编号。[双实例 CLI 更新验收](../results/2026-10-17-CLI镜像与双实例更新验收.md)只证明报告所列输入、边界和实际场景，其中约 1GB 数据和原终端的局部结果不能外推为全部 Agent／自动化、故障矩阵或本轮优化已通过。本轮已执行的前后端功能、真实HTTP／SQLite及约1GB隔离响应结果见[本轮实现验证](../results/2026-10-18-升级体验与启动观察实现验证.md)；本轮新包的五窗口Native升级、约1GB数据、两实例原资源和新界面单击实验见[发版验收](../results/2026-10-18-升级优化发版与双实例更新验收.md)，只计所列输入和实际范围。未执行的真实模型连续性、完整故障矩阵与正式资格仍保持planned／not-run，不改写历史执行结果。

**状态为实施中，完整门禁未通过。** 已实施实际权限、目录、controller、角色分离及验证入口，部分前端、SQLite 和真实角色 HTTP／WS 测试已执行，记录见[实施验证记录](../results/2026-10-12-升级实现验证记录.md)。同构真实升级与全部故障矩阵必须继续执行；未跑层保持 not-run，不能依据局部测试解除发布门禁。原型检查、截图和此前设计稿 QA 只证明对应设计交互，不计入这 52 条功能 AC 已通过。实现完成后必须保存实际执行记录，再逐项标记 passed、failed、partial 或 not-run。

## 1. 范围与验收口径 {#UPG-TEST-SCOPE}

遵循[共享测试策略](../../shared/29-测试策略与测试Agent.md)、[后端测试规则](../../backend/25-后端测试体系.md)与[前端测试规则](../../frontend/12-前端测试体系.md)。测试 case、Story、截图、REQ、AC 是不同计数；一个 case 可覆盖多个 AC，但不能用 case 总数或覆盖率代替指定层的实际结果。

产品场景按单个管理员或已授权操作人升级当前实例验收，不增加多用户并发升级、额外实例对照或多人协同流程。重复执行保护覆盖同一操作人的重复点击、丢回执和页面重开。

统一验证链为：**CD 验证并发包 → 实例只读发现 available → 有权限用户主动点击 → API 授权／CSRF／幂等 CAS 持久受理 → 实例 controller 执行固定最终目标与允许兼容链 → 内部桥接、兼容迁移和候选切换 → 最终目标 activation-confirmed → 不同实际 Web ready 时用户自主刷新 → 附着原任务／终端**。

- CD 的 `published` 只代表目录版本／安装包发布，不推进实例激活。未点击时，检查、首次／次日开页、关闭／稍后、目录变化、CI 重试、控制器重启都必须是 **0 command、0 attempt、0 执行安装包下载、0 线上迁移、0 候选部署、0 入口切换**。读目录元数据和真实性证据不算下载执行安装包。
- 用户升级命令与浏览器刷新分开。操作人通过原访问口令解锁后直接发起，无独立升级授权；服务端继续验证已有访问保护、Origin／CSRF、实例绑定及命令CAS。查版本、lookup 和刷新不能获取部署凭据。
- 原 sandbox、providerHandle、box／VM、tmux／PTY、AgentTask／run、job 与自动化保持。attachment、短期认证票据可以变化；不能新建替代终端、重放 initialPrompt／输入，或通过容器退出间接停任务。
- available 无 operation／attempt／百分比。用户级 operation 固定最终目标、允许的桥接节点及顺序，各技术 attempt 保留真实历史。子阶段有真实分子／分母才显示该阶段百分比；总体工作量未知时显示步骤与真实事实，不分配固定权重。中间桥接的技术 100 不等于 operation 完成；只有最终目标的实际入口、所需 Web 产物、兼容、连续性和整体激活确认后才整体 100。页面构建和 attach-ready 分别确认；sameWeb 或本页已目标不掩盖服务待升级，安装后无需强刷相同 Web。
- 上次完整确认版本、当前服务可用性、本次最终目标与结果、实际加载页面分开验证。部分组件已替换或健康恢复不改写历史，也不能代替最终确认；检查状态、复制诊断保持只读，没有合格修复计划时不提供泛化回滚／重启。
- HTTP／RPC 等待超时不等于原升级或启动操作终结。结果未知或仍执行时查询原 requestId／operationId，不重投、不另建 Guest、不释放真实占用；只有原操作确证终结才展示相应业务终态。
- 正常兼容升级必须达到[正式 SLO](#UPG-TEST-SLO)。必要残余维护、外部网络异常、真实凭据过期、任务自然退出和用户独立停止另列原因及影响，不能删掉失败采样或把它们冒充常规不停机通过。

## 2. 环境、数据与证据准备 {#UPG-TEST-SETUP}

每轮冻结旧／新主仓、API、Web SHA，实际镜像／Web／安装器 digest，构建输入指纹、manifest 与兼容桥链、schema／协议、目标架构和发布通道。目录签名或等效受控发布证明使用安装时固定信任根，另验包 digest；从未知地址拿 manifest 和 SHA256SUMS 不能自行证明真实性。各场景使用合成访问材料，由同一操作人验证已有访问保护的未解锁／已解锁／真实过期状态；解锁后直接升级，不提供独立升级密钥或二次授权。不建立多用户身份体系。

准备一个隔离实例：先验证发现新版、查看和关闭提示不会升级，再由同一操作人主动升级。实例有固定 Web 入口和独立 DATA_ROOT／SQLite／master key／端口／资源标签，不能挂生产数据、生产凭据或生产 Docker socket。旧 Web A、新 Web B 与 API A/B 必须是实际构建产物，复用产物保持真实原 SHA／digest，不改号伪装新构建。

固定至少一条需要桥接的允许链及一条无桥链，并准备受管默认镜像、自定义默认和显式旧镜像；预期 CLI 声明按实际 digest 保存，任务内实测另列来源。只读发现不预拉包或创建验收 Guest。

轻量响应与长检查隔离使用真实 SQLite。快速层可用受控慢 IO／Worker 屏障验证受理、状态读取不等待长工作，但该替身不证明 1GB 性能；I／N 层必须保存约 1GB 实际数据的逻辑量、物理量、schema、完整性检查和设备／inode 等身份，覆盖真实整库检查运行中。开始前冻结数据基线和响应计时点，不以稀疏文件大小、unit fixture 或仅最终 health 代替实际数据验收。启动故障分别准备原 start 返回超过 120 秒、响应丢失后最终成功、只心跳无实质进展及真实终结失败；Native 使用真实 provider 观测，不能用慢替身声称 VM 性能通过。

跨仓层准备生产 Next 构建、编译后的真实 Nest 控制角色、独立 StateCoordinator、RuntimeOwner 与实例 controller。候选和旧 API 使用真实 RPC 连接同一个唯一 Coordinator，不能原样启动两份当前完整 AppModule 分别迁移、scheduler、pump 或写同库。协议层须验证生产角色真实 DI／bootstrap，不能手工 new handler 绕过注册；角色分离尚未实现时，相应测试记 not-run。

原负载至少包含持续交互任务、等待输入的 Agent、用户终端长命令、无头任务、升级时到期的自动化；Agent 和两个用户终端已存在，选中第二个用户终端。保存真实身份／启动时刻、创建与命令消费计数、工作区摘要、日志 seq／cursor、取消意图、幂等记录与自动化 occurrence。长期原进程每秒持久追加唯一递增序号，不能在升级后换一个计数进程续写来伪装连续。

每个场景统一记录**准备已成立 → 实际进入被测阶段 → 操作／故障注入 → actual 与 expected 比较 → 证据路径 → 清理范围**。竞态使用可观测屏障／事务提交点，不靠 sleep 猜顺序；纯策略层可注入 Clock，真实联调和 native 的持续性／延迟使用单调时钟实测。清理只释放本轮专属资源，终止计数进程的 teardown 要在正式测量窗口后单独记账。

成功场景经真实业务API清理后，须观察全部所属角色实际停止才卸载专用测试文件系统；失败场景保留原资源与证据，不以直接SQL删除或强停任务使验收变绿。额外验证显式删除的终端书签同事务清理／回滚及迟到attach拒绝、已销毁资源零重复SDK调用、旧待清理记录的精确Owner证明、丢失回执的原operationId只读确认，以及清理队列在A→B→保留A新epoch后拒绝旧回执／SDK动作。局部HTTP／SQLite／文件系统结果不替代native运行。
