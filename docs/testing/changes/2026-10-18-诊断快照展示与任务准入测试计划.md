# 诊断快照展示与任务准入 · 独立前后端测试计划

本文件是架构整改 T08 的独立测试计划，依据 [WB](../../product/requirements/WB.md)、[SYS／DIA](../../product/requirements/SYS.md)、[DEP](../../product/requirements/DEP.md) 与 [LCH](../../product/requirements/LCH.md) 的现有 REQ／AC，同步验证前端入口、初始化协议与后端业务准入。不增加、删除或重排产品编号，也不并入 UPG 的 52 条 AC。通用执行口径沿用[共享测试策略](../../shared/29-测试策略与测试Agent.md)、[前端测试体系](../../frontend/12-前端测试体系.md)与[后端测试体系](../../backend/25-后端测试体系.md)。

**第1–6节定义计划范围；第7节按实际证据记录执行状态，不以测试总数推定整组条款通过。** 实际命令、源码版本、结果与未执行项由[架构整改执行记录](../results/2026-10-18-架构审查与整改执行记录.md)保存；不能把已有正常浏览器场景改称“失败历史快照”的回归。

## 1. 范围与不变量

1. 初始化保存的联网检查与设置页诊断缓存只说明那次探测的对象、结果和来源。失败结果可以提示用户检查网络，但不作为所有 Agent／所有任务不可用的证明，不直接禁用任务入口、表单提交或自动化入口。
2. 三条真实消费路径必须分别验证：`AppFrameContainer`、`useCommandPalette`、`SandboxTerminalContainer`。移除快照阻断后，项目就绪、所选 Agent、凭证、镜像、终端能力、表单合法性、请求在途与后端拒绝等原门禁继续生效。
3. 本项不新增模型网络预检、不轮询诊断、不因挂载入口自动开启探测，也不通过忽略后端错误来制造成功。使用原初始化查询缓存；初始化无历史结果时原有首轮检测／重试规则仍按 DEP 执行。
4. 初始化显式确认继续保留原 wire 字段 `acknowledgeOffline`、服务端判据与 `OFFLINE_NOT_ACKNOWLEDGED`。用户没点确认时前端不能代填；409 不得放行，不得写入初始化结果。提示限定为本次声明目标的探测结果，不能扩大成所有 Agent 不可用。
5. 历史 `checkedAt` 保留真实值；没有时刻就说明无法判断新旧。诊断结果优先只表示来源选择，不等于永久新鲜。没有时间戳的诊断缓存不得伪造“刚刚检测”、刷新历史时刻或通过重新读取升级成当前运行证据。
6. 状态读取失败与网络探测失败分开。init-status 的 500／不可达仍显示“无法确认平台状态”；401 由访问口令门处理。已有诊断缓存不能吞掉平台状态未知的事实。

## 2. 前端数据矩阵

使用实际 hooks、QueryClient、store、容器与 MSW；控制外部 HTTP／SSE 返回，不把准入 hook 整个替换为始终允许的桩。

| 输入 | 展示与来源断言 | 准入与请求断言 |
| --- | --- | --- |
| init-status 保存模型声明目标全部连接失败及明确历史时刻 | 展示限定探测范围的提示及原时刻，不宣称全部 Agent 不可用 | 三条消费路径不因它禁用；打开／正常提交仍走原表单与 HTTP |
| 历史模型失败，无 `checkedAt` | 明说时刻缺失，不补客户端当前时间 | 入口与提交不因未知新旧而禁用 |
| 当前会话诊断缓存的模型项失败，有或没有历史快照 | 使用诊断结果来源；没有时间戳不说实时／刚刚 | 诊断结果本身也不能成为客户端全局禁用条件 |
| 历史失败、诊断成功；历史成功、诊断失败 | 对应诊断结果优先，不串用历史时刻，不改 init-status 缓存 | 两种组合均不由快照替任务请求作能力判断 |
| 新轮只到 start／无有效联网 detail、诊断中断 | 不编造成功，不将未返回当失败；按既有规则保留已到事实 | 不能因诊断仍在运行而阻塞其他入口 |
| 无快照、空模型清单、仅镜像源失败、模型全部超时或部分失败 | 缺席保持未知；限定模型／镜像范围；超时不说成连接失败 | 不触发全局任务禁用或隐式确认 |
| init-status 500，含“已有诊断缓存”的组合 | 平台状态未知仍呈现；不转成联网失败，不被诊断优先分支隐藏 | 后续业务请求按真实结果处理，不伪造受理 |
| init-status 401／访问口令锁定 | 交给口令门；门后不再叠加误导的诊断阻断 | 访问保护照常，不通过本项绕过 |

治理提示验证关闭、当天不再提示与次日可重现；关闭提示不能改变任务准入、改写检查记录或自动运行检测。系统状态页与全局提示的 [重新检测] 仍由用户显式触发；保存代理不自动改变检测结果。需要保留的结果、历史时刻和读取错误分别断言，不能只看最终横幅是否存在。

## 3. 三入口与前端负例

| 本计划用例 | 真实消费路径与动作 | 必需断言 |
| --- | --- | --- |
| F01 | `AppFrameContainer`：顶栏／总览新任务及项目空组入口 | 历史失败提示在场仍能打开同一任务弹层；项目上下文正确。没有就绪项目仍按原原因禁用；不再出现由历史诊断生成的“需连接网络才能发起任务”原因 |
| F02 | `useCommandPalette`：⌘K 的“新任务…” | 历史或诊断失败不拦动作执行；正常关闭面板、打开同一弹层。无项目／克隆中等原限制继续有效，键盘 Enter 不绕过真正禁用 |
| F03 | `SandboxTerminalContainer`：项目内“发起第一个任务”、新建弹层提交 | 历史失败不锁入口或主按钮；合法数据只提交一次。Agent 未选、凭证失效、终端不支持、非法指令及创建中仍按现有规则阻断 |
| F04 | 真实提交返回缺项目、未知 runtime、镜像不兼容、资源不足或暂时失败信封 | 原码和事实在原位呈现，保留指令及规定的重试出口；不被旧快照盖成统一“离线”，不伪造任务 ID 或成功状态 |
| F05 | 跨设置页返回工作台、重开弹层与缓存更新 | 诊断来源优先、历史时间不刷新；挂载／切页不额外轮询 init-status、不自动发 diagnose 或模型请求；未知读取与 401 分流保留 |

主要回归落在 `web/src/acceptance/diagnostic-snapshot-admission.test.tsx`，并复用现行任务发起、系统诊断、初始化验收。测试应从实际消费路径点击／提交并核对请求次数和请求体；仅证明一个纯函数返回 false 不能替代 F01–F03。

## 4. 真实初始化与业务 HTTP／SQLite 负例

使用 `api/acceptance/dep/protocol/diagnostic-task-admission.spec.ts`。外部 registry 的声明元数据可控制；模型探测目标是隔离本机 HTTP listener 主动断开 socket，产生真实连接失败，避免访问外网、等待外部模型或依赖关闭端口不被复用。生产 `ConnectivityProbe`、初始化服务、Nest HTTP、应用服务、schema／迁移与 fresh SQLite 均使用真实实现。

| 本计划用例 | 操作 | 必需证据 |
| --- | --- | --- |
| A01 | 模型声明目标真实探测失败，未带显式确认时 POST init | 409 `OFFLINE_NOT_ACKNOWLEDGED`；initialized 未置位，初始化设置／快照无新增写入；错误说明限定声明目标，不说所有 Agent 不可用 |
| A02 | 用户明确确认后按既有协议 POST init | 201；保存真实失败模型行及真实 `checkedAt`，普通 GET 能读回；确认没有更改判据或把失败记录改成成功 |
| A03 | 保留该失败历史后，通过业务 HTTP 新建项目与合法任务 | 项目／任务真实持久化，创建受理并能经后续 GET 观察平台 running 状态；外部 Provider 仅复用 `ProtocolProvider` 的受控资源边界，不声称模型输出已成功 |
| A04 | 同一失败历史下请求不存在项目或未知 runtime | 分别仍按真实 404／400 拒绝，零任务创建；不能由取消前端快照拦截推导为放宽后端校验 |
| A05 | 请求结束后再次读取初始化状态及数据库 | 原失败探测行与原时刻保持，未因创建任务而重写历史／伪造重新诊断；受理次数、任务行和实际外部调用可对账 |

该协议反例证明“失败探测历史不应成为业务准入否决”，以及 ACK 与业务校验继续有效。它没有证明外部模型现在可达、Agent 回答成功、真实 Guest／CLI 可用或升级期间原任务连续性。

## 5. 浏览器联调与证据边界

常规跨仓浏览器回归复用 `e2e-contract` 的现行入口：真实 Web → Nest → fresh SQLite，沿普通页面创建项目、选择配置、发起任务与读取结果。Provider、模型与 PTY 等外部边界仍按既有受控 fixture，禁止使用生产数据或用户任务。

该正常场景验证移除拦截没有破坏常规链路，**不单独证明失败历史、最新失败诊断或 unknown 的反例已覆盖**。本次负例由 F01–F05 的实际 hook／MSW 与 A01–A05 的真实探测／HTTP／SQLite 分别提供证据；执行记录逐层标明，不把两种测试拼称一次真实浏览器模型验收。

原生 VM、模型服务凭据、真实 Agent／无头任务连续性、跨版本升级和完整故障矩阵属于[原不停机升级计划](./2026-10-10-不停机升级与沙箱续接测试计划.md)的独立范围；本项未执行这些内容时继续写 not-run，不能因本项通过解除原门禁。
