## 问题、修复与存量边界

现场共享文件系统遍历持有约936个 `O_PATH` 句柄，原 VMM 总 FD 接近1024，可能挤占 DNS 和网络连接创建所需额度；该观测不直接等同于 SDK 泄漏结论。生产 provider 创建参数改为有限额度 `maxOpenFiles=65536`，同时显式保留 SDK 的 `maxFileSize=1073741824` 与 `maxProcesses=1024`，避免其 security converter 整体替换资源限制时丢失其它默认值。

该策略只影响新 Owner 使用新版 provider 后新建的 Guest。当前用户 Guest `QymrgCpBLCHS` 已单独在线调整 VMM NOFILE 软／硬值至65536，未停止或重建；SDK 中原持久配置仍是1024，部署新版本不会自动迁移旧 Guest，不能据在线 `prlimit` 修复声称其 stop/start 后默认值已验证。
