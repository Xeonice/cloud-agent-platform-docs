> 状态：✅ 可评审（聚合前后端调研结论，2026-08）

## 0. 术语：两个都叫 "agent" 的东西，别混

全套文档里 "agent" 出现在两个完全不同的层，混用过一次就会导出错误结论，因此**统一如下，写文档时按这张表用词**：

| 指代 | 统一叫法 | 是什么 | 谁提供 |
|---|---|---|---|
| ① | **沙箱内 API** / `in-sandbox API` | 沙箱镜像里常驻的 HTTP 服务，监听容器内 `:8080`，123 个端点（`/v1/bash/exec`、`/v1/file/*`、`ws /v1/shell/ws`）。它只负责"在这个盒子里跑命令、读写文件" | **镜像作者**（`agent-infra/sandbox`），不是我们写的 |
| ② | **agent** / **agent 会话** / **agent CLI** | `codex` / `claude code` 这类真正干活的 AI CLI，由 ① 起进程拉起来 | 各 CLI 厂商 |

**判据**：谈端口、端点、HTTP、会话回收、文件读写 ⇒ 是 ①；谈提示词、上下文续接、工具调用、tmux 会话 ⇒ 是 ②。

**不受本约定影响的既有名字**（它们是标识符不是叙述，保持原样）：镜像名 `agent-infra/sandbox`、仓库名 `agent-platform-api` / `agent-platform-web`、代码标识符 `bootstrapAgentSession` / `AioSandboxAgentClient` / `agentEndpointPort`、MCP tool `run_agent_task`、tmux 会话名 `platform-agent`、产品名"云 Agent 管理平台"。

> **为什么单开一节**：这不是洁癖。① 的会话有**闲置回收**（04 §2.6 ★★★），而 ② 的会话由沙箱内的 tmux server 持有（04 §7 ★）——两者的生命周期规则完全相反。一句"agent 会话会被回收"在两种读法下会指向两个相反的结论。

## 1. 仓库划分

| 仓库 | 技术栈 | 职责 |
|---|---|---|
| `agent-platform-api`（后端） | NestJS 11 + TypeScript strict，pnpm workspaces 模块化单体 | sandbox 调度中心、runtime 适配、镜像契约、凭证保管、PTY 网关；对外暴露 REST(OpenAPI) + MCP + WebSocket 三种协议面 |
| `agent-platform-web`（前端） | Next.js（App Router）+ TanStack Query + Zustand + shadcn/ui + @xterm/xterm 6 | 简易管理入口：左侧 sandbox 列表，右侧 xterm 终端；runtime 帐号鉴权页 |

两仓库通过 OpenAPI codegen（生成后提交 + CI 漂移门禁）与 WS 协议手动同步（zod 运行时校验兜底）保持契约一致，不发 npm 包（详见文档 10）。

## 3. 限界上下文（后端）

| 上下文 | 职责 | 关键领域概念 |
|---|---|---|
| `sandbox` | 生命周期 + 资源调度 | Sandbox 聚合根、ResourceQuota VO、状态机、SchedulingStrategy |
| `runtime` | codex / claude code 适配 | RuntimeAdapter contract、AuthChallenge、RuntimeTaskSpec |
| `image` | 自定义镜像契约与校验 | ImageSpecManifest、ImageSpecProvider |
| `credential` | 订阅凭证保管库 | CredentialVault（加密存储、物化注入、吊销） |
| `terminal` | PTY 网关（横切） | ProcessStream（spawn tty）、TerminalSession、tmux attach / re-attach |

## 4. 核心流程

1. **创建 sandbox**：REST/MCP → Application Service → 调度器（配额登记互斥）→ SandboxProvider.create（aio/boxlite，按 quota 施加资源限额）→ 状态机 pending→…→running → WS 事件推送前端。
2. **终端接入**：前端 xterm → WS `/terminal` → TerminalGateway → `provider.spawn({tty:true})` attach 实例内 tmux session → 双向流转发 + resize 同步 + 断线 re-attach。
3. **无头 Task**：REST/MCP `run_agent_task` → 沙箱内 API 起异步作业(`sessions/create` → `exec async_mode` → `ws /v1/bash/ws` 附着) → `parseOutput` 逐行成 `RuntimeEvent` → 原始 JSONL 落盘 + 经 WS `/tasks` 按 `seq` 推前端 → 终态收产物、落退出码、释放作业。
4. **runtime 鉴权**：前端鉴权页 → 后端在容器 pty 内起交互式登录（`codex login --device-auth` / `claude setup-token`）→ Adapter 从 pty 输出捕获 URL/device-code → 前端展示 → 用户在自己浏览器完成授权 → CLI 落盘凭证 → Vault 加密收编 → 后续 sandbox 自动物化注入。

## 6. 关键取舍一览

- **内建 sandbox 双实现**：`aio`（默认，AIO Sandbox 容器——开箱即用的 agent 工作环境，自带 shell/浏览器/MCP 面）+ `boxlite`（BoxLite micro-VM，进程内嵌无 daemon，隔离强度更高）；同一 OCI 镜像两侧通用，contract 收敛为 6 个必须方法、`spawn` 统一进程原语（文档 04 §2）。
- **MCP 集成用 @rekog/mcp-nest**（社区活跃、DI 无缝），装饰器隔离在 interface/mcp 薄壳层，停更时可换官方 SDK，Application/Domain 零改动。
- **调度先 First-Fit**（单机足够），Best-Fit 与多节点 NodeSelector 作为可切换策略预留。
- **凭证不走后端代理 OAuth**，而是"容器内 CLI 交互 + 前端展示链接/设备码 + 用户自己浏览器授权"——后端不接触用户密码，安全边界清晰。
- **终端断线恢复一律走 tmux re-attach**（sandbox 内 CLI 跑在 tmux 里）。**tmux 是镜像必须项**（04 §7，2026-08 由「建议」升为「必须」）——原先的备选「网关 ring buffer + grace timer」随无 tmux 降级档一起取消（06 §6.3）。
- **持久化 better-sqlite3 + Drizzle 起步**，Repository 接口隔离，>50 并发 sandbox 或 QPS>100 时迁 Postgres。
- **前端逐层验证**：boundaries lint（静态）+ Storybook story（每 view 强制）+ bun 单测（hooks/services）+ Playwright（关键链路），四层机器强制。
